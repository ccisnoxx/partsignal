# GEO 数据完整性与分析闭环实施计划

## 实施步骤

1. **历史检查与契约**
   - [ ] 实现当前有效链尾的只读关系检查并在目标环境清零。
   - [ ] 更新数据库契约、列表筛选、历史、候选和 Citation 口径。
2. **数据库约束与共享查询**
   - [ ] 复用 `0007` 已有的 `supersedes_id` 唯一约束，只在 `0014` 增加必要筛选和 Citation 索引。
   - [ ] 实现当前有效观测基础查询，供列表、指标和工作台复用。
   - [ ] 实现确定性 URL 值对象。
3. **创建关系门禁**
   - [ ] 校验“可能影响”和实际引用绑定发布的产品与状态。
   - [ ] 仅对绑定发布的 Citation 校验 URL。
   - [ ] 并发更正由数据库唯一约束最终拒绝。
4. **列表、指标与历史 API**
   - [ ] 列表支持产品、问题、模型、测试日期、准确性和历史开关。
   - [ ] 历史端点返回完整更正链。
   - [ ] 指标按确认分子分母计算，工作台复用同一谓词。
5. **前端分析与更正**
   - [ ] URL 驱动筛选和 query key。
   - [ ] 从行进入更正，锁定产品/问题/来源 ID，不显示内部 UUID 输入。
   - [ ] 增加历史查看、包含历史开关和发布候选选择器。
   - [ ] 工作台近期错误深链到对应筛选结果。
6. **测试与文档**
   - [ ] PostgreSQL 测试覆盖关系门禁、并发更正和共享谓词。
   - [ ] 前端组件覆盖组合筛选、日期边界、更正和空样本。
   - [ ] 更新指标定义与操作文档。

## 关键测试

- 跨产品、低状态和绑定发布 URL 不一致均返回明确 422。
- 未绑定发布的 OFFICIAL/EXTERNAL_COMPANY Citation 正确计入引用率。
- OTHER 和可能影响发布不提高引用率。
- 并发更正只有一条成功成为直接后继。
- 原记录更正后从默认列表、指标和近期错误移除，历史仍完整。
- 列表结果数、指标样本数和工作台计数在相同筛选下可复算。

## 回滚点

- 历史检查失败不执行约束迁移。
- 共享谓词不一致时停止上线，不在各端点增加临时差异分支。
- 前端筛选缓存串用时停止 GEO 页面发布，修正 query key 后恢复。

## Goal 3 补充门禁

- [ ] Goal 2 的发布状态、平台一致性和异常语义已稳定。
- [ ] 列表、指标、Dashboard 和历史 preflight 导入同一链尾查询构造，不各自实现过滤。
- [ ] 可能影响关系与实际 Citation 分别校验、分别展示、分别统计。
- [ ] `citation_rate` 只统计 OFFICIAL 或 EXTERNAL_COMPANY Citation；OTHER 和可能影响关系不进入分子。
- [ ] 并发更正只有一个直接后继，失败请求不产生部分 Citation、附件或发布关系。
- [ ] 相同筛选下列表当前样本数、指标 sample_count 和 Dashboard 计数可复算。
- [ ] 完成后停止；不自动提交、推送或进入 Goal 4。
