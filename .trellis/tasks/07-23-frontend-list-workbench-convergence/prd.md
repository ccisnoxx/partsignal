# 第一批“数据列表工作台统一”

## 目标

统一用户管理、平台管理、AI 渠道和审计日志的数据列表工作台结构与视觉语言，减少同类页面在标题、指标、筛选、表格、状态和操作层级上的偏差，同时保持真实数据、业务逻辑、权限、路由和功能行为不变。

## 已确认事实

- `.trellis/spec/frontend/visual-system.md` 是唯一人类可读视觉规范；`frontend/src/app/theme.ts` 和 `frontend/src/styles/global.css` 分别拥有运行时语义值和全局样式实现。
- `PageHeader`、`MetricTile`、`TableRegion`、`StatusTag` 的现有接口已覆盖本任务需求，无需扩展公开 props。
- 用户管理和平台管理已有真实服务端汇总数据，但仍使用页面私有指标卡。
- AI 渠道使用私有页面标题和状态展示；状态轨道是 URL 同步的筛选控件，不是指标卡。
- 审计日志已具备本批目标结构，没有真实汇总指标，因此不应增加指标卡。
- 调查时四页已使用真实 API 数据渲染，桌面与 375px 均无文档级横向溢出，宽表由局部区域滚动。

## 需求

1. 范围仅包括用户管理、平台管理、AI 渠道主工作台及右侧详情子表、审计日志。
2. 顶层页面统一使用 `PageHeader`；服务端真实汇总统一使用 `MetricTile`；宽表统一使用 `TableRegion`。
3. 已知业务状态统一使用 `StatusTag`，高密度表格使用紧凑模式，状态不能只依赖颜色。
4. 筛选栏必须保留原查询参数、分页和 URL 同步，并为需要的控件提供可见标签和可访问名称。
5. 每行只保留一个高频主入口，低频和危险操作进入 Ant Design `Dropdown`，危险操作继续使用原确认流程。
6. 保留现有真实数据来源、API 请求、权限判断、路由、详情选择、批量操作、自动刷新、敏感值遮罩、错误传播和成功反馈。
7. 保留 Ant Design、`@ant-design/icons`、现有主题和系统字体，不新增前端依赖或第二套视觉系统。
8. `global.css` 仅允许针对本批页面做局部调整和删除确定失效的私有规则，不得整体重写。
9. `ui-ux-pro-max` 仅用于信息层级、表格与筛选交互、响应式、可访问性和 anti-pattern 检查；不得运行 `--persist` 或生成平行设计系统。

## 验收标准

- [x] 用户管理和平台管理分别显示原有 5 个真实 `MetricTile`；AI 详情显示原有 4 个真实用量指标；审计日志和 AI 状态轨道不生成伪指标。
- [x] 用户、平台、AI 渠道、审计日志顶层区域都有唯一 `h1` 和一致的 `PageHeader` 层级。
- [x] 用户账户/状态、平台状态、AI 启用/测试/模型/日志结果、审计账户/结果状态均使用文字与语义色共同表达。
- [x] 平台取消整行详情入口；AI 渠道以操作列“配置/查看”为唯一详情主入口；业务路由和结果不变。
- [x] 320、375、768、1024、1440px 下无页面级横向滚动，宽表仅在 `TableRegion` 内滚动，固定操作列可到达。
- [x] 浅色、深色、跟随系统、真实 200% 浏览器缩放、仅键盘和 reduced-motion 场景通过检查。
- [x] 用户、平台、AI、审计的现有组件测试和目标 Playwright 流程通过。
- [x] TypeScript、ESLint/主题颜色检查和前端构建通过。
- [x] 未修改后端、契约、数据库、权限模型、共享组件公开接口或依赖清单。

## 排除项

- Dashboard、GEO、编辑审核页面和认证页面。
- 后端、OpenAPI、数据库、部署、主题色重构和全局视觉重写。
- Tailwind、shadcn、Lucide、Phosphor、Heroicons、Web Font、新 `PageShell`、页面配置系统、筛选工厂或卡片工厂。
- 审计日志新增指标、独立 `target_id` 筛选或新的移动端折叠筛选结构。

## 风险

- 当前工作区存在大量由其他任务产生的未提交修改，且目标页面、测试、主题和 `global.css` 有重叠。实施必须基于逐文件 diff 保留既有改动，不得整文件替换或提交非本任务内容。
- 现有 AI E2E 含旧布局的几何断言；只调整本任务实际影响的断言，继续验证三栏布局和原业务流程。
