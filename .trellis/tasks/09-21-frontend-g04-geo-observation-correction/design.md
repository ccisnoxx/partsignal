# G04 设计边界

- `correction-context` 是当前链尾、冻结身份和文章候选的唯一权威。页面路由身份、query key、表单上下文与上传草稿由同一更正会话持有；路由切换不能复用旧会话的提交状态。
- 成功上下文建立表单初值。后台刷新若失败、资格撤销或链变化，旧草稿可见但写入冻结；显式成功重读后，按 Published Article ID 合并用户输入，新的候选维持未选，退出候选移除。历史只读投影不进入写入 payload。
- 命令提交时固定当前上下文和新证据 ID，检查精确 query 状态及上传完成。POST 201 是终态，先解除离开保护与重复提交入口，再按响应 ID 导航，跨域缓存失效不阻塞交接。
- 三类 409 分开处理：候选变化与 successor 可恢复但需显式 GET；context incomplete 只允许完整显式 GET 成功后解冻。所有情况保留 request ID、草稿和已完成 Evidence，不自动重放。
