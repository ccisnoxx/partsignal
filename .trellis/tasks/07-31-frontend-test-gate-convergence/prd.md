# 前端测试门禁收敛

## 1. 目标

恢复可信、可重复且能在合理时间内完成的前端测试门禁：修正一处已经落后于复用 Prompt 设计的 E2E 断言，并依据测量结果消除完整 Vitest 的异常耗时。

## 2. 已确认现状

- 全量 E2E 最近结果为 `51 passed / 1 failed`；唯一失败位于 `frontend/tests/e2e/mvp-flow.spec.ts`，仍使用 `platform_profile_id` 打开 Prompt 页面并断言已删除的“当前平台”文案。
- 当前页面的权威选择参数是 `platform_prompt_id`；选中 Prompt 后，以“Prompt 使用平台”区域展示绑定平台。
- 完整 Vitest 使用正确工作目录运行时持续推进，并非已证明的死锁；但约 166 秒仅完成 4/25 个文件、75 个测试，已不适合作为可判定门禁。
- 07-30 `sitewide-table-list-guidelines` 的实现已基本完成，旧 AC7/AC8 阻断已由后续“验收门禁恢复”任务解决。本任务不合并、不归档该任务，只处理新的前端测试门禁问题。

## 3. 需求

### R1：Prompt E2E 与当前产品合同一致

- 使用测试已创建的 `platformPrompt.id` 作为 `platform_prompt_id` 打开页面。
- 验证选中的复用 Prompt 身份，以及“Prompt 使用平台”区域中的绑定平台，而不是恢复旧的按平台编辑界面。
- 保留后续平台 Prompt 预览流程和原有业务断言。

### R2：完整 Vitest 恢复为稳定门禁

- 使用 Vitest 原生命令按文件或分片采集耗时，区分单文件本身缓慢与跨文件累积问题。
- 根据测量结果定位共同所有者或具体慢测试，只修确认的根因。
- 不通过提高全局超时、盲目增加 worker、跳过测试、削弱断言或固定成功来掩盖问题。
- 不新增测试框架或依赖；优先复用现有 Vitest、React Testing Library 和项目测试设置。

### R3：门禁入口明确

- 仓库根目录的权威完整前端命令为 `npm --prefix frontend run test`。
- 直接调用 Vitest 时必须在 `frontend/` 工作目录运行；错误工作目录产生的 `document is not defined` 不作为缺陷证据。
- 验证记录应包含命令、耗时、通过数和失败数，能区分测试失败、性能超限与环境失败。

### R4：范围约束

- 默认只修改前端测试、测试配置和测试公共设置。
- 不处理 PS-QA-201～PS-QA-203 等产品 UI/UX 缺陷，不修改后端、合同、数据库或业务行为。
- 如果证据表明只能修改产品代码才能解决，停止实施并重新评审范围。

## 4. 验收标准

- [x] 定向 Prompt E2E 通过，并明确验证正确 Prompt 及其绑定平台。
- [x] 完整 `npm --prefix frontend run test` 连续两次通过；每次在当前工作站 300 秒内完成，无挂起、无失败、无跳过。
- [x] 完整 `make e2e` 通过，预期恢复为 `52 passed / 0 failed`；若用例总数发生合法变化，以实际全量零失败为准并说明差异。
- [x] `npm --prefix frontend run lint`、`npm --prefix frontend run typecheck` 与 `git diff --check` 通过。
- [x] 未以提高全局超时、增加 worker、跳过或弱化断言替代根因修复。
- [x] 没有产品业务代码、后端、合同、数据库和 07-30 任务归档改动。

## 5. 非目标

- 不建立新的测试运行框架、性能基准平台或通用诊断抽象。
- 不顺带修复浏览器控制台噪声、Ant Design 弃用提示或其他未证明影响门禁的告警。
- 不在本任务中完成 07-30 任务的最终验收、提交或归档。

## 6. 开放问题

无阻断性开放问题。Vitest 的具体根因必须由实施阶段的分文件/分片测量决定，规划阶段不预设修复位置。
