# 精简初始账号与管理员改密入口

## Goal

让开发阶段的线上验收环境只保留一个管理员账号和一个普通工程师账号，并让登录用户能从界面明确进入自助修改密码流程。

## Background

- 旧版 `seed-demo` 创建 `admin` 与五个职责分离普通账号；`0009_config_center` 将它们映射为一个 `ADMIN` 和五个 `ENGINEER`，因此升级后的线上验收环境仍显示多个普通账号。
- 当前初始化命令只幂等确保 `admin`，不会清理旧账号。
- 后端已提供 `POST /api/v1/auth/change-password`，但工作台导航没有普通自助改密入口。
- `users` 被多张业务历史表通过 `RESTRICT` 外键引用；删除已产生业务数据的用户不能静默级联或清空历史归属。

## Requirements

- R1：旧版六个初始化账号清理后只保留 `admin` 管理员与 `content_editor` 普通工程师；管理员后续明确新增的其他账号不受清理影响。
- R2：本次允许物理删除旧版初始化产生的其他普通账号：`product_editor`、`product_reviewer`、`content_reviewer`、`analyst`。
- R2.1：物理删除只属于本次升级清理，不新增通用删除用户 API，也不在用户管理界面长期提供删除按钮；后续账号继续使用启用/停用生命周期。
- R3：物理删除不得级联删除产品事实、内容、发布、观测、配置或审计数据；存在业务外键引用时必须显式失败并报告被引用，不能猜测迁移归属。
- R3.1：四个目标账号在同一事务中清理；任一账号存在业务引用时整次清理回滚并列出被引用账号，不允许部分删除。
- R4：登录用户可从工作台顶部账号区域进入“修改密码”，提交当前密码和新密码；继续复用现有后端自助改密、撤销其他会话和审计规则。
- R5：管理员仍可新增 `ADMIN` 或 `ENGINEER`、重置其他用户密码，并保留最后管理员保护。
- R6：管理员不能通过管理接口重置自己的密码，必须使用自助改密并验证旧密码。
- R7：空数据库初始化命令自动创建 `admin` 与 `content_editor`；普通账号使用独立环境变量 `PARTSIGNAL_SEED_ENGINEER_PASSWORD`，且新建时设置 `must_change_password=true`。
- R7.1：初始化命令保持幂等，不得在重复部署时覆盖任一既有账号已经修改过的密码。
- R7.2：升级环境中已存在的 `content_editor` 保留当前密码，只设置 `must_change_password=true`；密码遗失时由管理员使用既有临时密码重置流程处理。
- R8：用户管理默认只展示启用账号，并允许管理员显式切换查看停用账号；这不改变服务端账号生命周期或权限判断。

## Acceptance Criteria

- [ ] 从旧版六账号数据升级后，数据库只剩 `admin` 与 `content_editor`；被删除账号的会话同时删除。
- [ ] 删除目标旧账号前若发现业务历史引用，迁移或清理操作显式失败且不产生部分删除。
- [ ] 新安装和重复部署不会重新创建已移除的旧职责账号。
- [ ] 空数据库初始化后恰有 `admin` 与 `content_editor` 两个账号，二者初始密码来源独立，`content_editor` 首次登录被强制改密。
- [ ] 管理员与普通工程师都能从顶部账号区域进入修改密码页面。
- [ ] 管理员使用正确旧密码可以修改自己的密码；错误旧密码失败，其他会话被撤销，密码不进入日志或审计详情。
- [ ] 管理员仍可新增后续用户，最后一个有效管理员不能被删除、停用或降级。
- [ ] 用户管理默认不显示停用账号，管理员可以显式查看并重新启用长期账号。
- [ ] 数据库迁移测试、身份接口测试、前端测试与账号 E2E 通过。

## Out Of Scope

- 删除或改写已由用户创建的业务历史记录。
- 免旧密码修改当前登录账号密码。
- 忘记密码、邮件找回、短信验证和外部身份提供商。
