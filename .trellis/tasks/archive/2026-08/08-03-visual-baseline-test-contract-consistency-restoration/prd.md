# 视觉基线与测试合同一致性恢复

## 1. 目标

恢复发布候选缺失的 11 张自动视觉基线，并让全部截图断言统一遵守 `.trellis/spec/frontend/visual-system.md` 规定的 `maxDiffPixelRatio: 0.02`，使视觉 E2E 能在真实隔离栈中完成有效比较，而不是因资产缺失或局部放宽阈值失去发布门禁能力。

本任务只修复视觉测试资产与测试合同，不重新设计页面，不修改业务行为、API、数据库、权限、主题、视觉规范或发布取消回焦问题。

## 2. 已确认事实

- 上线前最终发布候选验收在提交 `56ae5ac5b660438c2f8a6adfef6c82005e6136b2` 上运行 `make e2e`，结果为 51 通过、1 失败；唯一运行失败是 11 个预期视觉快照不存在。
- `56ae5ac` 相对父提交 `20108f2326f010bebff683cb29c75078d67cfb25` 精确删除 11 张 `cross-page-visual-convergence` 基线，同时新增 9 个 `frontend/.playwright-cli/` 诊断文件；没有修改产品代码或视觉测试源码。
- 父提交完整持有 11 张删除前基线：用户、Prompt、GEO 洞察各自的 1440×1000 浅/深色和 375×900 浅色九张，以及 Dashboard、内容审核两张 1440×1000 浅色锚点。
- Dashboard 与内容审核基线分别由已归档任务 `08-02-dashboard-visual-baseline-sync`、`08-02-content-review-visual-baseline-sync` 在用户明确批准后同步；删除前 SHA 可由父提交精确复核。
- 2026-07-25 的视觉系统重校准任务保存了 13 张用户明确批准的 1440×1000 浅色人工原图，并确认 `visual-system.md` 是唯一视觉规范；自动快照与人工批准原图分开维护。
- 当前 `cross-page-visual-convergence.spec.ts` 的桌面六张、用户移动一张和两张桌面锚点使用 `0.02`，但 Prompt、GEO 两张移动截图通过条件表达式使用 `0.035`。
- `visual-system.md` 明确要求 11 张截图固定使用 `0.02`，不得通过扩大阈值、整块遮罩、`skip`、固定成功数据或兼容 fallback 消除失败。
- 发布候选验收生成的 11 张 actual 已记录路径与 SHA 后精确清理，不能直接作为新基线；当前工作区没有残留快照目录。

## 3. 范围内要求

### R1. 基线来源与批准边界

- 基线必须来自可审计的既有批准链或本任务重新取得的明确视觉批准，不得把 E2E 自动生成的 actual 直接认可为基线。
- 已批准方案是精确恢复父提交 `20108f2` 中被 `56ae5ac` 删除的 11 个 Git blob，不重绘、不压缩、不批量生成替代资产。
- 若恢复后在统一 `0.02` 阈值下出现稳定视觉差异，必须停止并展示精确候选，取得用户对对应页面、主题和视口的明确批准后才能更新该基线。

### R2. 单一阈值合同

- 11 个 `toHaveScreenshot` 断言全部使用 `maxDiffPixelRatio: 0.02`。
- 删除 Prompt/GEO 移动截图的 `0.035` 条件分支及其放宽阈值注释，不增加其他阈值例外。
- 保持截图名称、视口、主题、既有精确动态遮罩、动画与光标设置不变；不得通过扩大遮罩规避严格阈值。

### R3. 产品与测试边界

- 不修改产品 TSX、CSS、主题 Token、API、合同、数据库、迁移、权限、业务状态或 E2E 数据准备。
- 不修改 Playwright 配置、snapshot path template 或视觉用例名称，除非实施证据证明当前恢复流程无法使用既有配置；任何此类发现必须返回规划评审。
- 不使用 `--update-snapshots` 批量接受 11 张图片；只允许对经过批准且精确归因的单张资产进行替换。

### R4. 验证与清理

- 先在真实隔离栈中运行目标视觉用例，确认 11 张基线均被消费且统一 `0.02` 下通过。
- 再运行完整 `make e2e`，记录通过、失败、跳过数量、耗时和首个失败；独立失败不得授权扩大本任务修改范围。
- 每次运行都必须确认隔离数据库和临时对象存储输出 `status=deleted` 且实际不存在，开发 Frontend 恢复到执行前边界。
- 精确清理 `test-results`、`playwright-report` 和本轮工具诊断产物，不删除既有会话、共享数据或无所有权文件。

## 4. 范围外

- 不修复发布“更多操作 → 标记已移除 → 取消”后的焦点恢复；该问题另行立项。
- 不重新设计或人工美化用户、Prompt、GEO、Dashboard、内容审核或共享壳层。
- 不改变 `visual-system.md` 的 `0.02` 合同，不为 Linux 字体换行建立阈值例外。
- 不恢复或提交 `frontend/.playwright-cli/` 诊断文件，不处理其他历史浏览器产物。
- 不运行上线前最终发布候选验收的七项完整门禁；本任务闭环后由新的冻结提交另行重跑最终验收。

## 6. 已确认决策

- 父提交 `20108f2326f010bebff683cb29c75078d67cfb25` 中被删除的 11 个精确 Git blob 是本任务唯一初始恢复源。

- 不批量更新快照，不扩大阈值、遮罩或修改页面来迁就旧基线。
