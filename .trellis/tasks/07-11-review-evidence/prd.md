# 事实与内容审核证据闭环

## Goal

让事实维护者、内容编辑者和审核者能够读取完整退回意见，并在批准内容前基于任务锁定的冻结事实和证据完成可追溯审核。

## Requirements

- 事实与内容审核记录以追加式历史只读展示，包含动作、意见、操作者和时间，不覆盖旧记录。
- 被退回者刷新后必须看到最新意见和完整历史，不能只看到状态。
- 内容审核视图必须展示当前正文、质量问题、版本差异、绑定事实版本的关键参数、测试条件、替代边界和证据。
- 审核上下文只能来自任务锁定的不可变事实版本和生成快照，不读取当前可编辑事实工作区作为替代来源。
- 阻断质量问题继续由服务端禁止批准，前端隐藏或提示不能代替服务端门禁。
- 事实与内容 `request-changes` 必须填写非空意见；`submit` 与 `approve` 意见可选，但批准需要显式确认。

## Acceptance Criteria

- [x] 事实和内容经过提交、退回、重新提交与批准后，所有历史意见按稳定顺序可读取。
- [x] 审核者无需离开内容页即可核对当前正文、差异、冻结事实、证据和替代边界。
- [x] 后续事实版本变化不会改变历史内容审核上下文。
- [x] 缺证据、事实退役、历史版本和阻断质量问题均有明确显示与正反向测试。
- [x] OpenAPI、运行时 Schema 和前端生成类型保持一致。
- [x] 空退回意见被服务端拒绝，提交和批准允许空意见；所有审核动作都形成追加式历史。

## Out Of Scope

- 不改变已批准事实和内容不可原地修改的规则。
- 不在本任务中引入新的账号类型或细粒度权限系统。

## 最终计划同步

- 有效优先级：`P1`；属于最终执行顺序 Goal 2，与发布闭环同批完成并等待 Goal 1。
- 发布与审核先共同冻结 OpenAPI，再按各自领域边界实现，避免共享 Schema 和前端生成类型冲突。
- 已确认新增 `GET /fact-versions/{id}/review-context`、`GET /content-versions/{id}/review-context`、统一 `ReviewRecord` 和演员摘要。
- `request-changes` 使用去除空白后非空的专用请求；`submit`、`approve` 意见可选。旧空意见记录只读展示，不补造数据。
- 本任务预计不新增业务表；现有审核记录是唯一历史来源。
