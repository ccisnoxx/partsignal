# 技术设计

## 1. 扫描边界

以最终 `frontend/src` 路由树为清单，逐页检查管理员和工程师路径：登录/改密、概览、产品事实、内容任务与生成、内容审核、发布、GEO、配置中心、用户管理和设置。

扫描同时覆盖：

- JSX/TSX 文本、Ant Design `title`、`label`、`placeholder`、`help`、`message`、`description`、空状态和通知。
- 页面配置、菜单、路由元数据、表格列、筛选器和图表文案。
- 表单规则和前端异常转换。
- 浏览器真实渲染后仍可见的英文文本。

`rg` 用于建立候选清单，但不能把正则零命中当成完成证据；技术术语、测试选择器和机器值必须人工区分。

## 2. 文本所有权

不引入 i18n。文本放在最接近权威业务所有者的位置：

- 跨页面稳定状态由现有 `StatusTag` 或相应共享展示映射统一维护。
- 角色等多个页面共同使用的稳定枚举使用一个共享 `{value,label}` 映射。
- 页面专属枚举和提示留在对应 feature。
- 后端业务错误若作为用户可见 message 直接展示，在后端权威异常处改中文；`error.code` 和 `details` 结构不变。
- 未知异常保持现有安全兜底机制，但兜底提示本身使用中文，不把原始敏感错误直接暴露给用户。

这避免建立第二套业务状态或无边界翻译字典。

## 3. 保留术语与值

下列内容以原值展示：`model_id`、API Key、URL、Markdown、JSON、Header、Prompt、HTTP 方法、Header 名、模型 ID、自定义参数键和 slug 值。

不直观但需要运营理解的字段采用中文标签加括号术语，例如：

```text
唯一标识（slug）
API 根地址（base_url）
模型标识（model_id）
```

显示 label 与提交 value 必须分离。不得修改 OpenAPI 枚举、后端常量、query key、路由路径或数据库值来实现中文化。

## 4. 状态与枚举一致性

先盘点现有 `StatusTag`、Select options 和局部映射，再决定唯一显示词。优先复用已存在且准确的中文，不重复创建映射。测试至少断言：

- 每个机器值有预期中文 label。
- 同一机器值在状态标签、筛选器和表单选项显示一致。
- 选择中文项后提交的仍是原机器值。
- 未知机器值按现有显式错误边界处理，不猜测翻译或静默显示错误状态。

## 5. 响应式与可访问性

- 中文按钮和标签允许合理换行，但关键操作保持可辨识、可点击。
- 表格优先使用现有响应式策略，不通过缩小到不可读字号解决溢出。
- 图标按钮继续提供中文 `aria-label`/Tooltip。
- 375/768/1024/1440 宽度以及浅/深色主题执行浏览器检查。
- 不因文案变化增加无意义动画、渐变或全局样式重构。

## 6. 验证策略

1. 用 `rg` 生成英文候选清单并逐项分类为“应翻译”“保留术语/数据”“非用户可见”。
2. 运行受影响组件和页面测试，断言中文展示和原 value 提交。
3. 运行前端全量测试、lint、typecheck 和 build。
4. 用管理员和工程师账号浏览关键路由，检查空状态、错误状态、弹窗和移动端。
5. 在 E2E 中保留稳定选择器，避免依赖可变文案定位；必要文案断言改为中文。
