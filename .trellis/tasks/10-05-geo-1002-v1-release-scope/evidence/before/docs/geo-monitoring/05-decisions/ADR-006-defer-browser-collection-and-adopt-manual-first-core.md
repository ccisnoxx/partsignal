# ADR-006：人工优先核心版与浏览器采集延期

- 状态：Accepted
- 日期：2026-10-05
- 接受依据：本会话用户明确变更产品决策，要求新增并接受本 ADR；未提供具名审批人，不补造审批身份。
- 适用范围：核心版采集方式、R7 剩余任务排期、R8 发布门禁；不改变 MANUAL/API 业务行为、指标或历史数据。
- 替代范围：替代 [ADR-005](./ADR-005-staged-collector-rollout.md) 及其 GEO-002 修订中“完整核心版首发必须具备至少两个自动化观测面及一个真实界面试点/受控试运行”的要求。其平台批准、外发、发送隔离、凭据、不可变和测试安全边界继续有效；保留原 ADR 与评审历史。

## 背景

公司当前先由员工在豆包、DeepSeek、元宝等真实平台人工执行精确问题，再向 PartSignal 登记完整回答、引用来源、截图和环境信息。这些平台名称描述人工观测场景，不代表批准任何 Browser Adapter、账号自动化或网络访问。

GEO-801、802、803 已真实完成并人工接受，分别提供独立隔离骨架、加密会话治理和本地合同套件。GEO-804 尚未实施真实 Adapter，原先因唯一平台批准范围及受控 staging smoke 授权/入口缺失而 blocked。GEO-805～807 尚未实施。R8 的依赖图没有指向 R7，但旧路线图、产品首发和无条件会话恢复要求形成了隐式门禁。

## 决策

1. MANUAL 回答级观测是核心版正式采集方式，按 [人工观测 SOP](../02-business/05-manual-geo-observation-sop.md) 执行，进入已有 Batch/Run、证据、分析、人工复核、指标、行动和复测闭环。它与旧文章关系级观测保持不同模型和分母。
2. 保留已有 API 能力；API 仅按实际批准与部署范围启用。核心上线不要求先增加两个自动化观测面，不因 MANUAL 优先删除或改变已有 API。
3. Browser Collection 是核心版之后的可选自动化扩展，保留目标设计及 GEO-801～803 的 done 状态、代码、测试和验收历史。
4. GEO-804、805、806、807 进入 `deferred`，`phase: R7` 保留原阶段归属，`release: post-core` 表示延期发布。deferred 不等于 done，也不等于实现失败；原 blocked 原因作为历史和恢复输入保留。
5. 核心发布顺序为 R6 → R8。R7 不再是核心发布前置门禁，不作为 R8 的直接或隐式依赖；R8 原有核心安全、恢复、性能与生产验收仍须完成。
6. 核心生产必须保持 `GEO_BROWSER_COLLECTION_ENABLED=false`，不启用 `geo-browser` 服务或会话挂载/能力凭据，不存在生产 Browser 会话。GEO-904/906 必须在目标环境核实，不能从仓库默认值推断生产事实。本次仅文档调整，未执行生产检查。
7. Browser 临时数据清理与会话恢复仅在 R7 已部署或实际存在相关材料时适用。未部署且确认无材料时标记有依据的 N/A；已有密文、密钥、会话引用或临时数据不能因延期而绕过保护、撤销、清理或恢复责任。

## R8 条件性验收

| 任务 | 核心版验收 |
|---|---|
| GEO-901 | raw payload、草稿、无引用文件的保留/清理仍必需；Browser 临时数据仅在部署或存在材料时适用，否则记录 N/A 及检查依据 |
| GEO-903 | 数据库、OSS 和适用密钥恢复仍必需；未部署 R7 且无 Browser 材料时，会话恢复 N/A；存在材料时仍须保护并验证恢复/撤销，不将历史证据一并豁免 |
| GEO-904 | 验证 Browser 开关 false、服务/profile 未启用、无生产会话/会话材料；MANUAL/API 的权限、CSRF、SSRF、secret 等检查不放宽 |
| GEO-906 | R7 deferred 不阻断核心上线；MANUAL 正式闭环及 R8 依赖完成，目标环境 Browser false、无生产会话，并记录试用、停止/恢复和监控证据 |

## 影响与约束

- 人工工作量和平台可变性需要明确责任、重复采样和数据质量检查；计划创建 Run 不代表平台已经返回回答。
- URL、模型版本或环境未知时记录证据和限制，不猜测、不把失败记成零表现；当前表单无法表达的完整样本先留草稿补证。引用缺失不改变既有服务端资格公式。
- MANUAL/API/BROWSER 默认分开，语言、地区、登录、问题版本与采样口径不静默混合；未知版本可能继续阻断严格复测。
- 不新增公共 API、数据库状态、Alembic revision、公式或生产部署动作；deferred 仅为交付治理状态。
- 不实现、模拟或访问真实平台 Adapter，不使用第三方账号/Cookie，不删除完成基础设施。CI 继续只用 fake provider/本地模拟站。

## R7 恢复条件

1. 产品明确重新排期，并指定产品、合规、工程与运维责任；当前这些后续责任尚待指定，不伪造姓名或承诺日期。
2. 明确唯一平台/真实域名及可定位批准记录，覆盖专用账号非敏感标识、用途、环境/地区、频率/并发、数据保留、停止和撤销规则；秘密只通过已有受保护通道提供。
3. 提供受控 staging smoke 的人工授权、入口和验收负责人。获准人工观测或已有 API 配置不等于获准浏览器自动化。
4. 重验 801～803 与每项前序依赖、当前 DOM/安全/网络/发送隔离及配额设计；按 task-manifest 和 Task Brief 逐项解除延期，重新评估 ready，不自动执行历史提示词。
5. 804～807 依序实现、本地合同与授权 staging 验证后进入 review，人工接受后才 done；全部试点门禁满足并取得独立生产启用授权后，方可评估 Browser 开关。不得绕过验证码、访问控制或反自动化保护，也不得批量扩展平台。
