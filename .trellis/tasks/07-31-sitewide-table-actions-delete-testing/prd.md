# 全站表格操作与删除安全测试

## Goal

以专业测试和产品审查视角，对上线页面中的全站表格/列表、操作列和删除流程进行系统测试，找出业务逻辑、交互一致性、权限与数据安全问题，并形成可复现、可分级、可回归的缺陷清单和发布风险结论。

## Background

- 用户已在上线页面观察到多处表格/列表问题。
- 部分页面的操作列功能不完整。
- 不同页面的删除行为存在明显差异，部分行为不符合用户预期。
- 删除流程需要重点审查安全性，不能只验证按钮是否可点击。
- 仓库中已有“统一全站表格列表规范”任务正在进行；本任务负责测试与产品验收，不默认替代该任务的实现范围。
- 规划取证发现 `docs/deployed-full-functional-acceptance-plan.md:684` 起包含完整 SSH 私钥；该文件已被 Git 跟踪且存在提交历史，当前 `main` 与 `origin/main` 无分叉。必须按凭据已泄露处理，不能仅删除当前文件内容后继续使用原密钥。

## Requirements

1. 在任何部署环境测试前完成泄露 SSH 凭据的撤销/轮换，从当前树移除秘密，并决定 Git 历史与远端副本的清理方式；不得使用已泄露密钥做验证。
2. 建立全站表格/列表页面清单，并记录页面入口、数据对象、用户角色和可用操作。
3. 检查表格结构、字段含义、排序、筛选、分页、空状态、加载状态、错误状态和响应式表现。
4. 检查操作列是否覆盖对象当前状态下允许的完整操作，并验证显示、禁用、提示和执行结果一致。
5. 对所有删除入口进行专项测试，至少覆盖权限校验、对象状态限制、关联数据影响、二次确认、重复提交、失败反馈、删除后页面与数据库状态一致性。
6. 验证服务端是删除权限和状态转换的最终裁决者；隐藏前端按钮不得作为安全控制。
7. 区分归档、软删除、硬删除及禁止删除等语义，不把名称相同但业务含义不同的操作强行统一。
8. 每个缺陷记录复现步骤、前置条件、期望结果、实际结果、严重程度、证据和影响范围。
9. 修复前先完成缺陷确认和优先级评审；修复后执行针对性回归，并检查同类页面是否存在相同根因。

## Acceptance Criteria

- [ ] 形成可追踪到页面、数据对象、角色和接口的全站表格/列表测试矩阵。
- [ ] 已泄露 SSH 密钥完成服务端撤销/轮换，仓库当前版本不再包含私钥，并对 Git 历史、远端副本和其他暴露位置形成明确处置结论。
- [ ] 所有操作列功能均有“允许显示、允许执行、禁止执行”三个层面的验证结果。
- [ ] 所有删除入口均有正常、异常、越权、状态冲突、重复操作和关联数据影响的测试证据。
- [ ] 每个确认缺陷都有唯一记录、严重程度、可复现证据和明确的预期行为；需求歧义单独列为产品决策项。
- [ ] P0/P1 缺陷完成修复与回归前，不给出可安全发布结论。
- [ ] 输出测试报告，明确已覆盖范围、未覆盖范围、缺陷分布、阻断项和残余风险。

## Out of Scope

- 规划阶段不修改业务代码。
- 未经确认，不执行不可恢复的数据删除或生产数据破坏性测试。
- 本轮不把与表格、操作列、删除及其直接业务链路无关的普通视觉润色作为核心范围。

## Open Questions

- 是否授权立即暂停常规规划，先从当前工作树移除已泄露私钥并建立安全处置步骤；服务端撤销/轮换及 Git 历史重写需要另行确认权限与影响。
- 需要确认生产环境允许执行到什么程度的删除安全测试，以及是否应默认在本地或专用测试数据上完成破坏性场景。
