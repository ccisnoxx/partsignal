在一个新的冻结提交上重新执行七项自动化门禁与关键页面真实浏览器 smoke，验证首次发布候选验收发现的阻断已经闭环，并输出唯一、可机械复核的 `GO` / `NO-GO` 报告。

## 3. 预期范围

### R1. 启动前置条件

- 正式启动复验前，冻结候选必须同时包含视觉修复 `e3dbe81` 与发布确认取消回焦修复 `a778393`，并核对两项归档报告中的针对性验证结果。
- 当前前置条件已满足；若启动时 HEAD、分支或修复提交包含关系发生变化，则停止取证并重新评审冻结候选，不在未知候选上运行耗时门禁。

### R2. 冻结与七项自动化门禁

- 在同一冻结提交上依次运行 `make contract-check`、`make test-unit`、`make test-integration`、`make e2e`、`make lint`、`make typecheck`、`make build`。
- 每项记录开始/结束时间、退出码、通过/失败/跳过数量、耗时和首个权威失败；失败不授权本任务修复。
- E2E 必须使用隔离数据库与临时对象存储；运行前控制共享 Redis 消费竞争，结束后恢复开发服务并验证资源精确清理。

### R3. 关键页面 smoke

- 复用首次验收的匿名边界、管理员桌面页面组和移动关键页矩阵，使用真实同源 `/api`，不 mock、不保存凭据、不写共享业务数据。
- 必须重新验证发布候选/记录 Drawer 回焦、发布“更多操作 → 标记已移除 → 取消”回焦和审计详情回焦；取消后焦点必须回到原触发器，不得落到 `BODY`。
- 检查页面身份、主要区域、请求失败、5xx、未解释 console error/warning、移动横向溢出和关键焦点结果。

### R4. 清理、报告与判定

- 精确清理本轮 E2E 数据库、临时对象存储、浏览器会话、测试报告和本轮工具诊断产物，不触碰既有资产或其他会话。
- `GO` 要求七项命令、全部关键 smoke、冻结复核和清理均为 `PASS`；任一 `FAIL`、`BLOCKED`、漂移或清理失败均为 `NO-GO`。
- 最终差异只允许当前 Trellis 任务资料；不部署、不 push、不创建 release。

## 4. 范围外

- 不在本任务中修复发布确认取消回焦、共享 Redis 隔离或本轮新发现的其他缺陷。
- 不修改视觉基线、阈值、测试断言、Playwright 配置或门禁命令。
- 不调用真实第三方 AI、生产 OSS 或真实发布渠道；不执行性能、容量、渗透、灾难恢复或生产数据迁移。
- 不重复第二轮全项目人工功能回归；本轮只执行七项门禁与批准的关键页面 smoke。
