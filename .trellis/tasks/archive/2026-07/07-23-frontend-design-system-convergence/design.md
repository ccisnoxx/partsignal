# 技术设计

## 1. 设计结论

本任务使用一份 Trellis 前端规范约束设计意图，继续由现有主题和全局样式承担运行时实现，不新增 `design-system/` 目录或平行文档。

```text
.trellis/spec/frontend/visual-system.md
        │  定义必须遵守的视觉与交互契约
        ↓
frontend/src/app/theme.ts
        │  提供唯一运行时语义颜色、状态、图表、玻璃与阴影值
        ↓
frontend/src/styles/global.css + Ant Design ThemeConfig
        │  实现全局尺度、壳层和组件视觉
        ↓
业务页面与共享组件
        └─ 只能消费契约；局部布局不得形成第二套系统
```

用户提供的原型总结决定视觉方向；`ui-ux-pro-max` 仅作为 UX、可访问性和反模式检查来源。Skill 自动生成的配色、字体、页面模式或依赖建议与本规范冲突时一律丢弃。

## 2. 文件边界

| 文件 | 责任 | 本任务变更 |
|---|---|---|
| `.trellis/spec/frontend/visual-system.md` | 唯一人类可读视觉规范 | 新增 |
| `.trellis/spec/frontend/index.md` | 前端规范导航与适用范围 | 增加链接并更新状态 |
| `frontend/src/app/theme.ts` | 唯一运行时主题值与 Ant Design 映射 | 只读，不修改 |
| `frontend/src/styles/global.css` | 全局字体、尺度、动效、壳层和 Token 消费 | 只读，不修改 |
| 共享组件与业务页面 | 复用既有契约 | 只读，不修改 |
| `design-system/MASTER.md` | 不属于本项目规范体系 | 不创建 |

规划文件 `prd.md`、`design.md`、`implement.md` 只记录任务范围与验收，不构成第二份稳定视觉规范；任务完成后稳定规则只从 `visual-system.md` 读取。

## 3. 规范结构

`visual-system.md` 按实现时的检索顺序组织：

1. 适用范围与权威来源。
2. 核心视觉方向与硬约束。
3. Token 与实现所有权。
4. 颜色、字体、布局和尺度。
5. 表面、玻璃、圆角和阴影。
6. 三类页面结构及特殊页面边界。
7. 卡片、表格、表单、按钮、状态、图标和图表。
8. 动效、响应式、浅色/深色与可访问性。
9. 复用规则、允许的局部例外与禁止模式。
10. 实施和验收清单。

规则使用“必须 / 应当 / 不得 / 仅当”。示例值只在它们本身就是视觉契约时出现；主题颜色不复制十六进制值，而是引用 `theme.ts` 中的现有语义角色，防止文档与运行时漂移。

## 4. 兼容与迁移

- 本任务没有运行时迁移，发布行为和用户界面均不变化。
- 新规范描述后续实现必须达到的目标，不声称历史页面已经全部符合。
- 发现现有页面违反规范时，只记录为后续视觉一致性审计输入；不得在本任务顺手修复。
- 若未来需要调整品牌色、增加 Token 或改变共享组件，必须另建任务，以原型实测、重复使用证据和可访问性结果为依据。
- 页面特有布局可以保留局部 class，但不得定义原始颜色、独立字体栈、平行状态色或另一套卡片表面。

## 5. 取舍

- 不采用 skill 的 `--persist`：Trellis spec 已承担跨会话检索，额外 Master 只会制造重复权威。
- 不复制全部主题色值到 Markdown：运行时值由 `theme.ts` 唯一拥有，规范只定义角色和使用边界。
- 不新增图标或字体依赖：现有 Ant Design Icons 与系统字体已满足统一性，新增依赖只会引入第二种视觉语言。
- 不抽象通用页面壳：三类页面结构是构图契约，不是要求所有页面使用同一 React 组件。
- 不在规范任务中同步修复页面：文档固化与页面迁移可独立验收，混合实施会扩大 diff 并掩盖既有改动。

## 6. 回滚

本任务仅涉及 Markdown。若规范内容与已确认范围不符，精确修改或删除本任务新增段落即可；不得使用破坏性 Git 命令，也不得回退工作区内其他未提交变更。
