# AI 渠道与模型管理页面

## 目标

在现有配置中心和 AI 配置单一数据源上实现“AI 渠道与模型”管理页面，以用户提供的桌面原型图为视觉基准，补齐渠道、凭据、请求 Header、模型、连接测试、权限与审计的真实管理闭环；不得建立平行配置体系、模拟成功路径或泄露敏感信息。

## 背景

- 项目已有配置中心、AI 渠道、Header、模型与调用链，本任务必须先确认其真实契约、数据所有者和调用关系，再决定改动范围。
- 现有 `07-13-configuration-center-navigation` 任务只覆盖前端信息架构与既有接口复用，并明确排除 OpenAPI、数据库和权限契约；其范围和视觉方案均不足以覆盖本任务。
- 工作区存在其他未提交变更，本任务不得覆盖、清理或提交不属于本任务的改动。

## 已确认事实

- 系统唯一支持的供应商协议是 `openai-compatible-chat-completions`，不存在可选择的 Provider 适配器枚举；未支持协议必须明确失败。
- 现有渠道列表响应一次返回 Header 和全部已启用模型摘要，前端不需要为数量再请求每个渠道的模型。
- 模型测试是真实、无业务数据的 Chat Completions 请求；测试对象必须是具体模型，渠道自身没有无模型测试语义。
- 单个生成作业最多调用供应商一次，不执行自动重试；显式重试会创建新作业并保留原非敏感快照。
- API Key 和敏感 Header 已使用认证加密保存，读取投影不返回明文；URL、DNS、TCP peer、Header、重定向和响应大小已有统一安全边界。
- AI 配置读取和写入均由服务端 `ADMIN` 权限控制，写请求还受 CSRF 保护；渠道、Header 和模型 CRUD/启停已有审计，模型测试与模型发现缺少审计。
- 渠道删除级联当前 Header/模型，并把历史作业外键置空；不可变快照保留历史含义，待执行作业遇到已删除配置会显式失败。
- 渠道没有描述字段；渠道级最近测试可从子模型确定性投影；调用状态、耗时和 token 已在 `generation_jobs` 保存，但没有渠道统计读取接口。

## 已确认产品方向

- 当前处于开发阶段，本任务以长期一致的目标态为准，不以最少改动或保持现有公共契约为优先目标。
- 允许在同一任务中调整 OpenAPI、数据库、权限、审计和前端生成类型；过时结构应直接替换，不保留双写、双读、兼容别名或平行页面。
- “最好方案”仍必须建立在真实业务语义上：原型字段需要明确所有权、状态机和安全边界，不能因为开发阶段而伪造供应商能力、统计、成功响应或模糊默认值。
- 渠道协议类型与供应商品牌分离：协议类型决定服务端适配器和真实调用能力；品牌只用于管理端识别、筛选和图标展示，不能改变调用语义或代表某个原生协议已经实现。
- 供应商品牌采用受控目录 `OPENAI | ANTHROPIC | GOOGLE | AZURE_OPENAI | ZHIPU | QWEN | CUSTOM`；`CUSTOM` 使用通用图标并由渠道名称表达具体身份，不增加自由文本品牌字段。
- 品牌与协议组合必须在服务端受控目录中有效；未知品牌、未知协议或未注册组合明确失败，不做隐式适配、别名兼容或自动回退。
- 供应商调用采用 `AT_MOST_ONCE + 显式手动重试`：开始发送 HTTP 字节后不自动重试；连接发送前可尝试同次安全解析中已批准的地址；失败后由用户显式创建新的可追踪作业。
- 使用统计只计正式业务生成和自然化作业，连接测试与模型发现归入测试状态和审计日志；默认最近 30 天，并提供 7 天、30 天、90 天和全部时间。
- 使用统计展示业务作业数、成功/失败数、成功率、平均响应时间、Token 用量和最近使用时间；无法由供应商响应确认的数据保持为空，不估算或补零。
- 顶部全局搜索只搜索当前用户有权访问的页面、导航名称和功能关键词，并跳转到既有路由；渠道搜索仍由本页负责，不在本任务中伪造跨内容、任务、平台或数据的聚合搜索。

## 需求

### R1 配置中心与页面结构

- 复用现有配置中心路由和页面，不建立平行页面或第二套路由状态。
- 配置中心左侧导航应提供：内容平台、平台规则、平台 Prompt、AI 渠道与模型、用户与权限、审计日志；具体 URL 和与现有一级导航的关系以现有路由、业务所有权及调查结论为准。
- 页面包含顶部面包屑、权限感知的页面与功能导航搜索、用户操作区，以及页面标题、“测试连接”“新增渠道”操作；全局搜索支持 `⌘/Ctrl + K`。
- 桌面主工作区按原型形成渠道状态分类、渠道表格和右侧详情面板三栏结构；以用户提供的原始 PNG 实际尺寸 1570×1001 为主要视觉验收基准。

### R2 渠道集合

- 展示全部、已启用、已停用分类及真实数量。
- 支持按渠道名称、描述或 API 根地址搜索，按状态和供应商品牌筛选，按已确认字段排序，并支持真实分页。
- 表格展示渠道名称与图标、启用状态、API 根地址、API Key 配置状态、Header 数量、已启用模型数量、最近测试状态和时间，以及测试、配置和更多操作。
- 搜索、筛选、排序、分页和渠道选择必须真实可用；选择渠道后右侧详情与 URL/页面状态的权威关系必须唯一且可恢复。

### R3 渠道详情与维护

- 详情面板提供基本信息、请求配置、模型管理、使用统计、操作日志页签；每项数据必须来自本任务确认的权威投影，不得伪造。
- 基本信息展示渠道名称、描述、协议类型、供应商品牌、API 根地址、状态、API Key 配置状态、请求 Header、超时、重试策略、创建及更新时间和创建人；重试策略固定展示“仅手动重试”，不伪造可配置次数。
- 提供新增、编辑、连接/请求配置、模型管理所需的弹窗或抽屉。
- 快捷操作包含测试连接、启停、复制非敏感配置和删除；复制不得包含 API Key 或敏感 Header 值。
- 新增、编辑、启停和删除必须调用真实服务端接口，并在并发或业务约束失败时显示可诊断错误。

### R4 模型与调用链

- 模型管理复用项目现有模型配置体系和生成调用链，不创建重复表、重复类型或第二套配置来源。
- 渠道与模型可用状态由服务端判定；未实现的供应商能力明确失败，不自动补值或使用兼容别名。
- 删除或停用渠道、模型时必须遵守现有任务、生成作业、历史快照和启用组合约束；具体规则以契约与调用链调查为准。

### R5 真实连接测试

- 连接测试由服务端使用当前渠道的真实非明文配置执行，不得由前端模拟或返回固定成功结果。
- 渠道级入口必须要求管理员明确选择一个具体模型；测试完成后该模型按现有安全状态机停用，管理员需在测试通过后显式重新启用，界面必须在执行前说明这一副作用。
- 返回成功/失败、发生时间和经过脱敏的诊断信息；普通日志、审计详情和前端错误均不得包含凭据或完整敏感响应。
- 开发测试适配器和真实外部服务必须显式区分，测试不能用固定成功路径掩盖真实能力缺失。

### R6 密钥与出站安全

- API Key 仅在创建或重新配置时提交，读取接口不返回明文；前端只显示配置状态和安全掩码，不写入 localStorage、URL、普通日志或持久化页面快照。
- 服务端必须复用项目已有密钥安全机制；若现状不足，只在设计中提出并经确认采用最小合规方案，不得明文落库。
- API Key、Authorization 及其他敏感 Header 不得进入普通日志、错误详情或审计差异。
- 服务端校验 API 根地址和自定义 Header；连接测试复用或加强项目既有 AI 出站 SSRF/解析重绑定防护，不新增弱化路径。

### R7 权限与审计

- 新增、编辑、测试、启停、删除、密钥重新配置和模型变更均执行服务端权限校验；前端隐藏操作仅用于体验。
- 上述管理操作记录既有审计体系能够表达的审计事件；敏感字段只记录安全摘要或变更事实，不记录明文差异。
- 用户与权限、审计日志在配置中心导航中的呈现不得形成新的权限或审计数据源。

### R8 视觉与交互

- 高保真还原原型的三栏比例、信息密度、间距、字体层级、颜色、圆角、边框、阴影、表格行高、状态样式、选中态和悬浮反馈。
- 复用现有设计 Token、组件和依赖；不得为视觉还原引入第二套主题或不必要依赖。
- 保持键盘操作、焦点管理、可访问名称、主题及项目已有响应式能力；原型桌面视口为主验收尺寸。

### R9 契约和文档一致性

- 若实现需要修改公共接口、数据库、权限或配置格式，同步更新 `contracts/openapi.yaml`、`contracts/database.md`、生成类型、配置中心与 AI 调用链权威文档及相关权限/审计测试。
- API 和数据库字段只能来自确认后的单一契约，不增加猜测字段、兼容别名或静默默认值。

## 验收标准

- [ ] AC1 管理员可从配置中心导航进入“AI 渠道与模型”；普通用户不能通过导航或直接 URL 访问管理能力。
- [ ] AC2 页面在原型桌面视口呈现三栏结构，主要比例、密度、字体、颜色、间距、圆角、边框、阴影、行高、状态和交互反馈与原型无明显偏差。
- [ ] AC3 分类数量、搜索、状态/供应商品牌筛选、排序、分页和渠道选择均由真实服务端集合契约驱动且可重复验证。
- [ ] AC4 渠道新增、编辑、启停、删除和非敏感复制配置完成真实服务端闭环；受约束操作明确失败且不破坏现有任务或历史。
- [ ] AC5 详情页签只展示有权威来源的数据；基本信息、请求 Header、模型管理和最近测试信息与服务端一致。
- [ ] AC6 连接测试要求明确模型并真实执行供应商请求，成功和失败均可诊断；测试后模型停用且需显式重新启用，开发适配器与真实外部服务边界明确，无固定成功响应。
- [ ] AC7 API Key 与敏感 Header 不通过读取接口、浏览器持久化、日志、错误、审计差异或截图泄露；复制配置不包含敏感值。
- [ ] AC8 API 根地址和 Header 由服务端校验，连接测试保持既有 SSRF、DNS 解析重绑定及重定向安全约束。
- [ ] AC9 渠道、模型及凭据相关变更执行服务端管理员权限校验并记录脱敏审计事件。
- [ ] AC10 OpenAPI、数据库文档、生成类型、实现、测试和权威方案文档保持一致，不存在重复配置源或模糊兼容字段。
- [ ] AC11 最小有效的后端单元/集成测试、前端组件测试、类型检查、lint、受影响构建和 Playwright 真实流程通过；按原型视口生成验收截图并完成视觉复核。
- [ ] AC12 最终 diff 不包含静态假数据、固定成功响应、敏感信息、静默回退、第二套配置源或无关改动。
- [ ] AC13 顶部搜索只返回当前用户有权访问的页面/功能并可真实跳转；不显示越权入口，也不声称搜索尚无契约的业务数据。

## 非目标

- 不新增未被现有调用链或明确产品规则需要的 Provider 工厂、插件层、通用配置框架或兼容层。
- 不根据原型伪造使用统计、操作日志、供应商能力、模型元数据、未登记品牌图标或时间字段。
- 不自动提交、推送、部署、创建分支或处理工作区中的无关改动。
