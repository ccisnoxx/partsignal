# 第三批：编辑与规则工作区视觉统一

## 目标

在不改变业务结构、权限、审批状态、API 和数据契约的前提下，统一内容编辑、产品事实、平台规则和 Prompt 管理的 PageHeader、面板表面、标签、表单、反馈状态与操作层级，使其符合现有 PartSignal 视觉系统。

## 已确认范围

- 产品事实入口：`/products`
- 产品事实详情：`/products/:productId`
- 内容编辑与审核：`/content/:contentVersionId`
- 平台规则：`/configuration/platform-rules`
- Prompt 管理：`/configuration/prompts`
- 上述页面直接使用的现有共享组件；现有共享接口已满足需求时保持不变。

## 工作区差异

- 产品事实入口保留搜索、URL 分页、表格、新增弹窗和管理员删除入口。
- 产品事实详情保留长表单章节导航、五类动态事实区、证据直传、粘性保存栏、不可变版本和审核上下文。
- 内容编辑保留“版本队列—Markdown 编辑/预览—质量与审核”三列业务关系，窄屏按内容优先顺序堆叠。
- 平台规则保留桌面四区以及窄屏“平台→版本→详情”的分阶段导航和元数据 Drawer。
- 平台 Prompt 保留列表—Markdown 编辑—真实输出预览三列；自然化 Prompt 保留编辑器—预览两列。

不得为视觉统一把以上工作区强行抽成相同的三栏组件。

## 需求

1. 五个目标路由继续使用现有 `PageHeader`，正常、加载和错误状态均保持唯一、可见的页面标题。
2. 面板表面统一使用 `theme.ts` 和 `global.css` 的现有语义 Token；不新增主题体系、字体、图标、编辑器、UI 或状态管理依赖。
3. 业务状态必须同时具有文字或图标，不能只依赖颜色；保存、失败、冲突和未保存状态可被读屏识别。
4. 每个编辑表面仅保留一个主提交按钮；预览、差异和重新加载为次操作；删除、退回等危险操作必须确认并与主提交分离。
5. 客户端校验失败聚焦首个无效字段；服务端失败和版本冲突聚焦错误反馈并保留本地输入，不猜测服务端字段映射。
6. 只读内容与禁用控件必须视觉可辨；不可变版本、快照和源文保持只读，禁用仅用于状态、权限或请求进行中。
7. 产品新增、产品事实、内容修订和平台规则弹窗补齐未保存提示；Prompt 保留现有 baseline/dirty、切换和离开保护。
8. Markdown 继续是内容和 Prompt 的唯一可编辑正文源；AI 预览继续创建真实、可审计的草稿作业。
9. 1440、1024、768、375、320px 下保持可读、可操作且无页面级横向溢出；窄屏操作栏不得遮挡字段或错误。
10. 键盘、焦点环、触控目标、浅色、深色、跟随系统和 `prefers-reduced-motion` 均通过真实浏览器验证。
11. 只修改目标页面的作用域样式，不一次性重写 `global.css`，不影响第一批和第二批页面。

## 验收标准

- [x] `/products`、`/products/:id`、`/content/:id`、`/configuration/platform-rules`、`/configuration/prompts` 均有且仅有一个 H1，并使用现有 `PageHeader`。
- [x] 五个目标路由的标题、表面、标签、表单、反馈与操作层级一致，原有列表、长表单、三列、四区和双模式结构保持独立。
- [x] 请求路径、方法、payload、`expected_revision`、CSRF、状态转换、审核历史和 `available_actions` 行为不变。
- [x] Markdown 唯一正文源、不可变快照、事实证据、规则版本和真实 Prompt 预览约束保持不变。
- [x] 未修改、未保存、提交中、成功、失败与冲突状态清晰；失败不丢草稿，确认放弃前不清理输入。
- [x] 首个客户端错误获得焦点；服务端错误可被读屏宣布；状态不是只通过颜色表达。
- [x] 320–1440px 无页面级横向溢出，窄屏主操作不遮挡内容，平台规则移动阶段和 Prompt 列表可用。
- [x] 浅色、深色、跟随系统和 reduced-motion 下文字、边界、焦点、只读和禁用状态清晰。
- [x] 目标组件测试、TypeScript、Lint、构建和真实 API Playwright 通过。
- [x] 第一、第二批页面源文件、登录、改密、后端、契约、依赖清单和锁文件无变更；`theme.ts` 仅包含已批准的共享控件边界修正。

范围调整（2026-07-24）：目标页面的文字与聚焦边界满足对比度要求，但原主题的未聚焦输入边界对比度为浅色 1.52:1、深色 1.86:1；原深色 `borderStrong` 在表面上也只有 2.84:1，低于视觉规范的 3:1。经批准，本任务将 Ant Design `colorBorder` 改为复用 `borderStrong`，并仅把深色 `borderStrong` 从 `#636366` 调整为 `#67676A`。Token 与真实浏览器计算样式均验证浅色 3.2605:1、深色 3.0180:1；未调整其他主题角色或扩大视觉重构。

## 排除项

- 不修改用户管理、平台管理、AI 渠道与模型、审计日志、Dashboard、GEO 观测、GEO 洞察和打印页。
- 不修改内容任务、人工发布、登录和改密页面。
- 不修改后端、数据库、OpenAPI、生成类型、权限、审批状态、业务流程或部署配置。
- 不修改第一、第二批页面源文件；共享控件边界变化必须通过其 Playwright 回归验证，不得顺带调整对应页面。
- 不创建新 `PageShell`、统一三栏组件、表单工厂、页面配置系统、共享状态框架或第二套设计系统。
- 不运行 `ui-ux-pro-max --persist`，不生成 `design-system/MASTER.md`。
- 不提交、归档或推送。

## 风险

- `global.css` 为共享文件，所有变化必须带目标页面根类并通过第一、第二批 Playwright 回归防止串扰。
- Ant Design 深层 DOM 选择器可能脆弱；优先给业务节点增加局部类，不依赖多层内部结构。
- 平台和 Prompt 列表数据量大，必须保留服务端/URL 分页和内部滚动，不创建客户端第二份数据源。
- 未保存语义因工作区而异，必须由各业务表面本地维护，不抽象成统一流程。
