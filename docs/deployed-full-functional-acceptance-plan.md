# PartSignal 已部署环境全站功能验收计划

## 1. 目标

通过真实浏览器对 `https://geo.962850.xyz` 做一次管理员与普通工程师视角的全站功能验收，覆盖：

- 认证、改密、权限与会话；
- 工作台、导航、主题、全局搜索；
- 产品、事实版本、审核与不可变历史；
- 内容任务、Prompt、AI 生成、人工修订、审核与自然化边界；
- 发布账号、人工发布登记、状态转换、重复发布与异常修复；
- GEO 问题库、观测、更正、分析洞察与打印；
- 平台类型、平台、Prompt、AI 渠道与模型；
- 用户管理、审计日志、筛选、分页、导出和错误状态；
- 桌面与移动端视觉、键盘操作、控制台和网络异常。

本计划只使用项目现有页面和服务端能力，不修改代码、不重新部署、不放宽公网安全配置，也不在真实第三方平台发布内容。

## 2. 执行原则

1. 使用项目安装的 `playwright-cli`，采用唯一命名会话；登录后开启 tracing，按模块检查 `console` 和 `requests`。
2. 所有测试实体使用统一前缀 `E2E-ACCEPT-<run-id>`，正文明确标记“完全虚构、仅用于验收、不得用于真实业务”。
3. 只有 `PUBLIC` 且已批准的事实版本可以进入第三方模型调用。
4. “模拟发布”仅指在 PartSignal 内创建、推进和登记人工发布记录；最终 URL 使用隔离测试平台允许的保留域名，不向知乎或其他真实平台提交内容。
5. 单个模块遇到可由用户配置修正的问题时，先通过 UI 修正后继续；无法修正时只阻断该场景，不中止其他独立模块。
6. 不删除审计日志，不改写已批准事实、内容版本、发布记录或 GEO 观测历史。
7. 不读取、输出或截图密码、Cookie、Token、API Key、敏感 Header；所有临时凭据只保存在进程内存中。
8. 每个写操作都检查成功提示、刷新后的持久化结果、审计记录和服务端状态约束。

## 3. 计划测试数据

| 数据 | 建议值 | 用途与边界 |
| --- | --- | --- |
| 运行 ID | `YYYYMMDD-HHmmss` | 所有测试数据的唯一后缀 |
| 平台类型 | `E2E 验收平台` | 测试新增、筛选和引用约束 |
| 具体平台 | `E2E Example <run-id>` | 独立承载 Prompt、账号、发布和任务 |
| 平台 slug | `e2e-example-<short-id>` | 只含小写字母、数字和连字符 |
| 官网/允许域名 | `https://example.com` / `example.com` | 使用 RFC 保留示例域名，不冒充真实平台 |
| 平台 Prompt | `E2E JSON Prompt <run-id>` | 严格输出四字段 JSON；仅依据 PUBLIC 事实 |
| 发布账号 | `E2E-ACCOUNT-<run-id>` | 不保存真实账号、密码、Cookie 或 Token |
| 产品 | `E2E-PRODUCT-<run-id>` | 完全虚构测试产品 |
| PUBLIC 事实 | V1 | 明确虚构、测试用途及禁止真实业务使用 |
| 内容任务 | `E2E-CONTENT-<run-id>` | 绑定测试平台和 PUBLIC V1 |
| 模拟文章 URL | `https://example.com/partsignal-e2e/<run-id>` | 只用于系统内发布登记 |
| GEO 问题 | `E2E-QUERY-<run-id>` | 只用于模拟观测 |
| 观测平台/搜索词 | `E2E 模拟搜索` / `E2E-PRODUCT-<run-id>` | 不声明真实搜索结果 |
| 工程师账号 | `e2e_engineer_<short-id>` | 测试首次改密、权限和会话撤销 |
| AI 渠道 | `E2E-CHANNEL-<run-id>` | 仅在有专用低权限测试 Key 时做真实连接测试 |

### 3.1 模型调用预算

默认最多进行以下真实模型调用：

1. 新平台内容原始生成 1 次；
2. 新 AI 渠道的模型连接测试 1 次，仅在有专用低权限测试 Key 时执行；
3. 自然化 1 次，仅在可安全配置并恢复全局自然化 Prompt 时执行。

模型返回格式错误时允许通过测试 Prompt 修正后再调用 1 次；每次调用及失败作业都必须记录 ID。不得循环重试。

## 5. 阶段 I：独立 UI/UX、视觉与交互验收

本阶段与功能验收并列，不以“按钮能点、请求成功”代替界面质量判断。每个主页面都要经过静态视觉、真实交互、异常状态和响应式四轮检查。

### 5.1 视口与显示条件

- 桌面主验收：`1440×900`，所有主路由和关键弹窗。
- 移动端主验收：`390×844`，所有主路由和关键弹窗。
- 中间断点：`1024×768`，重点检查三栏、侧栏、表格和 Drawer 的布局切换。
- 最小宽度：`320×800`，抽查登录、列表、编辑器、Prompt、AI 渠道和 GEO 洞察。
- 桌面 200% 缩放：抽查工作台、Prompt、内容审核、发布 Drawer、GEO 洞察。
- 浅色、深色和跟随系统：所有页面至少验证浅色；代表页面验证三种主题信息等价。

### 5.2 视觉层级与布局

- [ ] 页面标题、导航、面包屑、H1 和当前菜单名称一致，用户能判断所在位置。
- [ ] 主操作、次操作、危险操作有稳定的视觉优先级，不会出现多个同等抢眼的主按钮。
- [ ] 标题、说明、指标、筛选、表格和操作区的阅读顺序自然，关联内容距离更近。
- [ ] 页面左右边距、卡片内边距、表单行距、表格密度和区块间距在同类页面保持一致。
- [ ] 文本基线、标签、图标、按钮和输入框垂直对齐，无跳动、悬空或一像素错位感。
- [ ] 标题、正文、辅助文案、占位符和禁用文本字号及颜色层级清楚。
- [ ] 状态标签、指标颜色和图标语义一致，不只依赖颜色表达成功、警告或失败。
- [ ] 不出现突兀的大号感叹号、过度留白、无意义大卡片、密集文字墙或操作区失衡。
- [ ] Logo、头像、图表、空状态插图比例正确，不拉伸、不模糊、不挤压正文。

### 5.3 文本与真实数据承载

- [ ] 使用长产品名、长平台名、长 Prompt 名、UUID、长 URL、长错误和多标签验证承载能力。
- [ ] 时间、数量、revision、状态和更新人不会被无提示截断；必要截断提供 Tooltip 或详情入口。
- [ ] 中英文、数字、标点和 Markdown 混排正常，不发生单字孤行或代码块撑破容器。
- [ ] 表格列宽与业务重要性匹配；核心字段不是最先被压缩或隐藏的字段。
- [ ] 空值统一显示，零值与“暂无数据”不混淆。
- [ ] 按钮、错误提示、确认文案说明实际后果，避免“确定”“处理”等无上下文词语。

### 5.4 表单与操作反馈

- [ ] 必填标记、输入格式、示例、帮助文本和默认值清楚，首次使用无需猜测。
- [ ] 前端校验在相应字段附近显示；服务端错误聚焦到 Alert 或具体字段，不只出现瞬时 Toast。
- [ ] 提交中按钮有加载状态并阻止重复提交；成功后列表、详情和按钮状态及时更新。
- [ ] 禁用控件能解释原因，不能只有灰色按钮而没有可恢复路径。
- [ ] 修改后离开、切换模板、关闭弹窗、刷新和浏览器返回时提供未保存提示。
- [ ] 搜索、筛选、重置、分页和 URL 查询参数保持一致，刷新或返回后不会意外丢失。
- [ ] 删除、停用、批准、发布和异常处置的确认层明确对象、范围和不可逆后果。
- [ ] 上传显示文件名、进度、成功、失败、重试、移除和格式/大小限制。

### 5.5 Modal、Drawer、菜单与浮层

- [ ] 打开后遮罩、层级和初始焦点正确，背景不能被误操作。
- [ ] Tab 和 Shift+Tab 焦点保持在浮层内；Esc、右上角关闭和取消按钮行为一致。
- [ ] 关闭后焦点返回原触发控件，重复打开不会保留上一次不应保留的脏状态。
- [ ] 长 Prompt、长错误、下拉选项和多步骤表单可滚动，标题和底部操作不会遮挡内容。
- [ ] 下拉菜单、日期选择器、Tooltip 和确认框不被父容器裁切，也不超出视口。
- [ ] 移动端软键盘场景下输入框和提交按钮仍可到达，不出现双重滚动或页面被锁死。
- [ ] 点击遮罩是否关闭符合数据风险；存在未保存内容时不能无提示丢失。

### 5.6 列表、表格、卡片与图表

- [ ] 列表加载骨架与最终布局尺寸接近，避免明显跳动。
- [ ] 空状态说明为什么为空并提供合理下一步；无权限与无数据不使用相同文案。
- [ ] 表头、排序、筛选、固定列、行操作和分页在桌面及移动端都可发现、可操作。
- [ ] 移动端只允许 TableRegion 内横向滚动，文档本身 `scrollWidth` 不超过视口。
- [ ] 横向滚动后固定操作列不遮挡其他列，键盘仍能访问行操作。
- [ ] 卡片点击范围、悬停、选中和键盘焦点状态明显，不依赖鼠标 Hover 才能找到操作。
- [ ] 图表标题、坐标、单位、图例、空数据、极值和 Tooltip 完整；Tooltip 可通过键盘聚焦。
- [ ] 打印视图移除导航和交互控件，保留筛选范围、生成时间、图例和关键数值。

### 5.7 加载、空、禁用、错误与边界状态

每个核心页面至少观察以下适用状态：

- [ ] 首次加载与局部重新加载；
- [ ] 空列表、空详情、无候选项和无可执行操作；
- [ ] 表单未填写、部分填写、非法格式和超长内容；
- [ ] 无权限、对象不存在、revision 冲突和状态已变化；
- [ ] 请求失败、模型失败、上传失败和重试；
- [ ] 成功提示、状态刷新和返回列表后的持久化；
- [ ] 按钮禁用、处理中和防重复提交；
- [ ] 后台异步作业运行中、成功、失败和超时。

### 5.8 键盘、可访问性与动效

- [ ] 从页面顶部只用键盘可以到达导航、筛选、表格操作、主按钮和浮层。

## 6. 数据清理与保留

| 数据 | 验收结束处理 |
| --- | --- |
| 浏览器会话、Cookie、localStorage、sessionStorage | 全部清除，UI 退出登录后删除命名会话 |
| 临时截图、上传文件、下载 CSV | 保存在仓库外；敏感内容验证后移入废纸篓 |
| 临时 AI 渠道和模型 | 未被业务作业引用时停用并删除；审计保留 |
| 未绑定临时 Prompt | 用于验证删除后清理；审计保留 |
| 主测试 Prompt | 从测试平台解绑后可删除；生成作业快照保留 |
| 测试平台 | 因任务/发布历史引用不能删除，最终停用 |
| 测试发布账号 | 因发布历史引用不能删除，最终停用 |
| 测试平台类型 | 因测试平台引用保留，并明确标记测试用途 |
| 产品、事实、任务、内容、发布、观测、更正 | 保留为不可变测试审计链，不修改或删除 |
| 测试工程师 | 无业务引用时停用并删除；登录与管理审计保留 |

清理后再次检查工作台、活动平台、可选模型和发布账号，确保测试配置不会进入普通业务下拉选项。

## 7. 继续与停止条件

### 7.1 继续测试

以下问题只影响当前场景，记录后继续其他模块：

- 某个测试配置可通过 UI 修正；
- 某个第三方模型或 Logo 服务不可用；
- 单一页面发生 4xx/5xx，但其他模块仍可独立进入；
- 缺少专用 AI 测试 Key；
- 某条状态链因前置数据不满足而不能执行。

### 7.2 立即停止写操作

- 凭据、Cookie、Token、API Key 或敏感 Header 可能泄露；
- 发现测试数据不是明确的测试用途或事实不是 `PUBLIC`；
- 页面将修改真实业务对象、现有线上 Prompt、真实 AI 渠道或真实发布账号；
- 服务端允许未批准内容发布、RESTRICTED 事实调用第三方模型或越权管理；
- 数据写入目标与测试前缀不一致；
- 出现主机密钥冲突、认证异常或大范围 5xx；
- 清理动作可能删除审计或不可变业务历史。

停止写操作后仍可继续安全的只读页面、视觉、权限和诊断检查。

## 8. 证据采集

每个场景至少记录：

- 页面 URL、视口、时间和测试数据前缀；
- 预期结果、实际结果、通过/失败/阻断；
- 创建或变更的实体 ID、revision 和状态；
- 控制台错误/警告、失败请求、HTTP 状态码和业务错误码；
- 关键成功状态的 snapshot；
- 每个主页面至少保存一张桌面基线截图；关键编辑器、Modal、Drawer 和图表另存移动端基线；
- 视觉缺陷同时保存全页定位图和局部细节图，文件名包含模块、视口和问题编号；
- 交互缺陷记录操作前后截图、焦点元素、滚动宽度或边界框等可复核数据；
- 整段登录后流程的 trace；trace 不作为公开附件，避免其中的认证信息外泄。

密码输入后不截图；AI 渠道详情、审计详情和网络请求截图前先确认没有敏感值。

## 9. 缺陷分级

| 级别 | 定义 |
| --- | --- |
| 阻断 | 无法登录、主链路完全不可执行、数据安全/权限/审计失效、可能污染真实业务 |
| 严重 | 状态机可绕过、数据丢失或改写、敏感信息泄露、错误发布或重复发布 |
| 中 | 单模块核心功能失败，但可绕开并继续其他模块 |
| 低 | 文案、轻微视觉、非关键响应式或可用性问题 |

每条缺陷必须包含严重程度、模块、URL、前置数据、复现步骤、预期、实际、错误码、请求和截图路径。

视觉问题不能全部归为“低”：遮挡主操作、无法滚动或移动端不能完成流程属于“中”；关键信息不可见、误导用户执行危险操作或焦点陷阱导致流程不可完成可判为“严重”。

## 10. 最终报告结构

1. 总结论：通过 / 部分通过 / 阻断；
2. 环境、账号角色、视口和执行时间；
3. 模块通过率与场景统计；
4. 端到端业务链路及全部测试记录 ID；
5. 按步骤的预期与实际结果；
6. 功能缺陷；
7. 视觉与交互缺陷；
8. 权限、安全和审计问题；
9. 控制台错误、失败请求和异常状态码；
10. 未执行或被阻断项目及原因；
11. 测试数据保留/清理结果和浏览器会话清理证明；
12. 建议修复优先级；不直接修改代码。

## 11. 预计执行顺序与工时

| 阶段 | 预计时间 |
| --- | --- |
| A-B 环境、认证、用户权限 | 45–60 分钟 |
| C-D 配置中心、发布账号、AI 渠道 | 75–100 分钟 |
| E 产品事实、内容、审核 | 60–90 分钟 |
| F-G 发布、观测、洞察、异常修复 | 75–110 分钟 |
| H 审计、安全、网络诊断 | 45–60 分钟 |
