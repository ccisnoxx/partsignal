# ADR-005：按人工 → API → 浏览器顺序分阶段启用采集

- 状态：Accepted
- 日期：2026-10-01

## 背景

人工结果最可控但成本高；API 易自动化但与真实产品界面可能不同；浏览器采集更接近用户界面，但存在账号、条款、DOM、验证码、地区和运维风险。

## 决策

1. 先用 MANUAL 完成统一运行和证据模型；
2. 再用受控 API Collector 建立自动调度、费用、失败和恢复；
3. Browser Collector 作为独立服务，在合规批准、本地 contract tests、kill switch、专用账号和小规模试点后启用；
4. 未批准平台继续只允许 MANUAL；
5. 不把 API 和 Browser 结果静默混合。

## 原因

- 降低同时建设业务模型和复杂自动化的风险；
- 在真实账号投入前证明数据、指标和运营价值；
- API Worker 可复用现有网络和凭据安全边界；
- Browser 需要独立依赖和更严格治理。

## 后果

- 核心版早期可能仍需人工录入；
- Browser 能力不是 R1–R6 的阻断项；
- 每个 Browser adapter 单独批准和验收；
- CI 只使用本地模拟站，不访问真实平台。
