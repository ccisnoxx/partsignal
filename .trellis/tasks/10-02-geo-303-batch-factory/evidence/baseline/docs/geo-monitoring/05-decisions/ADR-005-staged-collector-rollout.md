# ADR-005：按人工 → API → 浏览器顺序分阶段启用采集

- 状态：Accepted
- 日期：2026-10-01
- 接受日期：2026-10-01
- 接受依据：用户在本会话明确接受本 ADR 及 GEO-002 评审修订。
- 适用范围：GEO 核心版 MANUAL、API、BROWSER 的分阶段交付、发送资格、数据外发、合规启用及完整首发门禁；平台和账号须另行满足其批准条件。

## 背景

人工结果最可控但成本高；API 易自动化但与真实产品界面可能不同；浏览器采集更接近用户界面，但存在账号、条款、DOM、验证码、地区和运维风险。

## 决策

1. 先用 MANUAL 完成统一运行和证据模型；
2. 再用受控 API Collector 建立自动调度、费用、失败和恢复；
3. Browser Collector 作为独立服务，在合规批准、本地 contract tests、kill switch、专用账号和小规模试点后启用；
4. 未批准平台继续只允许 MANUAL；
5. 不把 API 和 Browser 结果静默混合。

## 原因

- 降低同时建设业务模型和复杂自动化的风险；
- 在真实账号投入前证明数据、指标和运营价值；
- API Worker 可复用现有网络和凭据安全边界；
- Browser 需要独立依赖和更严格治理。

## 后果

- 核心版早期可能仍需人工录入；
- Browser 能力不是 R1–R6 的阻断项；
- 每个 Browser adapter 单独批准和验收；
- CI 只使用本地模拟站，不访问真实平台。

## GEO-002 评审修订（已接受）

- 接受结论：用户接受分阶段路线及以下评审修订；ADR 接受、平台合规批准和产品首发验收分别记录并满足。
- R1–R6 中间增量可不阻塞于 Browser，但不能据此宣称满足 PRD 的完整核心版首发条件。至少两个自动化观测面及一个合规界面试点/受控试运行的产品门禁需明确保留，或由产品负责人显式修订。
- API 与外部分析须沿用既有网络、凭据和非公开数据外发边界。批准 adapter 不自动授权 INTERNAL 数据外发；问题、附加上下文和原始答案的分级及批准依据需要由服务端冻结并校验。
- 自动调用必须在首个请求字节发送前，按当前有效 lease token、状态和租约原子持久化 SENT；恢复必须撤销旧 token，旧 Worker 校验失败不能发送。SENT/UNKNOWN 不自动重发；无法证明发送隔离时沿用过期 RUNNING 明确失败的保守行为。
- 未批准的平台，包括拟进行受控试运行的平台，仍不得启动 Browser 自动采集；批准范围需覆盖账号、用途、环境、速率和保留规则。
- 详细依据、冲突及备选方案见 [GEO-002 架构评审记录](./GEO-002-architecture-review.md)。
