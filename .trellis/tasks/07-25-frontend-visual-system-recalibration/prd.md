# 前端视觉系统重校准

## Goal

以用户提供的原始视觉描述和 13 张页面原型为上位视觉目标，重校准 PartSignal 现有前端视觉系统，使登录后桌面工作台在配色、字体、壳层、密度、间距、表面层级、交互反馈和三类页面构图上统一、精致、轻盈、专业且克制，同时保持现有真实业务、权限、API 和状态契约不变。

## Background

- 当前 `.trellis/spec/frontend/visual-system.md` 是唯一人类可读视觉规范，`frontend/src/app/theme.ts` 与 `frontend/src/styles/global.css` 分别持有运行时视觉值和布局实现。
- 既有跨页面视觉收口任务把历史原型降级为差异定位资料，并保持既有主题颜色和阴影值不变，因此当前实现虽然统一了 Token 与应用壳层，但没有以原型视觉为验收目标。
- 用户确认本任务进入 Trellis 规划，并批准将原始风格描述作为上位目标。
- 用户提供的 13 张桌面原型已固化在 `assets/prototypes/`，页面包括用户、审计、发布账号、Prompt、平台规则、平台、GEO 观测、GEO 洞察、发布、AI 渠道、内容任务、内容审核和总览。
- 用户批准以 `13-dashboard.png`、`01-users.png`、`08-geo-insights.png`、`12-content-review.png` 四张原型建立统一视觉锚点，其余九张只补充页面局部构图，不保留原型内部互相冲突的壳层几何。
- 原型图用于提取视觉语言、页面构图和密度关系；其中出现的字段、数据、操作和状态不自动成为产品需求，真实业务仍以现有代码、契约和权威文档为准。

## Requirements

### R1. 单一视觉权威

- 继续以 `.trellis/spec/frontend/visual-system.md` 作为唯一人类可读视觉规范。
- 原型作为规范从属的批准视觉参考和验收证据，不创建平行视觉规范。
- 精确运行时值继续由现有 `theme.ts`、Ant Design ThemeConfig 和 `--ps-*` 变量持有，不增加第二套主题或视觉框架。

### R2. 上位视觉方向

- 采用现代 macOS 原生生产力应用、轻量磨砂玻璃、高密度企业 SaaS、内容优先、柔和环境光和克制层级。
- 浅色主题为主要视觉校准目标，同时不得破坏现有深色与跟随系统主题。
- 环境光使用低饱和、强模糊蓝紫淡粉光晕；不得形成明显色带、霓虹或赛博朋克效果。
- 玻璃只用于导航、顶栏、轻量指标、筛选、抽屉和浮层；表格、编辑器、正文和复杂表单保持高不透明度。

### R3. 视觉尺度

- 桌面基准为 1440–1600px，优先恢复原型中的紧凑壳层、清晰留白和稳定内容密度。
- 页面标题、区域标题、正文、表格和辅助信息建立有限、可复用的字号与字重层级。
- 卡片、面板、控件和状态标签使用克制圆角，不得胶囊化。
- 列表页、编辑审核页和分析洞察页分别收敛为可识别但不强制抽象的页面构图。

### R4. 颜色、状态与图形

- 品牌蓝承担主交互，紫色只作辅助强调或图表系列；主操作可在不损害一致性与对比度时使用克制蓝紫处理。
- 成功、待处理、异常和中性状态使用低透明度浅背景，并保持文字或图标等非颜色表达。
- 图表使用细线、浅面积、低对比网格和清晰图例，不使用 3D、发光或装饰性高饱和图形。

### R5. 实现边界

- 复用 React、Ant Design、`@ant-design/icons`、现有共享组件和现有语义 Token。
- 不为相近线性图标风格新增 Lucide，不增加 Web Font、CSS 框架、卡片工厂、页面配置系统或三层 Token 脚手架。
- 优先调整共享根因，再处理页面局部布局；不得以页面补丁制造第二套视觉体系。
- 保持现有 API、权限、路由、业务状态、数据口径、可用操作和真实错误行为不变。

### R6. 可访问性与响应式

- 保持浅色、深色和跟随系统模式可用。
- 保持现有窄屏、320px、真实浏览器 200% 缩放、键盘焦点、reduced-motion 和打印边界。
- 文字、控件、状态和图表满足现有视觉规范中的对比度与非颜色表达要求。

### R7. 视觉验收

- `13-dashboard.png`、`01-users.png`、`08-geo-insights.png`、`12-content-review.png` 分别作为总览、列表、分析洞察和编辑审核的批准锚点。
- 其余九张原型只补充页面专属工作区关系，不创建页面级壳层或主题。
- 锚点以稳定视口、稳定数据区域、计算样式和人工视觉复核共同验收；不得用当前实现自动生成的快照反向证明设计正确。
- 动态业务数据可精确遮罩，但不得遮罩用于验证行高、列对齐、表面层级和页面构图的稳定区域。
- 只有人工批准后的页面才可更新为新的回归基线。

## Acceptance Criteria

- [ ] AC1：`visual-system.md` 明确记录批准视觉参考的从属地位、精确所有权和本任务确认的统一视觉尺度，且不存在第二份视觉规范。
- [ ] AC2：1440–1600px 下应用壳层、环境光、侧栏、顶栏、内容边距和页面标题层级与批准锚点的视觉关系一致。
- [ ] AC3：列表、编辑审核、分析洞察和总览代表页分别完成视觉重校准，且使用同一语义配色、字体、圆角、阴影和间距节奏。
- [ ] AC4：表格、编辑器、正文和复杂表单保持高不透明度与清晰对比；玻璃效果未扩散到连续阅读区域。
- [ ] AC5：状态、按钮、图标、图表和交互反馈满足统一语义及可访问性边界，不引入新视觉依赖。
- [ ] AC6：页面只展示现有真实字段、状态、指标和操作；API、权限、路由和业务行为无变化。
- [ ] AC7：375、768、1024、1440px、真实 200% 缩放、浅色、深色、键盘和 reduced-motion 验收通过，无新增页面级横向滚动或关键操作丢失。
- [ ] AC8：新的视觉基线来源和人工批准过程可追溯，测试能够阻止共享壳层、关键布局、颜色角色和稳定页面区域回退。

## Out of Scope

- 根据原型新增当前系统不存在的业务字段、统计指标、自动发布、自动登录、观测伪造或其他功能。
- 替换 React、Ant Design、图标库或现有前端架构。
- 新建通用页面配置引擎、视觉组件工厂或独立设计系统包。
- 在本任务中修改后端、OpenAPI、数据库、部署或权限契约。
