# 配置中心平台规则高保真复刻与版本闭环

## 目标

以用户批准的 1581×995 原型为视觉与交互规格，在现有 `/configuration/platform-rules` 页面上迭代，形成由 PostgreSQL、OpenAPI、服务端状态机和追加式审计共同约束的平台规则版本工作台；不得创建平行页面、第二套规则结构、前端业务状态或静态影响数据。

## 用户价值

- 管理员能按平台和版本查看真实规则、引用影响与变更历史，并在同一工作台完成创建、编辑、激活、直接退役和受约束删除。
- 内容任务继续锁定创建时使用的规则版本，平台当前规则切换不会改写内容、发布或 GEO 历史。
- 原型的四列信息架构、真实交互、响应式和可访问性可通过 Browser 与自动化测试复核。

## 已确认事实

- 批准原型和当前 Browser 基线分别为 `artifacts/platform-rules-prototype-1581x995.png` 与 `artifacts/current-platform-rules-1581x995.png`；禁止 ImageGen 和重新设计。
- 当前页只有平台筛选、全宽版本表格、新增/编辑 Modal 和删除菜单，缺少原型四列工作台及版本闭环。
- 平台规则权威字段只有：`target_audience`、标题/正文长度范围、`tone`、三个允许开关、`prohibited_phrases` 和 `sections`。
- 每个平台最多一个 ACTIVE 版本，由 PostgreSQL 部分唯一索引和服务端平台行锁共同保证；不保存第二个 `current_rule_id`。
- DRAFT 可编辑、激活或直接退役；ACTIVE/RETIRED 正文冻结。ACTIVE 只能在激活替代 DRAFT 时自动退役。
- 无内容任务引用时，DRAFT、ACTIVE、RETIRED 均可物理删除；删除 ACTIVE 后平台可合法进入无有效规则状态，不自动回退旧版本。
- `ContentTask.platform_profile_version_id` 是直接引用和生成上下文锁版来源；发布记录和 GEO 观测通过内容版本与任务间接追溯。
- 规则创建、更新、激活、直接退役、删除已有追加式审计；激活替换旧 ACTIVE 时，当前缺少旧版本自己的自动退役审计事件。
- 通用审计接口已支持按规则版本稳定 ID 过滤；平台管理在途任务已提供平台筛选和平台详情能力，本任务不重复实现。
- 详细调查、差异分类、字段对照和任务边界见 `research/gap-analysis.md`；视觉量化与验收点见 `research/visual-spec.md`。

## 已确认业务基线

用户于 2026-07-22 确认以下契约保守基线：

1. **规则字段**：本期只展示和编辑现有权威字段；原型中的“支持的内容格式、品牌露出要求、内容角度、CTA 要求、运营注意事项”不入库、不显示占位值，也不误用任务级同名字段。后续若扩展，另行定义类型、必填性、校验、生成消费和历史迁移。
2. **退役语义**：保持当前状态机。DRAFT 可直接退役；ACTIVE 不提供“退役此版本”，只能激活替代 DRAFT 后自动退役。更多菜单只展示服务端真实支持的动作。
3. **影响摘要分桶**：每个引用任务只进入一个桶，且 `bound = unpublished + reviewing + published`。优先级为：
   - `published`：至少一个关联发布记录当前状态为 `PUBLISHED` 或 `VERIFIED`；
   - `reviewing`：不属于 `published`，且存在当前 `PLATFORM_REVIEW` 发布记录或 `PENDING_REVIEW` 内容版本；
   - `unpublished`：其余所有引用任务，包括无发布、待人工发布、被拒绝、已移除、验证失败或尚未进入审核的任务。

## 功能需求

### R1 高保真工作台

- 保持现有 PartSignal 左侧导航、配置中心面包屑、顶栏真实控件和管理员守卫；不添加原型中项目没有契约的通知、帮助或应用切换按钮。
- 在 1581×995 优先还原平台列、版本列、规则详情列和右侧信息栏的宽度、间距、密度、层级、边框、圆角、阴影和选中状态。
- 首屏保留标题、说明、创建草稿、平台检索、版本卡、查看差异、规则键值行、版本状态、影响摘要、变更历史和危险操作顺序；原型左栏的“规则版本”页签和平台状态控件不作为验收依据。
- 使用现有 Ant Design、Ant 图标、`PlatformAvatar` 和语义 Token；不新增第二套设计系统、Emoji、远程占位资产或硬编码原型示例数据。

### R2 平台与版本导航

- 平台名称搜索复用平台集合服务端 `q`；平台列不提供启用/停用筛选，也不展示平台状态徽标或文字。
- 平台行展示真实 Logo、名称和版本数量；版本状态仅在独立版本列展示，版本卡按版本号倒序展示版本、状态、创建时间、创建人、自动差异摘要和内容任务引用数。
- 创建人、更新时间或激活时间没有权威审计事实时返回并显示明确空值；不得使用当前用户、迁移时间或创建时间代替。
- `platform_profile_id` 与 `version_id` 是可恢复选择状态；搜索也写入 URL。合法选择支持刷新、分享、前进和后退；不存在或无权访问的 ID 显示局部错误，不静默选择别的对象。
- 平台管理页进入规则页的既有 `platform_profile_id` 链接继续有效；本页“平台列表”入口回到真实平台管理页。

### R3 规则详情与差异

- 中央详情只读取 OpenAPI 生成的 `PlatformRules`，按稳定字段顺序展示全部现有规则，不把原型缺失字段补成空字符串或默认值。
- DRAFT 编辑继续使用现有表单、服务端范围校验、CSRF 和 `expected_revision`；保存冲突显示结构化错误并保留用户输入。
- “查看差异”允许选中同平台另一版本，默认比较上一个较低版本；没有可比较版本时动作不可用且有文本原因。
- 差异由前端对两个已加载、类型化的权威规则对象逐字段比较；数组按完整有序值展示，布尔值使用业务文案，不引入通用 JSON diff 引擎或差异存储表。
- 版本卡没有人工变更摘要来源时显示“与上一版本 N 项差异”或“首个版本”，不得生成似真的自然语言说明。

### R4 状态命令与物理删除

- 新增规则草稿可从页头或当前版本列触发；当前已选择平台时预选并锁定该平台上下文，未选择时显式选择平台。
- DRAFT 支持编辑、激活、直接退役；激活替换现有 ACTIVE 时保持同事务原子切换和 revision 校验。
- 自动退役旧 ACTIVE 时追加该旧版本自己的退役审计，包含 `reason=REPLACED` 和替代版本稳定 ID；新版本激活审计继续保留。
- ACTIVE/RETIRED 不可编辑或激活；ACTIVE 不直接退役。所有按钮与更多菜单使用服务端 `available_actions`，服务端仍执行最终权限、状态和 revision 校验。
- 物理删除严格沿用既有矩阵：任何状态在引用数为零时允许；有引用时返回结构化 `PLATFORM_PROFILE_VERSION_IN_USE` 和真实数量。前端不把删除改成退役，不做级联或自动回退。
- 成功状态操作提供短中文反馈并精确失效平台、版本列表、详情、审计和引用查询；失败停留当前上下文。

### R5 版本状态与元数据

- 右侧版本状态展示当前状态、版本号、创建人、创建时间、激活时间、最后变更时间、自动差异摘要和引用次数。
- 版本列表管理投影统一返回审计元数据、引用数和 `available_actions`，单版本影响由专用只读接口返回；前端不得遍历全局审计或任务列表推算。
- 版本列表引用数使用一次批量聚合，无 N+1；列表和详情引用数在同一数据库事实下保持一致。
- 审计演员已删除或历史记录确实缺失时按契约返回 `null`；UI 显示“—”并保留事件本身，不从其他对象猜测。

### R6 发布影响摘要与引用详情

- 影响摘要由服务端按 `ContentTask → ContentVersion → PublicationRecord` 实时聚合；PostgreSQL 仍是唯一来源，不新增快照表、缓存或定时回填。
- 每个 ContentTask 在总数和分桶中各计一次；多个内容版本或多个发布记录不得重复计数，分桶执行已确认的固定优先级。
- 影响摘要不改变删除门禁：任何 ContentTask 直接引用都会阻止物理删除，不因任务取消、发布失败或内容状态而忽略。
- “查看引用详情”进入 `/tasks?platform_profile_version_id=<id>`，任务列表把该参数传给服务端并显示可移除条件；不得只在当前页或已下载任务中前端过滤。
- `GET /content-tasks` 新增可选 `platform_profile_version_id`；与已有 `platform_profile_id` 同时提供时按 AND 处理，省略时保持现有全量响应。

### R7 变更历史

- 复用 `/api/v1/audit-logs?target_type=PlatformProfileVersion&target_id=...`，按时间倒序展示创建、更新、激活、直接退役、自动替换退役和删除前审计。
- 右栏先展示最近事件和总数，“查看完整历史”进入真实审计日志筛选或展开分页，不建立第二套历史表。
- action、revision、替代版本 ID 和命令 comment 只按真实审计详情展示；没有评论的创建/更新不能补造说明。
- 自动退役与新版本激活必须在同一事务写入，失败时版本状态和两条审计均不部分提交。

### R8 加载、错误、权限与可访问性

- 平台、版本、详情、审计和引用是独立查询边界；次级查询失败不得遮蔽已加载的身份和规则正文。
- 覆盖加载、空平台、无版本、无审计、零引用、局部错误、无权限、revision 冲突和删除引用阻断状态。
- 所有图标按钮有可访问名称，状态不只依赖颜色；列表选择、更多菜单、差异弹窗、确认框和 Drawer 可用键盘完成。
- 桌面四列各自管理溢出；1199px 以下按 `research/visual-spec.md` 降级，移动端不产生页面级横向滚动，关闭弹层后焦点返回触发控件。

### R9 性能与一致性

- 平台、版本、引用和审计使用现有索引及批量查询；不为未经测量的数据量增加缓存、物化视图、搜索扩展或第三方依赖。
- 状态写入锁顺序保持“平台行 → 规则版本”，激活并发不得产生双 ACTIVE；revision 冲突不得被最后写入覆盖。
- 前端只保留一份 URL 选择/筛选状态和一份 React Query 服务端状态，不增加 Provider、全局 Store 或兼容字段。
- 当前规则、版本状态、影响分桶、引用门禁、可用动作和审计均由服务端拥有，前端隐藏按钮不构成权限控制。

## 非目标

- 不扩展五类缺少定义的原型规则字段；后续若需要，另立任务定义完整业务语义。
- 不增加规则模板库、规则名称/标签、跨平台共享规则、规则复制、批量激活、定时激活或自动回滚。
- 不新增统计快照、缓存、Celery 任务、软删除、默认规则或 ACTIVE 直接退役。
- 不重做平台管理、平台 Prompt、发布工作台、内容审核或 GEO 页面；只增加本任务所需的精确规则版本筛选入口。
- 不提交或推送 Git；实施完成后的提交仍需另行给出计划并获得用户确认。
