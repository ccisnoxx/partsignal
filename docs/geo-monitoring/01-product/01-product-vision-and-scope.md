# PartSignal GEO 产品愿景与范围

当前支持人工 GEO 数据录入和已经实现的 API 型采集。Browser Collector、浏览器会话材料、自动登录和浏览器页面采集属于后续功能，当前版本不支持、不开启、不部署。

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 文档状态 | 目标设计 |
| 核心用户 | 公司内部 GEO、市场、产品、FAE、内容和管理人员 |
| 产品定位 | 面向电子元器件企业的纯 GEO 内容运营工作台（本模块承担 AI 搜索监测、机会与复测闭环） |

## 1. 产品愿景

PartSignal 的定位是**面向电子元器件企业的纯 GEO 内容运营工作台**，不是元器件参数数据库、替代推荐引擎或工程验证平台，也不是只记录搜索结果的表格工具。

本模块持续回答：

> 主流 AI 平台如何发现、提及、引用和推荐公司的品牌与产品；其描述是否忠实于公司已在系统外确认并内部批准的产品事实；这种表现是否稳定、具有竞争力，以及应采取什么内容与发布行动加以改善。

一句话定义：

> **监测 AI 如何认识公司的产品，并持续通过内容运营改善这种认识。**

## 2. 核心业务价值

### 2.1 对市场和 GEO 运营

- 知道哪些用户问题能够自然发现公司产品；
- 知道公司与竞品在不同平台和问题中的提及、推荐和引用差距；
- 知道哪些来源正在影响 AI 的答案；
- 将趋势下降和竞争异常转化为可执行机会。

### 2.2 对产品和 FAE

- 依据系统外已确认并内部批准的 `FactVersion` Markdown，发现 AI 回答中偏离公司口径的参数、封装、认证、应用条件或替代表述错误；
- 区分“产品未被发现”和“产品被错误描述”；
- 保留每次核验的回答、引用和人工复核证据；具体技术真实性与电路替代可行性仍由系统外产品、FAE、研发或质量体系负责裁决。

### 2.3 对内容和渠道运营

- 识别未覆盖问题、弱引用领域和竞品信源优势；
- 从机会直接创建内容任务、事实修订或发布修复；
- 将已发布内容与后续复测关联；
- 避免只按内容数量评价 GEO 工作。

### 2.4 对管理层

- 观察重点产品的监测覆盖、可见率、推荐率、准确性和风险处理情况；
- 了解投入后是否出现持续、同口径的相关变化；
- 对每个数字都能下钻到原始证据。

## 3. 目标用户场景

### 场景 A：自然可见度

用户提出非点名问题，例如“某进口型号有哪些国产替代方案”。系统需要判断公司产品是否自然出现、是否被推荐、排名和竞品情况。

### 场景 B：品牌事实与声誉

用户点名公司或型号提问。系统需要检查回答是否正确、是否遗漏关键边界、是否引用权威来源。

### 场景 C：竞品差距

同一组问题中竞品持续被推荐。系统需要展示竞品依赖的主要信源、问题覆盖和推荐理由，并生成差距机会。

### 场景 D：内容发布后的复测

某项内容任务完成并形成发布成果。系统按冻结的基线问题和采集配置发起复测，展示前后差异但不声称单一因果。

### 场景 E：风险处理

系统发现严重错误声明。运营人员查看原回答和引用，产品人员核验后创建事实修订或纠错内容任务，并保留处理链路。

## 4. 产品边界

### 4.1 核心版范围

```text
监测对象与别名
→ 问题主题与变体
→ AI 观测面和采集配置
→ 监测计划与重复采样
→ 观测批次和单次运行
→ 原始回答、截图和引用
→ 提及、推荐、竞品和声明分析
→ 人工复核
→ 可解释指标和趋势
→ 机会、任务和同口径复测
```

### 4.2 与现有 PartSignal 的关系

| 现有能力 | GEO 核心版如何复用 |
|---|---|
| `Product` | 自有产品身份和详情入口 |
| `FactVersion` | 声明准确性核验的权威事实快照 |
| `QueryTopic` | 稳定问题主题；新增问题变体而非复制问题库 |
| `ContentTask` | 内容缺口和优化机会的行动载体 |
| `PublishedArticle` | 干预和文章关系观测的发布成果 |
| `PublishedContentIssue` | 已发布页面异常和修复链路 |
| `FileRecord` | 截图、导出和采集证据 |
| `GeoObservation` | 保留现有文章关系观测，不直接改造成回答级运行 |
| `AuditLog` | 高价值配置、规则、机会和复测动作审计 |

### 4.3 产品与核心版非目标

- 电子元器件全参数数据库、参数级证据知识图谱、自动替代可行性判定与 BOM 替代推荐算法（`GeoSubject` 中的 `REFERENCE_PART` 仅用于标记 AI 搜索问题中的参考型号监测对象，不构成结构化替代关系库）；
- 实验室测试、工程验证管理，以及对技术事实本身的最终工程真实性判断；
- 供应商、价格、库存、交期等供应链管理；
- 多租户、收费和客户门户；
- 自动替代产品事实审核；
- 大规模无授权浏览器爬取、浏览器自动登录及跨平台通用 RPA 自动发布；
- 传统 SEO 全套工具；
- 统一、不透明 GEO 分数；
- 通过一次前后对比宣称单一因果；
- 用外部模型自动覆盖人工复核结论；
- 将 Redis、浏览器本地状态或统计快照作为业务事实源。

## 5. 产品成功标准

核心版上线后，应能够稳定回答以下问题：

1. 某公司产品在指定时间、平台和问题集合中的自然可见率是多少；
2. 它是否被推荐，推荐位置和稳定性如何；
3. 哪些竞品在相同条件下表现更好；
4. AI 引用了哪些自有、竞品和第三方来源；
5. 哪些产品声明错误、部分正确或无法判断；
6. 哪些数据因样本不足、采集失败或人工未复核而不可下结论；
7. 哪些异常已经转化为任务，任务处理到什么阶段；
8. 干预后同口径复测有什么变化；
9. 任意指标能否下钻到原始问题、答案、引用、截图、分析版本和人工复核；
10. 管理员能否知道自动监测为何失败、是否产生外部调用和是否可以安全重试。

## 6. 产品阶段

| 阶段 | 能力目标 | 是否可业务使用 |
|---|---|---|
| R1 主数据与计划 | 能设计和预览监测矩阵 | 仅配置 |
| R2 人工运行框架 | 能系统保存回答级人工观测和证据 | 可进行受控人工试用 |
| R3 API 自动观测 | 能按计划自动运行受控 API 采集 | 可形成持续监测基础 |
| R4 分析与复核 | 能形成可追溯提及、推荐、引用和准确性结果 | 可用于日常运营 |
| R5 指标与洞察 | 能发现趋势并解释证据 | 可用于日常运营 |
| R6 机会与复测 | 异常转化行动并按同口径复测 | MANUAL 正式采集支撑核心闭环 |
| R8 核心生产硬化 | 安全、保留、恢复、性能与上线验收 | R6 后直接进入；Browser false 且无生产会话 |
| R7 浏览器试点（post-core 可选） | 保留批准真实界面自动化目标与已完成基础设施 | 804～807 延期，不阻断核心发布 |

当前范围依据[ADR-006](../05-decisions/ADR-006-defer-browser-collection-and-adopt-manual-first-core.md)；人工回答级观测是正式采集方式，见[人工观测 SOP](../02-business/05-manual-geo-observation-sop.md)。

## 7. 关键产品原则

1. **原始证据永远先于指标。**
2. **事实准确性优先于单纯提及。**
3. **非点名自然可见度与点名声誉分开。**
4. **人工、API、浏览器结果不静默混合。**
5. **重复采样优于单次结论。**
6. **指标必须可解释、可下钻。**
7. **机会必须能形成行动和复测。**
8. **自动化采集必须合规、可控、可停。**
