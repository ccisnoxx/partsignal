# ADR-003：采集、机器分析和人工复核分别版本化

- 状态：Accepted
- 日期：2026-10-01
- 接受日期：2026-10-01
- 接受依据：用户在本会话明确接受本 ADR 及 GEO-002 评审修订。
- 适用范围：新回答级 GEO 的采集证据、机器分析、人工复核、事实核验、当前有效结果及归档报告；保持原始证据和历史分析可追溯。

## 背景

外部回答是原始证据；实体识别、推荐判断和事实核验可能随着别名、事实或分析器升级而变化。人工还需要修正机器结果。

## 决策

- `AnswerSnapshot` 不可变；
- 每次机器分析创建 `AnalysisRevision`；
- 人工确认/修正创建追加式 `RunReview`；
- 当前指标使用服务端选择的当前成功分析和最新有效复核；
- 重分析不修改原始回答，也不删除旧结果。

## 原因

- 可审计；
- 能评估分析器质量；
- 支持事实版本更新后的重分析；
- 防止机器结论被误当原始事实；
- 允许人工复核高风险声明。

## 后果

- 数据表和详情模型更多；
- 必须处理旧复核在新 revision 后失效；
- 指标查询需要确定当前有效结果；
- 大规模重分析必须异步和限批。

## GEO-002 评审修订（已接受）

- 接受结论：用户接受证据、机器分析和人工复核分别版本化及以下评审修订；当前结果选择、状态与证据保留按这些约束在后续合同任务中落实。
- 建议区分不可变采集结果、AnalysisRevision 执行状态和派生工作阶段/指标资格，避免重分析把终态 Run 倒退到 ANALYZING 或 NEEDS_REVIEW。
- 建议明确采用 Run 上唯一的 current_analysis_revision_id。新成功结果的发布、同 run 归属校验和复核 revision 校验在受控事务中完成；较旧分析不得覆盖较新成功结果。新分析失败保留原有效指针，新成功结果发布后旧复核只作历史。
- 原始引用 URL、顺序与采集证据属于 AnswerSnapshot；来源分类、subject 匹配和文章归属属于 AnalysisRevision 的派生结果，不写进不可变原始引用作为唯一结论。
- 多个我方产品分别绑定同产品的非空 APPROVED FactVersion；无权威事实的声明保持 UNJUDGEABLE。分析输入快照与幂等哈希还需覆盖分析器/模型/提示配置及规则版本，不能只依赖答案、别名和单一事实版本。
- 默认阻止删除被分析引用的事实版本；如采用完整冻结事实证据替代强引用，须明确批准其可复现性、保密与保留规则。UUID 或片段不足以替代完整核验依据。
- 归档报告冻结实际使用的 run、analysis、review 和指标口径版本；实时查询重算历史时明确标识新口径。
- 详细依据、冲突及备选方案见 [GEO-002 架构评审记录](./GEO-002-architecture-review.md)。
