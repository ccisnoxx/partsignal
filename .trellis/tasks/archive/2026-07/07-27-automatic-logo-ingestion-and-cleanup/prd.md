# 自动 Logo 导入与资源清理

## 目标

平台管理员能够从平台官网发现、预览并确认导入 Logo；新确认的图片保存到自有对象存储并只以 `logo_file_id` 作为权威引用，同时安全回收未被引用的 Logo 资源。既有外链在第一阶段仅保留只读展示，等待管理员逐个转换。

## 背景与已确认事实

- `platform_profiles.website_url` 已保存平台官网地址。
- 当前平台 Logo 支持 `NONE | UPLOAD | EXTERNAL`：上传模式保存 `logo_file_id`，外链模式长期保存并直接展示 `logo_external_url`。
- 上传 Logo 必须是 `VERIFIED`、`PUBLIC`、`PLATFORM_LOGO` 文件，允许 PNG、JPEG、WebP、ICO，最大 2 MiB，不接受 SVG。
- 当前 `EvidenceStorage` 只支持签发上传、读取元数据和生成下载 URL，没有对象删除能力。
- 替换 Logo 时，服务端只改写平台引用；旧 `FileRecord` 与对象存储对象不会删除，也没有后台清理任务。
- 平台资料查询会在保存后失效；内容任务列表使用独立缓存，当前不会随平台 Logo 更新立即失效。
- 知乎官网同时声明 32×32 favicon 与 152×152 Apple Touch Icon；只读取 `/favicon.ico` 会选到低分辨率资源。
- Icon Horse 已提供按域名发现、缓存并返回最佳 favicon 的服务；当前 `https://icon.horse/icon/zhihu.com` 返回内容与知乎官方 152×152 Apple Touch Icon 完全一致。
- Icon Horse 的公开用法是 `GET https://icon.horse/icon/{domain}`，响应为服务端已经选定的一张图片，不提供多个候选、候选来源或评分清单；本系统只能把该响应作为一张待管理员确认的候选图。
- Icon Horse 会为无法访问或没有图标的网站返回通用占位图。实测不存在域名仍返回 `200 image/png`，响应未提供可用于证明“这是真实站点 Logo”的明确标识，因此管理员预览确认仍有必要。
- Icon Horse 免费方案当前标示每月最多 1,000 个图标；把它作为一次性导入来源可避免所有终端展示都持续依赖第三方配额与可用性。

## 需求

### Logo 导入

- R1：管理员显式触发官网 Logo 发现；MVP 从平台 `website_url` 提取规范化域名，并通过 `GET https://icon.horse/icon/{domain}` 获取 Icon Horse 已选定的一张候选图。
- R2：平台官网与 Icon Horse 响应均是不可信输入。服务端只访问固定的 HTTPS 上游、拒绝重定向，并限制域名解析、响应大小、内容类型和下载时间；失败必须返回明确错误，不得猜测或回退到伪造图片。
- R3：导入结果写入自有对象存储并创建 `VERIFIED`、`PUBLIC`、`PLATFORM_LOGO` 文件记录；新确认或已转换的平台 Logo 只保存 `logo_file_id`，不再新增外部 URL 展示源。
- R4：每次成功替换使用新的唯一对象键，不覆盖旧对象，避免浏览器或 CDN 把旧内容当作新 Logo。
- R5：导入成功后，所有展示当前平台 Logo 的前端查询必须失效并重新读取服务端权威值。
- R6：保留手工上传作为无法提取或管理员需要指定品牌资产时的显式入口。
- R7：前端只展示 Icon Horse 返回的这一张待确认候选图；管理员确认后才把同一份已暂存文件绑定到平台。取消、关闭或放弃确认不得改变平台当前 Logo。
- R8：Icon Horse 的通用占位图或错误品牌图不得被系统静默认定为真实 Logo；MVP 由管理员预览承担最终品牌确认。
- R9：MVP 只接受现有 Logo 契约允许的 PNG、JPEG、WebP 和 ICO。Icon Horse 返回 SVG、HTML 或无法识别的内容时必须明确失败并引导手工上传，不增加 SVG 清洗或栅格化转换。

### 资源清理

- R10：上传与官网导入产生的 Logo 使用同一套文件生命周期和清理规则，不按来源复制实现。
- R11：平台替换、清空或删除 Logo 时，只在业务事务中解除旧引用，不同步删除对象存储文件。
- R12：后台清理只处理超过保留期且没有任何实际文件外键引用的 `PLATFORM_LOGO`；不得维护可漂移的引用计数。
- R13：清理必须在并发下重新锁定并检查引用；对象删除应幂等，失败可重试，不能留下仍被平台引用但对象已消失的记录。
- R14：清理使用分级保留策略：
  - `PENDING` 超过 `upload_expires_at` 后进入清理；
  - `FAILED`、`ABORTED` 在下一次清理时处理；
  - Icon Horse 已导入但未被管理员确认的 `VERIFIED` 候选保留 24 小时；
  - 曾被平台使用的 `VERIFIED` Logo 从解除最后一个引用起保留 7 天；
  - 对象删除失败的文件持续重试，不得因次数耗尽而标记成功。
- R15：外部站点上的原始资源不属于本系统，系统只停止引用外部 URL，并清理导入到自有对象存储的副本。

### 契约与可观测性

- R16：`contracts/openapi.yaml`、`contracts/database.md`、运行时 Schema、生成的前端类型及权威方案文档必须与最终行为一致。
- R17：导入、替换和清理应记录不含敏感响应正文的审计或结构化结果；未知远端失败不能记录为成功。

### 旧外链退出

- R18：MVP 发布后，平台创建和编辑不得再提交新的 `EXTERNAL` Logo；现有 `logo_external_url` 仅用于只读投影和展示。
- R19：管理员使用相同的显式预览确认流程，逐个平台把旧外链转换为自有 `logo_file_id`；不得在数据库迁移或后台任务中自动批量下载、猜测或确认品牌 Logo。
- R20：本阶段保留 `logo_external_url` 列和旧数据读取能力。所有环境的外链记录归零后，后续独立变更再删除数据库列、`EXTERNAL` API 类型和只读兼容分支。

## 验收标准

- [ ] AC1：给定有效平台官网，系统只展示 Icon Horse 返回的一张有效候选；管理员确认并保存后，平台引用自有 `logo_file_id`，后续展示不再请求 Icon Horse。
- [ ] AC2：Icon Horse 无可用响应、发生重定向、候选超限、内容类型不符或网络不可用时，平台原 Logo 保持不变并返回明确失败。
- [ ] AC3：成功替换后，平台管理和内容任务等现有 Logo 展示位置无需整页刷新即可显示新图。
- [ ] AC4：同一文件存在任一实际外键引用时清理器不得删除；最后一个引用解除并超过保留期后，对象最终被删除。
- [ ] AC5：对象删除暂时失败时，文件保留可重试状态；重试成功后不再生成可用下载 URL。
- [ ] AC6：过期 `PENDING`、`FAILED`、`ABORTED` 文件在下一次清理时处理；未确认候选在 24 小时后处理；旧已用 Logo 只在解除最后一个引用满 7 天后处理。
- [ ] AC7：手工上传仍可替代自动发现结果，且与自动导入使用相同的展示和清理生命周期。
- [ ] AC8：一次提取只显示 Icon Horse 返回的一张候选；管理员取消预览时平台 Logo 与 revision 均保持不变。
- [ ] AC9：新建或编辑平台不能再创建 `EXTERNAL` Logo；部署前已存在的外链仍可显示，并能经管理员确认转换为上传文件。
- [ ] AC10：数据库迁移和后台清理均不会联网批量转换旧外链；存在旧外链时也不会静默清空。
- [ ] AC11：Icon Horse 返回 SVG、HTML、超限或无法识别内容时，平台原 Logo 保持不变，界面明确提示改用手工上传。

## 范围外

- 不定期重新抓取官网并自动覆盖已确认 Logo。
- 本系统直接抓取官网、解析 HTML 图标声明或展示多个候选图。
- 本阶段删除 `logo_external_url` 数据库列、自动批量导入旧外链或隐藏未迁移的旧 Logo。
- 内容哈希去重、跨平台共享优化或通用文件垃圾回收框架；只有真实需求出现后再扩展。
- 删除或控制外部站点、Icon Horse 等第三方持有的原始资源。
