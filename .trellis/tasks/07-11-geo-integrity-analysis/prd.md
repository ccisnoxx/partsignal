# GEO 数据完整性与分析闭环

## Goal

确保 GEO 观测、发布关联、更正链、筛选指标和异常待办使用一致且可追溯的数据语义，使运营人员能够基于可信样本判断效果。

## Requirements

- 保留“可能影响的发布”和 `GeoCitation` 实际引用两种独立关系，前者不计入引用率。
- “可能影响”所选发布和 `GeoCitation` 绑定的发布记录都必须属于观测产品且状态至少为 `PUBLISHED`；绑定发布记录的实际引用还必须满足引用 URL 与发布最终 URL 一致。
- `citation_rate` 统计至少包含一条 `OFFICIAL` 或 `EXTERNAL_COMPANY` `GeoCitation` 的当前有效观测，不要求引用必须绑定发布记录；`OTHER` 不进入公司引用率分子。
- 列表、指标和近期准确性错误统一排除被后续更正替代的原观测，只把更正链末端作为当前有效记录，同时保留完整历史。
- 指标和明细支持一致的产品、问题、模型和测试日期筛选，筛选状态可刷新和复现。
- 更正从观测行发起并锁定原产品、问题与 `supersedes_id`，用户不接触内部 UUID。
- 默认列表只显示更正链当前有效记录，行内可读取完整历史，并提供显式“包含历史”筛选；历史记录不进入指标或当前异常计数。
- 工作台展示近期准确性错误和发布异常，并可进入对应处理上下文。
- 上线前只读检查必须识别跨产品、低于 `PUBLISHED` 或实际引用 URL 不一致的历史关联，输出稳定 ID 与原因并阻断上线；只能由用户通过追加式更正逐条处置，不改写或删除原观测。

## Acceptance Criteria

- [ ] 跨产品、未达到 `PUBLISHED` 和实际引用 URL 不一致的关联均被服务端拒绝。
- [ ] “可能影响”关系可追溯但不会提高引用率；未绑定发布记录的官网或外部公司实际引用仍正确计入，`OTHER` 不计入。
- [ ] 原观测被更正后不再进入当前指标和异常计数，更正链历史仍可读取。
- [ ] 产品、问题、模型、日期及组合筛选返回可复算的正确分子、分母和明细，空样本不伪装成 0% 准确率。
- [ ] 用户无需输入 UUID 即可追加更正，重复更正和字段漂移由服务端拒绝。
- [ ] 默认列表不混入已被更正记录；查看完整链或包含历史不会改变指标口径。
- [ ] 工作台非零待办能够进入对应过滤结果。
- [ ] 任一未处置历史非法关联都会阻止上线；追加更正后当前有效链满足新约束，原观测仍可追溯。
