# 审计并修复全站表格列宽：技术设计

## 1. 设计结论

不建立新的表格运行时抽象。每张业务表仍在自己的 feature 中直接声明列，按真实内容调整 `width`、唯一主列的弹性空间和 `scroll.x`；现有 Ant Design `Table`、`TableRegion`、`TableCellText` 与 `workspace.css` 保持唯一基础。

本任务解决的是“空间分配错误”，不是再次治理普通长文本。上一轮全站门禁已经覆盖文本越界与省略，本轮补齐有界字段控件被挤压、换行和裁切的测试盲区。

## 2. 审计模型

每张表按以下角色核对：

1. 主身份：名称、标题、型号、问题或业务对象；普通管理表优先承担剩余空间。
2. 辅助身份：平台、账号、版本、类型等；按实际内容有界，不与主身份竞争无限空间。
3. 有界字段：状态、布尔、数量、百分比、时间；按真实渲染组件的单行尺寸设置紧凑宽度。
4. 输入控件：Checkbox、Select 等；宽度必须覆盖组件图形、文字、箭头和单元格内边距。
5. 操作：主按钮与更多菜单；宽度覆盖最长真实业务文案和间距，但不为不存在的动作预留空间。

对每张表记录 `fixedWidthSum`、无宽度主列的预期最小余量、`scroll.x`、选择列及条件列。数字只用于发现风险，不作为自动改代码的规则；最终决定由真实 DOM 几何和业务文案共同确认。

## 3. 修复策略

### 3.1 普通管理表

- 保留一个主要弹性列；通过收紧次要固定列或提高 `scroll.x` 给主列留出明确可读空间。
- 行选择表把 Ant 选择列宽纳入总宽度。
- 可选列通过当前可见列集合计算局部 `scroll.x`，不增加跨页面 helper。

### 3.2 从属、分析与弹窗表

- 允许全固定列，但 `scroll.x` 不小于列宽合同；不让浏览器在错误的最小表宽中再次压缩列。
- `scroll.x` 远大于列宽总和且导致短字段机械膨胀时，优先让主列弹性吸收空间或降低最小表宽。
- 弹窗输入矩阵优先保证 Checkbox、Select 和短操作单行可读，窄屏继续在局部滚动。

### 3.3 不采用的方案

- 不创建全站列宽常量表或列工厂：业务文案与列角色不同，集中配置会形成第二个表格模型。
- 不使用 ResizeObserver 或运行时测量后改列宽：会增加布局抖动和测试复杂度。
- 不通过 `white-space: nowrap`、隐藏 overflow 或缩短中文文案单独掩盖错误宽度。
- 不统一把 `scroll.x` 设为 `max-content`：会放弃当前可控的主次宽度合同。

## 4. 测试设计

在 `cross-page-visual-convergence.spec.ts` 的当前 25 表循环中扩展表格边界断言：

- 扫描可见数据行中的 Ant Button、Tag、Checkbox wrapper、Select、时间和登记的紧凑文本节点；
- 读取控件/文字矩形与所属 `td/th`，断言内容被单元格包含；
- 对短文本叶子使用 Range 检查只形成一个文本矩形，防止“已发现/已提及”类文案换行；
- 对可横滚表确认页面根节点不溢出，滚动由 Ant `.ant-table-content` / `.ant-table-body` 持有；
- 保留现有长文本压力探针、固定列背景、1440/375 和 200% 缩放检查。

通用探针只检查稳定的组件几何，不登记每页业务文案或宽度数字。特殊表（动态 GEO 矩阵、移动卡片替代、弹窗输入矩阵）继续使用现有 inventory 元数据和最小局部断言。

## 5. 文件边界

预计修改：

- 经真实浏览器确认存在问题的 frontend feature 表格文件；
- `frontend/tests/e2e/cross-page-visual-convergence.spec.ts`；
- 对应已有 Vitest（仅当列条件或动态 `scroll.x` 形成可测试逻辑）；
- 必要时更新 `.trellis/spec/frontend/component-guidelines.md` 或 `quality-guidelines.md`。

不预计修改共享组件、主题、后端、合同、数据库或部署文件。`workspace.css` 只有在至少三张表需要同一稳定几何规则时才修改。

## 6. 风险与回滚

- 过度收紧导致长文可读性下降：主身份保留弹性或明确最小余量，完整值合同保持不变。
- 操作列在不同状态下动作长度不同：使用 fixtures 覆盖最长 `primary_task` 文案与更多菜单组合。
- 测试误报：只扫描稳定 Ant 组件和明确短文本，不把允许多行的复合身份、错误摘要或移动卡片纳入单行断言。
- 修改面扩大：按领域小批次提交到同一任务，每批可独立恢复原列宽；不引入共享运行时依赖。

任务不拆子任务。25 表清单、共同测试盲区和最终跨页验收属于同一展示不变量，拆分会产生中间状态下的重复审计与门禁漂移。
