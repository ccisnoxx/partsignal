# 技术设计

## 边界

本任务是共享组件消费方式的收敛，不创建新的页面抽象。`PageHeader`、`MetricTile`、`TableRegion`、`StatusTag` 和 `theme.ts` 保持不变；页面继续拥有自身查询、权限、路由、mutation 和详情状态。

## 页面设计

### 用户管理

- 删除页面私有 `SummaryCard`，将原有五项服务端汇总映射为 `MetricTile`。
- 保留原标签、值、加载态和“暂无历史基线”元信息。
- 账户类型和状态列使用紧凑 `StatusTag`，其余筛选、选择、批量操作、弹窗和侧栏不变。

### 平台管理

- 将五张私有指标卡替换为 `MetricTile`。
- 搜索、平台类型、状态和配置完整性筛选保留原 URL 参数，并补足可见标签。
- 平台状态使用紧凑 `StatusTag`；Prompt 配置完整性仍使用页面局部 `Tag`，因为它表示存在性而非共享状态枚举。
- 删除整行 `onRow` 详情激活，保留操作列“查看”作为唯一详情入口；编辑、启停、删除继续位于原菜单和确认流程。
- 窄屏 Drawer 即使在入场动画完成前关闭，也等待关闭时序结束并把焦点恢复到当前列表中的原“查看”按钮。

### AI 渠道

- 主工作台私有标题替换为 `PageHeader`，保留顶部现有操作。
- 左侧状态轨道继续作为 URL 同步的筛选器；工具栏补足可见标签。
- 渠道启用和测试状态使用紧凑 `StatusTag`。
- 渠道名称改为普通文本，操作列“配置/查看”成为唯一详情入口；单渠道测试、启停和删除归入 `Dropdown`。
- 详情标题和基本信息启用状态使用普通 `StatusTag`；模型表启用和测试状态使用紧凑模式。
- Header 表操作列固定右侧；模型表保留“测试”为高频入口，其余操作保留在菜单。
- 四项服务端用量统计改用 `MetricTile`；操作日志展示已有 `outcome` 状态，不新增 API 字段。

### 审计日志

页面 JSX 保持不变，作为本批结构参考。只通过局部 CSS 和跨页验收确认标题、筛选、表格、状态及操作密度一致。

## 样式与响应式

- 只在 `global.css` 的用户、平台、AI、审计现有选择器范围内调整标题间距、指标网格、筛选表面、表格密度、固定操作列和窄屏布局。
- 继续消费 `--ps-*` 与 Ant Design 主题值，不写原始颜色或第二套深色规则。
- 复用现有 1199、767、419px 断点；指标网格按可用空间减列，375px 用户和平台指标使用两列。
- 保留 AI 三栏布局的既有响应式折叠和各页面现有 Drawer/详情行为。

## 兼容性与回滚

- 无数据迁移、API、类型、路由或依赖变更。
- 每个页面可按文件独立回滚；`global.css` 的本任务改动必须使用现有页面命名空间，避免影响排除页面。
- 若实现发现共享组件接口确实不足，停止并回到规划，不在本任务内临时扩展接口或建立包装组件。
