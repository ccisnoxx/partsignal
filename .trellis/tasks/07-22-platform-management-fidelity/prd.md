# 配置中心平台管理高保真复刻与功能闭环

## 目标

以用户提供并批准的 1581×995 原型为视觉与交互规格，在现有 `/configuration/platforms` 页面上迭代，形成基于 PostgreSQL 权威数据的具体平台管理闭环；不得创建平行页面、第二套平台数据结构、重复接口、静态指标或前端业务判断。

## 用户价值

- 管理员能在一个高密度工作台中查看平台配置完整性、检索平台、打开详情，并完成已有或本任务批准的平台管理操作。
- 平台规则、Prompt、发布账号、内容/发布/GEO 历史继续由既有权威模型拥有，平台页只读取统一投影和调用现有命令。
- 原型视觉、可访问性和真实交互均可通过 Browser 与自动化检查复核。

## 已确认事实

- 接受规格是 `artifacts/platform-management-prototype-1581x995.png`；原始像素为 1581×995，禁止 ImageGen 和重新设计。
- 当前页面是 `frontend/src/features/configuration/PlatformsPage.tsx`，已有平台列表、新增、编辑、物理删除、Logo/官网/允许域名维护和当前规则激活选择。
- `/api/v1/platform-profiles` 当前返回全量 `items`，没有搜索、筛选、分页、统计、详情或导出参数。
- `PlatformProfile` 当前只有身份、类型、允许域名、品牌信息、修订号、当前 ACTIVE 规则投影和 `prompt_configured`；没有平台自身的启用状态。
- 平台可合法缺少 ACTIVE 规则或当前 Prompt；工程师创建内容任务时服务端要求两者同时存在。当前规则只由唯一 ACTIVE 版本派生，不保存第二个 `current_rule_id`。
- 平台 Prompt 由具体平台唯一持有；不存在类型级 Prompt、默认 Prompt 或兼容回退。
- 平台账号已有 `is_active` 数据，但现有公共 API 只有列表、创建和删除，没有账号启停命令。
- 平台物理删除必须先无规则版本、无平台账号；规则版本和账号各自继续通过外键与服务端检查保护内容任务、发布记录及历史。
- 平台、规则和 Prompt 写操作沿用管理员权限；平台账号创建沿用内容工程师权限、删除沿用管理员权限。所有写操作继续使用既有 CSRF、修订校验（适用时）和审计机制；PostgreSQL 是业务状态唯一来源。
- 用户已确认平台启停是独立于规则和 Prompt 的持久化状态：现有平台迁移为启用；停用平台仍可查看、编辑和重新启用，但不能用于新建内容任务、平台账号或发布记录；停用不自动改变既有账号、规则、Prompt 或任何历史记录；启用不代表配置完整。
- 用户已确认“平台被内容引用次数”统计引用该平台任一规则版本的 `ContentTask` 数量；每个任务只计一次。最近 30 天按任务 `created_at ∈ [as_of - 30 天, as_of)` 统计，历史次数统计全部任务；“查看引用分析”进入按该平台筛选的内容任务列表。
- 用户已确认五张统计卡只展示实时权威计数，原型趋势行统一显示“暂无历史基线”；本任务不新增统计快照表、定时任务或历史回填。
- 当前 Browser 基线见 `artifacts/current-platforms-1581x995.png`：已有外壳、导航、顶栏、标题和全量表格，缺少原型统计卡、筛选条、详情面板、导出、状态列、账号数、更新时间和引用摘要。

## 功能分类与差异

### 已存在，可直接复用

- 配置中心路由、管理员导航与权限守卫、页面标题、全局搜索、主题和用户区域。
- `PageHeader`、`TableRegion`、`AsyncState`、`StatusTag`、`PlatformAvatar`、`DirectUpload`、Ant Design 表格/表单/Drawer/Dropdown 和现有语义 Token。
- 平台创建、身份编辑、Logo、官网、允许域名、平台类型归属、当前规则选择、Prompt 状态、物理删除及结构化引用错误。
- 平台规则、平台 Prompt、平台账号、发布记录、审计日志和 GEO 页面已有真实数据与稳定入口。

### 后端已有但前端平台页缺失

- 平台类型名称关联展示。
- 规则版本状态、创建时间和当前 ACTIVE 版本。
- Prompt 更新时间（需按详情对象读取，不在当前列表投影）。
- 平台账号总数/启用数/停用数（数据存在，但需服务端聚合避免全量前端拼装）。
- 审计记录可用于平台更新时间投影，但当前 `PlatformProfile` 自身没有更新时间字段；无对应历史审计时必须返回空值，不得用迁移时间补造。
- 发布记录与 GEO 观测可沿现有关系定位平台，但本任务已确认引用摘要只统计关联平台任一规则版本的 `ContentTask`，不混入发布或 GEO 数量。

### 可由前端独立实现

- 按批准原型调整页面网格、统计卡/筛选栏/表格/详情面板的展示与响应式样式。
- 详情面板选择、关闭、独立滚动和底部固定操作区；选中平台 ID 写入 URL 查询参数以支持恢复。
- 加载、空数据、错误、无权限、键盘焦点和可见焦点展示。
- 关联入口跳转到已有页面并携带已有页面支持的真实筛选参数；目标页面不支持时不得伪造过滤。

### 需要新增后端、API、数据库或权限契约

- 平台服务端搜索、平台类型筛选、配置完整性筛选、分页和同条件总数。
- 五张统计卡的统一服务端投影和明确口径；趋势行固定展示已批准的“暂无历史基线”，不新增历史数据源。
- 当前筛选与权限范围内的真实导出。
- 平台详情聚合：类型、当前规则、Prompt、账号摘要、更新时间和已确认口径的引用摘要。
- 平台自身独立启停状态、显式命令及所有新建业务入口的服务端门禁。
- 平台名称、URL 和允许域名的统一服务端规范化/边界校验；当前创建和更新行为不一致。
- 对新增/变更命令继续执行管理员权限、CSRF、乐观锁、状态/引用校验和审计。

## 需求

### R1 忠实复刻现有页面

- 保持 PartSignal 左侧导航、配置中心展开、顶部栏和现有全局交互，仅把“内容平台”文案按批准原型统一为“平台管理”。
- 在 1581×995 视口优先还原原型的三栏比例、标题区、五张统计卡、筛选栏、平台表格和右侧详情面板。
- 复用现有主题变量与 Ant Design 组件，不建立第二套设计系统，不新增不在原型中的可见卡片、标签、文案或装饰。
- 平台 Logo 优先使用现有上传/外链资产；没有 Logo 时沿用现有可访问回退，不引入 Emoji 或品牌文字方块。

### R2 权威列表、统计、筛选和导出

- 列表、统计、筛选、分页、详情和导出使用同一服务端查询口径与当前接口的获权数据集合；管理详情和导出仍只对管理员开放。
- 搜索覆盖平台名称和所属平台类型；筛选覆盖平台类型、平台状态和配置完整性。
- 配置完整定义为：存在当前 ACTIVE 规则且当前平台 Prompt 已配置；规则有效与 Prompt 完整性只能由服务端计算。
- 统计卡至少返回平台总数、已启用平台、缺少 Prompt、缺少有效规则、配置完整平台；示例数字不得进入代码或种子数据。
- 趋势位置统一展示“暂无历史基线”；不新增统计快照、定时任务或从审计记录猜测历史状态。
- 导出采用当前筛选条件、稳定排序和权限范围，不接受前端全量后自行过滤的替代实现。

### R3 平台表格与详情

- 表格包含批准原型列：平台名称/图标、所属平台类型、官网、允许域名及数量、平台状态、当前规则版本、Prompt 状态、发布账号数量、更新时间和查看/更多操作。
- 选择查看后，详情面板与 URL 中平台 ID 同步；切换行实时切换真实详情，关闭后释放主区空间。
- 详情展示基本信息、当前规则、Prompt、账号摘要和引用摘要，以及对应真实入口。
- 引用摘要由服务端按 `ContentTask → PlatformProfileVersion → PlatformProfile` 关系聚合：每个任务只计一次；最近 30 天使用请求统一 `as_of` 和半开区间 `[as_of - 30 天, as_of)`，历史次数不设时间下界。
- 详情面板正文独立滚动，桌面底部操作区保持稳定；移动端沿现有 Drawer 规则确保可访问、无页面级横向溢出。

### R4 新增、编辑、状态和删除

- 新增/编辑继续复用现有字段与 Logo 能力，不根据原型猜测额外配置。
- 服务端统一规范化名称、官网 URL 和允许域名；重复 slug、同一平台内规范化后重复域名、非法主机名和修订冲突返回明确错误，不发明跨平台域名唯一约束。
- 平台新增独立 `is_active` 字段和显式启停命令；现有平台迁移为启用。停用后仍可由管理员查看、编辑和重新启用，但服务端禁止新建绑定该平台的内容任务、平台账号或发布记录。
- 平台启停不得自动改变既有账号、规则、Prompt 或任何历史记录；启用与配置完整互相独立，且不得与规则激活/退役隐式联动。
- 删除继续执行现有直接引用检查；任何新增历史约束必须写入数据库契约和服务，不得在前端静默改为停用。
- 删除被拒绝时返回结构化引用计数并明确引导管理员停用平台。

### R5 关联入口

- “查看规则详情”进入既有平台规则页并定位当前平台。
- “查看 Prompt 详情”进入既有平台 Prompt 页并定位当前平台。
- “查看账号列表”进入既有账号管理界面并定位当前平台；现有目标页若缺少 URL 过滤，本任务只增加最小真实过滤能力。
- “查看引用分析”进入按当前 `platform_profile_id` 服务端筛选的内容任务列表；不得创建空白占位分析页。

### R6 安全、历史与一致性

- 所有写入仅落 PostgreSQL；Redis 继续只作为 Celery Broker。
- 已发布规则、内容/生成快照、发布状态事件、GEO 观测和审计记录保持不可变；平台编辑不得回写历史快照。
- 新增公共 API、数据库字段、索引、权限或状态变更时同步 OpenAPI、数据库契约、生成类型、迁移、服务、前端和测试。
- 不使用 Mock、固定成功路径、静态业务数据、静默默认值、模糊兼容字段或前端第二套完整性判断。

### R7 可访问性、状态和响应式

- 语义化标题/区域/表格/表单，控件有可访问名称和标签；键盘可完成筛选、分页、详情、表单和危险操作确认。
- 覆盖默认、悬浮、选中、禁用、加载、空数据、错误和无权限状态，并保持可见焦点。
- 桌面按原型优先；375/768/1024/1440 和 200% 缩放沿现有响应式规则，无页面级横向溢出，核心操作可完成。
