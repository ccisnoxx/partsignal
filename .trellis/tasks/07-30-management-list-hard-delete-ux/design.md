# 技术设计：管理页面操作补齐与全站表格布局修复

## 设计边界

本任务在现有内容任务删除服务、服务端 `available_actions`、Ant Design 表格/菜单、`TableRegion` 和 `workspace.css` 内完成。API 路径、响应结构、权限模型、业务查询口径和编辑器状态不变；不增加全局动作注册表、表格组件框架、依赖、设计 Token 或兼容分支。

服务端继续是动作资格和删除边界的唯一权威。前端只消费 `available_actions`：它可以解释服务器未返回动作时的只读状态，但不能自行补造可执行动作。

当前任务不拆成动作与表格两个子任务：`ContentTasksPage.tsx`、`PublicationWorkspace.tsx`、对应测试和 `workspace.css` 同时承载两类改动，拆分会形成重复文件所有权和串行依赖。实施计划按后端删除、页面操作、全站表格三个可独立验证阶段推进。

## 内容任务物理删除

### 删除资格

| 任务状态与历史 | 结果 |
| --- | --- |
| 非 `CANCELLED` | 拒绝，返回 `INVALID_STATE_TRANSITION` |
| `CANCELLED`，仅有生成作业和 `DRAFT` / `PENDING_REVIEW` / `CHANGES_REQUESTED` 内容 | 允许，删除任务自有历史 |
| 任一内容为 `APPROVED` 或 `SUPERSEDED` | 拒绝；`SUPERSEDED` 表示内容曾经批准 |
| 任一任务内容已有发布记录，不论发布记录当前状态 | 拒绝 |
| 任务来自发布异常修复待办 | 拒绝 |
| GEO 引用/观测或发布修复历史 | 通过其发布记录或修复待办关系拒绝，不删除下游历史 |

### 事务与数据库保护

复用 `0030_publication_record_delete.py` 和事实版本删除的现有模式，新建紧跟 `0032` 的 `0033_task_owned_history_delete.py` 迁移：

1. 删除服务按现有工作流锁顺序锁定目标任务的生成作业、内容版本和任务，并重新检查任务状态与所有阻断关系，避免生成 worker、审核操作和删除互相覆盖。
2. 命中已批准/曾批准内容、任意发布记录或修复来源时，复用现有 `CONTENT_TASK_IN_USE` 业务错误并返回受保护资源计数；不能把外键异常直接暴露给 API。
3. 只有全部检查通过后，写入不含正文或 Prompt 的删除审计摘要，并设置事务局部变量 `partsignal.content_task_delete_id`。
4. 数据库触发器只允许目标任务的内容版本把 `source_job_id` 置空，用于拆开 `content_versions ↔ generation_jobs` 的循环外键；其他不可变字段和状态转换仍受原守卫保护。
5. 内容审核记录的 append-only 触发器只允许在事务变量精确匹配其父内容版本所属任务时删除；普通 `UPDATE`、普通 `DELETE` 和错配目标仍以 `55000` 失败。
6. 服务按顺序删除目标任务的生成作业、内容审核记录、内容版本和任务。事实版本、用户、平台、Prompt、发布记录、GEO 数据和审计日志不级联。
7. 任一步失败由同一数据库事务整体回滚；前端只发送一次任务删除请求。

不把相关外键改成 `ON DELETE CASCADE`，因为这会把受保护历史的删除边界从显式服务和数据库守卫扩散到任意任务删除语句。

### 动作投影

把 `backend/app/services/projections.py` 的“存在任意生产历史即不可删”批量口径改为“存在受保护历史才不可删”：

- `OPEN` 且没有在途发布，继续返回 `CANCEL`。
- `CANCELLED` 且没有已批准/曾批准内容、发布或修复来源，返回 `DELETE`，即使存在可清理的生成作业和未发布内容。
- 列表继续批量聚合，详情与列表调用同一资格函数，不增加逐行查询。

## 前端操作与详情

### 内容任务

- 列表保留“查看详情”为高频入口；根据每行 `available_actions` 在现有 Ant Design `Dropdown` 中提供取消和物理删除。
- 详情页复用同一取消、删除 mutation、确认和刷新逻辑。没有动作时显示只读说明；已取消但没有 `DELETE` 时明确说明存在已批准或下游历史。
- 取消继续提交当前 `revision` 和原因；物理删除继续二次确认。前端不拼接依赖删除请求。

### 发布记录

- 更多菜单始终渲染“物理删除”项。
- 服务端返回 `delete` 时，复用现有 mutation 和确认流程；未返回时保持禁用并说明已有公开、GEO 或修复历史，其他状态动作不变。
- 不改变现有发布记录删除 API、审计、资格判断和数据库守卫。

### 作业追溯与 02A / 02B

- 最新作业追溯卡只保留现有契约版本、渠道/模型和请求参数；删除 `system_message`、`user_message` 两个完整只读输入区。作业表已提供的身份、状态、结果和重试入口，以及后端不可变输入快照均不变。
- 桌面工作区改为两个 `minmax(0, 1fr)` 等宽列，卡片拉伸为等高，卡片正文使用现有布局让操作区底部对齐；现有窄屏断点仍堆叠为单列。

## 全站表格布局

### 审计基线

`research/sitewide-table-audit.md` 是本任务的全量清单，当前包含 24 张表。实施前再次用源码搜索核对清单，避免新增或遗漏的 `Table`、原生业务矩阵和弹窗表逃逸；每张表记录“通过、需要修复、业务例外”之一，并附浏览器几何结果。

### 共享不变量的最小实现

- `TableRegion` 继续只持有语义焦点和外层宽度边界；Ant Table 自己持有横向滚动。只移除经浏览器证明确实裁切滚动/sticky 的局部 `overflow:hidden`，不把滚动转移到第二层容器。
- 在 `workspace.css` 复用或收敛一个通用的可收缩单元格样式：`display:block; min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap`；一个无业务逻辑的 `TableCellText` 叶子组件只负责复用完整值 Tooltip 和键盘焦点。身份单元格允许固定两行，但两行各自省略。
- 每张表的列配置明确一个弹性文本列；状态、数值、时间和操作列保留固定宽度。`scroll.x` 至少覆盖固定列总宽与弹性列最小宽。
- 只有列宽合同和 `ellipsis` 需要时才使用 Ant Design 固定表格布局；不全局设置 `table-layout: fixed`，避免破坏动态 GEO 矩阵和小型指标表。
- 表格内 ID、URL、slug、账号和错误摘要使用单行省略及键盘可达完整值，不继续使用无上限 `overflow-wrap:anywhere` 把行高撑大。
- 为 `TableRegion` 下的固定右列提供不透明基础背景；页面已有的悬停、选中和异常行颜色继续覆盖固定列，但结果也必须不透明。
- 操作列按实际按钮组合校准宽度，保持单行；不缩小触控目标，也不隐藏现有高频入口。

这些规则只有一个共享 CSS 所有者和一个无业务逻辑的 `TableCellText` 叶子组件；不新增表格包装器、列工厂或配置注册表。各页仍直接声明业务列，避免为了视觉约束制造第二套表格模型。

### 页面组修复

1. 内容与事实：复核内容任务主列表；修复 AI 作业失败原因、内容版本标题、产品型号/品牌、事实版本变更说明与操作区。
2. 发布与 GEO：修复候选标题/账号、发布记录账号、发布异常平台/账号、GEO 观测平台/记录人、文章结果、问题库和内容排行；平台表现及原生覆盖矩阵按现有设计验证后只修实际违例。
3. 配置与系统管理：复核 AI 渠道和平台列表；修复 AI Header、模型、渠道日志、全局审计、模型发现弹窗、平台类型、发布账号和用户列表的长字符串、滚动及固定操作列。
4. 发布记录的最终 URL 继续只显示“打开”入口，不重新塞入完整 URL；完整 URL 由链接和详情持有。
5. 原生 GEO 覆盖矩阵保留动态列、打印与内部横向滚动，不为统一组件而改写。

### 浏览器几何判定

每张表在边界数据下量测：

- 文档 `scrollWidth <= clientWidth`；
- 表格滚动容器存在且可以键盘聚焦；
- 文本/控件的可视矩形不越过所属单元格；
- 相邻列和固定操作列的矩形不相交；
- 普通、紧凑、固定两行身份单元格分别保持预定行高；
- 固定列普通/悬停/选中/异常背景 alpha 为完全不透明；
- Tooltip、`title` 或详情入口可通过键盘获得完整值。

## 合同与权威文档

- `contracts/openapi.yaml`：更新内容任务 `DELETE` 的行为说明与 `409` 边界；路径、请求和响应结构不变。
- `contracts/database.md`：记录允许清理的任务自有历史、禁止删除的批准/下游边界、事务变量、触发器例外和删除顺序。
- `.trellis/spec/frontend/component-guidelines.md`：把全表统一验收不变量固化为稳定规范，防止新列表再次只按短测试数据设计。
- OpenAPI 类型形状不变，仍运行合同生成一致性检查；若生成文件没有差异则不保留机械改动。

## 测试设计

### 后端

- 已取消任务仅有生成作业、未发布内容及审核记录时，单次删除成功，任务自有记录全部消失，审计保留且不含正文/Prompt。
- `APPROVED`、`SUPERSEDED`、任意发布记录、修复任务分别稳定返回业务错误并保持所有记录不变。
- 非取消任务仍拒绝；事务守卫对未声明变量、错配任务、普通内容版本修改和普通审核记录删除继续报错。
- worker 或内容审核与删除竞争时只有一个符合状态机的结果，不残留孤儿记录，也不以外键错误暴露给 API。
- 列表与详情对同一任务返回一致的 `available_actions`，批量列表不退化为逐行查询。

### 前端与浏览器

- 组件测试覆盖内容任务列表/详情取消与删除入口、发布记录删除可用/禁用、追溯消息不渲染、两卡布局类，以及各页面长文本单元格的语义省略和完整值入口。
- 扩展现有列表 E2E 清单，真实访问 24 张表；详情页、Tab 和弹窗表通过清单中的打开步骤进入，不能只检查顶级路由。
- 共享测试数据使用接口允许上限附近的标题、平台、账号、记录人、URL、ID、slug、错误摘要和变更说明，不能在生产环境加入测试绕过。
- `1440×1000` 和 `375×900` 逐表执行通用几何判定；浅/深主题覆盖全部固定列状态。真实 200% tab zoom 使用现有浏览器扩展，覆盖五类代表表，不使用 CSS `zoom` 或 `Emulation.setPageScaleFactor` 代替。
- 对已复现三表保留精确的相邻列与行高断言；其他静态风险表按其长字段增加精确断言。截图保存在仓库外，不修改视觉基线。

## 兼容性、回滚与风险

- 迁移只放宽被声明任务的两项必要删除操作；正常内容不可变、审核追加式和受保护历史规则保持不变。降级恢复原触发器函数，不恢复已经合法删除的数据。
- 删除运行中生成作业的风险由任务已处于 `CANCELLED`、统一锁顺序和 worker 最终任务状态校验共同约束；并发测试必须证明 worker 不会在删除提交后重新写回内容。
- 布局修改只依赖项目已安装的 Ant Design 和 CSS，不增加浏览器兼容面。
- 全站表格改动的主要风险是共享 CSS 影响已经稳定的固定列和密集指标表。实施按三个页面组逐批运行 24 表清单，任何共享规则只有在所有已覆盖表均通过时保留；不以增加页面特例掩盖错误的全局规则。
- 本地测试数据与预发布记录不同；自动测试使用更长的边界数据，最终再以预发布只读数据做全路由抽样复测。
