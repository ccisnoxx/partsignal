# 统一正式新密码最小长度为 8 位

## Goal

保留首次登录强制改密，将正式新密码的前后端与 OpenAPI 最小长度统一为 8，并补齐测试。

## Requirements

- 用户使用临时密码首次登录后，继续由 `must_change_password` 强制进入修改密码流程。
- 用户设置正式新密码时，前端表单、服务端请求校验和 OpenAPI 契约统一要求至少 8 个字符。
- 管理员创建用户时的初始临时密码规则保持不变；管理员重置临时密码的既有至少 8 位规则保持不变。
- 保留旧密码校验、密码确认、登录态失效及其他现有改密行为，不新增兼容分支或第二套密码策略。
- 同步生成的前端契约类型，并为 7 位拒绝、8 位接受补充回归测试。

## Acceptance Criteria

- [x] AC1：普通用户首次登录仍被要求修改临时密码。
- [x] AC2：正式新密码为 7 个字符时，前端和服务端均拒绝；8 个字符时均接受。
- [x] AC3：OpenAPI 中 `ChangePasswordRequest.new_password.minLength` 为 8，生成类型与契约一致。
- [x] AC4：管理员创建用户的初始临时密码下限仍为 12，管理员重置临时密码下限仍为 8。
- [x] AC5：针对性后端测试、前端测试、类型检查和契约生成一致性检查通过。

## Notes

- 本任务只调整现有校验常量和对应测试，不修改数据库、权限或状态转换，因此按轻量任务执行。
- 验证通过：后端 Schema/运行时 OpenAPI 契约 4 条、前端改密 1 条和用户管理回归 7 条；Ruff、mypy、前端 lint、typecheck、`api:check` 与 `git diff --check` 均通过。
- PostgreSQL 首次登录集成用例因本地未配置 `PARTSIGNAL_TEST_DATABASE_URL` 跳过；对应状态转换代码未修改，静态链路与既有集成断言已复核。
