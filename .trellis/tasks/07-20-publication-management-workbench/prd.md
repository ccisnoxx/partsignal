# 发布管理人工发布工作台 PRD

## 文档状态

- Trellis 任务：`07-20-publication-management-workbench`
- 当前状态：`in_progress`
- 规划已于 2026-07-20 获用户批准，实施按 `implement.md` 执行。
- 完整审计证据见 `research/gap-analysis.md`，视觉研究见 `research/visual-design.md`。

## 当前问题

现有 PartSignal 已经完成发布闭环的关键业务能力，但 `/publications` 仍是三个基础页签加多个独立详情页：流程数量取已加载数组，发布记录只固定加载前 100 条，记录和异常列表缺少内容/平台上下文，发布动作散落在详情页，周期统计和最近动态没有聚合接口。结果是操作者难以在一页判断“现在该发布什么、处于什么状态、哪里需要处理”，原型所表达的信息层级也无法仅靠 CSS 调整得到。

本任务不重建发布业务，而是以现有数据库状态机和服务端动作为唯一权威，把候选、登记、验证、异常和历史组成一个人工发布工作台，并只补充完成该工作台确实需要的最小契约。

## 用户目标

1. 一眼看到真实、全量的当前发布流程分布和待关注数量。
2. 在高密度但易扫描的列表中按候选、发布记录和关注事项工作。
3. 在聚焦 Drawer 中完成发布准备、平台状态推进、结果登记、证据关联和页面验证，同时看到锁定版本、平台账号与服务端错误。
4. 通过真实发布指引、确定性异常分类、默认 7 天且可切换 30 天的数据概览和最近状态动态理解流程健康度。
5. 在 1536×1024、1024px 和 375×812 下均可使用，并完整支持浅色、深色、跟随系统和键盘操作。

## 纳入范围

### 1. 发布流程概览

- 以 PostgreSQL 当前数据全量聚合并展示真实状态：`PENDING_MANUAL_PUBLISH`（待人工发布）、`PLATFORM_REVIEW`（平台审核中）、`PUBLISHED`（已发布）、`VERIFIED`（已验证）和 OPEN `PublicationAttention`（发布需关注）。
- 七个 `PublicationStatus` 均在响应中计数，拒绝/下线/验证失败通过记录筛选和异常摘要访问；不创造前端状态。
- 已批准但尚未创建发布记录的候选只显示在“待发布候选”页签计数，不算作 `PENDING_MANUAL_PUBLISH`。

### 2. 列表与筛选

- 保留“待发布候选 / 发布记录 / 发布需关注”三个真实业务视图，页签、状态、平台和分页状态写入 URL。
- 候选列表展示内容标题、内容版本、锁定目标平台、匹配发布账号和可执行入口。
- 发布记录列表展示内容标题/版本、平台、发布账号、状态、实际标题、最终 URL、发布时间、最后验证时间和服务端 `available_actions`。
- 关注列表展示内容/平台上下文、触发状态、打开时间、修复任务、状态和服务端动作。
- 发布记录使用服务端分页和状态查询；候选和 OPEN 关注在完整返回集合上做确定性筛选。不得遍历分页结果计算全量数据。

### 3. 发布结果登记

- 使用按需右侧 Drawer，不保留无选中对象时的空固定栏。
- 候选阶段复用发布包、正文复制、匹配账号、栏目 URL、证据上传和幂等创建，生成 `PENDING_MANUAL_PUBLISH` 记录。
- 记录阶段严格按 `available_actions` 渐进显示：进入平台审核、平台拒绝、登记已发布、人工验证、标记下线或验证失败。
- 登记已发布保留实际标题、最终 URL、发布时间和备注，并允许把已 VERIFIED 的操作截图/证明文件在同一事务中追加绑定到发布记录。
- 目标平台、内容版本、发布账号和内容哈希只读展示；客户端不允许改写锁定绑定。

### 4. 发布指引

以静态业务说明呈现以下真实步骤：复制已审核内容；在锁定目标平台人工发布；登记最终 URL、平台状态和必要证据；完成人工页面验证；异常时进入关注和修复流程。不得实现帮助内容配置、后台编辑器或 CMS。

### 5. 常见异常类型

只采用现有稳定字段能够确定的三类：

- 平台拒绝：发布记录当前状态 `REJECTED`。
- 页面已下线：OPEN `PublicationAttention.trigger_status=REMOVED`。
- 页面验证失败：OPEN `PublicationAttention.trigger_status=VERIFICATION_FAILED`。

点击必须打开相应真实筛选。页面无法访问、URL 验证失败、内容与登记版本不一致等更细类别当前只可能存在于自由文本中，本任务暂缓，不做模糊匹配。

### 6. 发布数据概览

已确认默认展示滚动 7 天数据，并提供 7 天/30 天周期选择器；所选周期写入 URL，刷新和前进/后退后保持。指标包括登记发布数、验证通过数、验证通过率、新增异常数，以及截至响应时刻的当前未解决关注数。响应必须带 `window_days`、`window_start` 和 `as_of`，全部由后端聚合。

### 7. 最近发布动态

显示最近 5 条 `PublicationStatusEvent`，包含内容标题、内容版本、平台、真实状态、发生时间和发布记录深链。不得复用管理员全局审计日志，也不得逐条请求详情。

### 8. 视觉、主题、响应式和可访问性

- 视觉以原型的 macOS 磨砂玻璃、紧凑表格和层级关系为参考，但颜色、字体、圆角、阴影和状态语义全部复用 PartSignal 现有 Token 与组件。
- 1536×1024 为完整工作台；1024px 重排为两列辅助模块；375×812 简化信息优先级并使用全屏 Drawer。
- 保留可见焦点、逻辑 Tab 顺序、Escape 关闭与焦点恢复、语义标签、字段级错误、屏幕阅读器可感知的异步状态，以及移动端至少 44px 的操作目标。

## 非目标

- 批量发布、批量修改状态、导出、自动跨平台发布、自动操作第三方网页、绕过登录/验证码/平台审核。
- 发布排期、负责人分配、优先级、计划发布时间、目标栏目、全局搜索、通知中心、新平台适配器。
- Tailwind、shadcn/ui、新图表库、新 UI 组件库、GSAP 或第二套主题/图标/字体系统。
- 可配置发布指引、帮助内容管理、流量、销售额、ROI、曝光量、转化率和虚构趋势。
- 自动页面抓取、自动内容比对或自动验证；本任务继续采用当前人工验证语义。
- 对已有历史发布记录的编辑、删除、附件解绑或状态回退。

## 业务不变量

- 只有 APPROVED 内容和事实、OPEN 内容任务可以创建人工发布记录。
- 发布记录永久绑定具体内容版本、内容哈希、锁定平台对应账号和栏目 URL。
- 账号必须处于活跃状态并属于任务锁定平台；栏目 URL 和最终 URL 必须命中平台允许域名。
- 已发布标题、最终 URL、发布时间、平台和内容版本保留历史，不得原地覆盖。
- 状态事件和发布附件只追加；下线或验证失败不能删除历史发布事实。
- `PublicationAttention` 只由 REMOVED 或 VERIFICATION_FAILED 创建；创建修复任务不会自动解决关注事项，解决必须带当前 revision 和非空说明。
- 首个成功 VERIFIED 发布在同一事务中完成内容任务，已完成任务不重开。
- 前端只渲染服务端 `available_actions`；权限、CSRF、状态转换、平台匹配、URL、文件完整性和并发冲突仍由服务端裁决。
- PostgreSQL 是业务状态唯一来源；不建立前端第二套状态机，不使用固定成功、静默失败或模糊兼容逻辑。

## 模块验收标准

### 流程概览

- [x] 五个可见流程节点来自摘要 API 的全量计数，与数据库查询一致，翻页不改变数量。
- [x] 显示真实中文状态名称；不出现“负责人”“进度”或“平台处理中”等未定义状态。
- [x] 点击节点进入对应真实页签/状态筛选，并保留 URL 深链。

### 列表与筛选

- [x] 三类列表只使用契约字段，记录/关注列表在一个批量查询投影中获得内容与平台上下文，不产生按行详情 N+1。
- [x] 发布记录使用服务端 `total`、页码、页大小和状态筛选；候选/关注的客户端筛选仅针对已完整加载的数据。
- [x] 空、加载、错误、无权限状态均有可恢复反馈；宽表格可键盘聚焦且不撑破页面。

### 登记与验证

- [x] 账号选择只能来自候选的 `matching_accounts`，服务端仍拒绝跨平台或停用账号。
- [x] 栏目 URL、最终 URL、内容批准态、锁定版本、CSRF、幂等键、状态转换和真实服务端错误全部保留。
- [x] `mark-published` 成功时标题、URL、时间、备注、状态事件和新增证据原子提交；失败时不得把已上传文件显示为已绑定。
- [x] 已发布字段和历史记录不能被后续表单静默覆盖；并发过期命令显示 409 并刷新权威详情。
- [x] 人工验证必须明确确认内容匹配；验证失败、下线和拒绝保留原因及状态事件。

### 异常与修复

- [x] 只展示平台拒绝、页面已下线、页面验证失败三类确定性异常，数量与真实状态/OPEN 关注一致。
- [x] 关注事项的动作来自服务端；修复任务保持原产品/平台边界，创建后关注仍 OPEN。
- [x] 显式解决要求当前 `expected_revision` 和非空处置说明，历史不可删除。

### 数据概览与动态

- [x] 默认 7 天，切换 30 天后由后端按新窗口重新聚合；窗口、分母、历史发布和异常语义按 `design.md` 执行，零分母显示“—”而不是 0%。
- [x] 后续 REMOVED/VERIFICATION_FAILED 不从历史登记发布数中扣除。
- [x] 最近动态来自状态事件的单次批量查询，不暴露管理员审计日志或敏感自由文本。

### 视觉与无障碍

- [x] 与登录页、总览页、内容任务台、审核页和全局导航的 Token、玻璃层级、状态标签一致，不复制原型模拟内容。
- [x] 1536×1024、1024px、375×812 无页面级横向溢出，Drawer 在移动端全屏且主操作可达。
- [x] 浅色、深色、跟随系统均通过对比度、边框、焦点、遮罩、状态和系统主题变化验收。
- [x] 全流程可键盘操作；Drawer 焦点圈闭/恢复、字段错误提示和异步状态可被辅助技术感知；减少动态设置生效。

## 原型能力取舍

### 采用

流程概览、状态页签、聚焦筛选、高密度列表、按需右侧登记面板、发布指引、异常摘要、默认 7 天且可切换 30 天的数据概览、最近状态动态、玻璃视觉、三态主题、响应式和键盘可访问性。

### 删除

模拟数字、人员、文章、平台商标、负责人、优先级、计划发布时间、目标栏目、批量处理状态、模拟进度、批量操作、导出、全局搜索和通知入口。

### 暂缓

自动页面验证、细粒度异常原因、流量/销售/ROI/曝光/转化指标和趋势线。它们没有当前权威采集字段或稳定枚举，不能为还原截图而制造。
