# 内容任务改为产品驱动

## Goal

把内容任务创建从“目标问题 + 产品”改为直接围绕产品策划内容：用户选择产品、已批准事实版本和目标发布平台，并填写受众、内容角度、转化目标、形式、长度及官网权威页；新任务不再要求或保存目标问题。

## Background

- 当前“创建内容任务”弹窗仍把“目标问题”作为必填项（`frontend/src/features/content-tasks/ContentTasksPage.tsx:63`）。
- 当前创建契约、数据库和服务端同样强制 `query_topic_id`，因此这不是只隐藏一个前端字段即可完成的改动（`contracts/openapi.yaml:2268`、`backend/app/models/content.py:48`、`backend/app/services/content_planning.py:302`）。
- 内容任务已经具有产品、批准事实版本、平台规则、目标受众、内容角度、转化目标、内容形式、长度、权威页和工程师 Prompt，足以表达产品内容生产要求。
- 已有内容任务、生成快照、内容版本、发布记录和审计历史必须保持可追溯，不能删除或伪造历史目标问题。
- 目标问题仍被历史 GEO 模型观测引用；本任务不得破坏历史记录的读取。

## Requirements

### R1 新内容任务不再使用目标问题

- “创建内容任务”弹窗不加载、不展示也不提交目标问题。
- 新内容任务以产品为首要选择，并继续要求一个属于该产品的已批准事实版本。
- 平台、受众、内容角度、转化目标、内容形式、长度和官网权威页的现有要求保持不变。

### R2 服务端与契约一致

- 新建内容任务请求不再接受或要求 `query_topic_id`。
- 服务端不再查询或校验目标问题即可创建普通内容任务。
- 内容任务输出允许历史任务携带目标问题身份，同时允许新任务没有目标问题。

### R3 生成链路产品驱动

- 新任务的生成输入和不可变作业快照不得虚构目标问题。
- 没有目标问题时，模型输入由产品事实、平台 Prompt、任务受众、内容角度、转化目标、格式、长度、官网权威页和工程师 Prompt 组成。
- 历史任务继续使用其真实目标问题，不改写已存在的任务或作业快照。

### R4 发布修复与历史兼容

- 基于新任务产生的发布异常仍能创建修复任务，修复任务继承产品和平台，不要求目标问题。
- 基于历史任务创建修复任务时保留原目标问题关联，不删除、不替换也不猜测迁移。
- 已有内容、发布和 GEO 历史继续可读取；任何兼容字段都必须明确可空，不使用占位目标问题。

### R5 界面与文档一致

- 内容任务弹窗、任务详情、发布修复页及用户可见说明不再把目标问题描述为新任务必需输入。
- OpenAPI、数据库契约、前端生成类型、方案文档与实际行为一致。
- 业务设置中的目标问题库暂时保留，用于历史数据查看与兼容；不在本任务中删除目标问题 API 或历史模型观测能力。

## Acceptance Criteria

- [x] 创建内容任务弹窗没有“目标问题”，且不会请求目标问题列表。
- [x] 只选择产品、批准事实版本、可用平台并填写现有任务要求即可创建新任务。
- [x] 新任务数据库记录没有 `query_topic_id`，API 返回和前端类型能明确表示该值为空。
- [x] 新任务可以保存工程师 Prompt、创建生成作业并生成草稿，发送给模型的消息和作业快照均不包含伪造的目标问题。
- [x] 历史任务仍保留并可读取原目标问题；既有作业快照、内容、发布和 GEO 记录不被改写。
- [x] 新旧任务都能通过发布异常创建修复任务；新任务修复不要求目标问题，旧任务修复保留真实历史关联。
- [x] 数据库迁移、OpenAPI 契约、后端测试、前端测试和纵向 E2E 覆盖新行为并通过。
- [x] 权威方案文档不再声称新内容任务必须选择目标问题。

## Out of Scope

- 删除 `query_topics` 表、目标问题管理 API 或历史目标问题数据。
- 改写历史内容任务、生成快照、文章、发布记录或旧 GEO 模型观测。
- 新增自动选题、关键词规划、搜索抓取、OCR 或第二套内容任务模型。
- 改变 GEO 人工文章观测流程；该流程继续只选择产品并登记站外人工搜索证据。

## Dependencies

- 复用现有产品、事实版本、具体平台规则、平台 Prompt、内容任务、生成作业和发布修复模型。
- PostgreSQL 继续作为任务状态和历史关系的唯一权威来源。
