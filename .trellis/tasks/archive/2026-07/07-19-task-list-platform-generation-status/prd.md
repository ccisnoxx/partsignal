# 内容任务列表平台与生成状态

## Goal

让内容任务列表以一次权威列表响应展示产品、单一目标平台、任务状态、AI 生成状态、创建时间和快捷操作，并在平台管理中支持可选的上传 Logo 或外部 Logo URL 与平台官网。

## Background

- 当前 `ContentTask` 契约只返回 `product_id`、`platform_profile_version_id`、任务状态等任务字段，没有产品名称、具体平台名称或聚合后的生成状态（`contracts/openapi.yaml:2264-2310`）。
- 当前平台资料只包含名称、slug、允许域名和平台类型，没有 Logo 或平台官网（`contracts/openapi.yaml:1964-2051`）。
- 生成状态目前只能通过逐任务 `/generation-jobs` 接口读取（`backend/app/routers/production.py:183-201`），任务列表不得为每行发起额外请求。
- 项目已有对象存储直传、完整性校验和 `DirectUpload`，但现有文件分类不包含平台 Logo；对象下载 URL 是短期签名 URL，不能作为上传 Logo 的持久值。
- 一个内容任务只绑定一个 `platform_profile_version_id`，列表不得实现多平台聚合展示。

## Requirements

- R1：平台资料支持可选 `website_url`，以及互斥的上传 Logo 文件或外部 Logo URL；未配置 Logo 时使用不伪造品牌的通用回退图形。
- R2：上传 Logo 复用现有直传与完整性校验链路，新增明确的平台 Logo 文件分类、图片类型和体积限制，不将短期签名 URL写入数据库。
- R3：平台创建、编辑、列表和 OpenAPI 契约同步支持上述资料；服务端负责校验 Logo 两种来源不能同时存在。
- R4：内容任务列表响应一次性投影产品显示资料、具体平台显示资料和最新一次 `GENERATE` 作业状态；`HUMANIZE` 属于内容版本后处理，永不覆盖任务列表的 AI 生成状态。任务创建契约和一个任务一个平台的绑定关系保持不变。
- R5：任务列表列调整为产品名称、目标平台、任务状态、AI 生成状态、创建时间和快捷操作；产品/平台名称可保留内容角度作为次级信息，不复制多平台图标组。
- R6：任务状态和 AI 生成状态分别复用服务端枚举，使用项目现有状态标签组件和主题变量实现可区分的浅色/深色语义色，不建立第二套状态机。
- R7：任务列表不得发送逐任务产品、平台或生成作业请求；服务端列表查询应批量读取关联数据，避免数据库 N+1。
- R8：保持现有搜索、筛选、统计、URL 分页恢复、创建任务 Modal、任务详情和权限行为；新增可筛选字段必须来自当前列表响应。
- R9：更新数据库权威文档、OpenAPI、生成类型、相关前后端测试和方案文档，保证迁移、代码与契约一致。

## Acceptance Criteria

- [x] AC1：平台可只配置上传 Logo、只配置外部 Logo URL，或两者都不配置；同时提交两种来源时服务端明确拒绝。
- [x] AC2：平台可配置可选平台官网 URL；创建、编辑和重新加载后值保持一致。
- [x] AC3：上传 Logo 仅接受批准的图片格式和大小，必须处于 `VERIFIED` 状态且类别正确才能绑定平台。
- [x] AC4：`GET /api/v1/content-tasks` 每项包含产品显示资料、单一平台显示资料和最新一次 `GENERATE` 作业状态；只有 `HUMANIZE` 作业时仍按没有生成作业处理，空生成状态有明确契约表示。
- [x] AC5：任务列表不新增逐行 API 请求；后端相关查询数量不随任务数量线性增长。
- [x] AC6：列表状态颜色在浅色、深色和跟随系统主题下可区分，并保持文本标签与键盘可访问性。
- [x] AC7：现有任务创建、任务详情、分页 URL、加载、错误、空状态和重试测试继续通过。
- [x] AC8：数据库迁移、OpenAPI 校验与类型生成、后端测试、前端测试、lint、typecheck、build 和 Playwright 验收通过，或明确记录无法运行的环境限制。

## Out of Scope

- 不改变一个任务绑定一个平台规则版本的业务模型。
- 不在列表展示负责人、优先级、模拟进度或多平台 Logo 组。
- 不新增图标库、图表库或第二套上传框架。
