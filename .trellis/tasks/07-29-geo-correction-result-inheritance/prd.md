# 修复 GEO 更正表单逐篇结果继承

## 目标

修复验收缺陷 DEF-04，使创建 GEO 更正时以被更正人工观测为完整业务基线，用户只修改需要纠正的字段；提交后追加新链尾，原观测及其逐篇事实不可变，避免未操作字段被错误重置并污染统计。

## 背景与已确认事实

- 验收报告和 `G-correction-defaults.png` 证明：原逐篇结果为“发现、提及、准确”，更正表单却显示“未发现、未提及、未判断”。
- 详情接口已经返回完整 `ManualGeoObservation.article_results[]`，无需新增读取接口或数据源。
- 根因位于 `GeoObservationForm`：更正初始化丢弃详情中的逐篇结果，再从候选文章列表写入 `false/false/null`。
- 服务端已通过 `supersedes_id` 追加新记录，锁定链尾和当前候选集合，并禁止普通 UPDATE；数据库与 API 的追加式模型无需变更。
- 历史附件按更正链聚合读取，每个版本只保存本次新增附件；附件关系不能复制到新版本。
- 补采前历史允许 `discovered/mentioned = null`，其语义是“未知”，不得推断为 `false`。

## 范围内要求

- **R1 完整预填**：更正表单从待更正详情响应继承产品、问题主题、人工搜索平台、实际搜索词、观测时间、备注和每篇文章的发现、提及、准确性。
- **R2 单一基线**：更正逐篇事实只以待更正详情响应为基线；候选文章接口不用于重建、覆盖或猜测原事实。
- **R3 显式未知**：原记录中的历史未知布尔事实保持未知，用户必须显式选择后才能提交，不得静默转换为“否”。
- **R4 附件边界**：历史证据继续聚合展示；请求中的 `attachment_file_ids` 只包含本次新增文件。
- **R5 追加式提交**：请求携带待更正记录 ID 作为 `supersedes_id`；服务端继续校验当前链尾、稳定业务维度和完整候选集合，候选变化时显式失败。
- **R6 原记录不可变**：更正成功后生成新观测和新逐篇关系，原观测及其关系不更新、不删除；默认列表与指标使用新链尾，历史读取仍可追溯原记录。
- **R7 回归保护**：覆盖正确预填、只修改一个逐篇字段而其他字段不变，以及持久化后形成追加式更正链且原记录不变。
- **R8 文档一致性**：更新 GEO 权威设计文档与稳定前端约束，明确更正预填、历史未知值和附件边界；不修改没有发生变化的 OpenAPI 与数据库 Schema 契约。
- **R9 验证输出无已知噪声**：修复本任务验证中暴露的 jsdom 伪元素样式能力提示和 Starlette TestClient 旧 `httpx` 回退弃用警告，不通过全局过滤或吞掉控制台输出掩盖问题。

## 验收标准

- [x] **AC1（R1、R2）**：打开一个逐篇事实为 `true/true/ACCURATE` 的更正表单，发现、提及、准确性及其他可更正业务字段与原记录一致。
- [x] **AC2（R1、R7）**：两篇文章的原记录中只修改一篇的一个事实后提交，请求中该字段改变，另一篇及所有未修改字段保持原值。
- [x] **AC3（R3）**：补采前 `null` 布尔事实不会变为 `false`；未显式选择时不能提交，选择后按真实选择提交。
- [x] **AC4（R4）**：已有证据仍可见，但没有新增上传时请求的 `attachment_file_ids` 为空。
- [x] **AC5（R5、R6、R7）**：集成测试证明新记录的 `supersedes_id` 指向原记录，原记录及原逐篇关系保持不变，新记录保留未修改字段并成为当前链尾。
- [x] **AC6（R5）**：当前候选集合变化仍由服务端返回 `GEO_PUBLICATIONS_CHANGED`，前端不自动补成“未发现”。
- [x] **AC7（R8）**：代码、测试、GEO 设计文档和前端规范对上述不变量描述一致，契约检查无需生成差异。
- [x] **AC8（R9）**：前端定向测试不再输出 `getComputedStyle() method: with pseudo-elements`。
- [x] **AC9（R9）**：后端定向集成测试使用 Starlette 指定的 `httpx2` TestClient 路径，不再输出对应弃用警告。

## 范围外

- DEF-01、DEF-02、DEF-03、DEF-05、DEF-06 及验收报告中的其他偏差。
- 修改 GEO 指标公式、洞察筛选、删除完整更正链或历史附件聚合规则。
- 新增更正专用 API、数据库字段、迁移、前端全局状态或业务数据兼容回退。
- 部署、提交、推送或线上数据修复。

## 技术约束

- PostgreSQL 和现有详情响应仍是业务事实的权威来源。
- 服务端继续负责链尾、权限、不可变性和候选集合最终校验。
- 不把历史未知值、缺失候选或请求失败编码为默认业务结论。
- 保持新建人工观测的现有默认交互不变；修复只作用于更正数据流及其测试。
