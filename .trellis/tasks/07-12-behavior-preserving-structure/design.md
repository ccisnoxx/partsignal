# 阶段五：行为保持的代码结构改善设计

## 不变量

- HTTP 路径、方法、请求与响应字段、状态码和错误码不变。
- 数据库表、列、约束、状态值、审计事件和版本语义不变。
- 事务、行锁、乐观锁、幂等键和审计写入必须随业务状态转换处于同一权威应用服务中。
- PostgreSQL 继续作为唯一业务状态来源；Redis 不缓存或复制业务状态。
- 前端继续消费 `contracts/openapi.yaml` 生成的 `schema.d.ts`。

## 目标边界

### Router

Router 保留 FastAPI 路由声明、认证和权限依赖注入、CSRF / Cookie / Header 等 HTTP 语义、请求 Schema 解析、响应 Schema 构造及领域错误映射。无需事务协调、跨实体状态写入或审计编排的单表只读查询可以继续留在 Router。

### 应用服务

应用服务拥有会改变业务状态的用例，包括事务提交、锁顺序、revision 校验、状态转换、跨实体权限门禁、幂等检查、版本号分配、审计写入及外部调用前后的持久化协调。服务公开用例级函数，不为每个 Router 函数机械创建一一对应包装。

### 查询与命令

仅发布域存在已经验证的查询和命令复杂度，拆成查询投影与状态命令两个边界；其他模块保持同一应用服务，除非后续证据证明拆分能消除真实耦合。不得把该选择扩展为全局 CQRS。

### ORM 模型

按稳定领域拆为身份与审计、文件、产品事实、AI 配置、平台配置、内容生产、GEO 与发布等模型模块。所有模型仍继承同一 `Base`，跨模块外键优先使用字符串表名；仅在建立 `relationship()` 的模块导入相关类型。`app.models` 包初始化只导入模块以完成 mapper 注册，不重导出模型类。Alembic 继续通过导入 `app.models` 后读取 `Base.metadata`。

### Pydantic Schema

按认证与身份、文件、产品事实、AI 配置、平台配置、内容任务与版本、生成、审核、GEO、发布与公共分页 / 错误等真实接口领域拆分。Router 与服务直接从领域模块导入，不建立兼容性重导出层，也不改变 Schema 名称和字段。

### 前端

只拆分已证实同时混合查询、mutation、表单、业务状态和展示的大型页面：发布工作区与详情 / 异常 / 修复、配置中心的 AI 渠道与平台配置、内容编辑器的容器与展示。简单页面保持现状。建立精确的 query key 注册表，仅消除字符串重复，不改变 key 数组、失效范围或缓存时机。

## 切片边界

1. 基线与特征测试：不移动生产逻辑。
2. 重复投影与依赖修正：删除重复 `platform_version_out`，将文件校验归还文件域，将 Markdown 派生和发布只读投影归入权威查询边界。
3. AI 与平台配置：迁移事务、锁、revision 复核、启停和审计协调。
4. 产品事实：迁移工作区替换、图校验、事实版本和状态写入。
5. 内容策划与生产：迁移任务、prompt / classification、生成输入快照、幂等作业、重试和内容修订。
6. 身份、文件、GEO：仅迁移已验证的状态用例，不为简单读取增加层。
7. Schema 物理拆分：只移动声明和更新直接导入。
8. ORM 模型物理拆分：只移动映射声明，保持 metadata 和迁移图不变。
9. 前端物理拆分：只移动组件和 query key 定义，保持接口调用与界面行为不变。

## 兼容性与风险控制

- 每个切片开始前补足该路径的特征测试，完成后运行定向测试、类型检查和契约检查。
- 每个切片只移动一个权威边界；不得同时改变状态机、Schema 字段、SQL 或用户交互。
- ORM 切片前后比较表名集合、表数、mapper 数和 Alembic heads；Schema 切片比较 OpenAPI 生成结果。
- 前端切片前后使用组件测试和 Playwright 关键流验证；query key 使用测试固定精确数组。
- 任一切片发现外部行为变化、迁移需求或无法证明的双重所有权时，回退该切片并停止后续实施。

## 不处理事项

- 不因为文件长而拆分没有稳定职责边界的模块。
- 不给简单 CRUD、纯投影或一行数据库调用套 Service / Repository。
- 不统一所有模块目录形状，不建设未来可能需要的抽象。
- 不在本任务修复阶段四以外的产品、权限或 E2E 设计问题。
