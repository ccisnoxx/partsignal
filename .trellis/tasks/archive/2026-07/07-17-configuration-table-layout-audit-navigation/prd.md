# 修复配置表格布局与审计导航

## Goal

让管理员在常见桌面和移动视口下都能直接理解配置列表、访问关键操作，并把审计日志放回正确的系统管理信息架构中。

## Background

- 已部署 AI 配置页的表格可视宽度约为 `1094px`，实际滚动宽度为 `1480px`；操作列在初始视口不可见。对应实现为 `frontend/src/features/configuration/AIChannelsPage.tsx:50`。
- 生产接口 `/api/v1/ai-channels` 实际只返回一个已启用模型；该模型的 `display_name` 与 `model_id` 都为 `deepseek-v4-flash`。当前渲染同时显示两个字段，因此一个模型看起来像两个，见 `frontend/src/features/configuration/AIChannelsPage.tsx:98`。
- 平台管理页当前规则下拉框设置了 `minWidth: 190`，实际桌面单元格宽度约为 `182px`，已经越出单元格，见 `frontend/src/features/configuration/PlatformsPage.tsx:69`。
- 多个列表没有按字段语义分配宽度，Ant Table 会把剩余空间平均分给所有未定宽列。例如平台规则页在 1440px 视口下七列均约 `156px`，见 `frontend/src/features/configuration/PlatformRulesPage.tsx:65`。
- 审计日志当前同时位于配置中心子菜单和 `/configuration/audit` 子路由，见 `frontend/src/app/AppLayout.tsx:27` 与 `frontend/src/app/App.tsx:55`。

## Requirements

- R1：AI 配置列表提供可访问的“列设置”，允许管理员显示或隐藏非关键列；渠道名称、状态、已启用模型和操作列不得被隐藏。
- R1.1：AI 配置默认隐藏“请求超时”和“请求 Header”，默认保留“API Key”；列设置只控制当前页面会话，重新进入页面恢复默认值。
- R2：AI 配置默认列必须在常见桌面视口中直接露出操作入口；横向滚动时操作列仍保持可见。
- R3：当模型 `display_name` 与 `model_id` 相同时只显示一次；不同时继续同时展示名称和模型 ID。
- R4：平台管理的当前规则下拉框不得越出单元格，且“管理规则”入口保持可达。
- R5：主要列表页按字段内容角色分配宽度：短状态、版本、数字和操作列使用紧凑宽度，长文本列吸收剩余空间；不得继续让所有列机械均分。
- R6：仅在表格的最小可用宽度确实超过容器时保留表格内部横向滚动；页面本身不得产生横向滚动。
- R7：审计日志改为“系统管理”一级管理员入口 `/audit`，从配置中心子菜单移除；普通用户直接访问时仍被重定向到首页。
- R8：不修改后端接口、数据库契约或业务状态，不新增前端依赖，不创建通用表格框架。

## Scope

- 优先修复已复现的 AI 配置、平台管理、平台规则、平台类型、Prompt 管理、用户管理、产品、内容任务和人工发布列表的明显失衡列宽。
- 已按内容角色设置宽度且实测正常的 GEO 观测列表不做无意义改写。
- AI 渠道详情等工作区内部表格仅在同类缺陷可复现时调整。

## Acceptance Criteria

- [x] AC1：AI 配置页存在键盘可操作的“列设置”，可切换请求超时、API Key、请求 Header 等可选列，关键列始终显示。
- [x] AC1.1：首次进入 AI 配置页时不显示请求超时和请求 Header，显示 API Key；通过列设置可重新显示两个默认隐藏列。
- [x] AC2：AI 配置默认视图在 1440px 下无需横向滚动即可看到操作列；在 1024px、768px 和 375px 下，横向滚动不隐藏固定操作列。
- [x] AC3：一个名称与 ID 相同的启用模型只出现一份可见文本；名称与 ID 不同的模型仍能辨认两者。
- [x] AC4：平台管理页的当前规则下拉框在 1440px、1024px、768px 和 375px 下均不越出单元格。
- [x] AC5：平台规则等已识别列表的短字段和操作列不再机械均分；桌面端空间优先给长文本字段，移动端仅在表格区域内部滚动。
- [x] AC6：管理员可从系统管理一级菜单进入 `/audit`；配置中心不再显示审计日志；普通用户不可直接访问 `/audit`。
- [x] AC7：相关组件测试、路由/导航测试、TypeScript 类型检查和前端构建通过。
- [x] AC8：使用 `playwright-cli` 对部署后页面进行管理员登录验证，控制台无非预期错误，验证结束后退出登录并清理会话数据。

## Out of Scope

- 不持久化管理员的列显示偏好；如后续确认需要跨会话保存，再独立选择 URL 或用户偏好存储的唯一所有者。
- 不修改 AI 渠道、平台规则或审计日志的后端接口、权限、数据结构和业务行为。
- 不新增表格封装、列工厂、状态库或运行时依赖。
