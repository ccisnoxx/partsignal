# PartSignal 已部署环境全量验收计划

## 1. 文档定位

本文用于对已部署环境开展一次从配置、业务数据、AI 草稿、审核、发布登记、GEO 观测到审计闭环的专业验收。

本轮验收不是“逐页点按钮”的功能清单，而是围绕四个核心视角组织：

1. **风险矩阵**：优先验证会造成数据泄露、越权、错误发布、历史篡改或业务闭环失真的风险。
2. **状态机矩阵**：验证合法状态流转、非法跳转、不可逆约束和状态副作用。
3. **端到端工作流**：从 0 到 1 建立测试配置和测试业务数据，走通正常、异常与恢复路径。
4. **UI/UX 专项**：独立检查视觉层级、交互反馈、响应式、可访问性和异常状态，而不是把“能点击”视为界面合格。

此前已经执行的浏览器检查只作为历史基线和回归线索，不直接继承“通过”结论；本轮须按本文重新取证。

### 1.1 验收目标

- 证明核心业务不变量在浏览器真实操作和服务端校验下均成立。
- 证明主要角色、配置组合、状态组合和失败分支具备清晰、可恢复的用户体验。
- 证明完整业务链路能够从测试配置和测试数据开始，到发布登记、GEO 观测和审计记录结束。
- 发现功能、逻辑、权限、可靠性、UI、UX、响应式和可访问性问题，并提供可复现证据。

### 1.2 范围

- 目标环境：`https://geo.962850.xyz`
- 浏览器尺寸：
  - 桌面主验收：`1440 × 900`
  - 移动端主验收：`390 × 844`
  - 补充断点：`1024 × 768`、`320 × 800`
  - 代表页面补充检查：浏览器缩放 `200%`
- 角色：未登录用户、管理员、工程师。
- 业务域：认证、用户权限、平台、Prompt、AI 渠道与模型、产品、事实版本、内容任务、AI 作业、内容审核、发布管理、发布核验、GEO 观测、洞察、审计日志。

### 1.3 不在范围内

- 不修改项目代码、不重新部署。
- 不为了通过测试而绕过页面直接修改数据库。
- 不使用真实业务产品、真实客户内容或真实第三方发布账号。
- 不在第三方平台真正发布内容；“发布”仅在系统内使用明确测试 URL 登记和验证。
- 不审核通过或发布非测试数据，不删除审计记录。
- 不实施容量压测、渗透测试或破坏性安全测试；只做安全的权限与输入边界验证。

## 2. 验收原则与执行规则

### 2.1 测试依据

执行前以以下材料为准，并记录版本或读取日期：

- 部署与测试文档：确认登录入口、测试账号和环境限制。
- `docs/GEO多平台内容运营系统方案设计.md`：确认业务流程和状态定义。
- `contracts/openapi.yaml`：确认接口、错误码和字段约束。
- `contracts/database.md`：确认数据状态、唯一性和历史保留规则。
- 已部署页面与真实网络响应：确认实际实现。

当文档、合同和线上行为不一致时，不自行选择“更容易通过”的解释，应记录为需求/实现不一致。

### 2.2 浏览器执行约束

- 使用项目 `playwright-cli` skill 和真实浏览器操作。
- 优先复用项目已有 Playwright 流程；没有覆盖时再建立临时验收会话。
- 认证使用命名持久会话或未跟踪的 storage state。
- 不使用 `page.route`、固定成功响应或本地 mock 伪造线上验收结果。
- 普通诊断使用 snapshot、`find`、console、requests 和 trace。
- 截图只用于视觉基线、缺陷证据和关键状态；密码输入后不截图。
- trace、storage state 和网络详情视为敏感证据，不进入公开报告。
- 结束后退出登录、关闭会话并清理本地认证状态。

### 2.3 凭据与敏感信息

- 只从部署文档指定的安全来源读取测试凭据。
- 报告和命令输出不得包含密码、Cookie、Token、API Key、Authorization、敏感请求头或完整 storage state。
- AI 渠道仅允许使用项目已提供的测试密钥；不得复制、导出或回显。
- 若页面或接口泄露上述信息，立即停止相关路径并按 P0 缺陷记录。

### 2.4 结果状态

每个用例只能使用以下一种结果：

| 状态 | 含义 |
|---|---|
| `PASS` | 预期行为、禁止行为、数据副作用和证据均符合要求 |
| `FAIL` | 已执行且至少一项明确要求不符合 |
| `BLOCKED` | 因环境、权限、依赖或上游缺陷无法继续，且已说明阻断点 |
| `NOT_RUN` | 尚未执行，不能等同于通过 |
| `NOT_APPLICABLE` | 经确认不适用于当前环境，并说明依据 |

### 2.5 单用例记录模板

每个用例至少记录：

- 用例 ID、关联风险、业务不变量和前置状态。
- 角色、测试数据 ID、页面 URL。
- 操作步骤、预期状态、禁止状态和实际结果。
- 业务副作用：新增或未新增了什么，历史是否保持不变。
- UI/UX 观察：反馈、层级、焦点、滚动、响应式和可恢复性。
- 控制台错误、失败请求、HTTP 状态码和业务错误码。
- 截图、trace 或审计记录位置。

## 3. 风险矩阵

风险优先级同时决定执行顺序和退出标准。P0 必须全部执行并通过，P1 不允许遗留阻断主流程的问题。

| 风险 ID | 风险 | 等级 | 主要触发条件 | 必验控制 |
|---|---|---:|---|---|
| R01 | 密码、Token、API Key、Cookie 或敏感请求头泄露 | P0 | 登录、渠道配置、日志、错误提示、网络详情 | 页面不回显；接口不返回；报告脱敏；会话可撤销 |
| R02 | `RESTRICTED` 或未批准事实被发送给第三方模型 | P0 | 创建 AI 草稿、重试、补写、渠道切换 | 服务端拒绝；不创建外部作业；提示具体原因 |
| R03 | 审核、发布或核验状态被越级或逆向修改 | P0 | 直接路由、重复提交、旧页面、接口重放 | 非法流转拒绝；状态和历史不变；有审计 |
| R04 | 已批准事实、已批准内容、发布记录、GEO 历史或审计被覆盖/删除 | P0 | 编辑、删除、纠错、重复提交 | 采用新版本或追加记录；原记录保持不变 |
| R05 | 内容被错误平台、错误账号、错误 Prompt 或重复发布 | P0 | 平台切换、账号切换、并发登记、历史已发布 | 绑定一致；域名校验；去重；快照可追溯 |
| R06 | 工程师获得管理员配置、用户或审计权限 | P0 | 导航隐藏、直达 URL、直接请求 | 前端不暴露且服务端返回明确拒绝 |
| R07 | Prompt/model 配置漂移导致历史作业不可追溯 | P1 | 更新 Prompt、改模型参数、禁用渠道 | 作业快照不变；revision 明确；旧版本可追溯 |
| R08 | 重复点击、超时、重试或迟到响应创建重复数据 | P1 | AI 创建、审核、发布登记、观测提交 | 幂等或明确冲突；按钮防重；最终状态一致 |
| R09 | GEO 纠错覆盖历史或当前指标取错版本 | P1 | 新增纠错、重复纠错、洞察聚合 | 追加纠错链；历史保留；当前指标取链尾 |
| R10 | 禁用平台/渠道/模型后仍可创建新业务，或污染历史 | P1 | 配置禁用、页面缓存、旧标签页 | 新建受阻；历史可读且不被改写 |
| R11 | 关键页面在桌面、移动端或键盘操作下不可用 | P1 | 表格、弹窗、抽屉、长文本、软键盘 | 无不可达控件；焦点、滚动、关闭和错误反馈正常 |
| R12 | 外部模型、文件上传或异步任务失败后无法理解或恢复 | P2 | 超时、无可用模型、返回格式错误、上传失败 | 状态可见；错误明确；允许安全重试；不伪造成功 |
| R13 | 列表、筛选、分页、详情、导出和统计口径不一致 | P2 | 查询组合、刷新、返回、纠错后统计 | URL/条件持久；总数一致；数据来源明确 |

## 4. 核心业务不变量矩阵

| 不变量 ID | 必须成立的规则 | 正向验证 | 反向验证与证据 |
|---|---|---|---|
| INV-01 | 只有非空、`PUBLIC`、`APPROVED` 事实可发送给外部模型 | 使用测试 PUBLIC 已批准事实创建一次 AI 草稿 | 使用 DRAFT、CHANGES_REQUESTED、RESTRICTED 事实分别尝试；确认无外部作业 |
| INV-02 | AI 输出只能创建内容 `DRAFT` | 成功生成后检查内容和作业详情 | 尝试从生成流程直接批准或发布，应不存在路径 |
| INV-03 | 生成请求固定由平台 Prompt 和事实 Markdown 组成 | 检查目标平台、Prompt revision、事实版本和作业快照 | 修改当前 Prompt 后确认历史作业快照不变 |
| INV-04 | 模型响应必须是含 `title`、`summary`、`body_markdown`、`tags` 的单一 JSON 对象，四项非空 | 使用测试 Prompt 获得一次合规响应 | 使用明确测试 Prompt 产生格式错误；不得自动修复、补默认值或伪造草稿 |
| INV-05 | 绑定中的 Prompt 不可删除，更新使用 revision 乐观锁 | 新建、绑定、更新并观察 revision | 用旧 revision 提交冲突；当前内容和审计保持正确 |
| INV-06 | 已批准事实和内容不可原地修改 | 正常审核后查看只读状态 | 尝试编辑/覆盖；只能创建新版本或被拒绝 |
| INV-07 | 发布只接受已批准内容和明确平台，账号必须属于该平台 | 使用匹配平台和测试账号登记 | 未批准内容、跨平台账号、禁用账号均应拒绝 |
| INV-08 | 同一平台与内容不能重复进入发布流程；曾公开发布后不能靠换账号绕过 | 首次测试登记成功 | 重复点击、换账号重复登记；确认无重复记录 |
| INV-09 | 发布状态事件追加保存，不能覆盖历史 | 推进测试发布记录的合法状态 | 返回列表和详情确认完整时间线；不可删除/改写旧事件 |
| INV-10 | 内容任务完成由首个关联发布 `VERIFIED` 驱动，完成后不可逆 | 完成发布核验并观察任务 | 尝试取消或退回；状态保持 COMPLETED |
| INV-11 | 有进行中/已发布记录的任务不可取消；`CANCELLED` 任务可清理生成作业、审核记录和未批准内容，已批准或曾批准内容、任一发布记录或发布修复来源必须阻断删除 | 分别创建仅有任务自有未批准历史和具有受保护历史的取消任务 | 前者由服务端允许并完整清理任务自有历史；后者明确拒绝且原记录不变，不仅是隐藏按钮 |
| INV-12 | 发布失败从 `PUBLISHED`/`VERIFIED` 产生唯一待办，修复任务和待办解决相互独立 | 制造允许的测试异常并观察 | 重复触发不产生多个 OPEN 待办；单独创建修复任务不自动解决 |
| INV-13 | GEO 观测和纠错只追加；未知事实不能推断为否 | 新增测试观测和纠错 | 原观测保持不变；洞察使用最新纠错链尾 |
| INV-14 | 平台禁用只阻止新业务，不改变历史记录 | 禁用测试平台后尝试新建 | 已有任务、作业、发布和观测仍可读且内容不变 |
| INV-15 | AI 渠道默认禁用；模型须测试通过后才可用，关键配置变化会使测试失效 | 新建测试渠道/模型、测试连接、启用 | 改模型、凭据、请求头或参数后确认测试状态失效 |
| INV-16 | 审计记录不可删除或更新，且不包含敏感值 | 对配置和业务状态做测试变更 | 检查动作、操作者、对象、时间和差异；无删除入口、无秘密字段 |
| INV-17 | 服务器是权限和状态校验的最终权威 | 从正常 UI 验证合法操作 | 使用直达 URL 或页面产生的真实请求验证非法操作仍被拒绝 |

## 5. 覆盖矩阵

### 5.1 角色与权限

| 能力 | 未登录 | 工程师 | 管理员 |
|---|---:|---:|---:|
| 登录页与会话失效提示 | 可见 | 可见 | 可见 |
| 工作台与普通业务页 | 不可见 | 可用 | 可用 |
| 产品、事实、内容、发布、GEO | 不可访问 | 按职责可用 | 可用 |
| 平台、Prompt、AI 渠道 | 不可访问 | 禁止 | 可用 |
| 用户管理、审计日志 | 不可访问 | 禁止 | 可用 |
| 直达无权限 URL/API | 重定向或 401 | 明确 403 | 按权限可用 |

补充验证：

- 最后一个启用管理员不能被禁用。
- 管理员禁用用户或重置会话后，旧会话立即失效。
- 退出登录后，浏览器后退不能恢复受保护页面数据。

### 5.2 数据分类与生命周期

| 组合 | 列表/详情 | 编辑 | AI 生成 | 审核 | 发布 |
|---|---|---|---|---|---|
| PUBLIC + DRAFT | 可见 | 可编辑 | 禁止 | 可提交审核 | 禁止 |
| PUBLIC + PENDING_REVIEW | 可见 | 只读或受限 | 禁止 | 可批准/驳回 | 禁止 |
| PUBLIC + APPROVED | 可见 | 不可原地编辑 | 允许 | 历史可见 | 仅内容批准后允许 |
| PUBLIC + RETIRED | 历史可见 | 不可原地编辑 | 禁止 | 不适用 | 禁止新用 |
| RESTRICTED + 任意状态 | 按权限可见 | 按状态 | 始终禁止外部模型 | 按状态 | 不得因分类被绕过 |

### 5.3 配置组合

| 对象 | 可用组合 | 必验不可用组合 |
|---|---|---|
| 平台 | 启用平台 + 有效平台类型 | 平台禁用、平台类型缺失或冲突 |
| Prompt | 平台已绑定 + 当前 revision | 未绑定、旧 revision、绑定后删除 |
| AI 渠道 | 启用渠道 + 可用模型 | 新建默认禁用、凭据缺失、渠道禁用 |
| 模型 | 启用 + 最近一次连接测试通过 | 未测试、测试失败、配置变化后测试失效、模型禁用 |
| 平台账号 | 启用 + 与目标平台一致 | 禁用、跨平台、域名不匹配 |

## 6. 状态机验收矩阵

每个状态机都要验证：

1. 合法转换可达且产生正确副作用。
2. 非法转换被服务端拒绝。
3. 刷新、后退、重复提交后状态一致。
4. 列表、详情、时间线、统计和审计显示一致。

### 6.1 产品事实版本

| 当前状态 | 允许动作 | 目标状态 | 必要条件/副作用 |
|---|---|---|---|
| DRAFT | 提交审核 | PENDING_REVIEW | 内容非空；记录操作者和时间 |
| PENDING_REVIEW | 批准 | APPROVED | 审核记录追加；版本进入不可变 |
| PENDING_REVIEW | 要求修改 | CHANGES_REQUESTED | 评论非空；审核记录追加 |
| CHANGES_REQUESTED | 修改后重提 | PENDING_REVIEW | 保留此前审核历史 |
| APPROVED | 退役 | RETIRED | 历史引用仍可读取 |

非法转换：DRAFT 直接 APPROVED、APPROVED 原地编辑、RETIRED 再用于 AI 生成。

### 6.2 内容版本

| 当前状态 | 允许动作 | 目标状态 | 必要条件/副作用 |
|---|---|---|---|
| DRAFT | 编辑或提交审核 | DRAFT / PENDING_REVIEW | Markdown 为唯一正文源；提交时校验阻断项 |
| PENDING_REVIEW | 批准 | APPROVED | 追加审核记录；进入不可变 |
| PENDING_REVIEW | 要求修改 | CHANGES_REQUESTED | 评论非空；记录阻断原因 |
| CHANGES_REQUESTED | 修改后重提 | PENDING_REVIEW | 历史审核记录保留 |
| APPROVED | 被后续版本替代 | SUPERSEDED | 原版本继续可追溯 |

非法转换：AI 输出直接 APPROVED、存在 blocker 时批准、APPROVED 原地改正文、未批准内容发布。

### 6.3 AI 生成作业

| 场景 | 预期结果 | 必查信息 |
|---|---|---|
| Prompt 已确认 + 模型已选 + 数据合规 | 创建一个作业并进入异步处理 | 平台、Prompt/revision、事实版本、模型、参数和输入快照 |
| 未确认 Prompt | 创建按钮禁用 | 禁用原因可理解 |
| 未选择模型 | 创建按钮禁用 | 焦点可到模型选择；提示清楚 |
| 无可用模型 | 不可创建 | 空状态说明如何恢复 |
| 模型返回合规 JSON | 创建一个 DRAFT | 四字段完整，无额外修复 |
| 模型返回非法 JSON/空字段 | 作业明确失败，不创建伪草稿 | 原始错误脱敏；允许安全重试 |
| 重复点击/网络迟到 | 不产生重复草稿或无归属结果 | 作业数量、内容数量和最终状态一致 |

### 6.4 内容任务

| 当前状态 | 触发 | 目标状态 | 约束 |
|---|---|---|---|
| OPEN | 用户取消 | CANCELLED | 不存在进行中或已发布的关联发布 |
| OPEN | 首条关联发布 VERIFIED | COMPLETED | 自动完成；记录关联发布 |
| CANCELLED | 删除 | 记录删除 | 可同时清理生成作业、审核记录和 `DRAFT / PENDING_REVIEW / CHANGES_REQUESTED` 内容；存在 `APPROVED / SUPERSEDED` 内容、任一发布记录或发布修复来源时拒绝 |
| COMPLETED | 任意回退动作 | 不变 | 完成不可逆 |

### 6.5 发布记录

| 当前状态 | 允许目标状态 | 关键验证 |
|---|---|---|
| PENDING_MANUAL_PUBLISH | PLATFORM_REVIEW | 人工登记信息完整；平台与账号匹配 |
| PLATFORM_REVIEW | PUBLISHED / REJECTED | 状态事件追加；拒绝原因清楚 |
| PUBLISHED | VERIFIED / REMOVED / VERIFICATION_FAILED | 最终 URL 域名允许；证据关联清楚 |
| VERIFIED | REMOVED / VERIFICATION_FAILED | 原 VERIFIED 历史保留；生成唯一开放待办 |
| REJECTED / REMOVED / VERIFICATION_FAILED | 按产品设计允许的恢复动作 | 不得伪装成成功；修复路径明确 |

非法转换：PENDING_MANUAL_PUBLISH 直接 VERIFIED、跨平台账号登记、重复发布、覆盖旧状态事件。

### 6.6 异常待办与修复

| 当前状态/动作 | 预期 |
|---|---|
| 发布从 PUBLISHED/VERIFIED 进入失败状态 | 对同一对象产生至多一个 OPEN 待办 |
| 对同一异常重复上报 | 更新可追踪信息或返回已有待办，不创建重复 OPEN 待办 |
| 创建修复任务 | 待办仍为 OPEN，除非用户显式解决 |
| 用户解决待办 | OPEN → RESOLVED，保留解决人、时间和备注 |
| 已解决待办再次出现真实新异常 | 按业务标识产生可追踪的新事件，不覆盖旧记录 |

### 6.7 AI 渠道与模型

| 操作 | 预期状态 |
|---|---|
| 新建渠道 | 默认禁用 |
| 新增模型 | 未测试或不可用 |
| 连接测试成功 | 仅对应模型获得通过状态 |
| 渠道至少有一个测试通过模型 | 才允许启用渠道 |
| 修改连接、凭据、敏感头、模型标识或参数 | 既有测试状态失效 |
| 禁用模型/渠道 | 阻止新作业，历史作业保持可读 |

### 6.8 GEO 观测与纠错

GEO 观测没有覆盖更新路径，纠错必须追加新记录：

- 新观测保存产品、主题、搜索平台、搜索词、观测结果和时间。
- 纠错记录沿用同一业务键并引用前序记录。
- 原记录和完整纠错链均可追溯。
- 当前指标、列表摘要和洞察使用纠错链尾。
- 未观察到的信息保持“未知”，不得自动推断为否。

## 7. 端到端工作流

所有测试对象统一使用运行标识：`E2E-ACCEPT-<run-id>`。每条工作流记录涉及的对象 ID、revision 和状态变化。

### W0：认证、角色和基础配置

**前置条件**：安全获得管理员和工程师测试账号。

**主路径**：

1. 验证未登录访问、错误登录、正确登录、刷新、会话过期和退出。
2. 管理员进入用户管理、配置中心和审计日志。
3. 工程师进入普通业务页。
4. 管理员从 0 创建测试平台类型、测试平台、测试 Prompt 并完成绑定。
5. 新建测试平台账号；检查平台关联和允许域名。
6. 在有安全测试密钥时，新建测试 AI 渠道和模型，执行连接测试后启用。

**负向分支**：

- 工程师通过导航、直达 URL 和真实请求访问管理员能力。
- 尝试禁用最后一个启用管理员。
- 新建未测试模型后直接启用或用于生成。
- Prompt 更新使用过期 revision；绑定中的 Prompt 尝试删除。
- 禁用测试平台后从旧标签页新建任务、账号或发布记录。

**输出**：平台类型、平台、Prompt/revision、账号、渠道、模型、用户和审计记录 ID。

### W1：测试产品与事实审核

**主路径**：

1. 新建明确标记为测试用途的产品。
2. 创建非空 `PUBLIC` 事实版本。
3. 提交审核，先走一次“要求修改”，补充内容后重新提交并批准。
4. 创建一条 `RESTRICTED` 测试事实，用于验证 AI 边界；不向第三方发送。
5. 检查版本列表、详情、审核时间线、只读状态和审计日志。

**负向分支**：

- 空事实提交审核。
- DRAFT 事实直接用于 AI。
- APPROVED 事实原地编辑。
- RETIRED 事实用于新 AI 作业。
- RESTRICTED 事实通过旧页面、刷新页或直接请求尝试生成。

**输出**：产品 ID、PUBLIC 事实版本 ID、RESTRICTED 事实版本 ID、审核记录 ID。

### W2：内容任务、AI 草稿与内容审核

**主路径**：

1. 使用 W1 的产品和 PUBLIC APPROVED 事实创建内容任务。
2. 打开“确认 Prompt → 选择模型 → 创建草稿”弹窗。
3. 验证目标平台、实际绑定 Prompt、内容、revision 和可选模型。
4. 分别验证未确认 Prompt、未选择模型、加载、空、禁用和错误状态。
5. 允许实际创建一次 AI 草稿，记录任务、作业和草稿 ID。
6. 如需验证自然化且已有安全能力，可执行一次自然化；不得循环消耗模型。
7. 将测试草稿提交审核，先驳回一次，再修订并批准。
8. 检查原草稿、修订版、AI 作业快照和审核历史。

**负向分支**：

- 使用 RESTRICTED 或非批准事实创建 AI 作业。
- 使用未测试、禁用或测试状态已失效的模型。
- 双击创建、刷新等待页、返回后重试。
- 模型返回格式错误时确认不自动剥离代码块、不补字段、不创建伪草稿。
- 存在 blocker 时尝试批准。
- APPROVED 内容尝试原地修改。

**输出**：任务 ID、AI 作业 ID、草稿/内容版本 ID、审核记录 ID。

### W3：发布登记、核验与任务闭环

这里的“发布”是系统内测试登记，不代表向外部平台真正发布。

**主路径**：

1. 使用 W2 已批准内容和匹配的测试平台账号创建发布记录。
2. 依次推进 `PENDING_MANUAL_PUBLISH → PLATFORM_REVIEW → PUBLISHED → VERIFIED`。
3. 最终 URL 使用允许域名下明确的测试地址，例如 `https://example.com/e2e-accept-<run-id>`。
4. 如环境支持测试证据上传，上传允许类型 `OPERATION_SCREENSHOT` 并完成绑定。
5. 检查发布状态时间线、证据、内容任务自动完成和审计记录。

**负向分支**：

- 未批准内容、错误平台账号、禁用账号、非法域名。
- 同一内容和平台重复登记，或换账号规避重复限制。
- 跳过中间状态、重复点击、关闭弹窗后重提。
- 上传不支持类型；上传成功但绑定失败时页面须明确说明“未绑定”，不能显示成功。
- COMPLETED 任务尝试取消或退回。

**输出**：发布记录 ID、发布事件 ID、证据 ID、最终任务状态。

### W4：GEO 观测、纠错与洞察

**主路径**：

1. 为测试产品新增主题、查询词或页面允许的等价测试配置。
2. 新增一条明确测试 GEO 观测。
3. 对该观测追加一次纠错，不覆盖原记录。
4. 检查列表、详情、纠错链、当前值、聚合指标和洞察页面。
5. 验证筛选、分页、排序、URL 查询参数、刷新与返回。

**负向分支**：

- 必填项为空、边界数值、超长搜索词、重复提交。
- 对不存在或非测试记录纠错。
- 把未知事实自动显示为否。
- 纠错后列表、详情、图表和统计仍使用旧值。

**输出**：主题/查询 ID、原观测 ID、纠错观测 ID、相关洞察截图。

### W5：发布异常、待办和修复闭环

仅对 W3 创建的测试发布记录执行。

**主路径**：

1. 按系统允许路径将测试发布记录推进到 `REMOVED` 或 `VERIFICATION_FAILED`。
2. 确认生成唯一 OPEN 待办。
3. 新建修复任务，确认待办不会被自动解决。
4. 单独解决待办，检查解决人、时间、备注和历史。

**负向分支**：

- 重复报告同一异常。
- 非法状态直接创建待办。
- 工程师执行超出职责的解决动作。
- 解决待办覆盖或删除原发布事件。

**输出**：异常事件 ID、待办 ID、修复任务 ID。

### W6：恢复性、并发和跨页面一致性

选取 AI 创建、事实提交审核、发布登记和 GEO 新增四个关键写操作，验证：

- 双击、快速连续点击和 Enter 重复提交。
- 请求进行中关闭弹窗、刷新页面、浏览器后退再前进。
- 两个标签页基于同一 revision 更新 Prompt 或业务记录。
- 401、403、409、422、429、5xx 和网络超时的可理解反馈。
- 操作失败后表单输入是否合理保留，成功后是否避免重复提交。
- 列表、详情、工作台指标、审计日志和重新登录后的最终状态一致。

不得通过制造高流量或持续请求来验证这些场景。

## 8. 跨域逻辑与可靠性检查

| 专项 | 检查内容 | 通过标准 |
|---|---|---|
| 权限 | 导航、按钮、直达 URL、真实请求、会话撤销 | 前端提示与服务端授权一致，无仅靠隐藏按钮的保护 |
| 数据分类 | PUBLIC/RESTRICTED 在 AI、审核、发布中的边界 | 任何旁路均不能把受限事实发送到模型 |
| 乐观锁 | Prompt 和其他带 revision 对象的并发更新 | 旧 revision 明确冲突，无静默覆盖 |
| 幂等与防重 | 创建作业、审核、发布、观测的重复提交 | 不重复创建；冲突结果清晰可恢复 |
| 异步一致性 | 排队、执行、成功、失败、迟到响应、刷新 | 状态最终一致；无永久加载或孤儿草稿 |
| 错误恢复 | 空状态、依赖失败、超时、格式错误、上传失败 | 原因、影响和恢复动作明确，不伪造成功 |
| 历史追溯 | revision、快照、审核、发布事件、纠错链、审计 | 当前与历史边界清楚，旧记录不被当前配置改写 |
| 查询一致性 | 筛选、排序、分页、详情、返回、URL、导出 | 条件不意外丢失；总数和明细一致 |
| 文本边界 | 中英文、长标题、长标签、URL、Markdown、空白 | 无截断导致信息丢失；服务端验证明确 |
| 安全显示 | 富文本、Markdown、错误信息、日志 | 不执行脚本；不泄露秘密；用户输入安全显示 |

## 9. UI/UX 与可访问性专项

UI/UX 必须单独判定。功能成功不代表界面通过。

### 9.1 全局质量矩阵

| 维度 | 检查点 | 不通过示例 |
|---|---|---|
| 信息架构 | 导航命名、面包屑、页面标题、当前菜单、返回路径一致 | “Prompt 管理”在导航与标题叫法不同；用户不知道当前位置 |
| 视觉层级 | 主标题、说明、状态、主操作、次操作、危险操作层级合理 | 大号感叹号抢占视觉；危险操作像普通主按钮 |
| 栅格与间距 | 对齐、留白、卡片密度、表单节奏一致 | 标签拥挤、按钮错位、内容贴边、卡片高度跳动 |
| 字体与可读性 | 字号、行高、对比度、长文本、数字和时间易读 | revision/更新时间被压缩或截断且无法查看 |
| 状态表达 | loading、empty、disabled、error、success、readonly 有明确差异 | 空白代替空状态；失败仍显示成功；只读像可编辑 |
| 操作反馈 | 点击后立即反馈、防重复、结果可定位、失败可恢复 | 按钮无变化；保存失败后输入丢失 |
| 一致性 | 同类按钮、状态标签、日期、数量、表格和弹窗行为一致 | 同一状态多种颜色或文案；关闭方式不同 |
| 响应式 | 无横向不可控溢出，关键按钮、表单、弹窗可操作 | 移动端底部按钮被遮挡；弹窗无内部滚动 |
| 可访问性 | 键盘顺序、焦点可见、语义标签、对比度、错误关联 | 焦点逃出弹窗；只能鼠标操作；错误不关联字段 |
| 用户掌控 | 取消、关闭、返回、危险确认和未保存提示合理 | Esc 丢失数据且无提示；遮罩误触直接提交 |

### 9.2 页面组专项

#### 工作台

- 首屏能回答“当前有什么待处理、异常和下一步”。
- 指标口径、时间范围和跳转目标明确。
- 卡片可点击性不依赖猜测；空数据不显示误导性零值。
- 桌面端信息密度合理，移动端不因卡片堆叠失去优先级。

#### 配置中心：平台、Prompt、AI 渠道

- 导航和页面标题使用相同术语。
- 平台绑定以紧凑清晰的标签或卡片呈现。
- 平台名称、绑定数量、revision、启用状态、测试状态和更新时间层级合理。
- 不出现突兀的大号感叹号、文字拥挤、错位、截断或不可解释图标。
- API Key 和敏感请求头只显示“已配置”等安全状态。
- revision 冲突、连接测试失败、禁用依赖和删除受阻均给出具体恢复建议。

#### 产品、事实、内容任务和审核

- 列表可快速区分产品、分类、版本、状态、更新时间和下一动作。
- 历史已完成任务明确只读；不可用动作不伪装成可点击。
- 不能生成 AI 草稿时显示具体原因和恢复路径。
- 页面存在清晰的“新建内容任务”引导。
- RESTRICTED 事实明确说明不会发送给第三方模型。
- 审核意见、阻断项和历史版本之间的关系清楚。

#### AI 草稿弹窗

- 显示目标平台、实际绑定 Prompt、Prompt 内容与 revision。
- 只能选择已启用且测试通过的模型。
- 未确认 Prompt 或未选模型时创建按钮状态正确，并解释原因。
- 加载、空、禁用、错误、重试和成功状态完整。
- 桌面端弹窗层级、间距、颜色、内部滚动和关闭方式正常。
- 移动端不超出视口；标题、正文和底部操作均可到达。
- 打开后焦点进入弹窗，Tab 不逃逸，Esc 行为明确，关闭后焦点返回触发元素。

#### 发布管理、异常待办和 GEO

- “系统内登记”与“已在第三方实际发布”不会混淆。
- 状态时间线能辨认当前状态、历史事件、操作者和时间。
- 复制操作只表达复制成功，不暗示外部发布成功。
- 证据上传、绑定、失败和未绑定状态清楚。
- GEO 表格与图表说明指标含义；空数据不绘制误导图形。
- 纠错入口明确表达“追加纠错”，不暗示覆盖原记录。

### 9.3 视口与键盘清单

每个主工作流至少在 `1440 × 900` 完整执行一次；以下页面在 `390 × 844` 复查：

- 登录与工作台。
- Prompt 管理、AI 渠道。
- 产品事实详情、内容任务详情。
- AI 草稿弹窗。
- 发布详情/状态更新弹窗。
- GEO 新增观测和详情。

补充检查：

- `1024 × 768`：侧栏、表格、双栏表单和中型弹窗。
- `320 × 800`：最窄支持宽度下的主操作可达性。
- `200%`：代表性表单、弹窗和详情页无关键内容丢失。
- 仅键盘完成登录、打开/关闭弹窗、填写关键表单和提交。
- 检查焦点环、Tab 顺序、Shift+Tab、Enter、Space、Esc 和焦点恢复。

### 9.4 视觉证据

- 每个页面组保留一张桌面基线图；关键移动页面保留一张移动基线图。
- 视觉缺陷必须包含缺陷截图；截图中不包含密码、Token 或密钥。
- 文件名格式：`<run-id>-<case-id>-<viewport>-<short-name>.png`。
- 截图目录：`artifacts/deployed-acceptance/<run-id>/screenshots/`。
- trace 与敏感网络证据单独存放，不在报告中以内嵌形式公开。

## 10. 测试数据、模型预算与清理

### 10.1 数据边界

- 只使用名称带 `E2E-ACCEPT-<run-id>` 的新建测试对象。
- 产品必须明确标记测试用途。
- AI 正向路径只使用本轮创建并批准的 `PUBLIC` 事实版本。
- `RESTRICTED` 事实只用于验证拦截，不发送给第三方模型。
- 不修改历史任务、历史 Prompt、真实平台账号或真实业务记录。
- 若某模块不允许创建隔离测试数据，跳过写操作并报告缺失条件；继续不依赖它的其他模块。

### 10.2 建议测试对象

- 1 个平台类型、1 个平台、1 个平台账号。
- 1 个可用 Prompt、1 个格式错误测试 Prompt；均明确标记测试用途。
- 1 个测试 AI 渠道、1 个通过模型、1 个未测试或禁用模型。
- 1 个管理员辅助测试用户、1 个工程师测试用户（环境允许时）。
- 1 个产品、1 个 PUBLIC 事实版本、1 个 RESTRICTED 事实版本。
- 1 个主内容任务、1 个仅含生成作业、审核记录和未批准内容版本的 `CANCELLED` 可删除任务。
- 至少 1 个受保护删除边界任务，包含 `APPROVED / SUPERSEDED` 内容、发布记录或发布修复来源之一。
- 1 条发布链路、1 条 GEO 观测及其纠错。

### 10.3 外部模型调用预算

- 合规 AI 草稿：1 次。
- 模型连接测试：每个必要模型最多 1 次。
- 自然化：只有功能存在且不影响主验收时 1 次。
- 格式错误验证：最多 1 次，且须使用明确测试 Prompt。
- Prompt 修正后的额外重试：最多 1 次。

禁止用循环重试让流程“碰巧通过”。每次失败先记录响应、作业状态和根因。

### 10.4 清理原则

- 退出所有测试账号并撤销本地浏览器认证状态。
- 测试渠道、模型、平台、账号等配置优先禁用；仅在产品明确允许且无历史引用时删除。
- 除受控删除边界用例明确创建并删除的任务自有未批准历史外，业务记录、状态事件、审核记录、AI 作业、发布记录、GEO 观测和审计记录保留，以便追溯。
- 报告列出所有保留的测试对象 ID 和最终状态，方便管理员后续治理。
- 不因清理目标而破坏“历史不可删除”的业务规则。

## 11. 执行波次与检查点

| 波次 | 内容 | 进入条件 | 完成检查点 |
|---|---|---|---|
| 0 | 文档、环境、账号、浏览器、风险基线 | 目标环境可访问 | 记录环境版本、测试账号角色、已知阻断 |
| 1 | W0 认证、权限和测试配置 | 管理员可登录 | 测试平台、Prompt、账号、渠道/模型可用；权限负向通过 |
| 2 | W1–W4 正常业务闭环 | 安全测试配置已建立 | 事实、AI 草稿、审核、发布登记、核验、GEO 全链路有 ID |
| 3 | 状态机与负向路径 | 正向测试数据可复用 | 非法转换、受限数据、重复发布、历史不可变均有证据 |
| 4 | W5–W6 异常恢复和一致性 | 主链路稳定 | 待办/修复、并发、防重、刷新和错误恢复完成 |
| 5 | UI/UX、响应式和可访问性 | 关键状态数据齐全 | 桌面/移动/键盘检查和视觉证据完成 |
| 6 | 审计、清理与报告 | 所有写操作结束 | 审计一致、会话清理、记录 ID 汇总、结论可判定 |

建议拆成两个连续执行时段：

- 时段 A：波次 0–2，完成隔离测试数据与主业务闭环。
- 时段 B：波次 3–6，完成状态机负向、恢复性、UI/UX、审计和报告。

完整执行预计需要 10–14 小时；若外部模型、异步任务或环境稳定性造成等待，应单独记录，不把等待时间算作页面测试完成。

## 12. 继续、暂停与停止规则

### 12.1 可继续

- 某个独立模块被阻断时，记录 `BLOCKED`，继续执行不依赖该模块的权限、只读、UI/UX 和其他业务检查。
- 页面缺少测试数据时，优先通过正常用户界面创建允许的隔离测试数据。
- Prompt 或测试渠道配置导致合规性失败时，可像正常管理员一样修改本轮新建的测试配置，再验证 revision、审计和恢复路径。
- 已完成 AI 草稿但不能真实外部发布时，可使用明确测试 URL 做系统内发布登记，继续核验后续流程。

### 12.2 必须立即停止相关写路径

- 发现凭据、Cookie、Token、API Key 或敏感请求头泄露。
- 页面无法区分测试数据与真实业务数据，继续操作可能污染真实记录。
- 将要向第三方模型发送 RESTRICTED、未批准或非测试事实。
- 出现 P0 不变量失效，继续可能造成错误发布、历史覆盖、审计丢失或越权写入。
- 目标域名、环境或账号与部署文档不一致。
- 连续出现大范围 5xx、数据明显串扰或环境处于发布/迁移中。

停止某条危险写路径不等于结束整个验收；安全、独立的只读和 UI/UX 检查仍可继续。

## 13. 缺陷、证据与报告

### 13.1 严重程度

| 等级 | 定义 | 示例 |
|---|---|---|
| Critical / P0 | 泄密、越权写入、受限数据外发、历史破坏、错误或重复发布 | 工程师可配置 AI 密钥；RESTRICTED 事实进入外部作业 |
| High / P1 | 主流程无法完成、核心状态错误、关键移动/键盘路径不可操作 | AI 弹窗底部按钮完全不可达；已批准内容被原地修改 |
| Medium / P2 | 有替代路径但明显影响效率、理解或恢复 | 错误提示无恢复建议；筛选返回后丢失 |
| Low / P3 | 不阻断任务的轻微视觉或一致性问题 | 次要间距不一致、非关键文案轻微偏差 |

UI 缺陷按实际影响定级，不因“只是前端问题”自动降级。

### 13.2 缺陷记录字段

- 缺陷 ID、标题、类型（功能/逻辑/权限/可靠性/UI/UX/可访问性）。
- 严重程度、关联风险和不变量。
- 页面 URL、角色、视口、浏览器会话。
- 前置数据 ID 和状态。
- 最短复现步骤。
- 预期结果与实际结果。
- 控制台错误、失败请求、HTTP/业务错误码。
- 截图或 trace 路径。
- 是否阻断后续工作流、可安全继续的范围。

### 13.3 最终报告结构

1. **结论**：通过 / 部分通过 / 阻断。
2. **环境与范围**：时间、环境、角色、视口、实际执行和未执行范围。
3. **风险矩阵结果**：各风险的 PASS/FAIL/BLOCKED/NOT_RUN。
4. **状态机结果**：合法与非法转换、不可逆和历史保留结论。
5. **工作流结果**：W0–W6 的预期、实际、状态和证据。
6. **功能与业务逻辑缺陷**：按严重程度排序。
7. **UI/UX 与可访问性缺陷**：单独排序，含桌面和移动证据。
8. **控制台与网络异常**：错误、失败请求、异常状态码和影响。
9. **测试记录 ID**：配置、产品、事实、任务、作业、草稿、审核、发布、证据、GEO、待办、修复任务。
10. **清理结果与残余风险**：退出、会话清理、保留测试数据和未覆盖项。

## 14. 验收退出标准

### 14.1 “通过”

同时满足：

- 所有 P0 风险均已执行且通过。
- 主工作流 W0–W4 完整通过，W5–W6 中适用部分通过。
- 核心不变量无失败；无 Critical/High 未关闭缺陷。
- 桌面主流程、移动关键页面和 AI 弹窗可完成操作。
- 无敏感信息泄露、越权、历史覆盖、受限数据外发或错误发布。
- 控制台和失败请求中不存在影响结论的未解释异常。
- 测试记录 ID、审计证据和会话清理完整。

### 14.2 “部分通过”

核心安全边界成立且主流程大部分可用，但存在以下任一情况：

- 非 P0 模块被环境或依赖阻断。
- 存在不阻断主链路的 Medium/Low 缺陷。
- 部分视口、异常分支或外部依赖场景未执行。

报告必须明确哪些能力不能据此宣称通过。

### 14.3 “阻断”

存在以下任一情况：

- P0 风险失败或无法验证。
- 无法安全建立隔离测试数据。
- 主业务链路在事实、AI、审核或发布核验关键节点中断。
- 环境、权限或依赖使大部分测试不可执行。
- 继续测试可能泄露秘密、污染真实数据或破坏历史。

最终结论不得以“页面大致可用”或“基本功能能点通”替代上述退出标准。
