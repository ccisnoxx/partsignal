# 发布管理页 UI/UX 重构

## 目标

在不改变已经验收通过的发布业务模型、权限、状态转换和 API 合同的前提下，从运营人员的实际任务顺序重新设计 `/publications` 的信息架构与响应式呈现，使用户进入页面后先看到需要处理的工作，并能在桌面与移动端清楚、可靠地完成现有发布动作。

本任务不是给当前页面补几条 CSS，而是替换失控的页面构图；同时删除与新结构脱节的旧发布页样式，避免继续维护两套无效结构。

## 已确认事实

- 已完成的发布管理业务重构明确要求“页面首先展示现在需要处理什么，其次提供已完成发布结果与历史查询”，并保持“发布工作 / 只读发布成果 / 发布后内容问题”的业务责任边界：`.trellis/tasks/archive/2026-08/08-03-publication-management-logic-redesign/prd.md`、`design.md`。
- 首次核验失败继续待处理，直到复核成功或带原因显式关闭；成功形成只读发布成果，关闭同时取消来源内容任务。该业务规则已经完成本地、预发布和真实业务 UAT，本任务不得重新解释或改写。
- 当前页面使用未定义的 `.page-shell` 与 `.metric-grid`：`frontend/src/features/publications/PublicationsPage.tsx:536-545`。五个最小高度 112px 的 `MetricTile` 因此纵向堆叠：`frontend/src/styles/workspace.css:516`；375px 实测指标区约 605px 高，核心工作列表被推到首屏之后。
- 工作表使用 1050px 横向宽度与 230px 固定操作列：`frontend/src/features/publications/PublicationsPage.tsx:510-516,599`。375px 实测表格区域约 301px 宽，固定操作列遮挡内容列，并阻断标题详情入口。
- `workspace.css` 仍保留 `.publication-workbench`、`.publication-list-panel`、`.publication-tabs`、`.publication-drawer` 等旧发布页样式：`frontend/src/styles/workspace.css:420-506,1205-1216`，但当前组件没有消费这些结构，页面实现与视觉系统已经脱节。
- 当前组件测试只覆盖 URL、服务端动作投影、失败复核和显式关闭：`frontend/src/features/publications/PublicationsPage.test.tsx:122-177`；现有 E2E 只验证文档级无横向溢出、表格区域边界和抽屉业务语义，不能发现固定列遮挡、移动端入口不可点击或首屏没有核心任务：`frontend/tests/e2e/mvp-flow.spec.ts:713-737`、`frontend/tests/e2e/cross-page-visual-convergence.spec.ts:136-215,552-643`。
- 项目视觉规范要求数据列表工作台按“页头 → 可选紧凑真实指标 → 筛选 → 表格 → 按需详情”组织，复用 `PageHeader`、`MetricTile`、`TableRegion`、`StatusTag`、Ant Design 与现有主题 Token；不得新增页面壳、组件库、字体、图标库或平行视觉规范。

## 需求

### R1. 任务优先的信息架构

- 默认视图必须先呈现当前可行动事项，不得让大面积摘要卡、说明文字、历史成果或已关闭记录占据首屏主体。
- 页面必须继续清楚区分未完成发布工作、只读发布成果和发布后内容问题，但一级导航与分组名称应使用运营人员能直接理解的任务语言，而不是数据库对象语言。
- 统计只能作为紧凑导航或筛选辅助，使用服务端真实摘要；不得在页面重算口径，也不得用五张大卡复制状态列表。
- 已关闭工作、已解决问题和只读成果属于查询与追溯层，不得与当前待办争夺默认视觉优先级。

### R2. 桌面工作密度与层级

- 1440×1000 下，页头、紧凑摘要/导航和至少一组当前工作必须在首屏可见。
- 桌面列表保持高密度表格；内容/标题列作为弹性主列，状态、时间与操作列保持紧凑，固定操作列不得覆盖相邻字段。
- 每行只保留服务端 `primary_action` 作为高频操作，其他 `available_actions` 继续进入“更多操作”；不得复制状态或权限判断。
- 筛选、列表标题、空态、分页和选中详情必须形成清晰层级，避免裸控件和多个无归属标题连续堆叠。

### R3. 移动端任务呈现

- 375px 下当前待办不得继续使用会遮挡内容与操作的固定列宽表格；应采用适合纵向扫描的任务卡片/列表项，明确展示对象、阶段、最近情况与主操作。
- 移动端所有关键入口必须可点击且触控目标至少 44×44 CSS px；不得依赖横向拖动才能发现主操作。
- 次要详情允许渐进展开或进入全宽 Drawer，但当前状态、推荐动作和阻断原因必须在列表层可理解。
- 页面不得产生非预期文档级横向滚动、文字遮挡、操作重叠或焦点不可见。

### R4. 详情与动作层级

- 工作、成果与问题详情继续由 URL 中的选中对象驱动；关闭后清理查询参数并恢复触发器焦点。
- 桌面 Drawer 使用有界宽度和明确分区；移动端使用全宽 Drawer。对象摘要、当前状态、主要字段、核验/事件历史和可用动作按任务重要性排列。
- 只读发布成果必须保持只读提示；关闭工作、登记问题等有风险动作继续使用现有确认与说明边界。
- 操作 Modal 只调整视觉层级与响应式，不改变字段、载荷、校验、成功反馈或错误处理。

### R5. 业务与技术边界

- 保留现有服务端 `available_actions`、`primary_action`、接口路径、类型和发布业务状态机。
- `/publications`、`tab=works|articles`、`status`、`page` 与 `selected` 继续有效；统一待处理视图需要显式资源类型和独立分页时可以增加 URL 查询键。旧 `tab=issues` 由已批准的新信息架构替换，不保留平行入口。
- 不修改 OpenAPI、数据库、后端、权限、GEO 候选规则或内容任务状态转换；若实现中发现现有合同无法支撑获批的信息架构，必须回到规划评审，不得在前端猜测或兼容。
- 复用现有 Ant Design、`@ant-design/icons`、共享组件、主题 Token 和 `workspace.css` 加载边界；不新增依赖、全局 Store、通用页面壳或卡片工厂。
- 删除本页不再使用的旧 `.publication-*` 样式；新的局部样式只表达本页真实布局，不创建第二套视觉系统。

### R6. 可验证的 UI 质量

- 组件测试继续覆盖现有业务动作，同时增加信息架构、桌面/移动呈现分支和关键可访问名称断言。
- 真实浏览器回归必须直接检查：首屏核心工作可见、固定列/卡片内容不相交、移动端标题与主操作可点击、Drawer 可操作、URL 状态可恢复。
- 在 375、768、1024、1440px，浅色、深色、跟随系统、200% 浏览器缩放、键盘与 reduced-motion 场景完成页面验收。
- 只有用户明确批准最终页面后，才能登记或更新该页面的人工批准截图/自动视觉基线。

## 验收标准

- [ ] AC1：1440×1000 首屏可同时看到发布管理页身份、紧凑状态导航和当前可行动内容，不需要先滚过五张指标卡。
- [ ] AC2：默认视图中每条待办都能直接回答“是什么、处于什么阶段、为什么需要处理、下一步是什么”。
- [ ] AC3：桌面表格的内容主列、状态、时间和操作边界清楚；固定操作列在 1024px、1440px 与 200% 缩放下不遮挡相邻内容。
- [ ] AC4：375px 使用移动任务列表/卡片呈现当前工作；所有详情入口与主操作均可点击，触控区域不小于 44×44 CSS px，页面无横向溢出或文字重叠。
- [ ] AC5：发布成果与已结束记录不抢占默认待办层级；成果详情保持只读，问题与历史能够从清晰的次级入口查询。
- [ ] AC6：工作、成果与问题 Drawer 在桌面与移动端具有清楚的摘要、字段、历史和操作层级，关闭后 URL 与焦点恢复正确。
- [ ] AC7：现有发布动作、字段、权限、确认文案、API 载荷、失败复核与显式关闭规则全部保持不变；URL 只发生已确认信息架构所必需的资源类型与分页调整。
- [ ] AC8：浅色、深色和跟随系统下文字、边界、状态、焦点与浮层可辨；键盘可以完成全部现有操作，reduced-motion 下不依赖动画表达状态。
- [ ] AC9：自动化回归能够在移动端固定列再次遮挡内容、主操作不可点击或桌面首屏再次被摘要挤占时失败。
- [ ] AC10：当前失效的旧发布页样式被删除；实现没有新增依赖、第二套视觉规范、页面壳、状态源或业务判断。

## 范围外

- 不修改发布管理业务模型、数据库、OpenAPI、后端服务、权限或 GEO/内容任务边界。
- 不重新设计发布账号、内容审核、内容任务、GEO 页面或全站导航。
- 不新增搜索、批量操作、拖拽、图表、自动发布、通知中心或其他当前合同没有的能力。
- 不为这一个页面引入新设计系统、组件库、字体、图标库、状态管理或通用响应式框架。
- 本任务不包含提交、推送或部署；这些操作分别遵守现有确认门禁。

## 已确认产品决策

- 默认一级视图采用统一“待处理”工作台，把待开始、进行中、待核验、需处理工作和开放内容问题按处理优先级放在同一入口。
- “发布成果”和“历史记录”作为次级入口；默认页面不再使用“发布工作 / 发布成果 / 内容问题”三个完全平级的 Tab。
- “历史记录”只承载已关闭发布工作与已解决内容问题；核验成功的工作通过只读“发布成果”追溯，不在历史页重复展示。
- 待处理入口允许按业务类型分区呈现，不强行把发布工作、内容问题和待开始项拼成一个伪统一表格；进入页面时仍按需处理程度优先展示。
