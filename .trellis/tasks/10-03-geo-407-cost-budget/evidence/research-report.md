你拟定的实施策略没有发现硬性业务冲突，但需要明确币种比较、日分区归属，以及哪些未知费用属于“未结消费”。

- **费用事实与覆盖率。** 未知费用必须保持 `cost_amount/cost_currency=NULL`；已知费用必须成对提供，金额有限、非负、`numeric(14,6)`，币种为三位大写代码，wire 金额为十进制字符串。三个 token 字段各自可空，不能把未报告值补零或由其他字段推算。Collector 的明确 `Money` 估价可以用于预留，但不能转成 provider 已报告费用；能力声明、测试通过和模型名称也不能生成价格事实。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:834)、[Worker 架构](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/05-worker-and-collector-architecture.md:457)。Batch 状态按每个 cell 最新 attempt 投影，费用及未知覆盖统计使用**全部 attempt**；重试不能覆盖前序费用，也不能增加 `requested_run_count`。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:847)、[API 合同设计](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/03-api-contract-design.md:290)。

- **引用提交。** 引用 URL、首次位置、重复出现位置、标题和 extraction source 属于不可变回答证据。复用既有 URL 规范化 owner：相同规范 URL 合并，保留首次原始 URL，`occurrences` 唯一升序且不互相占用位置；没有批准的追踪参数清单就保留 query。Answer、全部 citations、Run 采集事实必须一次提交，提交后不得追加引用。Subject/Article 匹配与分类属于后续 AnalysisRevision。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:901)、[ADR-003](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/05-decisions/ADR-003-separate-collection-analysis-review.md:41)。405 基线拒绝非空 citations，407 需要接通该既有证据边界，而不是另建引用事实来源。见 [405 implement.md](/Users/sc/PycharmProjects/partsignal/.trellis/tasks/10-03-geo-405-collection-worker/implement.md:46)。

- **Batch 预算。** 冻结的 `budget_limit` 是正确来源，`NULL` 表示未设上限。执行门禁应在领取/发送前同时考虑已报告费用和并发预留；超限不能再发请求，已发送请求不能因预算变化回撤。PostgreSQL 行锁或原子预留必须覆盖所有 Worker，前端检查不足以兑现该合同。见 [Worker 架构](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/05-worker-and-collector-architecture.md:391)。预算阻断是 `PENDING→BUDGET_BLOCKED`，错误阶段 `COLLECTION`、代码 `BUDGET_EXCEEDED`，不能先进入 RUNNING 再伪装为未发送预算阻断。见 [状态机](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/02-business/03-workflows-and-state-machines.md:131)、[database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:836)。

- **币种。** 旧 Batch/Plan 预算只有金额，没有币种字段。当前 preview 合同仅对唯一已知币种比较，混币时显式 `BUDGET_CURRENCY_MISMATCH`，不换汇；全未知时金额、币种均为空。见 [API 合同设计](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/03-api-contract-design.md:222)。因此，日预算配置 `CURRENCY` 合理，但 Batch 预算也必须形成可审查的唯一比较币种，并拒绝混币消费。不能把不同币种实际报告相加，或借用日预算币种将其静默解释为同币种。

- **日预算归属和时区。** 系统是公司内部单租户共享业务，`created_by` 仅用于追溯，因此全局 GEO 日预算比按用户计账更符合当前归属。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:797)。运维文档只列出 `GEO_DAILY_BUDGET_LIMIT`，没有固定币种、日界线或归属。见 [部署运维](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/08-deployment-and-operations.md:77)。采用 UTC 日与数据库 UTC 时间合同兼容；计划的 `Asia/Shanghai` 默认值是 Cron 调度语义，不能据此推导费用日界线。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:6)、[database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:26)。还需固定跨午夜时按 admission 或 SENT 时间归日，并让结算、释放始终引用该冻结日分区；文档允许任务内选择。

- **未知费用阻断。** 受预算约束时，未知估价或已经发送却无法结算的费用阻断后续 admission，是符合“不补零、不猜价格”的保守策略。未设任何预算时允许采集未知费用，也不违反现有合同。需要区分“费用覆盖统计未知”与“可能已发生的未结消费”：历史 `unknown_attempt_count` 包含未发送、人工、预算阻断等 attempt，不能把所有 `cost=NULL` 都认作已消费或待结。后者应依据 ledger 的 SENT/UNKNOWN 事实判断，否则新批次会被自身尚无结果的 PENDING 行阻断。

- **锁与失败原子性。** 405/406 固定了配置锁 `Channel→Model→Surface→Profile→Batch→Run`；显式 retry 在前面增加 User 锁，结果和恢复只走 `Batch→Run`，不能反向追配置锁。Profile 必须保留 `FOR NO KEY UPDATE`，避免 Answer/Run 外键复验形成锁环。见 [405 design.md](/Users/sc/PycharmProjects/partsignal/.trellis/tasks/10-03-geo-405-collection-worker/design.md:14)、[406 implement.md](/Users/sc/PycharmProjects/partsignal/.trellis/tasks/10-03-geo-406-at-most-once/implement.md:25)。新增预算/profile admission 锁要有一致顺序；预留与领取、SENT 与账本发送事实、结果结算与 Answer/citations/Run/Batch 必须分别落在同一个数据库事务边界，外部 I/O 继续位于事务外。失败不能留下半个回答或已扣预算但未领取的中间态。

- **账本恢复不变量。** `reserved/sent/settled/unknown/released` 是文档未固定、但符合 407 范围的持久化实现细节。NOT_STARTED 预留只有在锁内确认未发送、撤销旧 token 后才能释放；SENT/UNKNOWN 不得因 lease 到期而释放为“零消费”，也不得自动重发。旧 token 的迟到结果不能写回答、改终态或重复结算。见 [Worker 架构](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/05-worker-and-collector-architecture.md:614)、[database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:845)。还应区分并发槽释放与未知费用保留：已终结的未知请求可以结束占用并发槽，同时保留预算阻断事实。

- **Profile 并发、速率与 429。** 文档要求独立 profile 限流，却没有固定数值、窗口算法或 API 默认并发数。见 [部署运维](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/08-deployment-and-operations.md:152)。新增可选 `max_concurrency=1`、`requests_per_minute=60` 属于可在任务内固定的技术策略；旧快照省略字段按同默认解释可以成立，但应保留旧快照原文并记录解释合同。现有 settings 是闭合集合，数据库冻结校验函数和快照校验都要通过新迁移/合同更新支持新键，不能只让运行时 Schema 接受。见 [database.md](/Users/sc/PycharmProjects/partsignal/contracts/database.md:119)。429 必须记录 `PROVIDER_RATE_LIMITED`，完整响应中的 `Retry-After` 可用于后续限流/新 attempt 的等待，但同 attempt 绝不自动重试。见 [Worker 架构](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/05-worker-and-collector-architecture.md:263)。

一个文案歧义可以直接收敛：PRD 写“达到批次预算上限”后阻断剩余运行，[PRD](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/01-product/02-geo-core-prd.md:1364)；更精确的 preview 合同规定已知金额**等于上限不阻断，超过才阻断**，[API 合同设计](/Users/sc/PycharmProjects/partsignal/docs/geo-monitoring/03-technical/03-api-contract-design.md:222)。按 `reported + reserved + next_estimate <= limit` 允许 admission、超过才阻断，能够统一两者，无需将此升级为业务决策阻塞。

实际费用超过估价仍可能发生。文档允许保留已发送请求并阻断后续请求，因此预留机制保证的是并发 admission 不超出当时已知消费与估价额度，不能宣称 provider 最终实际账单绝不会超限；结算时应如实记录实际费用并更新后续门禁。
