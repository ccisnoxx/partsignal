# 修复已删平台来源的发布成果永久删除

## 目标

修复管理员永久删除发布成果时，来源内容任务已失去实时平台绑定会触发数据库约束冲突的问题；发布事件和核验记录继续作为发布聚合的内部删除范围，外部公开页面与独立 GEO 历史不受误删。

## 已确认事实

- 生产数据 `PublishedArticle=5d83fc70-6169-447e-a581-44ea84f17d9e` 没有 GEO 观测、GEO 引用、GEO 优化来源或发布后问题，删除资格预览正确放行；5 条发布事件和 2 条核验记录只是聚合删除计数，不是阻断项。
- 来源任务 `dc6e31ed-3257-4ba6-a0d3-d6a25d4598bc` 为 `COMPLETED`，但其平台已按终态历史解耦规则删除，因此 `platform_profile_id=NULL`，只保留平台名称快照。
- 成果删除服务当前无条件把来源任务改为 `OPEN`：`backend/app/services/publication.py:1102-1103`；数据库约束要求 `OPEN` 任务必须有非空实时平台，因而以 `23514` 拒绝，统一错误处理最终显示“数据约束冲突”。
- 让来源任务继续保持 `COMPLETED` 也不成立：完整性预检要求每个 `COMPLETED` 任务仍存在成功发布工作，删除成果聚合后该条件不再满足：`backend/app/services/integrity.py:27`。
- 发布就绪查询要求任务为未归档 `OPEN`，且通过内连接取得现存活动平台：`backend/app/services/publication_queries.py:246-275`。已删除平台的历史任务无法直接再次发布，也不能确定性改绑到另一个平台。
- 现有合同明确：永久删除发布成果只删除 PartSignal 内部发布聚合，不验证或删除 `final_url` 指向的外部页面；GEO 下游引用存在时仍应作为独立历史阻断删除。

## 需求

### R1 删除边界

- 发布成果永久删除仍原子删除所属 `PublicationWork`、`PublishedArticle`、发布事件、核验、附件关系和内容问题。
- 发布事件、核验及外部 URL 只作为确认范围展示，不得被误报为删除阻断项。
- 外部页面不得访问、验证或删除；存在 GEO 观测/引用或 GEO 优化来源时继续返回结构化阻断，不静默解绑独立历史。

### R2 来源任务状态

- 删除成功后，来源任务不得保持缺少成功发布工作的虚假 `COMPLETED`。
- 仍绑定现存平台的来源任务保持现有行为：恢复为 `OPEN` 并递增 revision，保留 `archived_at`。
- 来源平台已被删除、实时平台外键为空时，不得制造无平台 `OPEN` 任务，不得猜测或自动改绑其他平台。
- 来源平台已删除、实时平台外键为空时，来源任务转为 `CANCELLED` 并递增 revision；若任务已经归档，继续保留 `archived_at`。
- 删除确认文案和权威合同必须明确“平台仍存在时恢复待发布；原平台已删除时转为已取消”。

### R3 错误与一致性

- 无 GEO 阻断且确认、revision 均有效时，已删平台来源的成果删除必须成功，不再落入通用“数据约束冲突”。
- 并发修改、GEO 阻断、错误确认文本和过期 revision 继续原子失败，不写成功墓碑。
- 不新增状态、通用删除框架、兼容层或第二平台来源。

### R4 文档与验证

- 更新 `contracts/database.md`、发布工作台规范及与删除确认文案相关的前端测试，使状态合同一致。
- PostgreSQL 集成测试必须覆盖“终态任务的平台被删除后，再永久删除发布成果”的真实顺序，并断言发布内部历史清理、来源内容保留、外部 URL 不参与验证。
- 保留现有“平台仍存在时恢复 OPEN”和“有 GEO 下游引用时阻断”的回归覆盖。

## 范围外

- 删除或探测第三方公开页面。
- 允许无平台 `OPEN` 任务，或把历史任务自动改绑到新平台。
- 改造 GEO 数据模型、取消真实 GEO 下游引用阻断。
- 批量删除、回收站、软删除或通用状态机重构。
- 修复与本缺陷无因果关系的其他数据库约束错误。

## 验收标准

- [x] 管理员可永久删除没有 GEO 下游引用、但来源平台已删除的发布成果，不返回“数据约束冲突”。
- [x] 成果、工作、事件、核验、附件关系和内容问题按既有聚合边界原子删除，批准内容与事实版本保留，外部公开页面不被访问或删除。
- [x] 来源任务提交态满足数据库与完整性预检：不保持虚假 `COMPLETED`，也不形成无平台 `OPEN`。
- [x] 来源平台仍存在时继续恢复 `OPEN`；归档标记继续正交保留。
- [x] 来源平台已删除时转为 `CANCELLED`；即使任务已归档也保留 `archived_at`，恢复归档后仍是 `CANCELLED`。
- [x] GEO 阻断、revision、权限和确认文本行为不变。
- [x] 前端明确区分“删除范围计数”和“独立下游阻断”，并说明外部页面不会删除。
- [x] 目标 PostgreSQL 集成测试及相关前端测试通过，合同、规范、实现和测试一致。

## 产品决策

- 用户确认：来源平台已经删除时，永久删除发布成果后，将来源任务转为 `CANCELLED`。
- `archived_at` 继续作为正交可见性标记，不因状态回落而自动清空。
