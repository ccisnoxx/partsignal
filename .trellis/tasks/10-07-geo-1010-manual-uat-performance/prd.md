# GEO-1010-UAT：执行真实 MANUAL GEO 业务与性能验收

## 基本信息与执行门禁

- 展示 ID：GEO-1010-UAT；Trellis ID/slug：`geo-1010-manual-uat-performance`。
- 初始状态：planned；依赖 GEO-1010-UI done、GEO-1010-DEPLOY done。
- 父任务：[GEO-1010](../10-07-geo-1010-manual-pilot/prd.md)。
- 目标：以公司真实但受控的产品、问题和人工观测，判断是否支持日常 GEO 监测与行动闭环。
- 本规划不创建真实数据、不访问真实 AI 平台。执行前记录获批内部环境/候选、数据范围、人员、平台人工使用许可、时间窗口、反馈渠道和具名业务/运维验收人。

## 试点样本与数量口径

- 2～3 个重点产品，每产品 3～5 个竞品；3 个真实 AI 平台；2～4 名内部试用人员。
- 20～30 个问题是跨上述产品分配的试点问题总数，不再按产品数重复做笛卡尔积；每问题在每平台人工重复 2 次，目标 `20～30 × 3 × 2 = 120～180` 个 MANUAL Run。
- 运行数以服务端矩阵 preview 为准；保存实际问题/Profile/重复映射和预计数。Retest 的新增 Run 单列，不能混入初始完成率分母或借此掩盖未完成样本。
- 缩小范围须记录原计划、调整后的矩阵/数量、原因、具名批准人与时间；缺失/失败/取消等 Run 仍须有可解释结果，不能全部记成成功。

## 人工观测流程

1. 从系统领取精确问题；在真实平台的新会话中人工执行，记录实际平台、观测时间和已知版本/模式。
2. 复制完整回答；登记引用标题、URL、域名和顺序。URL 不可见时保存缺失原因，不猜测或补写链接，不将缺失引用推断为没有引用。
3. 上传可追溯截图，检查没有账号/敏感界面；提交回答，等待分析，必要时人工复核，再查看指标和报告。
4. 正式答案、引用、截图、分析/复核历史和 publishing 记录保持现有不可变合同；指标沿服务端资格/分母，不手工改数。

## 完整业务闭环

至少完成一个真实案例：发现问题 → 管理员通过页面显式评估 → 确认 Opportunity → 页面创建 Content Task → 内容生产和审核 → 登记发布 → 页面 Retest preview/create → 人工执行复测 → 查看前后比较 → 明确“不证明因果” → 人工 resolve 或 continue。

内容生产只产生草稿，未知产品事实显式失败；批准事实不可原地改写。发布使用已有人工登记能力，不自动发布；使用获批平台和事实，自动外部 AI 调用不因 UAT 获得授权。基线不可比时不得强行创建 Retest，也不得根据一次变化宣称因果。

## 可用性记录

记录每个主要流程的起始/完成次数与完成率、员工需要开发者帮助的次数、易错字段、放弃点和内部用户反馈。问题分为业务阻断、高优先级可用性、普通改进、V1.1 建议；记录负责人、复现材料和处置结论。

## 性能记录与初始目标

| 项目 | 初始目标 / 记录要求 |
|---|---|
| 普通列表页 | P50/P95；P95 ≤ 2 秒 |
| Run Detail | P50/P95；P95 ≤ 2 秒 |
| GEO Overview | P50/P95；P95 ≤ 3 秒 |
| 筛选与分页 | P50/P95，记录页面、数据量和筛选条件 |
| 人工提交、文件上传 | 实测耗时分布；记录样本数和文件大小 |
| 分析 | 队列等待时间与提交到分析完成时间分别记录；完成 P95 ≤ 60 秒 |
| Worker / API / DB | Worker 内存、API 5xx、慢查询与定位结果 |
| 并发 | 5 名获批内部用户的表现，另行记录测试账号/参与者和负载；不以2～4名日常试用人数替代并发目标 |
| UAT 主流程 | 成功率 ≥ 95%，明确分母、失败和需帮助完成情况 |

记录候选、环境规格、浏览器/网络、数据规模、测量起止点、样本数、冷/热条件和原始结果。页面耗时不能以服务端 API 时间代替，队列等待不能混作页面等待；小样本限制如实说明。若规格导致目标需调整，必须保留原阈值、实测、调整原因、具名人工接受人与时间，不静默改阈值。

## 缺陷处理与候选变化

UAT 只观测、验收和记录。代码问题必须建立独立缺陷任务，附级别、owner、复现、候选和预期行为；不得在 UAT 内顺手改源码。若修复改变候选，先通过独立修复验收和获批 DEPLOY 候选绑定/重部署，记录旧/新身份与影响，再续 UAT 或重验受影响流程。旧结果不可冒称适用于新候选。

## Go/No-Go 交付

最终报告列明已通过/未通过流程、P0/P1、性能结果、内部反馈、V1.1 backlog；具名人工选择“内部继续试用”“修复后继续”或“停止推广”，记录范围、条件、负责人和时间。任何未验证项保留未知，不由代理推断 Go。该结论针对内部试运行，不授予正式生产 Go。

## 范围外

Browser 自动化、API 自动采集、大规模公网用户、多租户、商业计费、AI 排名提升保证、一次复测因果断言、UAT 内实现修改和正式生产开放。

## 独立验收

- [ ] 120～180 个目标 Run 有可解释完成结果，或有具名批准的缩小范围；实际样本与完成率可核验。
- [ ] 至少一个真实 Opportunity—Action—Retest 闭环，关键用户操作通过页面。
- [ ] 所有正式指标可追溯到完整答案、引用、截图及分析/复核；缺失原因真实可见。
- [ ] 无未处理 P0；每个 P1 有明确负责人和处置结论，未通过项不能写通过。
- [ ] 主要页面性能、提交/上传、分析/队列、内存/5xx/慢查询与5人并发有实测值；阈值调整有完整批准链。
- [ ] 有内部用户反馈、分级问题清单、V1.1 backlog 和正式具名内部 Go/No-Go。
- [ ] UAT 工作验收后先 review，人工接受后才 done；三个子任务全部 done且集成工作验收后父任务才 review，父任务另经人工接受才能 done。
