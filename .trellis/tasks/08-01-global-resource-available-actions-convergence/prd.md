# 全局资源动作投影收敛

## 1. 目标

修复第二轮回归的 `PS-QA2-FUNC-001`～`003`，并实施已经批准的 `PS-QA2-DEC-002`：所有现有资源绑定的状态、危险、编辑、保存、凭据和子资源命令，统一由服务端 `available_actions` 投影决定前端是否呈现或启用。服务端命令守卫仍是最终权威，前端不得再从 `status`、角色或局部关联数据复算资格。

## 2. 已确认根因

- 目前只有内容任务取消/删除、事实与内容审核、发布记录/关注事项、GEO 观察等少量资源具备动作投影；其余资源命令仍由页面按角色、状态或引用数据自行推断，形成第二套资格逻辑。
- `PS-QA2-FUNC-001`：`ContentTasksPage.tsx` 仅用 `generationJob.status === "FAILED"` 显示“重试原快照”，未消费后端 `retry_generation_job` 的终态内容任务限制，导致按钮可见但命令返回 `LEGACY_GENERATION_RETRY_FORBIDDEN`。
- `PS-QA2-FUNC-002`：后端已为已解决发布关注事项返回 `available_actions=[]`，`PublicationRepairPage.tsx` 仍无条件呈现修复任务表单。
- `PS-QA2-FUNC-003`：后端已为非尾部 GEO 记录移除 `CORRECT`，`GeoObservationForm.tsx` 只生成错误提示，提交与附件交互仍可操作。
- 动作资格的权威事实分散在各服务命令的权限、状态、引用和并发守卫中；新建一个与命令守卫脱离的前端状态表或全局通用判定器只会产生新的漂移源。

## 3. 已批准的合同边界

### 3.1 范围内

- 资源绑定的编辑、保存、启用/停用、测试、重试、审核、凭据替换、删除、修复、更正，以及 Header、模型、版本、生成作业等子资源命令。
- 目前只由 API 暴露但属于上述类别的资源命令，例如查询主题更新；合同应完整，不以当前页面是否已放置按钮为判断标准。
- 现有投影继续保留各自的动作名称和大小写，不改变已工作的内容任务、审核、发布和 GEO 语义。
- 列表、详情和非删除命令响应中的同一资源必须返回一致、基于当前操作者和当前数据库状态的 `available_actions`。
- 前端由返回的动作数组控制命令入口；命令失败仍按既有错误合同处理并发状态变化，不把投影当作安全控制。

### 3.2 范围外

- 集合级新建按钮和创建接口，包括创建产品、用户、平台、内容任务、GEO 记录等；本任务不引入 collection-level action 合同。
- 纯导航、查看、复制、筛选、导出、打印，以及登录、退出、修改本人密码等认证自服务。
- 文件上传、下载、分片、终止传输、Logo 候选预览等文件传输内部动作。
- 新增业务命令、重命名既有命令、统一所有资源为一个通用 Action enum，或建立一套通用权限/状态规则引擎。
- 修改 PostgreSQL Schema、迁移、业务状态机、角色模型或命令错误码。
- 其他六组回归问题、集中回归报告和 `.playwright-cli/` 诊断产物。

## 4. 资源覆盖要求

| 资源 | 必须投影的现有命令类别 |
| --- | --- |
| 用户 | 编辑、重置密码、启用/停用、删除；本人、最后一名管理员和历史引用限制与命令守卫一致 |
| 产品、事实工作区、事实版本 | 编辑、删除、保存事实、创建版本、审核和版本删除 |
| 查询主题 | 编辑 |
| 平台档案、平台类型、平台 Prompt、内容自然化 Prompt | 编辑/保存、启用/停用、删除 |
| AI 渠道、Header、模型 | 编辑、替换凭据、启用/停用、测试、删除、发现/创建其资源绑定子项 |
| 平台账号 | 编辑、启用/停用、删除 |
| 内容任务、生成作业、内容版本 | 保留任务取消/删除；补充资源绑定的生成、人工版本、重试、自然化、修订和审核命令 |
| 发布候选、发布记录、发布关注事项 | 登记发布及现有发布/验证/删除/修复/解决动作；现有 token 不变 |
| GEO 观察 | 保留 `CORRECT`/`DELETE`，让更正表单的全部交互消费同一 `canCorrect` |

精确 token、响应 Schema 和权威服务位置以 `research/action-inventory.md` 与 `design.md` 为实施基线；实施中若发现现有命令不属于已批准类别，先回到规划评审，不自行扩张。

## 5. 功能需求

### R1. 单一服务端资格所有者

- 每类资源在现有领域服务内提供聚焦的动作投影函数；投影必须复用或提取命令函数已经使用的资格谓词。
- 权限、状态、引用计数、当前版本/尾部记录、父资源状态等判断不得分别在投影和命令中复制。
- 服务端命令入口继续独立执行相同守卫，防止投影返回后状态变化造成越权或错误写入。
- 列表投影不得逐行发出资格查询；涉及引用或当前性时使用现有聚合结果或批量查询。

### R2. 明确的跨层合同

- 在 `contracts/openapi.yaml` 为范围内资源 Schema 增加必填 `available_actions`，每个资源使用自己的 `Literal`/enum；不引入万能动作类型。
- 后端 Schema、投影器、列表/详情/命令响应、生成的 `frontend/src/shared/api/schema.d.ts` 必须同步。
- 同一资源的鉴权上下文必须显式传入投影；认证自服务响应明确返回空数组，不使用缺省猜测或兼容回退。
- DELETE 继续返回 `204`，不要求删除后的动作投影。

### R3. 前端唯一消费路径

- 范围内命令入口只读取所属资源或服务端上下文的 `available_actions`；删除页面内基于角色、状态、引用关系复算资格的分支。
- 非删除命令成功后使用响应内的新投影或失效并重取所属查询；不得本地手工拼装下一状态动作。
- 若某动作不可用，隐藏或禁用方式遵循页面既有交互；不得保留仍能提交同一命令的旁路。
- 批量用户状态操作仅在所选用户都包含目标动作时启用，避免静默跳过不合格资源或发送已知无效的混合请求。

### R4. 三个原缺陷闭环

- 生成作业重试按钮仅在该作业包含 `RETRY` 时出现；终态任务下的失败作业不得出现重试入口。
- 发布关注事项修复页在 `CREATE_REPAIR_TASK` 不可用时不呈现可提交表单，并明确显示只读/已处置状态。
- GEO 更正页从一个 `canCorrect` 派生表单、附件和提交可操作性；非尾部记录不能上传、移除附件或提交更正。

### R5. 永久回归证据

- 后端测试覆盖各资源动作投影与实际命令守卫的一致性，至少包含允许与拒绝状态、角色边界、引用约束和列表无逐行资格查询的关键路径。
- 前端测试覆盖范围内每类命令入口只消费 `available_actions`，并对三个原缺陷做定向回归。
- OpenAPI 生成类型和合同门禁证明跨层字段同步；不得手改生成类型绕过合同。
