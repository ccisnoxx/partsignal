# 补齐管理页面操作能力与修复全站表格布局

## 目标

补齐内容任务与发布管理页面的操作入口，允许清理带任务内生成历史的已取消任务，并修复详情信息过载、并列卡片失衡及全站数据表在真实长数据下的列宽、换行、固定列和滚动问题，使服务端支持的操作在前端完整可见、危险操作边界清楚、所有业务列表稳定可读。

## 背景与已确认事实

- 预发布环境 `https://geo.962850.xyz` 在 `1440×1000` 视口下完成只读复现；页面身份、业务请求和控制台均正常。
- 内容任务物理删除链路已经存在：
  - `DELETE /api/v1/content-tasks/{content_task_id}` 定义于 `contracts/openapi.yaml:1297`，服务实现位于 `backend/app/services/publication.py:917`。
  - `backend/app/services/projections.py:72` 只在任务为 `CANCELLED` 且没有生成作业、内容版本时投影 `DELETE`。
  - 前端仅在 `available_actions` 包含 `DELETE` 时显示入口，见 `frontend/src/features/content-tasks/ContentTasksPage.tsx:469`。
  - 预发布现有 3 条已取消任务中，两条已有成功生成作业；另一条虽显示“尚未生成”，但已有内容版本，因此三条均没有删除资格。当前页面没有解释入口为何消失。
- 内容任务列表当前只提供“查看详情”，见 `frontend/src/features/content-tasks/ContentTasksPage.tsx:203`；取消和物理删除操作只在详情页按服务端 `available_actions` 条件渲染，因此不满足旧门禁时页面完全看不到对应按钮。
- 实施前服务端列表与详情复用同一动作投影：`OPEN` 且没有在途发布时返回 `CANCEL`，`CANCELLED` 且没有生成作业或内容版本时返回 `DELETE`，其他情况返回空数组；动作数组为空时，详情页也没有只读原因说明。
- 发布记录物理删除链路已经存在：
  - `DELETE /api/v1/publication-records/{publication_id}` 定义于 `contracts/openapi.yaml:1712`，服务实现位于 `backend/app/services/publication.py:772`。
  - `contracts/database.md:261` 只允许删除从未进入 `PUBLISHED` / `VERIFIED` 且没有 GEO 引用、文章观测或待修复来源的记录。
  - 前端已实现删除 mutation 和确认流程，见 `frontend/src/features/publications/PublicationWorkspace.tsx:220`；入口同样受服务端 `available_actions` 门控。
  - 预发布现有 5 条发布记录均已发布、已验证或验证失败，不满足物理删除资格；更多菜单只显示适用的状态操作，没有解释删除条件。
- 内容任务详情在 `frontend/src/features/content-tasks/ContentTasksPage.tsx:548` 展示最新作业追溯快照，并完整渲染 `system_message` 与 `user_message`；没有截断、折叠或长度上限。预发布测试消息较短，但真实内容可达数千字。
- 02A / 系统 AI 生成与 02B / 手动录入由 `frontend/src/styles/workspace.css:400` 配置为 `.8fr / 1.2fr` 且顶部对齐。预发布实测两卡约为 `470×318` 与 `706×217`，宽高均不一致。
- 发布记录表位于 `frontend/src/features/publications/PublicationWorkspace.tsx:512`：
  - 发布账号列宽 `150px`，预发布长测试账号的单元格内容宽约 `204px`，溢出到相邻列并把标准行高撑至 `84px`。
  - 现有测试只断言文本和操作，没有覆盖长文本几何、截断或列间不重叠。
- 待发布候选表位于 `frontend/src/features/publications/PublicationWorkspace.tsx:447`。标题列没有明确宽度或截断边界，在 `1440px` 下吸收剩余宽度至约 `452px`；需要验证极长连续标题不会扩大表格或页面。
- GEO 观测表位于 `frontend/src/features/geo-observations/GeoObservationsPage.tsx:234`：
  - 观测平台 `150px`、记录人 `96px`，均未设置单行省略。
  - 预发布超长平台名和记录人把对应行从标准 `52px` 撑至约 `123px`。
- 已对登录后的管理页面做服务端路由与前端入口映射核对，未发现其他“服务端动作已实现但前端完全没有入口”的确定性缺口；动作补齐仍聚焦内容任务和发布记录，不扩展为新的全站动作框架。
- 表格布局范围不是三个已报告页面。源码清点确认登录后共有 24 张业务数据表/表格型列表，覆盖内容任务、产品事实、发布、GEO、配置中心、设置和用户管理；完整清单、初始风险和统一验收不变量记录在 `research/sitewide-table-audit.md`。
- 除已复现的待发布、发布记录和 GEO 观测外，静态审计还发现 AI 作业失败原因、内容版本标题、事实版本变更说明、发布异常账号、GEO 文章/问题库、AI Header/模型 ID、审计动作、平台类型 slug、发布账号和用户身份列等缺少稳定边界。
- `.trellis/spec/frontend/visual-system.md` 与 `component-guidelines.md` 要求名称/标题保留弹性列，其他有明确上限的字段保持紧凑；宽表只能在 `TableRegion` 内横向滚动，单元格控件和长文本不得撑破列宽。

## 范围内需求

### R1. 内容任务删除可发现性

- 用户已确认：已取消任务即使存在生成作业或生成内容，也必须允许物理删除，不能继续以“存在生产历史”为由隐藏或拒绝删除。
- 用户已确认删除边界：物理删除可以级联清理该任务拥有的生成作业，以及状态为草稿、待审核、要求修改的未发布内容及其审核记录；内容一旦批准或曾经批准，或已经产生发布记录、GEO 引用/观测及修复历史，服务端必须明确阻断删除。
- 内容任务列表不能只有“查看详情”；每行必须根据服务端 `available_actions` 直接提供适用的取消或物理删除入口，低频危险操作进入“更多操作”并保留确认。
- 详情页同步展示服务端允许的取消或物理删除按钮；列表与详情不能维护两套资格判断。
- 物理删除必须由服务端事务处理任务拥有的生成作业、内容版本及其仅属于该任务的从属记录，并写入删除审计；不得由前端拼接多次删除请求或伪装成功。
- 若任务内容已经批准或进入独立发布、GEO、修复历史，删除必须在事务开始阶段返回稳定业务错误，不能依靠数据库外键异常决定用户体验。

### R2. 发布记录删除可发现性

- 发布记录的更多操作中必须能够看见“物理删除”能力及其当前可用状态。
- 可删除记录继续使用现有服务端 action、确认流程、审计和 `DELETE` API。
- 不可删除记录必须说明资格边界；状态操作、权限、发布历史和 GEO 修复来源保持服务端权威。

### R3. 作业追溯信息收敛

- 任务详情不再直接展示完整系统消息和用户消息。
- 保留支持定位作业身份和执行配置的必要追溯信息；作业历史、重试原快照和后端不可变快照不变。
- 页面不得因数千字 Prompt 或事实 Markdown 形成超长只读输入区。

### R4. 02A / 02B 并列卡片重设

- 桌面双列下两张卡片等宽、等高，标题、说明和操作形成一致的垂直层级。
- 窄屏继续按现有断点堆叠；任务状态、可用操作和表单行为不变。
- 复用现有 Ant Design Card、按钮、Alert 和 `workspace.css`，不新增卡片组件或设计 Token。

### R5. 全站数据表与表格型列表审计修复

- `research/sitewide-table-audit.md` 中的 24 张表全部纳入逐表源码、真实浏览器和边界数据审计；已报告的待发布、发布记录和 GEO 观测只是必须修复的样本，不是范围上限。
- 每张表都必须明确主要弹性列、固定业务列、操作列、横向滚动和行高边界。普通长文本单行省略；“名称 + 次要标识”最多保持固定两行且每行独立省略。
- 连续 ID、slug、账号、URL、错误摘要和变更说明不得无上限换行或越过单元格；完整值必须通过键盘可达 Tooltip、`title`、详情入口或等价方式查看。
- 固定操作列在普通、悬停、选中和异常行状态下保持完全不透明，按钮不换行、不裁切、不与滚动内容叠加。
- 文档根节点不能产生横向滚动；宽表只在表格内部滚动。`TableRegion` 保持语义焦点和宽度边界，局部 `overflow:hidden` 不得裁切 Ant Table 的滚动或 sticky 内容。
- GEO 覆盖矩阵等确有动态列的原生表保留横向滚动设计，但同样必须通过移动、打印和长平台名验证。
- 对已有局部约束且未确认失败的表先验证；满足统一不变量时不做机械改写，违反任一不变量时纳入本任务修复。
- 固定操作列、现有高频入口、更多菜单、权限、筛选、分页和查询口径保持不变。

### R6. 全站列表回归保障

- 相关组件测试覆盖删除入口的可用/不可用状态与说明，以及各页面长文本渲染所需的语义类、Tooltip/标题和操作入口。
- `list-workbench-convergence.spec.ts` 或同层现有 E2E 持有 24 张表的显式清单；每张表都必须被真实浏览器访问并检查表格身份、文档无横向溢出、内部滚动和操作可达。
- 使用接近接口允许上限的长标题、平台、账号、记录人、URL、ID、slug、错误摘要和变更说明，断言内容不越过单元格、相邻列不相交、数据行维持预定高度、固定操作列遮挡正确。
- 全表至少覆盖 `1440×1000` 和 `375×900`；真实 200% 浏览器缩放覆盖普通宽表、固定操作列、紧凑指标表、原生动态矩阵和弹窗表五类代表，并检查浅色、深色、键盘、控制台与失败请求。
- 不扩大视觉差异阈值，不遮罩表格稳定几何，不用短测试数据代替长文本边界，也不把 CSS `zoom` 或 CDP 页面缩放当成真实浏览器缩放。

### R7. 前端操作覆盖核对

- 对内容任务和发布记录的服务端动作枚举、列表、详情和更多菜单做逐项映射；服务端已支持且当前用户有权限执行的操作不得只存在于 API。
- 当服务端因状态、引用或权限不返回动作时，前端必须显示稳定的只读状态或资格说明，不能自行补造可执行动作。
- 复用现有 Ant Design `Dropdown`、确认、通知和 `available_actions` 模式，不新增第二套动作注册表、权限逻辑或前端状态机。

## 验收标准

- [x] AC1：内容任务列表与详情均根据同一份服务端 `available_actions` 呈现取消、物理删除操作；无可执行动作时仍能理解当前只读原因。
- [x] AC2：带任务内生成作业、草稿或未发布内容版本的已取消任务可在单次确认后完成物理删除，批准清理范围内的依赖不残留，删除审计保留。
- [x] AC3：任务内容已经批准，或存在发布记录、GEO 引用/观测、发布修复历史时，服务端在删除前返回稳定业务错误且不删除任何记录。
- [x] AC4：发布记录始终可见“物理删除”能力；满足服务端资格时可完成现有删除流程，不满足时入口不可执行且能理解原因。
- [x] AC5：任务详情不直接渲染 `system_message` 和 `user_message`，保留必要追溯元数据、作业历史与重试能力。
- [x] AC6：02A / 02B 在桌面双列下宽高一致、操作对齐，窄屏堆叠无重叠或关键入口丢失。
- [x] AC7：24 张全站数据表均有清单记录、源码结论和真实浏览器结果；清单中的静态高风险项全部修复或以几何证据证明满足统一不变量。
- [x] AC8：发布记录长账号不进入最终 URL 或操作列；待发布极长标题不改变表格总宽；GEO 超长平台和记录人不把常规行异常撑高。
- [x] AC9：其他表中的标题、错误、变更说明、问题、Header、模型 ID、审计动作、slug、账号、URL 和用户名称均保持在所属单元格内，完整值可访问。
- [x] AC10：所有固定操作列的按钮可达、背景不透明且不与滚动内容叠加；页面无横向滚动，宽表只在自身滚动容器内滚动。
- [x] AC11：24 张表在 `1440×1000` 与 `375×900` 通过浏览器清单回归，五类代表表通过真实 200% 浏览器缩放，浅色/深色及键盘状态没有遮挡或入口丢失。
- [x] AC12：针对性组件测试、真实浏览器几何测试、TypeScript、触及文件 ESLint 与主题颜色守卫通过。
- [x] AC13：删除审计、权限、API 载荷、查询键、筛选、分页和状态转换保持服务端权威；没有前端补造动作或第二套权限判断。

## 范围外

- 为测试数据增加生产环境专用绕过、级联删除或固定成功路径。
- 删除已批准内容、发布记录、验证结果、GEO 引用/观测或发布修复历史。
- 对未复现出动作缺口的其他管理页面做批量操作入口改造，或新建全局动作注册框架。
- 把普通帮助说明、表单字段、时间线和导航列表重做成表格。
- 重做整套表格组件、给所有表机械套用同一个 `table-layout`、引入新依赖、设计 Token、CSS 框架或第二套组件库。
- 修改未经用户确认的视觉基线、自动提交、推送或部署。
