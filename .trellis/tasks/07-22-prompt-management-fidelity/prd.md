# 配置中心 Prompt 管理高保真复刻与功能闭环

## 目标与用户价值

在现有 `/configuration/prompts` 页面上，以批准原型
`/var/folders/m5/j06tv2sn1hn93d6f33j559jm0000gn/T/codex-clipboard-4a946b23-3b37-460c-9799-0787c29335ad.png`
（1581×995）为桌面端视觉与交互规格，完成平台 Prompt 和全局自然化 Prompt 的真实管理闭环。
管理员应能在一个高密度工作台中定位权威配置、编辑唯一 Markdown 正文、处理并发冲突、确认删除影响并查看不可编辑的安全边界；页面不得制造第二套 Prompt、固定模型输出或可覆盖系统约束的假能力。

## 已确认事实

- 当前平台 Prompt 的唯一所有者是具体 `PlatformProfile`；每个平台零或一条 `platform_prompts` 当前行。权威端点为 `GET/PUT/DELETE /api/v1/platform-profiles/{platform_profile_id}/prompt`，不存在类型级 Prompt、默认 Prompt、双读或兼容回退。
- 全局自然化 Prompt 是 `content_humanization_prompts.id=1` 单例，仅支持管理员首次创建和按 revision 更新；不存在删除、种子默认值、平台副本或环境回退。
- 两类 Prompt 都只保存 Markdown 正文、revision、更新人和时间；不保存 HTML、编辑器 JSON 或平行正文。
- Prompt 读取和写入只允许管理员；写请求还受 CSRF 保护。保存和平台 Prompt 删除都使用 `expected_revision` 乐观锁并记录脱敏审计。
- 原始生成的 system message 顺序是固定系统契约 → 当前平台 Prompt；user message 顺序是工程师 Prompt → 已批准事实 → 任务要求。平台规则冻结在任务要求并参与质量检查。
- 自然化的 system message 顺序是固定系统契约 → 固定自然化契约 → 当前全局自然化 Prompt；user message只包含冻结的源文章、批准事实和原任务要求。
- 新建生成或自然化作业会冻结最终 system/user message、Prompt revision/正文及非敏感调用上下文；重试复制原快照，不读取当前 Prompt。审核上下文可追溯快照，发布阶段不重新拼接 Prompt。
- 平台 Prompt 删除后，新任务和新生成作业显式返回 `PLATFORM_PROMPT_MISSING`；历史作业快照仍可读。全局自然化 Prompt 缺失时显式返回 `HUMANIZATION_PROMPT_MISSING`。
- `/api/v1/platform-profiles` 支持服务端名称/类型搜索、平台类型筛选和成对 `page/page_size` 分页，并返回平台 Logo、类型、Prompt 配置状态/更新时间、ACTIVE 规则和配置完整性；Prompt 页面已直接接入这些权威投影。
- 当前页面使用真实 API，已形成平台/自然化标签、带行号 Markdown 编辑、显式保存状态、revision 冲突恢复、删除确认、脏草稿保护、三栏工作台和安全边界摘要。
- 仓库不提供无痕 Prompt 预览 API；配置页通过现有可追溯生成/自然化作业创建真实 AI 草稿，并从任务级作业列表轮询状态后读取不可变内容版本。

详细证据位于 `research/` 下六份调查文档。

## 关键产品决策

- 输出预览复用现有可追溯作业链，不新增无痕临时调用 API。
- 平台 Prompt 预览由管理员显式选择当前平台下符合门禁的 OPEN 内容任务和已启用、测试通过的模型，使用**已保存**平台 Prompt 创建普通 `GENERATE` 作业并展示新 DRAFT。
- 全局自然化 Prompt 预览由管理员显式选择符合门禁的 OPEN 内容任务、其中合格的 AI 草稿和模型，使用**已保存**自然化 Prompt 创建 `HUMANIZE` 作业并展示新 DRAFT。
- 两类预览都会产生真实、可审计、可追溯的 `GenerationJob` 和 `ContentVersion`；未保存 Prompt 不允许试跑，页面必须明确提示先保存。
- 原型没有展示任务、源版本、模型和生成触发控件，但这些控件是完成真实预览所必需的批准差异；不得用自动调用、固定问题或静态答案保持表面一致。

| Prompt 独立历史版本/恢复 | 当前模型不存在，非本次必需 | 作业级历史继续由不可变快照追溯；不建立通用 Prompt 版本框架 |

## 范围内要求

### R1. 忠实页面框架

- 保留现有 PartSignal 应用壳、配置中心展开状态、全局搜索、主题、用户区和管理员路由门禁。
- 页面首屏严格遵循批准原型的信息层级：面包屑/标题/说明、两类 Prompt 标签、安全提示、平台列表、编辑区、输出预览区和安全边界摘要。
- 桌面端以 1581×995 为主验收视口；优先复用现有主题 Token、Ant Design 组件、图标和玻璃表面，不建立第二套设计系统。
- 原型未定义移动信息架构；窄屏沿用现有配置中心规则，保证无页面级横向溢出、内容可访问和核心操作可完成。

### R2. 平台列表与视图状态

- 平台标签页使用服务端 `q`、`platform_type_id`、`page`、`page_size` 查询；搜索、筛选、分页和当前 `platform_profile_id` 写入 URL 并支持前进/后退恢复。
- 列表展示真实 Logo、名称、类型、Prompt 已配置/未配置、ACTIVE 规则有无/状态和 Prompt 最后更新时间；Prompt 时间来自选中 Prompt 或平台详情的 `prompt_updated_at`，不得误用平台自身 `updated_at`。
- 当前平台不在筛选页或 URL 无效时显示明确状态，不在前端猜选另一个平台；首次无选择时可按现有工作台约定选中当前结果第一项并同步 URL。
- 平台未配置 Prompt 也必须可选并进入首次创建状态，不能从列表隐藏。

### R3. Markdown 唯一正文与编辑状态

- 平台 Prompt 和全局自然化 Prompt 只编辑 `template_markdown`；不保存 HTML、编辑器 JSON、模板变量模型或第二正文。
- 使用现有 textarea 能力实现可滚动的行号、正文、可见焦点和字数/行数；不新增编辑器依赖。
- 状态至少区分：未配置、已加载且未修改、未保存修改、保存中、保存失败、保存成功、revision 冲突和无权限。
- 保存只由显式按钮触发，不自动保存。切换平台、切换标签、离开路由或关闭含草稿的窄屏容器前必须确认；取消离开保留原草稿。
- 保存成功后使用响应中的最新 revision/正文/更新时间更新本地基线并清除 dirty；保存失败保留草稿。

### R4. 删除与并发

- 只有平台 Prompt 提供删除；全局自然化 Prompt 不显示或实现删除。
- 删除前确认文案明确：平台本身和历史快照保留，但重新配置前不能创建新任务或新生成作业。
- 删除请求携带当前 `expected_revision`；服务端锁定后仅在 revision 匹配时删除，否则返回 409。删除成功后清空正文基线、更新列表配置状态并留在当前平台的未配置态。
- 保存或删除冲突不得自动重试、覆盖或回退；用户可重新加载服务端当前值后再决定。

### R5. 安全边界与权限

- 页面只向管理员开放；服务端继续以 `AdminUser` 和 CSRF 为最终权威。
- 可编辑 Prompt 永远只能追加在固定系统契约之后，不能覆盖平台规则、批准事实、数据分级、固定输出结构或安全约束。
- 安全摘要至少表达：批准事实优先、禁止编造输入外产品事实、AI 只能创建草稿、输出结构受系统契约控制；摘要来自当前权威代码/文档，不保存为配置。
- “前往平台规则”带当前 `platform_profile_id` 跳转真实规则工作台；“查看安全边界说明”定位页面内说明或打开只读说明，不创建可编辑安全规则页。
- Prompt/模型输出渲染继续经 DOMPurify；危险链接、脚本和事件属性不得执行。响应、日志和审计不得包含凭据、敏感 Header、完整 provider body或额外内部指令。

### R6. 错误、加载与空态

- 身份集合、选中 Prompt、用户映射和预览按各自区域处理加载、失败、重试和空态；次级失败不得遮蔽已加载的兄弟区域。
- 明确覆盖：无平台、筛选无结果、平台未配置 Prompt、自然化 Prompt 未配置、保存失败、删除失败、revision 冲突、403、预览无合格任务/源版本/模型、作业失败和模型调用超时。
- 不使用 broad catch、固定成功响应、静态 CloudFlow 文案、随机数据或静默默认值。

### R7. 真实输出预览

- 平台标签页只列出当前平台的 OPEN 内容任务；前端可提前过滤明显不满足 `PUBLIC`、空任务 Prompt 等条件，但服务端继续重验事实、分类、平台、Prompt、任务状态和模型可用性。
- 全局自然化标签页先选择 OPEN 内容任务，再从该任务的真实内容版本中列出 `source_type=AI` 且状态为 `DRAFT | CHANGES_REQUESTED` 的来源；服务端继续重验完整自然化门禁。
- 模型选项只读取所选任务的 `generation-options`，不得从 AI 配置页自行拼装可用模型。
- 用户显式触发后使用现有幂等键创建作业，通过任务级 Job 列表按返回的 Job ID 轮询至终态；不得为预览请求包含完整 `input_snapshot` 的 Job detail。成功时读取其 `content_version_id` 对应的不可变内容版本，失败时展示脱敏 `error_code/error_summary`。
- 右栏只读展示真实版本的标题、摘要、Markdown 正文、标签和作业状态，并支持全屏；CloudFlow 示例问题、结论和来源文案不进入代码。
- 预览生成后若 Prompt 又被修改或保存，既有结果仍属于原作业快照，不改写也不冒充当前 Prompt 的结果；用户需显式再次生成。

### R8. 契约、测试与文档一致性

- 平台列表增加从当前 Prompt 权威行派生的可空 `prompt_updated_at`；平台 Prompt DELETE 增加必填 `expected_revision` 查询参数。同步修改 `contracts/openapi.yaml`、后端 Schema/服务、生成的前端类型和契约测试；不修改数据库模型。
- 输出预览只复用现有内容任务、生成选项、作业和内容版本端点，不增加预览 API、表或队列。
- 更新 Prompt/生成链路权威文档和相关 Trellis spec，删除与实现冲突的旧描述；不重复维护同一事实。
- 保留并扩展现有后端集成测试、前端组件测试和 E2E 真实闭环；开发确定性生成器必须与真实外部调用路径明确区分。

## 不在范围

- 新建平行 Prompt 页面、类型级 Prompt、默认 Prompt、兼容回退、双读双写或第二配置源。
- Prompt 模板变量、循环/条件、通用 Prompt 框架、Provider 工厂、自动保存或 Prompt 版本恢复系统。
- 让管理员编辑固定系统契约、安全边界、平台规则、批准事实或模型输出 Schema。
- 把 CloudFlow 示例、固定问题、固定答案、随机文本或开发适配器成功结果作为生产预览。
- 重做平台管理、平台规则、AI 渠道/模型、内容任务、审核或发布页面；只复用其现有契约和入口。
- 擅自设计原型未提供的移动端信息架构或新增运行时依赖。
