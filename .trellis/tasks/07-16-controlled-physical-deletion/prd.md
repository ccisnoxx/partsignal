# 受约束物理删除

## 目标

为开发阶段的管理员提供可诊断、可重试的物理删除能力：没有业务历史引用时直接删除当前配置或测试数据；存在引用时由服务端拒绝并列出引用类型，不自动改写归属或级联删除历史。

## 依赖与范围

- 依赖 `07-16-configuration-hierarchy-cards` 完成平台级 Prompt、可空有效规则和平台可用性契约。
- 本子任务覆盖产品、平台规则版本、具体平台、平台账号和平台类型删除，并统一前一子任务 Prompt 删除的权限与冲突展示。
- 当前事实工作区子项继续使用既有整体替换语义，不新增逐条删除 API。

## 需求

### R1 通用删除规则

- 所有物理删除仅允许 `ADMIN`；`ENGINEER` 不显示入口，直接请求也必须被服务端拒绝。
- 服务端在同一事务中锁定目标、统计直接阻断引用；无引用时才删除。
- 冲突返回 `409`、稳定错误码和 `details.references[{type,count}]`，前端以中文列出真实引用类型和数量。
- 清理全部阻断引用后，管理员重试同一删除应成功。
- 不自动级联删除、改写、转移或匿名化历史业务数据；数据库外键继续作为最终约束。
- 删除成功和冲突均遵循现有审计及敏感信息规则。

### R2 产品及当前事实工作区

- 管理员可物理删除未被历史引用的产品。
- 产品删除前检查 `FactVersion`、`ContentTask` 和 `GeoObservation` 直接引用。
- 删除产品时由既有外键级联清理该产品当前事实工作区及其当前子项。
- 存在任一历史引用时拒绝删除；不得自动删除事实版本、审核、内容、发布、文件或观测历史。

### R3 平台规则版本

- 未被 `ContentTask` 引用的平台规则版本可以物理删除，包括当前 `ACTIVE` 版本。
- 删除 `ACTIVE` 版本后只删除该版本，具体平台保留并进入“无有效规则”状态。
- 无有效规则的平台继续出现在管理员页面，管理员仍可创建和激活新版本。
- 工程师不能选择无有效规则的平台创建内容任务，直到新版本被显式激活；若 Prompt 同时缺失，仍保持不可用。
- 不自动激活草稿或历史版本，不把规则引用转移到其他版本。

### R4 具体平台、账号和类型

- 具体平台仅在规则版本、平台账号及其他直接引用全部清理后物理删除。
- 平台当前 Prompt 是平台拥有的可变配置，可随具体平台删除；历史生成作业只读快照不受影响。
- 平台账号仅在未被 `PublicationRecord` 引用时物理删除；存在发布引用时返回冲突。
- 平台类型仅在没有具体平台引用时物理删除；不得自动删除所属平台。
- 平台删除和类型删除不得改写内容任务、生成作业或发布历史。

### R5 前端交互

- 仅管理员在产品列表/详情和平台配置页面看到删除入口。
- 删除前显示对象名称、不可恢复说明和影响边界，不能使用含糊的通用确认文案。
- 冲突时显示服务端返回的引用类型和数量，并保留页面数据；成功后只失效相关查询缓存。
- 删除当前有效规则后页面立即显示“无有效规则”，工程师平台选择集合立即排除该平台。

## 验收标准

- [x] 管理员能删除没有历史引用的产品，产品和当前事实工作区从数据库消失；工程师请求返回权限错误。
- [x] 产品被事实版本、内容任务或 GEO 观测引用时返回完整引用列表；不存在只报告首个外键错误的情况。
- [x] 未被内容任务引用的平台规则版本可删除，包括 `ACTIVE` 版本；被引用版本返回明确冲突。
- [x] 删除 `ACTIVE` 规则后平台保留、显示“无有效规则”、管理员仍可配置，工程师不可选；激活新规则后按平台可用性条件恢复。
- [x] 没有规则版本和平台账号的具体平台可删除；存在任一阻断引用时返回对应类型。
- [x] 未被发布记录引用的平台账号可删除；被引用账号返回 `PublicationRecord` 冲突。
- [x] 没有具体平台的平台类型可删除；有平台时拒绝且不级联。
- [x] Prompt 删除、平台删除和作业快照之间没有历史漂移或读取失败。
- [x] 删除权限、引用矩阵、成功后缓存、冲突展示和审计均有自动化测试。

## 非目标

- 不为事实版本、内容任务、内容版本、发布记录、文件或 GEO 观测增加通用物理删除接口。
- 不提供“强制删除”“级联清空历史”“改绑到其他用户/产品/平台”或绕过外键的管理开关。
- 不把开发环境整体清空包装成长期业务功能；需要全量清理时使用受控数据库重置流程。
- 不改变当前事实表单中保存时整体替换当前工作区子项的行为。
