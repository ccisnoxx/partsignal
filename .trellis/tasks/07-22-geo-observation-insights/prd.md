# GEO 观测分析洞察页面

## Goal

在现有「GEO 观测 > 观测记录」体系内新增「分析洞察」页面，以用户提供的 1570×1001 桌面原型图为视觉基准，用真实、可筛选、可追溯的数据呈现 GEO 趋势、平台、转化、内容、问题覆盖和优化建议，并提供使用同一筛选与同一数据口径的报告导出能力。

用户已于 2026-07-22 批准本文件、`design.md` 和 `implement.md`，任务已激活并进入实施。

## Confirmed Facts

- `/observations` 已有真实服务端筛选、分页、指标、详情、新建和追加式更正；分析洞察必须复用它的布局、URL 状态、错误语义、状态样式和共享筛选边界。
- 当前公共布局只有 GEO 分组下的“观测记录”，没有分析洞察路由、顶部全局搜索、通知、洞察导出或图表组件。
- 当前 `/api/v1/geo-metrics` 只返回一个筛选周期的汇总，没有比较周期、时间序列、平台分组、漏斗、排行、覆盖或建议。
- 只读旧模型观测拥有问题主题、模型、提及、推荐、引用和准确性；当前可写人工观测拥有自由文本 GEO 平台、自由文本问题、全部当前公开内容的逐篇推荐/未推荐、截图和备注。这两类记录不是同一分析契约。
- 人工逐篇结果没有发现、提及、引用或准确性事实；人工观测也没有问题主题关联，无法按现有数据真实完成内容级漏斗、长期未提及和问题全集覆盖。
- 内容发布平台可由发布记录稳定关联 `platform_profile_id`；“内容主题”已确认精确映射真实字段 `ContentTask.content_angle`。
- 项目未安装图表或报表导出库，但已有 Ant Design、dayjs、图表色 token、响应式工作台、数据表、空/错状态和平台头像组件。
- PostgreSQL 是业务状态唯一来源；分析指标必须由一个服务端实现计算，前端不得复制公式。
- 工作树已有用户未提交的 GEO 观测记录改动。本任务不得覆盖、清理或混入无关修改。

## Approved Decisions

- **D1（2026-07-22）**：以当前人工观测作为未来唯一洞察数据集。新登记和更正必须关联真实 `query_topic_id`，并为每篇发布内容保存发现、提及、引用和准确性事实；现有 `recommendation_status` 继续作为逐篇推荐事实。
- 只读旧模型观测和补采前人工记录继续保留历史可读性，但不混入新洞察分母。无法补采的历史字段保持 `NULL`，页面和响应展示数据完整性及排除数量，不做推断回填。
- **D2a（2026-07-22）**：指标、内容排行和 GEO 转化漏斗统一以“当前链尾人工观测 × 当次公开发布内容”关系为基础单位。阶段严格累计：完成发布 → 被检索发现 → 获得提及 → 获得推荐 → 展示引用 → 结果准确（`ACCURATE`）；后续阶段必须满足全部前序条件。
- **D2b（2026-07-22）**：“未推荐内容数量”是当前筛选周期内至少存在一次完整观测、但从未达到 `RECOMMENDED` 阶段的去重 `publication_record_id` 数量；同一内容只要有一次获得推荐，就不计入未推荐内容。
- **D2c（2026-07-22）**：“表现最佳内容 Top 5”只接纳当前筛选周期至少 3 次完整观测的内容，依次按引用率、推荐率、提及率、观测次数降序，再按 `publication_record_id` 升序稳定排序；不使用加权综合分。
- **D2d（2026-07-22）**：“表现下降内容 Top 5”比较当前筛选周期与紧邻的前一个等长周期，两个周期都至少需要 3 次完整观测。引用率、推荐率、提及率任一项下降至少 10 个百分点即进入候选；依次按最大单项下降、引用率下降、推荐率下降、提及率下降、当前观测次数降序，再按 `publication_record_id` 升序取前 5。响应返回触发指标及前后值，不使用加权综合分，其他指标改善不抵消已达阈值的单项下降。
- **D2e（2026-07-22）**：“长期未获得提及的内容 Top 5”要求当前筛选周期至少覆盖 30 个自然日、内容截至 `date_to` 已发布至少 30 天、当前周期至少 3 次完整观测且提及次数为 0。未提及持续天数从最近一次历史提及时间计算，从未提及时从 `published_at` 计算；依次按持续天数、当前周期观测次数降序，再按 `publication_record_id` 升序取前 5。短于 30 天的筛选周期明确返回不可用，不静默扩大；更早历史只用于确定最近提及时间。
- **D2f（2026-07-22）**：搜索问题覆盖按 `query_topic_id + GEO 平台` 统计；一次完整人工观测中任一发布内容达到“获得提及”，该观测记为命中，覆盖率分母是完整观测数而非内容关系数。至少 3 次完整观测后，`≥60%` 为稳定覆盖、`≥30% 且 <60%` 为偶尔命中、`<30%` 为尚未覆盖；0–2 次为独立“数据不足”状态，不补零或强行归类。
- **D2g（2026-07-22）**：优化建议使用最小确定性规则集。高优先级包括长期未提及内容、内容或 GEO 平台最大单项下降 `≥20` 个百分点；中优先级包括下降 `≥10 且 <20` 个百分点、至少 3 次完整观测但从未推荐的内容、至少 3 次观测且覆盖率 `<30%` 的问题/平台组合；低优先级包括覆盖率 `≥30% 且 <60%` 的组合及 0–2 次观测的数据不足组合。相同对象的同因低优先级建议由更高优先级建议抑制；固定按优先级、影响关系数、`rule_code`、关联 ID 排序，返回触发值、阈值和关联对象，不调用 AI 或增加可配置规则引擎。
- **D3（2026-07-22）**：导出采用 `/observations/insights/print` 打印专用路由，携带当前全部筛选并复用同一 `GET /api/v1/geo-insights` 响应；报告包含筛选摘要、生成时间、数据完整性及全部主要分析区块，通过浏览器原生打印/另存为 PDF，不新增服务端 PDF/XLSX 接口、依赖或第二套模板。
- **D4（2026-07-22）**：本任务不实现顶部全局搜索。顶部继续复用现有主题切换和账户操作区，真实问题/发布内容搜索由分析筛选器完成；不放置无结果链路的装饰搜索框。跨内容、任务、平台和数据的全局搜索另立任务定义索引、权限、排序和跳转，本页验收接受该项相对原型的明确差异。
- **D5（2026-07-22）**：分析筛选器中的“内容主题”精确映射为关联发布内容所属 `ContentTask.content_angle`。选项只从具有真实发布记录的内容任务读取 distinct 原值；不按分词、别名、大小写或相似度归并，不新增独立主题表、管理页面或第二主题字段。

详细证据见 `research/current-state.md`。

## Requirements

### R1. 页面入口、布局与视觉

- 在 GEO 分组内增加 `/observations/insights`，与 `/observations` 分别对应“分析洞察”和“观测记录”；两页共享真实路由页签和当前紧凑工作台壳，不建立平行 GEO 模块。
- 页面包含原型中的筛选器、5 张趋势卡、平台表现、转化链路、三类内容 Top 5、搜索问题覆盖分析、优先优化建议和“导出洞察报告”操作。
- 以 1570×1001 为主要截图验收视口，重点对齐导航宽度、内容起点、区块比例、卡片高度、信息密度、间距、字号、颜色、边框、圆角、阴影、图表、状态色和悬浮反馈。
- 1440×900 和 1024×768 等较窄桌面视口不得发生整页横向溢出、内容遮挡或关键操作不可达；必要时只让表格/矩阵区域局部滚动。
- 复用现有主题 token 和 Ant Design，不引入第二套设计系统或功能重复依赖。GEO 平台没有可信 Logo 时使用文字或中性标识，不伪造第三方资产。
- 顶部用户操作区复用现有主题和账户菜单。本任务不实现顶部全局搜索，不增加无真实结果链路的空入口；验收时将其作为相对原型的已批准差异。

### R2. 分析筛选

- 支持时间范围、内容平台、GEO 观测平台、内容主题、发布内容和搜索问题；提供重置和折叠。
- 默认时间范围沿用观测记录的近 30 个 UTC 自然日，首尾均包含；筛选和展开状态写入 URL，刷新、前进/后退和复制链接后可恢复。
- 时间、平台、主题、内容和问题必须使用服务端认可的精确值或 ID。自由文本 GEO 平台只允许精确匹配，不做别名猜测、大小写合并或候选字段轮询。
- “内容主题”使用 D5 的 `ContentTask.content_angle` 精确原值，只有关联真实发布记录的任务值进入选项。
- 任一筛选变化必须让全部卡片、图表、排行、问题覆盖、建议和导出使用同一查询键与同一服务端范围；不存在只改变前端显示的筛选。
- 无效 UUID、日期、范围和枚举由服务端返回明确 422/404；前端只做输入约束和错误呈现，不静默换成另一条件。

### R3. 数据权威与完整性

- 由 `backend/app/services/geo_observation.py` 中一个权威洞察聚合实现拥有人工洞察的指标公式、时间分桶、比较窗口、分组、排行和建议规则；现有 `/geo-metrics` 的旧模型字段必须显式标为 `legacy_*`，同名指标不得同时指向旧模型观测和人工逐篇关系。两者只复用已证实相同的筛选/SQL 边界。
- 任何没有分母的比率返回 `null`，页面显示“暂无数据”；不得用 `0` 表示没有样本。
- 纠正链默认只统计当前链尾，不能重复计算已被更正的旧记录。历史记录仍可在观测记录详情中查询，但不作为洞察的隐式后备数据。
- 历史人工记录不得回填发现、提及、引用、准确性或问题主题等未知事实；响应必须返回数据完整性说明和被排除数量。
- 不使用静态、随机、固定成功、模糊兼容或客户端派生数据填充原型；缺数据展示分区空状态，数据契约不完整展示可诊断原因。

### R4. GEO 指标趋势

- 展示提及率、推荐率、引用率、结果准确率和未推荐内容数量。
- 每张卡展示当前值、上一相邻等长周期值、环比变化、选定周期内的真实时间序列和可键盘/鼠标触达的日期 Tooltip。
- 比率点必须携带真实分子、分母和值；分母为 0 时值为 `null`，折线断开且 Tooltip 说明无样本。
- “未推荐内容数量”按 D2b 的去重发布口径计算，不能沿用当前结果次数掩盖单位差异。

### R5. 平台、转化和内容分析

- 平台表现按同一权威 GEO 平台维度展示观测次数及提及、推荐、引用、准确率；每个比率必须使用与趋势卡一致的分析单位和空分母规则。
- 转化链展示完成发布、被检索发现、获得提及、获得推荐、展示引用和结果准确，并给出数量与相邻阶段转化率；各阶段必须使用同一分析单位和经批准的包含关系。
- 内容表现展示表现最佳、表现下降和长期未提及各 Top 5，严格使用 D2c–D2e 的排序、比较窗口、长期天数和最小样本，并在 Tooltip/表头中可见。
- 内容行使用稳定 `publication_record_id`，展示真实标题、内容平台和已批准指标；点击进入现有发布详情或按已批准交互打开详情，不复制发布详情实现。

### R6. 搜索问题覆盖

- 以已配置 `QueryTopic` 作为可覆盖问题全集，并按 GEO 平台展示稳定覆盖、偶尔命中、尚未覆盖的数量或矩阵。
- 当前人工观测如需参与，必须有明确 `query_topic_id`；不得按自由文本相似度把实际搜索词猜到一个问题主题。
- 覆盖率、三个覆盖状态和数据不足门槛使用 D2f 的固定口径；状态必须同时用文字/图例和颜色表达。

### R7. 优先优化建议

- 建议由服务端确定性规则生成，包含规则代码、建议文本、量化依据、关联内容/平台/问题、高/中/低优先级和详情入口。
- 不调用 AI 生成建议，不保存静态文案充数，不为同一事实创建第二份可编辑建议状态。
- “查看全部建议”展示当前筛选响应中的完整建议列表；首页区域只截取经稳定排序的前几项。
- 规则阈值、优先级、抑制和排序使用 D2g 的固定口径。必要事实缺失时不生成该条建议，并在数据完整性区说明原因。

### R8. 报告导出

- “导出洞察报告”必须使用当前 URL 中的真实筛选，并消费与页面相同的服务端洞察响应；不得重新计算或漏掉过滤条件。
- 导出固定使用浏览器原生打印版并支持用户另存为 PDF，不新增服务端 PDF/XLSX 接口、导出依赖或第二套渲染模板。
- 报告必须包含筛选摘要、生成时间、数据完整性说明及页面各主要区块；无数据或部分不可用时保留明确说明，不能伪造完整报告。

### R9. 权限、错误和可访问性

- 洞察读取沿用 `CurrentUser`。若登记契约补充字段，新建和更正继续由 `EngineerUser + CSRF` 在服务端强制；前端隐藏控件不构成权限控制。
- 页面级、筛选选项、洞察请求和导出分别提供加载、错误、重试或关闭行为；4xx/5xx 不能转换为空数组或默认成功。
- 筛选、折叠、图表 Tooltip、页签、排行/建议入口和导出可用键盘操作并有可识别名称；颜色不是唯一信息来源。

### R10. 契约、文档与验证

- 经批准的数据/API/数据库变更同步更新 `contracts/openapi.yaml`、`contracts/database.md`、后端 Schema/服务、生成前端类型、页面、测试和 `docs/GEO多平台内容运营系统方案设计.md`。
- 为聚合、时间窗口、空分母、筛选一致性、纠正链、数据完整性、排行和确定性建议增加最小有效后端测试；为 URL、空/错状态、Tooltip、入口和导出增加前端测试。
- 使用真实 PostgreSQL/FastAPI 路径验证服务端；前端单测可 mock 契约响应，但 Playwright 不得拦截业务 API 为固定成功。
- 使用项目 `playwright-cli` 验证页面加载、筛选/重置/折叠、趋势 Tooltip、排行与建议入口、导出、控制台错误和失败请求；生成 1570×1001 验收截图并逐区比较。
- 最终检查完整 diff，排除重复公式、猜测兼容、静默回退、无关修改、新重复依赖和未说明行为变化。

## Out of Scope

- 自动调用外部搜索或模型重新生成观测；本页面只分析已保存的真实观测。
- AI 生成建议、Redis 业务缓存、通用 BI 平台、可配置公式引擎或图表框架。
- 对 GEO 之外页面进行全局视觉重构，或在没有真实 API 的情况下补通知、帮助、全局搜索等装饰入口。
- 猜测修复历史数据、按文本相似度归并问题/平台、从截图 OCR 推导业务事实。
- 未经用户批准直接新增平台注册管理、服务端 PDF/XLSX 依赖或数据库回填。

## Acceptance Criteria

- [ ] AC1：`/observations` 与 `/observations/insights` 在同一 GEO 二级导航内真实切换，1570×1001 下主要区域比例和信息密度与原型一致，1024/1440 桌面无关键遮挡。
- [ ] AC2：六类筛选、重置和折叠写入 URL；一次筛选变化真实影响全部洞察区块和导出，请求参数与服务端筛选一致。
- [ ] AC3：五张趋势卡显示当前周期、相邻等长周期、环比和真实序列；空分母为 `null/暂无数据`，Tooltip 可读且不显示伪造点。
- [ ] AC4：平台表现的观测次数和四率使用同一分析数据集、同一平台维度和明确分母；未知平台不被别名合并。
- [ ] AC5：转化六阶段使用同一计数单位并满足已批准的包含关系；数量和相邻转化率可由数据库事实复算。
- [ ] AC6：三类 Top 5 的排序、窗口、最小样本和长期阈值均有服务端测试；每行能追溯到真实发布记录。
- [ ] AC7：问题覆盖只使用配置问题及明确关联的观测；三种状态阈值有测试，未关联自由文本不被猜测归类。
- [ ] AC8：优化建议由稳定服务端规则生成，包含依据、关联对象和优先级；缺少事实时不生成并显示原因。
- [ ] AC9：导出使用当前真实筛选和同一洞察响应，包含筛选、时间、完整性说明和所有主要区块；导出失败明确可诊断。
- [ ] AC10：加载、空、部分不可用、4xx/5xx、导出失败和无权限均不被静默回退；关键交互具备键盘和可访问名称。
- [ ] AC11：契约、数据库文档、生成类型、实现和测试一致；`make contract-check`、相关后端/前端测试、lint、typecheck 和前端构建通过。
- [ ] AC12：真实 Playwright 完成指定交互、控制台/失败请求检查和 1570×1001 截图对比；最终 diff 无重复数据源、兼容猜测、无关改动或新重复依赖。
