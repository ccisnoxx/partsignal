# GEO 观测记录页面

## 目标与用户价值

在现有 `/observations` 路由上实现可投入使用的“GEO 观测 > 观测记录”页面。用户可以用真实服务端数据查看统计、组合筛选、排序和分页记录，创建或纠正人工观测，并在右侧详情面板核对完整问题、类型对应的结论、关联发布内容、证据截图、备注和记录信息。桌面视觉以用户提供的 1582×995 原型图为目标，同时保持项目既有主题、权限、追加式历史和契约优先约束。

## 当前实现与可复用能力

- `frontend/src/app/App.tsx` 已注册 `/observations`；`frontend/src/app/AppLayout.tsx` 已提供响应式侧栏、顶栏、鉴权用户信息和主题切换。
- `frontend/src/features/geo-observations/GeoObservationsPage.tsx` 已使用真实接口展示 4 个指标卡、全量记录后的前端分页、展开行详情和新建人工观测弹窗。
- 现有新建流程已经串联产品选择、当前公开文章候选、逐篇推荐结论、`DirectUpload` 上传 `OPERATION_SCREENSHOT` 和 `POST /api/v1/geo-observations`，无需重写业务流程。
- 可直接复用 `PageHeader`、`MetricTile`、`StatusTag`、`TableRegion`、`DirectUpload`、Ant Design `Drawer`/`Table`/`Form`/`Pagination`、React Query 和 OpenAPI 生成类型。列设置可沿用 `AIChannelsPage.tsx`，详情抽屉可沿用 `PublicationDrawer.tsx` 的交互和主题模式。
- 后端 `backend/app/services/geo_observation.py` 已校验产品、当前全部可观测发布候选、逐篇结果唯一且完整、证据文件类别、同产品且尚未被纠正的人工观测，并以新增记录和 `supersedes_id` 保存纠正历史。
- `GET /api/v1/geo-metrics` 已默认排除被纠正记录，并提供历史模型指标和人工观测/逐篇结果指标；现有文件读取与短期下载地址接口足以按需预览截图。
- 现有 OpenAPI 联合类型明确区分 `LEGACY_MODEL_RESULT` 与 `MANUAL_ARTICLE_SEARCH`；PostgreSQL 是唯一业务状态来源，Redis 只作为 Celery Broker。
- 基线验证已通过：`make contract-check`；`npm --prefix frontend run test -- GeoObservationsPage`（1 个测试通过，jsdom 的 3 条伪元素 `getComputedStyle` 能力提示不影响退出码）。

## 与原型和目标能力的缺口

- 左侧 GEO 入口仍是单层菜单；页面缺少原型中的紧凑桌面层级、标题说明和“观测记录”当前页标识。
- 指标、列表和筛选没有共享查询语义；列表会全量加载后在前端每 10 条切页，后端按行补关系数据，存在 N+1 查询，也没有稳定 ID 次排序。
- 缺少日期、类型、产品、问题/搜索词、来源、内容主题、关联发布内容、类型专属结论、记录人和“仅看我的记录”等组合筛选，以及重置、清除筛选和当前/历史切换。
- 缺少服务端分页、可选每页条数、观测时间升降序、列设置、明确空状态和 URL 可恢复的视图状态。
- 行展开不能满足原型的右侧详情面板、深链和截图预览；当前记录只包含记录人 UUID，不能直接显示记录人名称，也没有服务端操作能力投影。
- 新建入口已存在，但列表行没有“查看详情”和“发起纠正”操作；现有 E2E 通过 `page.request` 写入 GEO 观测，未验证真实 UI 交互。
- 当前 4 张指标卡和通用页面密度与原型的 5 卡、两行筛选、密集表格及右侧面板差异明显。

## 产品决策

- 人工观测继续只保存搜索词、逐篇观测结果、证据截图和人工备注，不保存模型回答摘要；不新增数据库列或迁移。
- 历史模型观测展示真实 `answer_summary`；人工观测明确说明该类型不保存模型回答摘要，并以逐篇结果和截图承载结论与证据。
- “分析洞察”是 GEO 观测下与“观测记录”同级的独立页面。本任务不实现、不展示其入口，也不创建空路由或占位内容。
- “导出记录”不纳入本任务；页面移除该按钮，不新增导出接口。
- 观测详情保持只读。原型截图区的新增入口不实现，因为已批准观测不得原地补附件；需要修正时创建新的人工观测并通过 `supersedes_id` 关联历史。

## 功能需求

### R1. 导航、页头与视觉结构

- 左侧导航把 GEO 观测呈现为可展开分组，本任务只包含并选中“观测记录”子项；桌面折叠和移动端抽屉行为沿用现有 `AppLayout`。
- 页面展示“GEO 观测”标题、真实业务说明、单一“观测记录”当前页标识和“新建观测”主操作；不展示分析洞察和导出入口。
- 在 1582×995 视口下形成紧凑的左侧导航、5 张统计卡、两行筛选、密集表格和右侧详情抽屉；颜色、字号、间距、边框、阴影和状态色使用现有主题 token，不硬编码第二套设计系统。

### R2. 统计卡片

- 展示 5 项真实指标：观测总数、历史模型样本数、模型提及率、人工观测数、文章推荐率。观测总数由 `sample_count + manual_observation_count` 计算，其他值直接使用现有 `GeoMetrics` 字段。
- 指标与列表使用相同的日期、产品、类型、来源、问题/搜索词、内容主题、关联内容、结论、记录人、仅看本人和历史范围筛选；空样本比率按契约展示“暂无数据”，不得补零伪装成 0%。

### R3. 筛选与 URL 状态

- 支持：日期范围、观测类型、产品、问题/搜索词、搜索平台、模型、内容主题、关联发布内容、历史模型的提及/推荐/引用/准确性、人工逐篇推荐结论、记录人搜索、“仅看我的记录”和“包含纠正历史”。
- 类型专属筛选有明确适用范围：选择历史模型条件时人工记录不匹配；选择人工逐篇条件时历史模型记录不匹配，不把两种结论强行映射为同一字段。
- 默认状态为近 30 天、仅当前纠正链尾记录、观测时间降序、每页 20 条。`date_from`/`date_to` 按现有契约使用包含首尾的 UTC 自然日语义，前端不自行换算成另一套日期边界。
- “重置”恢复上述默认状态；“清除筛选”移除日期和业务筛选、关闭“仅看我的记录”，但仍保持只看当前链尾、默认排序和每页条数。
- 筛选、页码、每页条数、排序、是否包含历史和选中详情记录写入 URL 查询参数；任何会改变结果集的筛选变化都回到第 1 页。非法页码或枚举值由前端规范化或服务端显式返回 422，不静默猜测兼容值。

### R4. 记录表格

- 后端返回 `items`、`page`、`page_size`、`total`，默认按 `tested_at DESC, id ASC` 稳定排序，并支持观测时间升序。
- 默认列覆盖：观测来源、完整问题的单行摘要、观测时间、提及、推荐、引用、准确性、关联发布内容、证据状态、记录人和操作；不适用于当前观测类型的单元格显示“—”。
- 问题摘要只负责表格压缩，完整文本必须在详情中可见。状态使用现有 `StatusTag` 语义色，不以纯颜色作为唯一信息。
- 列设置沿用现有本地 UI 状态模式，允许切换可选列，保留来源、问题、时间和操作等必要列；本任务不新增服务器端列偏好或本地持久化结构。
- 分页支持 20、50、100 条/页、总数和页码跳转；窄屏通过 `TableRegion` 局部横向滚动，不能造成整页横向溢出。

### R5. 右侧观测详情

- 点击行、眼睛按钮或带 `record` 的 URL 时打开 Ant Design 右侧 `Drawer`；关闭时只移除详情参数并保留筛选、分页和排序。
- 详情通过独立 `GET /api/v1/geo-observations/{observation_id}` 获取，不能依赖记录仍位于当前页；不存在的记录显式返回 404 并提供可恢复的错误状态。
- 公共区域展示观测类型、产品、来源/模型、完整问题、观测时间、记录人、创建时间、是否当前记录、上一条纠正记录和人工备注。
- 历史模型观测展示真实回答摘要、提及、推荐、引用和准确性；人工观测展示“不保存模型回答摘要”的说明和全部逐篇推荐结论。
- 关联发布内容展示已有标题、平台、最终 URL 和版本/标识信息；不得把普通 URL 猜测成已关联发布记录。
- 证据截图在打开详情后使用现有文件元数据和短期下载地址按需加载；图片可预览，非图片附件显示文件名与下载入口。下载失败显示明确错误，不用占位成功图掩盖。

### R6. 新建、纠正和权限

- 保留并重排现有“新建观测”真实表单，继续要求产品、搜索平台、搜索词、测试时间、当前全部公开文章的逐篇结论、至少一张已验证操作截图和备注。
- 行操作只包含“查看详情”和服务端允许时的“发起纠正”。纠正使用现有 `POST /api/v1/geo-observations` 与 `supersedes_id`，不更新旧记录。
- 纠正固定原记录的产品、搜索平台和搜索词，重新读取当前发布候选并要求用户重新完成全部逐篇结论、测试时间、截图和备注；不得沿用已变化候选集制造不完整记录。
- 列表和详情仍允许所有已认证用户读取；新建和纠正仍由服务端 `EngineerUser` 与 CSRF 校验最终授权。响应中的 `available_actions` 只用于呈现，不替代写接口的 403/409 校验。

### R7. 错误、加载、空状态与可访问性

- 列表、指标、详情、附件和提交分别具有加载、错误、重试或关闭行为；不得用空数组、静态数据或默认成功吞掉请求错误。
- 表单校验错误就地展示，服务端 404/409/422/403 使用现有错误解析呈现真实原因；提交中防止重复操作。
- 筛选控件、列设置、分页、行操作、详情关闭和截图链接可用键盘操作并有可识别名称；焦点在打开/关闭抽屉后按组件原生行为恢复。
- 适配 light、dark、system 主题，以及 375、768、1024、1440 和原型 1582×995 视口；200% 缩放下核心功能仍可访问。

### R8. 契约、文档和测试

- 更新 `contracts/openapi.yaml` 及生成的 `frontend/src/shared/api/schema.d.ts`，只增加本页面实际使用的分页、筛选、详情和投影字段；不维护手写前端 DTO。
- 更新 `contracts/database.md` 中纠正链尾查询和历史语义，并同步更新相关系统设计/测试文档；确认没有数据库结构变化时明确记录“无需迁移”。
- 后端测试覆盖筛选组合、分页边界、稳定排序、当前/历史链、详情 404、投影和权限；前端测试覆盖 URL 状态、重置/清除、列设置、详情分型、错误状态和操作可见性。
- Playwright 使用真实本地栈完成新建、筛选、排序、分页、详情、截图预览和纠正流程；不得拦截为固定成功响应。测试数据准备可以调用真实 API，但被验收的业务动作必须通过页面完成。

## 前端、后端、契约与数据层影响

- 前端：`AppLayout` 的 GEO 子菜单、`GeoObservationsPage` 页面拆分或局部组件、查询键/查询选项、主题样式、单元测试和 Playwright 流程。
- 后端：`observation` 路由与现有 GEO 服务增加共享筛选、分页、批量投影、详情读取和服务端 `available_actions`；移除当前列表逐行关系查询。
- 契约：GEO 列表分页查询参数和响应元数据、详情路径、记录人的 `ActorSummary`、产品显示文本、当前记录标识和操作集合；指标接口增加与列表一致的筛选参数。
- 数据层：复用现有观测、纠正、发布关联、附件、产品和用户表；当前没有证据需要新表、新列、新索引或 Alembic 迁移。实施中只有在真实查询计划证明现有索引不足时才另行报告，不在本任务中猜测添加索引。

## 不在范围内

- 分析洞察页面或入口、记录导出、GEO 趋势图或新的统计口径。
- 人工观测回答摘要、模型调用、网页搜索结果正文抓取或未知产品事实推断。
- 原地编辑已保存观测、在详情中追加截图、删除观测或改写纠正历史。
- 数据库迁移、Redis 业务缓存、新依赖、服务器端列偏好或通用筛选框架。
- 对其他业务页面的全局视觉重构。

## 验收标准

- [ ] AC1：`/observations` 在桌面展示 GEO 分组下唯一“观测记录”入口、页头、5 个真实指标、筛选区、表格和新建入口；不存在“分析洞察”或“导出记录”。
- [ ] AC2：默认近 30 天且仅显示纠正链尾；列表和指标对所有支持的筛选使用相同语义，“仅看我的记录”按当前会话用户生效。
- [ ] AC3：“重置”和“清除筛选”符合 R3 定义；筛选、页码、每页条数、排序、历史开关和详情选择可由 URL 刷新恢复。
- [ ] AC4：服务端分页总数正确，20/50/100 切换和跳页可用；同时间记录按 ID 稳定，观测时间升降序可切换，筛选变化回到第 1 页。
- [ ] AC5：列设置真实控制表格列；表格在桌面保持原型密度，在小视口只让表格区域横向滚动。
- [ ] AC6：详情深链可直接加载记录；历史模型与人工观测按各自契约展示，人工观测不出现伪造摘要；关联发布、截图、备注和记录信息完整可读。
- [ ] AC7：新建和纠正通过真实 UI 提交；旧记录不被修改，纠正创建新记录并成为默认链尾；无权限、过期纠正目标、不完整候选和无效截图由服务端拒绝。
- [ ] AC8：加载、空、404、附件失败和提交错误不会被静默回退；主要控件具备键盘可达性和可识别名称。
- [ ] AC9：在 1582×995 视口分别截取列表态与详情态，与原型并排核对导航宽度、卡片比例、筛选密度、表格行高、抽屉宽度、间距、边框、阴影、字体层级和状态标签；同时检查 375/768/1024/1440、200% 缩放和三种主题。
- [ ] AC10：OpenAPI、运行时 Schema、生成前端类型、数据库文档、系统设计、测试与实现一致；无手写兼容字段、固定 mock 成功路径、无关修改或新依赖。
