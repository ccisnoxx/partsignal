# 统一全站表格列表展示

## 目标

统一全站业务表格的信息架构、视觉层级和现有列表控件的展示方式，并继续治理列宽、行高、长文本截断、完整值提示和响应式问题，使用户能快速识别每行主体、状态、关键指标与可用操作。任务以现有 24 张业务表为范围，不改变服务端搜索、筛选、排序、分页或响应合同。

## 背景与确认事实

- 已归档任务 `07-30-management-list-hard-delete-ux` 清点了登录后的 24 张业务表，并修复过长文本越界、异常行高、固定操作列遮挡、页面级横向滚动和真实 200% 浏览器缩放问题。该清单继续作为本任务基线。
- 当前稳定展示边界已经存在：
  - Ant Design `Table` 持有业务表和内部横向滚动；
  - `TableRegion` 持有语义焦点与外层宽度边界；
  - `TableCellText` 已支持单行省略，并在鼠标悬停或键盘聚焦时显示完整值；
  - `workspace.css` 持有共享表格视觉规则。
- 用户确认“展示问题”包含：
  - 列的信息架构和主次层级；
  - 现有搜索、筛选、排序、结果数量、分页与批量操作的视觉组织；
  - 列宽、行高、截断、完整值提示和响应式；
  - 不改变服务端能力。
- 普通长文本不应凭内容长度撑宽列。超出可用宽度时显示省略号，鼠标悬停和键盘聚焦可读取完整值；列宽应由业务重要性决定，而不是由最长数据决定。
- 用户进一步明确：上述长文本合同必须覆盖现有 24 张业务表中的全部可变长文本列，不能只修复已经复现溢出的页面。状态、数值、时间、布尔值和操作等固定短值不机械增加 Tooltip。

## 已确认缺陷：GEO 观测平台与问题列重叠

### 现象

GEO 观测记录表中，超长“观测平台”名称会与相邻“搜索词 / 问题”列重合，破坏可读性。这是本任务必须首先修复并补回归的明确 bug。

### 根因

- `frontend/src/features/geo-observations/GeoObservationsPage.tsx:235` 的“观测平台”列声明宽度为 180px，但内容由 Ant `Space` 包裹图标和 `TableCellText`；该复合容器没有 `min-width: 0` 和明确的可收缩文本槽。
- `TableCellText` 自身具备 `overflow: hidden` 与 `text-overflow: ellipsis`，但它只能约束自身，不能替代父级 flex/Space 容器的收缩边界。Ant Table 自动布局中的 `width` 也不是内容硬上限。
- 因此短值能够正常显示，长平台名却可能扩大复合单元格的最小内容宽度，并推入相邻列。

### 上一轮测试为何漏检

- `frontend/tests/e2e/cross-page-visual-convergence.spec.ts:149` 只检查 `TableRegion` 没有超出视口、`.table-cell-ellipsis` 的计算样式为 `overflow:hidden/nowrap`，以及固定列背景不透明；没有检查单元格内容是否被自己的 `td` 包含，也没有检查相邻列内容是否相交。
- 24 表循环在 `frontend/tests/e2e/cross-page-visual-convergence.spec.ts:504` 只调用上述通用边界断言。归档计划中提出的 GEO 相邻列几何断言没有落实到当前测试，属于测试与验收承诺漂移。
- GEO 页面专项 E2E 在 `frontend/tests/e2e/dashboard-geo-convergence.spec.ts:69` 只验证页面无横向溢出、表格存在及指标区域；保存的截图不是像素基线断言。
- 前端测试固定值是 `DeepSeek`，纵向 E2E 创建值是 `DeepSeek E2E`，均远短于后端允许的 160 字符平台/模型名称，没有覆盖真实边界数据。

结论：上一轮测试验证了“页面外框没有溢出”和“省略 CSS 存在”，却没有验证“内容真的被列宽约束”。这是测试设计缺口，不是本次数据异常。

### 部署后复现：Tooltip 存在但不可读

- 公网页面已加载包含整格 Tooltip 修复的最新构建，完整平台名也真实存在于 `role="tooltip"`，因此不是发布遗漏或缓存旧资源。
- 实际截图显示浮层为空白白框；浏览器计算样式证明 Tooltip 前景和背景均为白色，对比度只有 1:1。
- 根因是 `AntThemeProvider.tsx` 把 `colorBgSpotlight` 覆盖为浅色 `bgRaised`，却没有同步覆盖配套 `colorTextLightSolid`，使 Ant Design 的默认白字落在项目白色浮层上。
- 上一轮 E2E 只验证 Tooltip DOM 可见且包含完整文本，没有验证最终计算样式或文字对比度，因而把“存在但不可读”误判为通过。

### 内容任务删除术语缺陷

- 内容任务列表、详情、确认弹窗和只读说明把服务端的物理删除实现直接写成用户操作“物理删除”，错误暴露了存储实现细节。
- 用户操作统一显示“删除任务”，确认按钮显示“确认删除”；不可恢复及关联清理范围继续由确认正文说明。
- 该修正不改变 `DELETE` 接口、`available_actions`、删除资格、级联范围或审计合同。

## 范围内需求

### R1. 24 表逐表展示审计

- 复用 `.trellis/tasks/archive/2026-07/07-30-management-list-hard-delete-ux/research/sitewide-table-audit.md` 的 24 表清单；实施前只核对新增或删除项。
- 每张表明确：
  - 用户识别一行时首先阅读的主身份；
  - 辅助识别信息；
  - 状态、时间、数值和操作；
  - 必须保留、可以收紧、可以放入详情或列设置的字段；
  - 普通表、紧凑表、从属表、动态矩阵或弹窗表等业务例外。
- 每张表还必须逐项登记可变长文本列，确认其使用 `TableCellText`，或在保留链接、按钮等交互语义时使用同一 `.table-cell-ellipsis` 收缩标记与 hover/focus Tooltip。
- 不以共享 CSS 代替逐表判断，也不为了整齐隐藏完成任务所必需的信息。

### R2. 列的信息架构和宽度

- 普通管理列表最多有一个主要弹性文本列；其余身份、状态、时间、数值和操作列使用与业务内容相符的有界宽度。
- 列顺序遵循“主身份 → 关键上下文 → 状态/指标 → 时间 → 操作”，但详情从属表和分析表可以按阅读任务采用明确例外。
- `width` 表达展示意图，复合单元格还必须提供可收缩容器；不能假设 Ant Table 的列宽会自动压住任意子元素。
- 数值按适用情况右对齐，状态和短枚举保持紧凑，时间保持稳定格式，ID/slug/账号等机器值使用等宽样式并截断。

### R3. 全站长文本、行高与完整值

- 24 张业务表中的每一个可变长文本列都必须进入统一展示合同，不以“当前测试数据较短”或“尚未收到缺陷报告”作为跳过依据。
- 普通长文本使用单行省略；“名称 + 次要标识”最多两行，且每行独立省略。任意长值不得决定整列宽度或行高。
- 继续复用 `TableCellText` 提供完整值，不新建平行 Tooltip 组件。交互标题或链接不能直接换成普通文本，应在保留点击目标的同时提供完整值提示。
- 完整值必须同时支持鼠标悬停和键盘聚焦；触屏用户仍可通过进入详情查看完整内容。
- 所有受合同保护的文本节点统一带 `.table-cell-ellipsis`，使跨页压力测试同时覆盖普通文本和交互文本；不得维护仅有局部 CSS、却游离于全站回归之外的省略实现。
- 普通、紧凑和固定两行单元格分别保持明确的行高档位；错误摘要等内容不得无限换行撑高一行。

### R4. 现有列表控件的视觉组织

- 统一表格标题、结果数量、主搜索、现有筛选、现有排序、列设置、清除条件、批量操作和分页的主次、位置、间距、标签和反馈。
- 搜索与高频筛选优先，低频筛选可以放入已有展开区域；排序、列设置等次级动作不能抢占主操作层级。
- 结果数量属于列表反馈，不与页面级业务指标重复竞争视觉焦点。
- 内容任务的删除能力使用面向任务的用户文案，不把“物理删除”等存储术语作为菜单项、按钮或弹窗标题。
- 待发布候选不提供破坏已批准历史的“删除”；行内提供“取消待发布”，执行前读取内容任务当前 `available_actions` 与 revision，再复用既有取消接口使其退出候选列表。
- 发布记录只有服务端返回 `delete` 时才显示“删除记录”；不可删除且没有其他次级动作时不渲染空的更多菜单，也不展示禁用的“物理删除”。
- 本任务只重新组织已有控件，不给缺失能力的页面新增搜索、筛选、排序、分页或导出。

### R5. 加载、空、失败和权限状态

- 加载、首次无数据、筛选无结果、请求失败、权限不足和批量选择状态必须能够区分。
- 继续复用现有 `QueryLoading`、`NoData`、`QueryFailure`、清除条件和重试入口；不建立第二套异步状态组件。
- 不以隐藏按钮代替权限解释，也不改变服务端 `available_actions` 或业务权限。

### R6. 响应式、主题与可访问性

- 页面根节点不得产生横向滚动；宽表只在 Ant Table 内部滚动，`TableRegion` 保持可聚焦。
- 在 `1440×1000`、`375×900`、浅色、深色、键盘和真实 200% 浏览器缩放下保持可读与可操作。
- 固定操作列在普通、悬停、选中和异常行状态下保持不透明，不覆盖滚动内容。
- GEO 覆盖矩阵等动态列原生表保留自己的滚动和打印设计，不机械套用管理表规则。

### R7. 最小共享边界

- 复用现有 Ant Design、`TableRegion`、`TableCellText`、主题 Token 与 `workspace.css`。
- 共享规则只承载跨至少三张表成立的不变量；复合身份单元格的收缩布局由现有或局部语义类持有。
- 不新增全局表格包装器、列工厂、列注册表、第二套组件库、页面级状态 Store 或新依赖。

### R8. 防止同类测试漏检

- GEO 观测回归必须使用接近合同上限的长平台名和长问题，验证：
  - 平台内容与问题内容不重合；
  - 两者均被各自单元格边界包含；
  - 平台文本实际发生省略；
  - 鼠标悬停平台复合根、平台标记和平台文字，以及键盘聚焦复合根，均显示完全一致的原始值；
  - 行高保持在预定档位。
- 24 表 E2E 增加长文本压力探针：对已登记的可省略文本注入长内容后，验证其可见边界不越过所属 `td`，而不只检查计算样式。
- 继续保留页面无横向溢出、表格内部滚动、固定列背景、移动端和真实缩放断言。
- 截图只作为诊断证据；需要防回归的几何和 Tooltip 行为必须有可失败的明确断言。

## 范围外

- 统一或重写服务端搜索、筛选、排序、分页和响应结构。
- 为缺少能力的列表新增搜索、筛选、排序、分页或导出。
- 开放任意列排序、每列筛选或新的分类筛选。
- 改变业务字段、权限、状态机、批量动作、`available_actions` 或数据来源。
- 把表格改成卡片流、虚拟列表或另一套组件库。
- 重做已经通过验收的 `TableRegion` 与 Ant Table 内部滚动分工。
