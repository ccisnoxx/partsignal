## 审计口径

- 本表是规划期静态风险清单，不等同于运行时缺陷结论。
- “高”表示固定列总和已大于 `scroll.x`，或固定列已占满而仍存在无宽度主列/选择列；“中”表示主列余量、可选列或条件列明显可疑；“低”表示源码合同基本一致，仅需浏览器抽查。
- 最终是否修改以真实 DOM 几何、有界控件单行可读性和业务主次关系为准。

## 共享结论

1. 旧门禁重点保护长文本和页面边界，未保护短标签/控件的内部换行与裁切。
2. 多数风险来自页面局部列数字，不需要共享运行时代码；首选逐表最小修复。
3. `scroll.x` 小于声明列宽总和不一定单独产生可见 bug，但它是必须进入浏览器验证的强信号；无证据时不机械批改。
4. 本轮不重复上一任务的 58 个长文本槽审计，只验证它们未因宽度调整回退。

## 实施结论

- 已修复 16 张表：内容任务、AI 作业、内容版本、产品事实、事实版本、GEO 文章观测结果、GEO 问题库、GEO 平台表现、AI 渠道、AI 请求 Header、AI 模型、AI 渠道日志、模型发现、平台、发布账号、用户。
- 保持 9 张表：待开始发布、发布工作、发布成果、内容问题、GEO 观测记录、GEO 内容排行、GEO 覆盖矩阵、全局审计日志、平台类型。它们未复现短控件换行/裁切，且现有弹性列、固定列或移动卡片合同成立。
- 共享根因修复：`workspace.css` 只对 `.ant-btn-icon-only` 应用 24px/44px 方形尺寸，文字主按钮恢复自然宽度。
- 1440×1000 浏览器实测：观测表“已发现/已提及”各 76px、单行；平台主按钮 100px、图标按钮 24px；用户表用户名主列 219px；AI Header 最长主按钮约 123px，全部由操作单元格包含。
- 375×900 浏览器实测：观测表局部滚动 `321/780`，AI Header `331/524`，平台表 `349/1200`；三个页面根宽均为 `375/375`，无页面级横向溢出。
- 受影响 7 个页面的 95 个定向测试、完整前端 190 个测试、24 个视觉合同、lint、typecheck、生产构建和 `git diff --check` 均通过。
- 全站 Playwright 两项在进入表格循环前被环境数据门禁阻断：当前数据缺少同时包含内容版本和 AI 作业的共享视觉任务。未运行会向当前远端数据库写入持久 VISUAL 数据的 setup；新增探针已用同等 DOM 几何在四类代表表上执行通过。
