# 全项目功能、业务逻辑与 UI/UX 重新验收：测试设计

## 1. 设计结论

本任务建立一份新的全项目质量基线，不复用历史“通过”结论，也不修改业务代码。测试结果统一汇总为一份跨模块报告，便于识别状态机、权限、查询一致性和共享交互中的共同根因；不拆分子任务。

覆盖范围是整个 PartSignal 产品。24 张业务表、全部操作列、13 个删除接口及其直接链路按高风险专项加深测试，但不替代认证、配置、事实、内容、发布、GEO、文件和审计的完整业务验收。

## 2. 测试依据与冲突处理

测试开始时记录代码提交、数据库迁移 head、前端构建和目标环境。判定依据按以下顺序使用：

1. `contracts/openapi.yaml`：HTTP 路径、请求、响应和错误合同。
2. `contracts/database.md`：数据库约束、删除守卫、历史保留和迁移语义。
3. 当前服务端实现及前端生成类型：运行时权限、状态、`available_actions` 和页面消费方式。
4. `.trellis/spec/`：稳定开发、视觉、交互和测试约束。
5. `docs/GEO多平台内容运营系统方案设计.md`、`docs/deployed-full-functional-acceptance-plan.md` 等产品与验收文档。
6. 当前开发环境的真实浏览器、网络、服务端、数据库和审计结果。

文档、合同和实现冲突时不自行选择容易通过的解释。报告分别记录各来源、当前行为、用户影响和建议权威结论；本任务不直接修正文档或代码。

## 3. 测试环境与真实边界

### 3.1 两层执行环境

- **确定性全栈基线**：使用项目既有本地/CI 栈，真实 PostgreSQL、Redis、Celery Worker、API、前端和实际保存字节的开发对象存储适配器。AI 调用通过项目定义的本机 OpenAI-compatible HTTP 替身，验证真实传输、严格解析和作业状态，不使用固定成功服务层。
- **已部署开发页面复核**：在确定性基线之后，对用户实际使用的开发部署页面执行同一关键流程、全路由 UI/UX 和重点缺陷复现，确认部署产物、代理、主题和浏览器行为没有偏差。

开发测试数据允许真实删除和重建。权限、历史不可变、受限事实和敏感信息仍是产品不变量，不能因环境可重建而跳过。

### 3.2 外部服务边界

- 主验收不依赖真实第三方平台发布；当前产品的发布流程验收对象是系统内登记、状态事件、核验、证据和异常闭环。
- AI 正向与失败路径优先使用项目本机 OpenAI-compatible HTTP 替身，保证可复现且真实经过网络边界。
- 若开发配置中已有专用真实模型凭据，只增加一次可选 smoke test；缺少凭据时标记 `NOT_APPLICABLE`，不影响核心业务结论。
- 浏览器 `page.route` 或 `playwright-cli route` 只能用于明确的 UI 失败恢复或纯视觉压力场景，不能把被拦截的业务成功当作功能通过。

## 4. 覆盖模型

### 4.1 自动化基线

按失败归因依次运行合同、单元/组件、PostgreSQL 集成、现有 Playwright、lint、类型检查和构建。完整项目测试是本任务明确范围，因此这些检查属于必需基线，不以少量定向测试替代。

自动化结果只证明已有断言覆盖的合同。测试通过后仍需执行产品逻辑、真实浏览器和 UI/UX 审查，特别是现有自动化未覆盖的操作列、删除路由 HTTP 权限矩阵和跨页面结果一致性。

### 4.2 全项目业务域

| 业务域 | 主要验收对象 |
|---|---|
| 认证与会话 | 登录失败/成功、改密、退出、过期、撤销、后退缓存 |
| 总览 | 指标口径、待办、跳转、空/失败状态、角色可见性 |
| 用户与权限 | 创建、编辑、停用、删除、批量操作、最后管理员、审计 |
| 平台配置 | 平台类型、平台、Prompt、revision、绑定、启停和删除 |
| AI 配置 | 渠道、敏感 Header、模型发现、连接测试、启停、删除、快照 |
| 产品与事实 | 产品、Markdown 事实、分类、版本、审核、不可变历史、删除 |
| 内容生产 | 任务、生成选项、AI 作业、人工首稿、自然化、内容审核 |
| 发布管理 | 候选、账号匹配、登记、状态事件、证据、核验、删除 |
| 发布异常 | 唯一待办、修复任务、显式解决、历史保留 |
| GEO | 问题库、人工/模型观测、纠错链、文章结果、洞察与打印 |
| 文件与审计 | 上传/绑定/失败、独占清理、审计追加、敏感信息脱敏 |

### 4.3 状态机与跨域不变量

每个核心状态机同时测试：

- 合法转换与预期副作用；
- 非法跳转、逆向修改和旧 revision；
- 双击、重复请求、两个标签页并发和迟到响应；
- 列表、详情、工作台指标、审计和重新登录后的最终一致性；
- 已批准事实/内容、发布事件、GEO 纠错链和审计的不可变或追加式边界；
- 禁用配置只阻止新业务，不污染历史；
- 未知事实显式失败，不猜测、不补零、不伪造成功。

## 5. 重点专项

### 5.1 24 张业务表

复用 `cross-page-visual-convergence.spec.ts` 的显式清单。每张表记录：

- 页面、角色、数据对象、主身份、状态、时间、指标和操作；
- 加载、首次空数据、筛选无结果、失败和权限状态；
- 搜索、筛选、排序、分页、详情、返回和总数口径；
- 长文本、行高、固定列、内部滚动、移动端和真实 200% 缩放；
- 操作前置、执行结果、失败恢复、缓存刷新和跨页面一致性。

### 5.2 全部操作列

每个动作至少覆盖：

1. 服务端允许时，前端显示且可执行；
2. 服务端不允许时，前端不误导，直接请求仍被拒绝；
3. 状态在弹窗打开后变化时，旧页面不能绕过最新门禁；
4. 成功后相关查询与详情同步；
5. 失败时对象仍存在、错误可理解且输入不会无故丢失；
6. 鼠标与键盘均可进入菜单、确认、取消并恢复焦点。

### 5.3 13 个删除接口

为用户、产品、事实版本、内容任务、发布账号、发布记录、GEO 人工观测链、平台类型、平台 Prompt、平台、AI 渠道、请求 Header 和 AI 模型建立统一记录模板，但保留各对象真实语义。

每个接口验证：

- 未登录、工程师、管理员和业务角色权限；
- CSRF、目标不存在、状态不允许、关联占用和旧 revision；
- UI 二次确认、对象名称、影响说明、危险按钮文案；
- 快速双击、直接重复 DELETE、并发状态变化；
- 204/错误码、数据库行、关联记录、附件清理调度和审计；
- 页面缓存、列表总数、详情、工作台和重新登录后的结果；
- 禁止删除的历史没有被级联、部分清理或静默改写。

## 6. UI/UX 与可访问性

### 6.1 视口和主题

- 主桌面：`1440 × 1000`。
- 主移动：`375 × 900`。
- 补充断点：`1024 × 768`、`320 × 800`。
- 代表页面使用真实浏览器 200% 缩放。
- 浅色、深色、跟随系统；关键流程补 reduced-motion。

### 6.2 判定维度

检查信息架构、页面标题、术语、视觉层级、操作优先级、危险动作、表单错误、加载/空/失败/只读/权限状态、反馈、焦点、键盘、对比度、滚动、弹窗和移动触控。功能执行成功不自动代表 UI/UX 通过。

截图只作为视觉或缺陷证据；功能结论必须同时有可观察状态、网络或数据副作用。普通诊断优先使用 snapshot、`find`、console 和 requests，只有失败链路或复杂状态才保存 trace。

## 7. 测试数据与会话

- 每次运行使用 `E2E-FULL-<run-id>` 前缀，记录所有对象 ID、revision 和最终状态。
- 管理员、工程师、未登录分别使用命名隔离浏览器会话，认证状态不进入 Git。
- 正向业务数据通过真实页面建立；自动化共享前置数据可复用项目现有 setup，但不能把 setup 成功当作页面功能通过。
- 删除专项建立无引用、有关联、受保护历史、并发变化等独立对象，避免一个用例污染另一个结论。
- 审核、发布事件、GEO 纠错链和审计等按产品合同保留；可删除配置和临时对象在记录结果后清理。

## 8. 结果、缺陷与证据

### 8.1 用例状态

只使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`NOT_APPLICABLE`。未执行和被阻断不得计入通过。

### 8.2 缺陷分级

- **P0**：泄密、越权写入、受限数据外发、历史破坏、错误或重复发布。
- **P1**：主流程中断、核心状态错误、重要页面或关键移动/键盘路径不可操作。
- **P2**：存在替代路径，但明显影响理解、效率、恢复或数据判断。
- **P3**：不阻断任务的轻微视觉、文案或一致性问题。

UI 缺陷按实际影响分级，不因位于前端自动降级。

### 8.3 任务产物

- `research/coverage-matrix.md`：路由、业务域、角色、状态机和执行状态。
- `research/table-action-delete-matrix.md`：24 表、全部操作列和 13 删除接口专项。
- `research/findings.md`：经复现的缺陷和产品决策项。
- `report.md`：最终结论、风险矩阵、覆盖、缺陷分布、阻断和残余风险。
- 大体积截图、trace 和网络证据保存在 `artifacts/full-project-acceptance/<run-id>/`，任务文档只引用路径，不嵌入秘密。

## 9. 停止与继续规则

- 单一模块被阻断时记录 `BLOCKED`，继续不依赖它的模块。
- 出现秘密泄露、受限事实外发、历史破坏、越权写入或大范围数据串扰时，立即停止对应写路径并记录 P0；仍可继续安全且独立的只读或其他模块测试。
- 发现缺陷不修改业务代码。只有测试夹具或测试环境本身阻断且修正不改变被测行为时，也先记录证据并向用户报告，不在本任务内擅自修复。
- 同一失败在环境或代码未变化时不重复运行；先归因，再决定是否继续其他波次。

## 10. 设计取舍

- 不创建新的测试框架、页面对象层或全局表格模型；优先复用现有测试、Playwright 配置、共享数据和浏览器工具。
- 不为 24 张表机械生成大量同质用例；共享不变量由现有跨页测试保护，对业务操作和删除采用对象级矩阵。
- 不拆分 Trellis 子任务：最终风险结论依赖跨模块状态、角色和数据一致性，统一执行与报告比独立归档更可靠。
- 本任务不修复发现的缺陷；报告按共同根因和优先级给出后续修复任务建议。
