# 技术设计

## 1. 设计结论

继续使用现有 React、Ant Design Table/Dropdown 和 `TableRegion`。本任务不建立通用表格组件：列内容与操作属于各业务页面，直接修正现有 `columns` 是最短且所有权最清晰的实现。

列宽遵循同一规则，但不强求同一数值：

- 状态、版本、数字和单按钮操作等有明确上限的字段使用紧凑 `width`。
- 名称、标题、域名、目标受众等长文本列保留为弹性列，必要时仅设置 `minWidth`。
- 每张表至少保留一个弹性内容列吸收桌面剩余空间，避免所有列机械均分或等比放大。
- 只有最小可用宽度超过容器时才设置 `scroll.x`；关键宽表的操作列使用 Ant 原生 `fixed: 'right'`。
- 页面级不增加横向滚动容器，不恢复会破坏 sticky 表头定位的外层 `overflow`。

## 2. AI 配置

`AIChannelsPage` 在页面内维护可选列 key 数组。使用 Ant Dropdown 的多选菜单作为“列设置”，不新增 Checkbox 弹窗或状态依赖。

- 必选列：渠道名称、状态、已启用模型、操作。
- 默认可见列：API 根地址、API Key。
- 默认隐藏列：请求超时、请求 Header。
- 可选列不写入 URL、localStorage 或服务端；重新进入页面恢复上述默认值。
- 操作列固定右侧；默认列总宽度控制在 1440px 页面内容区内。
- `display_name === model_id` 时只渲染一份文本；两者不同时继续用名称加 ID 表达，不对接口数组做前端去重。

这里修复的是呈现歧义而不是数据：生产接口已经确认 `enabled_models.length === 1`，不得通过集合去重掩盖未来真实的服务端重复。

## 3. 表格宽度修正范围

根据 1440px、1024px、768px、375px 的部署页实测，调整以下明显失衡页面：

| 页面 | 调整重点 |
|---|---|
| AI 配置 | 列设置、默认列总宽度、固定操作列 |
| 平台管理 | 当前规则列容纳下拉框；Select 使用单元格可用宽度；操作列固定 |
| 平台规则 | 版本/状态/正文范围紧凑，平台/受众弹性，时间和操作按内容分配 |
| 平台类型、Prompt 管理 | 避免操作列被平均放大 |
| 产品、内容任务、人工发布、用户管理 | 压缩状态、版本、数量、操作等短列，把空间留给名称/标题 |
| 业务设置 | 目标问题与平台账号列表按长文本、状态、操作角色分配 |
| 审计日志 | 时间与动作紧凑，请求 ID 吸收剩余空间 |

GEO 观测和 AI 渠道详情的主要宽表已经按字段角色设置宽度并通过实测，本任务不为统一外观改写它们。

## 4. 审计日志导航

- `AppLayout` 把审计日志从配置中心 children 移为“系统管理”一级管理员菜单项，路径改为 `/audit`。
- `App` 把 `AuditLogPage` 移出 `ConfigurationLayout` 子路由。
- `AuditLogPage` 复用 `UserManagementPage` 的现有页面内管理员守卫：非管理员返回 `<Navigate to="/" replace />`。不为两个页面创建新的权限抽象。
- `routePrefetch` 将 `/audit` 映射到现有 `auditLog` loader。
- 删除旧 `/configuration/audit` 路由，不保留兼容重定向；该路径尚未形成对外契约，保留第二入口会继续表达错误归属。
- 后端 `/api/v1/audit-logs`、查询 key 和管理员权限保持不变。

## 5. 测试与回滚

- 组件测试验证列设置默认值和切换、相同/不同模型名称与 ID 的呈现、平台规则业务操作保持不变。
- 导航和路由测试验证 `/audit` 一级菜单、管理员可达与普通用户重定向。
- E2E 使用现有管理员/工程师流程，验证新路径权限、AI 操作列可见、平台 Select 不越出单元格。
- jsdom 不断言像素；真实尺寸由 `playwright-cli` 在 1440/1024/768/375px 验证。
- 每组变更可按页面精确反向应用；不使用兼容分支、第二套列定义或破坏性 Git 命令。

## 6. 文档影响

本任务改变前端导航路径和稳定的表格布局约定，需要更新 `frontend/README.md` 的前端交互说明；不涉及 OpenAPI、数据库或部署文档。
