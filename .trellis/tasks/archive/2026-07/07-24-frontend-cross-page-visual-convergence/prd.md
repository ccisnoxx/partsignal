# 跨页面视觉系统收口

## 目标

以 `.trellis/spec/frontend/visual-system.md` 为 PartSignal 唯一视觉与交互规范，消除登录后业务页面之间由多套应用壳层、页面级字体、派生基础 Token、任意圆角和阴影造成的视觉割裂，使用户在不同路由间切换时始终感知为同一个 macOS 原生秩序感、轻量磨砂玻璃、高密度企业 SaaS 工作台。

本任务允许重构现有前端壳层和页面视觉结构，但不得改变真实数据、API、权限、路由、查询口径、状态转换、表单保存、审核、发布或其他业务行为。

## 背景与已确认事实

- `visual-system.md` 已明确设计意图、运行时权威顺序和禁止模式；本任务不重新选择品牌配色、字体或组件技术栈。
- `AppLayout` 当前按路由组合 Dashboard、GEO、配置中心、用户管理、审计、平台管理、平台规则和 Prompt 管理等多种 `app-shell-*` class，并为侧栏使用多组宽度。
- `global.css` 从视觉规范固化时的 908 行增长到当前 1721 行；当前有 8 组 `app-shell-*` 页面壳层，并包含 `--geo-*`、`--um-*`、`--audit-*` 等页面级基础视觉变量。
- 现有 `check-theme-colors.mjs` 能阻止十六进制和 RGB 字面量，但不能阻止 `color-mix()` 派生的第二套页面配色、页面字体、壳层变体或任意圆角/阴影。
- 现有 Playwright 会输出截图，但没有形成跨路由共享壳层断言或稳定的视觉回归基线。
- `ui-ux-pro-max` 只作为对比度、焦点、键盘、反馈、响应式和 anti-pattern 检查表；其候选风格、字体、颜色和图标建议不得覆盖本项目规范。

## 范围

### 包含

1. 统一所有 `AppLayout` 下业务路由的侧栏、品牌区、顶栏、全局搜索、主题与账号操作区、内容画布、桌面宽度、折叠宽度和响应式 Drawer。
2. 清除路由驱动的视觉壳层 class 和与业务路由绑定的侧栏宽度；路由判断只保留导航选中、面包屑、页面上下文和真实业务行为。
3. 统一字体、字号角色、圆角、阴影、玻璃表面和基础间距的运行时所有权，使 Ant Design 与项目 CSS 消费同一组值。
4. 删除页面级基础视觉 Token 和页面字体覆盖；保留真实数据可视化所需的系列语义、动态尺寸和业务布局 class。
5. 必要时调整页面视觉结构、容器层级和 CSS 选择器，以移除无效 Card 嵌套、页面级壳层和高饱和渐变，但不强制不同业务页面采用同一种内容布局。
6. 建立跨路由、跨主题和代表视口的可重复视觉门禁，覆盖三类页面结构及特殊打印边界。
7. 扩展现有静态检查，阻止重新引入页面级壳层、页面字体、基础视觉 Token 和绕过主题的颜色表达。
8. 根据 2026-07-24 用户追加授权，更新既有 `mvp-flow.spec.ts` 已过期的请求字段，并使预览步骤显式满足当前业务前置条件；范围限于 E2E 请求、建数与确定性断言，不修改 API、backend 或产品业务流程。

### 路由覆盖

- 总览：`/`
- 数据列表与详情：`/products`、`/products/:productId`、`/tasks`、`/tasks/:taskId`、`/publications` 及其详情/修复路由、`/observations`、`/settings`、`/users`、`/audit`
- 编辑审核：`/content/:contentVersionId`、产品事实编辑、平台规则、平台 Prompt
- 分析洞察：`/observations/insights`
- 配置中心：`/configuration/ai`、平台类型、平台管理、平台规则、平台 Prompt
- 特殊边界：`/observations/insights/print` 的打印输出

### 不包含

- 登录页和修改密码页的重新设计；只验证本任务没有破坏其现有独立认证壳层。
- 品牌色、状态语义色、图表系列色或深浅主题方向的重新选择。
- API、OpenAPI、数据库、后端、权限、业务状态、查询参数或数据口径修改。
- 更换 Ant Design、`@ant-design/icons`、现有图表实现或系统字体栈。
- 新增 Tailwind、shadcn、Lucide、Phosphor、Web Font、CSS-in-JS、视觉测试服务或其他运行时依赖。
- 创建新的 `PageShell`、卡片工厂、页面配置系统或一次性完成全仓 CSS Modules 迁移。
- 为了外观统一把数据列表、编辑审核和分析洞察强制抽成同一内容结构。

## 需求

### R1：唯一视觉权威

- `visual-system.md` 是唯一人类可读视觉规范。
- `theme.ts` 和 `global.css` 只实现该规范，不得生成第二套 `MASTER.md`、页面 override 或品牌方案。
- 若实现需要澄清字体、圆角、动效等运行时所有权，只能同步修正文档中的所有权描述，不得改变已批准视觉方向。

### R2：单一应用壳层

- `AppLayout` 下所有桌面业务路由使用同一套壳层 class。
- 规划基线为：桌面侧栏 220px、折叠侧栏 76px、顶栏 64px、桌面内容内边距 24px；窄屏继续使用 280px Drawer，并按现有断点收敛到 16px/12px 内容边距。
- Dashboard、GEO、用户管理、审计和配置页面不得改变侧栏、品牌区、顶栏、全局搜索、账号区或全局画布。
- 页面只允许改变自身内容构图、数据密度和业务面板，不得创建路由级新主题。

### R3：字体、圆角、阴影与动效所有权

- 全站只使用现有系统字体栈和等宽字体栈；删除页面级 `font-family`。
- Ant Design 与 CSS 必须消费同一组字体、圆角和动效常量，不得分别维护等价字面量。
- 普通业务页面只使用 `--ps-radius-sm/md/lg`、允许的 4px 紧凑状态和已批准认证例外。
- 普通、浮层和模态阴影只使用 `--ps-shadow-sm/md/lg`；选中指示和焦点可保留非 elevation 的 inset 表达。

### R4：页面表面与内容结构

- 删除 `--um-*`、`--audit-*` 以及 `--geo-border/surface/text-*` 等重复基础视觉角色。
- GEO 图表固定业务语义继续使用 `theme.ts` 的 `geoSeries*`；数据驱动的比例、坐标和局部 accent 可以保留。
- 共享 `PageHeader`、`MetricTile`、`TableRegion`、`StatusTag` 的最终计算样式不得被页面重建为另一套组件。
- 允许重排页面视觉容器和删除冗余 Card；必须保留字段、操作、权限判断、查询状态、错误恢复和真实业务工作区。

### R5：颜色与品牌保护

- 不调整 `actionPrimary`、文字、状态、图表、画布和玻璃角色的品牌语义。
- 业务页面不得通过 `color-mix()` 从图表色生成新的主按钮、导航选中、文字或基础表面体系。
- 紫色只保留辅助识别或图表序列，不再作为所有页面主按钮的第二端渐变。

### R6：可执行门禁

- 扩展现有前端静态检查，至少覆盖十六进制、RGB、HSL、OKLCH 等原始颜色，页面字体、禁止的基础 Token 前缀和路由级壳层 class。
- 使用现有 Playwright 建立：
  - 全部主要业务路由的壳层计算样式一致性矩阵；
  - 数据列表、编辑审核、分析洞察三个代表页面的浅色/深色视觉基线；
  - 三个代表页面的 375px 窄屏检查；
  - system、200% 缩放、键盘、焦点和 reduced-motion 行为检查。
- 动态数据、时间和用户标识必须通过稳定种子、遮罩或区域级断言处理；不得用跳过测试掩盖缺少数据。

### R7：业务行为保持

- 所有当前路由保持可达，导航选中、URL、Drawer、表格、表单、图表、打印和权限行为不变。
- 不修改 contracts、backend、API schema、query key、请求载荷或服务端状态权威。
- 现有单元、集成和 E2E 行为测试必须继续通过。

## 风险与约束

- 删除高特异性和 `!important` 页面规则可能暴露此前被遮蔽的 Ant Design 默认样式，必须按路由矩阵逐步验证。
- 系统字体在 macOS 与 Linux 的像素渲染不同；视觉基线应以稳定区域、合理阈值和计算样式断言组合，不能依赖全页逐像素零差异。
- 当前工作区存在与本任务无关的 `.playwright-cli/console-2026-07-23T23-17-17-038Z.log`，任何提交计划都不得包含该文件。
- 最终规划已于 2026-07-24 获得用户批准；只有 `task.py start` 成功把状态切换为 `in_progress` 后才能修改前端产品代码。
