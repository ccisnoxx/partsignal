# PartSignal 前端视觉系统

> 本文是 PartSignal 前端唯一的人类可读视觉与交互规范。新页面、页面改造和 UI/UX 审计在实施前必须完整读取本文。

## 1. 适用范围与权威来源

本规范适用于登录后工作台、总览、认证、设置、数据列表、编辑审核、分析洞察及其共享组件。它约束视觉角色、页面构图、组件选择、交互反馈、响应式和可访问性，不改变 API、数据口径、权限或业务状态。

权威顺序如下：

1. `.trellis/spec/frontend/visual-system.md` 定义设计意图、组件边界和验收规则。
2. `frontend/src/app/theme.ts` 是运行时语义颜色、玻璃材质、状态色、图表色、阴影、字体栈、圆角和动效的唯一值来源；`frontend/src/app/AntThemeProvider.tsx` 只负责将这些值按需映射为 Ant Design `ThemeConfig`。
3. `frontend/src/styles/global.css` 实现所有路由共用的基础、认证和登录样式；`frontend/src/styles/workspace.css` 实现已认证工作台的壳层、字号与业务布局尺度。两者只消费 `--ps-*` Token，不重复持有运行时视觉值。
4. Ant Design、`@ant-design/icons` 和现有共享组件提供业务页面必须复用的实现骨架。
5. 业务页面只能消费上述契约；局部样式不得成为第二套配色、字体、Token、主题、状态或卡片体系。

不得创建 `design-system/MASTER.md`、页面 override 文档或其他平行视觉规范。规划文件和原型总结只记录任务上下文，不替代本文。现有页面与本文不一致时，应当在独立审计任务中处理，不得把历史实现描述成已通过验收。

### 1.1 批准视觉参考及从属关系

`.trellis/tasks/archive/2026-07/07-25-frontend-visual-system-recalibration/assets/approved/manifest.md` 登记本轮人工批准的 13 张 1440×1000 浅色实施截图及其 SHA-256。批准资产是本文的视觉验收证据，不是平行规范；规范意图仍以本文为准，精确运行时值仍以 `theme.ts`、`global.css` 和 `workspace.css` 为准。

- `13-dashboard.png`、`01-users.png`、`08-geo-insights.png`、`12-content-review.png` 分别约束总览、数据列表、分析洞察和编辑审核页面家族，并共同决定统一壳层、密度和视觉层级。
- 审计、发布账号、Prompt、平台规则、平台、GEO 观测、发布、AI 渠道和内容任务九张原型及实施截图只补充对应页面的局部构图，不得产生页面级壳层、主题或业务契约。
- 原型和实施截图中的身份、时间、正文、数值、状态与操作只记录采集时的真实页面，不成为固定产品事实；代码、API 和服务端状态仍是业务权威。
- 未登记在批准清单中的候选图不得用于更新自动视觉基线，也不得反向修改本文或运行时 Token。

## 2. 核心视觉方向

PartSignal 必须呈现“macOS 原生应用秩序感 × 轻量磨砂玻璃 × 高密度企业 SaaS 工作台 × 克制的数据可视化”：

- 界面必须以内容、数据和操作效率为中心，保持浅色、通透、精细、稳定和专业的桌面生产力工具气质。
- 信息层级必须由间距、分栏、文字层级、细边框和轻阴影建立，不得依赖大面积高饱和色块。
- 品牌蓝承担主要交互；紫色仅承担辅助识别或图表序列；成功、警告、危险色仅表达对应语义。
- 环境光只能使用 `theme.ts` 已有语义颜色混合形成低饱和、强模糊背景，不得形成抢夺内容注意力的清晰色带。
- 登录后的业务页面不得使用官网式 Hero、聊天窗口结构或展示型数据大屏结构。
- 所有页面必须显示真实数据、真实状态和现有功能；未知产品事实、虚构指标和未获业务契约支持的操作必须失败或不渲染，不得猜测、补零或用占位成功状态掩盖。

## 3. Token 与实现所有权

### 3.1 颜色角色

业务代码必须通过 Ant Design 主题值或 `theme.ts` 映射出的 `--ps-*` 变量使用颜色，不得复制原始十六进制、RGB 或独立浅深色值。

| 角色 | 唯一来源 | 使用边界 |
|---|---|---|
| 画布 | `bgCanvas` | 应用背景和页面最底层 |
| 普通表面 | `bgSurface`、`bgSubtle`、`bgRaised`、`bgSunken` | 正文、表格、表单、层级分区和禁用区域 |
| 玻璃表面 | `glassSurface`、`glassSurfaceStrong`、`glassBorder`、`glassBackdrop` | 导航、顶栏、轻量指标、筛选、抽屉和浮层 |
| 环境光 | `ambientBlue`、`ambientPurple`、`ambientPink` | 仅由统一应用壳层组合低饱和径向光晕，业务页面不得直接消费 |
| 文字 | `textPrimary`、`textSecondary`、`textTertiary`、`textDisabled`、`textInverse` | 标题、正文、辅助信息、禁用和反色文字 |
| 边界 | `borderSubtle`、`borderDefault`、`borderStrong` | 分隔、容器、控件和强调边界 |
| 主交互 | `actionPrimary`、`actionPrimaryEnd`、`actionPrimaryHover`、`actionPrimaryActive`、`actionPrimarySoft`、`actionOnPrimary` | 主操作、共享主按钮渐变终点、交互状态和低强调选中背景 |
| 链接与选中 | `link`、`selectionBg`、`focusRing` | 链接、文本选择和可见焦点 |
| 状态 | `success`、`successSoft`、`successText`、`warning`、`warningSoft`、`warningText`、`danger`、`dangerSoft`、`dangerText`、`neutral`、`neutralSoft`、`neutralText` | 成功、警告、危险和中性状态，不得互换业务含义 |
| 图表 | `chartSeries1` 至 `chartSeries6`、`geoSeries*`、`chartGrid`、`chartAxis`、`chartTooltip*`、`chartRail` | 数据系列、GEO 固定语义、坐标、网格、提示和轨道 |
| 阴影 | `shadowSm`、`shadowMd`、`shadowLg` | 普通容器、浮层和高层级模态 |

浅色与深色模式必须使用同一组语义角色。业务页面不得自行生成新配色、字体、Token、主题或卡片体系，也不得通过局部变量改写状态含义。仅当同一视觉语义在多个真实场景重复出现、现有角色无法表达，并经独立任务确认后，才能在 `theme.ts` 或 `global.css` 增加 Token；不得为单次局部值创建变量。

本轮批准的浅色基准值如下；深色对应值继续由 `theme.ts` 的同名角色持有，不复制浅色原型：

| 角色 | 批准值 |
|---|---|
| 画布 / 普通表面 / 弱表面 / 下沉表面 | `#F4F7FC` / `#FFFFFF` / `#F7F9FD` / `#EDF2F8` |
| 玻璃表面 / 强玻璃表面 / 玻璃边界 | `rgba(255,255,255,.74)` / `rgba(255,255,255,.90)` / `rgba(102,122,160,.16)` |
| 主文字 / 次文字 / 辅助文字 | `#172033` / `#526079` / `#68758C` |
| 弱边界 / 默认边界 / 强边界 | `#E5EAF2` / `#D7DFEB` / `#8795AA` |
| 主交互起点 / 终点 / Hover / Active | `#315CF5` / `#5A3FF0` / `#244CE0` / `#1E40C6` |
| 蓝 / 紫 / 粉环境光 | `rgba(92,145,255,.16)` / `rgba(132,102,255,.12)` / `rgba(255,151,178,.10)` |

### 3.2 字体与数字

- 所有界面必须复用 `theme.ts` 注入的 `--ps-font-sans` 系统字体栈；不得加载 Inter、Google Fonts 或其他 Web Font。
- 代码、请求标识、版本、哈希和适合纵向比较的数值必须使用 `--ps-font-mono`；表格数字和指标必须启用等宽数字。
- 普通正文与表格内容使用 400；标签和导航使用 500；区域标题、页签和按钮使用 600；页面标题和核心数字仅在需要时使用 600–700。不得大面积使用 800–900 或以极细字重弱化信息。
- 辅助信息使用 10–12px、至少 1.35 行高；表格、状态和筛选使用 11–13px、至少 1.4 行高；正文和输入使用 14px、1.55–1.8 行高；区域标题使用 15–16px、1.4–1.6 行高。
- 默认页面标题必须复用 `PageHeader` 与现有 `workspace.css` 层级，保持 24–30px；只有总览、认证等已定义特殊页面才能使用现有变体。核心指标保持 24–36px，不得继续放大并挤压业务内容。
- 正文不得使用纯黑或仅靠更细字重区分次要信息；层级必须同时由语义文字色、字号、字重或间距表达。

### 3.3 布局与间距

桌面验收基准为 1440–1600px。批准后的共享几何如下，所有值由 `AppLayout`、Ant Design 主题或 `global.css` / `workspace.css` 的现有所有者实现：

| 项目 | 精确值 |
|---|---:|
| 桌面侧栏 / 折叠侧栏 / 移动导航 Drawer | 208px / 72px / 280px |
| 顶栏高度 / 全局搜索最大宽度 | 64px / 480px |
| 桌面 / 768–991px / 最窄内容边距 | 20px / 16px / 12px |
| 页面主间距 / 页面最大宽度 | 16px / 1520px |
| 标准详情面板 | 340px |
| 控件高度 / 标准卡片标题区 | 36px / 44px |
| 标准表头 / 常规数据行 | 44px / 52px |
| 指标卡最小高度 | 112px |
| 紧凑 / 控件 / 普通容器 / 大面板圆角 | 6px / 8px / 12px / 16px |
| 快速 / 常规 / 慢速动效 | 160ms / 200ms / 240ms |

- 主内容必须保持 `.page-stack` 的 1520px 宽度上限和居中规则；经批准的 GEO 观测与内容审核等高密度页面可以使用现有更宽局部上限，但不得建立无限宽壳层。
- 侧栏、折叠侧栏、移动 Drawer 和顶栏几何必须复用 `AppLayout`；业务页面不得覆盖其尺寸或创建第二个全局导航。
- 顶栏必须保持轻量，只承载页面上下文、全局搜索、主题和账号等全局入口；页面主操作必须位于内容区标题右侧。
- 页面必须以 8px 为基础网格：紧凑控件间距使用 8–12px，卡片和主要区块间距使用 12–20px，桌面内容边距使用 20px，窄屏使用 12–16px。
- 普通卡片内边距必须保持 16–20px；高密度表格、筛选和侧栏可使用现有更紧凑尺度，但同一区域必须一致。
- 详情面板桌面宽度应当保持 300–380px；信息超出该宽度时使用 Drawer 或进入详情页，不得压缩主编辑区到不可读宽度。
- 局部布局必须使用 CSS Grid、Flexbox 和 Ant Design 响应式能力。不得用绝对定位复制整页构图，也不得制造页面级横向滚动。

### 3.4 圆角、阴影与边界

- 状态标签和紧凑子容器使用 `--ps-radius-compact`，普通控件使用 `--ps-radius-sm`，局部业务容器使用 `--ps-radius-md`，Ant Design `Card` 与页面级大面板使用 `--ps-radius-lg`；已有 Ant Design 映射必须继续复用。
- 24px 认证或已批准特殊壳层圆角只允许在 `global.css` 已定义的对应场景使用；不得扩散为通用尺度。
- 圆形图标容器只能用于指标、状态或身份图形，不得把所有按钮和容器胶囊化。
- 普通卡片使用 `shadowSm`，悬浮菜单与固定操作区使用 `shadowMd`，模态、抽屉等最高层级使用 `shadowLg`。不得在业务页面写入更沉重的独立阴影。
- 容器层级优先使用 `borderSubtle` 或 `glassBorder` 表达；只有输入焦点、选中对象和阻断状态才能使用更强边界。

### 3.5 玻璃边界

- 玻璃仅允许用于侧边导航、顶部栏、轻量指标、筛选、详情抽屉、模态和下拉浮层。
- 表格、Markdown 编辑器、正文阅读区和复杂表单必须使用 `bgSurface` 或 `glassSurfaceStrong` 支撑的高不透明度表面，保证连续阅读和数据比较。
- 同屏玻璃层级不得超过导航/壳层、业务轻表面、浮层三层；不得给每个容器重复模糊。
- 浏览器不支持 `backdrop-filter` 时必须沿用所属 CSS 边界中的不透明表面回退，不得用透明背景降级。

### 3.6 CSS 加载边界

- `main.tsx` 只能静态导入 `global.css`。该文件持有 reset、链接与焦点、认证启动、登录、独立改密页及真正跨路由的按钮和 reduced-motion 规则。
- `AppLayout.tsx` 导入 `workspace.css`。应用壳层、业务页面、工作台响应式与打印规则必须留在此文件，由现有 `React.lazy` 边界在认证成功后加载。
- 全路由 `ThemeProvider` 只能持有主题状态并注入 `--ps-*` Token，不得静态导入 Ant。`AntThemeProvider` 只在 `AppLayout` 和独立 `/change-password` 路由加载；匿名登录不得加载 `ConfigProvider`、locale 或 Ant CSS-in-JS。
- 受保护但不经过 `AppLayout` 的路由目前只有 `/change-password`；它依赖的 `.centered`、`.password-card`、`.eyebrow`、主按钮和移动端触控尺寸必须留在 `global.css`。不得为修复该页而让匿名入口加载整个 `workspace.css`。
- 两个 CSS 文件都由 `scripts/check-theme-colors.mjs` 执行同一套 Token、圆角、阴影和字体守卫。新增规则先按真实消费者选择文件，不得在两边复制同一声明。
- 分包变更至少断言：匿名 `/` → `/login` 不请求 `AppLayout`、改密页或工作台 CSS；直接 `/change-password` 不请求工作台 CSS；认证工作台会请求 `AppLayout-*.js` 与 `AppLayout-*.css`。

## 4. 页面结构

三类结构是构图契约，不是要求新增通用 `PageShell`、三栏组件、卡片工厂或页面配置系统。

### 4.1 数据列表工作台

内容任务、产品事实、发布账号、用户管理和审计日志等列表页必须按以下顺序组织：

1. 使用 `PageHeader` 呈现标题、说明、面包屑和每页唯一主操作。
2. 只有服务端提供真实聚合口径时才显示 1–5 个紧凑 `MetricTile`；无真实指标时直接省略，不得用零值或虚构评分补位。
3. 使用紧凑筛选区承载搜索、状态和时间等真实查询参数；筛选状态必须与 URL 或既有权威状态同步。
4. 使用 Ant Design `Table` 和 `TableRegion` 呈现高密度列表。
5. 仅当存在真实选中对象时显示桌面详情面板或 Ant Design Drawer；移动端必须使用全宽 Drawer 或详情页。

筛选、表格、分页和详情必须保持同一查询口径。加载、空态、失败和权限不足不得遮蔽页面身份、返回入口或可恢复操作。

### 4.2 编辑审核工作区

内容与审核、事实版本、平台规则和 Prompt 管理等页面必须按业务需要组合：

- 对象或章节导航负责定位真实对象、版本或章节。
- 中央区域负责 Markdown 正文、表单、配置或差异，必须使用稳定高不透明度表面。
- 审核、证据、版本和安全边界位于辅助区域；服务端状态、可用操作和不可变快照必须保持权威。
- 保存状态必须明确区分未修改、未保存、保存中、已保存和失败；审核决策必须保留确认、意见、修订号和服务端校验。
- 窄屏必须按对象导航、主工作区、审核辅助区的任务优先级折叠或分段，关键保存与审核操作不得消失。

不得为了视觉统一把所有编辑审核页面强制抽象成同一个三栏组件。

### 4.3 分析洞察工作台

分析洞察页必须按以下顺序组织：

1. 紧凑筛选器和数据质量说明。
2. 少量真实趋势指标。
3. 平台或序列对比。
4. 内容表现、问题矩阵或漏斗。
5. 由真实观测和明确口径支持的行动结论。

图表、矩阵和结论必须能追溯到现有 API 数据、时间范围和统计口径。数据不足时必须明确显示“数据不足”或对应真实状态，不得外推、补零或生成装饰性趋势。

### 4.4 特殊页面边界

- 总览页仅能从现有 API 或真实事件契约明确提供的核心指标、运营状态、待办、快捷入口和近期动态中选取内容；无对应契约的数据必须省略，不得复制完整列表页或分析页。
- 认证页仅能在现有认证壳层中使用全视口环境光、居中高层玻璃卡和品牌图形，并且只能呈现现有认证字段、错误和安全说明；不得变成营销落地页。
- 设置与配置页按真实对象关系使用列表、表单、详情或编辑工作区；不得为了统一外观强套指标卡或三栏结构。
- 审计、打印和其他高密度特殊页面仅能保留已批准的局部尺度，并且必须继续消费全局语义 Token，满足本文的主题、响应式和可访问性规则。

## 5. 组件与交互

### 5.1 卡片

- 普通业务容器使用 Ant Design `Card`；服务端指标使用 `MetricTile`，不得复制指标卡实现。
- 卡片标题使用 15–16px、600，标题区和内容区仅在有助于扫描时使用一条细分隔线，操作放在右上角。
- 指标卡必须紧凑，只包含名称、真实数值、单位、进度或短说明；不得堆叠长文、每卡使用不同高饱和背景或展示无法解释的综合评分。
- 同一平面不得通过层层嵌套 Card 制造层级；优先减少容器，使用标题、分隔线和间距。

### 5.2 表格

- 数据表使用 Ant Design `Table`；宽表必须包在 `TableRegion` 中，并由 `Table.scroll.x` 持有局部横向滚动。
- 表头保持 11–13px、500–600，数据行保持 12–14px；现有常规表头 40–48px、数据行 44–58px 的密度范围必须按页面一致使用。
- 状态、数量、时间和操作等有明确上限的字段使用紧凑列宽；名称、标题等长文本至少保留一列弹性宽度。
- 横向滚动的关键宽表必须固定操作列；不得给所有列分配相同固定宽度，也不得用单元格控件撑破列宽。
- 每行只保留一个高频主入口；低频和危险操作放入 Ant Design `Dropdown`。危险操作必须进入现有确认流程。
- 行悬停、选中、异常和焦点必须使用语义 Token；异常不得只靠整行红色，必须同时显示状态文字、图标或说明。
- 不得把整行设为第二个交互入口，也不得给 `tr` 添加 `tabIndex`；行内焦点沿用 `:focus-within`。

### 5.3 表单与 Markdown 编辑器

- 业务表单和改密页必须使用 Ant Design `Form`、现有控件和服务端校验契约；输入高度、圆角、边框和焦点由主题及所属 CSS 加载边界控制。
- 匿名登录是唯一性能例外：使用 `global.css` 中的原生 `form/input/button`，但必须继续绑定 `LoginRequest` 与现有登录 API，保留最短八位校验、首个错误字段聚焦、`aria-invalid` / `aria-describedby`、密码显隐、pending、服务端错误和成功跳转。不得将该例外扩散到业务表单。
- 必填、说明、错误和保存反馈必须与字段建立语义关联。错误必须显示在字段下方或错误摘要中，不得只改变边框颜色。
- 长表单必须复用 `errorFields`、`scrollToFirstError`、显式修订号和既有保存状态，不得静默吞掉失败。
- Markdown 是内容唯一可编辑正文源；不得保存可独立编辑的 HTML 或编辑器 JSON。
- Markdown 编辑器必须使用高不透明度表面、清晰工具栏分隔、14px 正文和 1.65–1.8 行高；工具栏只包含现有业务需要的格式能力。
- 预览中的标题、列表、链接、引用、表格和代码必须使用 `workspace.css` 现有语义样式；不得为预览引入第二套排版或复杂富文本依赖。

### 5.4 按钮与操作层级

- 每页只能有一个与当前任务对应的主操作，例如新建、保存或提交审核；使用 Ant Design `primary` 与主题主交互色。
- 共享 `.ant-btn-primary` 是蓝紫渐变的唯一例外：固定使用 112deg 的 `actionPrimary` → `actionPrimaryEnd`，Hover/Active 只替换起点为对应语义状态。危险主按钮和 `.review-approve-button` 必须排除在外，分别使用危险色和成功色。
- 渐变例外只能由 `global.css` 的共享 Ant 选择器和匿名登录 `.login-submit` 持有，并由主题颜色静态扫描精确放行；业务页面不得复制渐变、增加页面级 allowlist 或把 `actionPrimaryEnd` 用作独立强调色。
- 次按钮用于查看差异、测试连接、重置筛选等可逆操作，使用默认或文本按钮。
- 成功色实心操作仅用于批准等明确成功决策区域，不得作为普通导航或装饰。
- 删除、停用、退回等危险操作不得成为默认显眼操作；必须显示影响、权限和确认流程。
- 图标按钮必须有可访问名称；语义不明确或仅图标操作必须提供 Ant Design `Tooltip`。

### 5.5 状态、空态与反馈

- 已知业务状态必须通过 `StatusTag` 统一映射中文标签、语义 tone 和图标；业务页面不得重写状态配色或猜测未知状态含义。
- 状态必须至少同时使用文字与颜色；阻断、警告和成功在复杂区域应当增加图标、边界或说明。
- 加载、空态和错误必须复用现有查询状态组件与 Ant Design 反馈；可恢复错误必须保留重试，空态仅在同屏无等价主操作时提供操作。
- 留在当前页面的长期保存、删除、启停和显式状态操作必须使用现有 `App.useApp().message` 规则提供短中文反馈；失败不得伪装成成功。

### 5.6 图标

- 业务图标只能使用 `@ant-design/icons`，默认操作尺寸 16–18px，导航尺寸 18–20px；同一区域必须保持同一线性风格和视觉重量。
- 平台 Logo 仅能使用官方标识，并且容器、对齐和尺寸必须统一。
- 不得新增 Lucide、Phosphor、Heroicons 或第二套图标库，不得用 Emoji 代替业务图标。

### 5.7 图表

- 图表必须选择最直接表达真实关系的二维类型：时间趋势使用折线或克制面积图，类别比较使用条形图，阶段转化使用二维漏斗或进度表达，覆盖关系使用矩阵。
- 默认序列按 `chartSeries1` 至 `chartSeries6` 顺序使用；GEO 固定语义必须使用对应 `geoSeries*`。危险红只表示异常、失败或负向变化。
- 同一图表默认不超过 4 个主要序列；仅当真实比较对象要求且图例仍可清晰辨认时才能使用第 5–6 个序列。
- 折线使用 2px，数据点只在焦点、悬停或关键节点显示；面积填充必须低透明度；坐标文字保持 11–12px，网格使用 `chartGrid`。
- 图例、坐标、Tooltip 和数据点必须支持键盘或等价数据表读取；颜色相近的序列必须同时使用标签、线型、标记或直接数值。
- 禁止 3D、发光、霓虹、高饱和渐变、装饰性饼图和无法解释的数据表达。

### 5.8 动效

- 动效必须复用 `--ps-motion-fast`、`--ps-motion-base`、`--ps-motion-slow` 和现有缓动；快速反馈、常规反馈和慢速页面反馈分别为 160ms、200ms、240ms。
- 允许动画的属性仅包括 `opacity`、`transform`、背景、边框色和阴影；不得动画布局尺寸、长距离位置或影响表格阅读的属性。
- Hover 只能轻微改变背景、边界或阴影；现有局部位移不得超过 1px。不得新增弹跳、持续漂浮、呼吸灯、视差或循环装饰动画。
- `prefers-reduced-motion: reduce` 下必须沿用 `global.css` 停止动画、平滑滚动和非必要过渡；任何状态变化都不得依赖动画才能被理解。

## 6. 主题、响应式与可访问性

### 6.1 浅色与深色

- 浅色、深色和跟随系统三种模式必须由现有主题机制切换，不得在页面内创建独立模式。
- 深色模式必须保持深蓝灰、清晰边界和克制品牌色，不得变成纯黑、黑紫霓虹或高饱和赛博朋克主题。
- 主题切换后，正文、表格、编辑器、状态、图表、Tooltip、模态和焦点必须继续使用同一语义角色。
- 仅当原型实测与可访问性证据证明现有主题值不满足规范时，才能在独立任务中调整 `theme.ts`；不得把原型总结中的示例色值直接写入业务页面。

### 6.2 响应式与缩放

- 必须复用 `global.css` / `workspace.css` 已有断点；不得为视觉微调新增相邻、冲突的页面断点。
- 宽度不足时，指标和多栏布局必须依次减列、堆叠或进入 Drawer；表格只能在 `TableRegion` 内横向滚动。
- 低于现有移动断点时，页面标题与操作必须纵向排列，主要操作保持可见，表单控件占满可用宽度，详情使用全宽 Drawer 或独立页。
- 320px CSS 视口和浏览器 200% 缩放下不得出现页面级横向滚动、文字遮挡、焦点不可见或关键操作丢失。
- 200% 缩放验收必须使用真实浏览器缩放；不得只通过缩小窗口代替。

### 6.3 键盘、焦点与语义

- 所有操作必须可由键盘完成，并保持符合阅读顺序的焦点顺序；不得使用仅 Hover 才出现且无法聚焦的必要操作。
- 可交互元素必须使用原生语义或 Ant Design 组件，并具有可访问名称；图标按钮、Drawer、表格滚动区和复杂图表必须提供明确标签。
- `:focus-visible` 焦点必须清晰、连续且不被粘性区域或浮层遮挡。路由 pathname 变化后的焦点管理必须沿用 `AppLayout`，查询参数变化不得抢焦点。
- 模态、Dropdown 和 Drawer 必须沿用 Ant Design 的焦点圈定、Escape 关闭和触发器焦点恢复，不得手写第二套焦点管理。
- 移动端关键操作目标必须至少为 44 × 44 CSS px；桌面紧凑控件不得牺牲键盘可用性。

### 6.4 对比度与非颜色表达

- 普通文字与背景对比度必须至少为 4.5:1；大号文字至少为 3:1。
- 图标、输入边界、焦点指示和理解操作所需的非文字界面元素与相邻背景对比度必须至少为 3:1。
- 链接、选中、成功、警告、危险和图表序列不得只靠颜色区分，必须增加文字、图标、边界、线型、标记或位置。
- 禁用状态仅能降低视觉强调，文字仍必须可辨认；占位符不得承担必需说明。
- 玻璃、环境光和阴影不得降低正文、表格、坐标或焦点对比度。

## 7. 复用、例外与禁止模式

### 7.1 必须复用

- React、Ant Design、`@ant-design/icons`、现有系统字体栈和 `theme.ts` 的 Ant Design 映射。
- `PageHeader` 负责业务页标题、说明、面包屑和操作区。
- `MetricTile` 负责真实服务端指标，不计算业务口径。
- `TableRegion` 负责宽表的可聚焦、可感知横向滚动区域。
- `StatusTag` 负责已知状态的中文标签和语义 tone。
- 现有 QueryFailure、NoData、查询加载、确认、通知和表单能力。

不得新增 Tailwind、shadcn、第二套组件库、Web Font、图标库、通用 `PageShell`、卡片工厂、页面配置系统或只转发字段的视觉包装组件。

### 7.2 允许的局部例外

局部 class 仅能服务于真实业务布局、数据密度、打印或明确数据表达，并且必须：

1. 继续消费 `--ps-*` 或 Ant Design 语义值；
2. 不定义原始颜色、独立字体栈、平行状态色或通用卡片表面；
3. 不改变 API、权限、字段、状态、查询口径或保存行为；
4. 不被推广为页面级新主题；
5. 在窄屏、深色、200% 缩放和键盘场景下仍满足本文。

### 7.3 禁止模式

以下模式一律禁止：

- 营销官网式 Hero、聊天机器人界面、赛博朋克和霓虹科技风。
- 廉价紫蓝 AI 渐变模板、全容器高透明玻璃、纯白加纯黑的无层级后台模板。
- 巨大 KPI、无法解释的综合评分、过度圆角、全组件胶囊化、沉重阴影和高对比边框。
- 3D 图表、发光曲线、高饱和渐变柱、装饰性数据和仅靠颜色表达的数据。
- 电子元器件、芯片、PCB、工业仪表、工程图纸等与真实产品无关的行业暗示。
- 虚构数据、补零、未知事实猜测、未支持功能、自动伪造观测或固定成功路径。
- 页面硬编码颜色、页面级字体、重复 Token、独立深色覆盖、第二套状态标签或卡片体系。
- 新图标库、新 Web Font、新 CSS 框架和为视觉统一引入的推测性抽象。

## 8. 实施与验收清单

### 8.1 人工批准与自动视觉基线

- 人工批准资产保存在任务 `assets/approved/` 并由 `manifest.md` 记录页面、对应原型、最终文件名、SHA-256、视口、主题、批准者、北京时间和批准原话；自动快照不得替代此记录。
- `cross-page-visual-convergence.spec.ts` 固定保护 11 张基线：用户、Prompt、GEO 洞察各自的 1440×1000 浅/深色与 375×900 浅色九张，以及 Dashboard、内容审核的 1440×1000 浅色两张。
- 只有用户明确批准最终页面后才能创建或更新对应基线。未批准候选、当前实现自动生成图和单纯测试通过均不能证明设计获批。
- 动态身份、时间、正文和业务数值只能使用页面已有精确选择器遮罩；不得遮罩卡片边界、表头、行高、列对齐、三栏比例、共享壳层或其他稳定构图。
- 截图比较固定使用 `maxDiffPixelRatio: 0.02`，不得通过扩大阈值、整块遮罩、`skip`、固定成功数据或兼容 fallback 消除失败。
- 基线必须通过本地/CI 真实 API E2E 栈生成；缺少产品、任务、内容版本、平台或其他前置数据时显式失败，不得用虚构数据补齐。
