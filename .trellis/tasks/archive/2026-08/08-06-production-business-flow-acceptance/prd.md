# 生产环境全业务流程验收

## 目标

通过独立命名的 `playwright-cli` 会话，在 `https://geo.962850.xyz` 对上线后的真实页面执行一次可追溯、可清理的管理员端业务验收：覆盖从产品与事实、内容任务、AI 生成与审核、发布登记、GEO 观测到分析洞察的纵向闭环，同时覆盖平台、Prompt、AI 渠道与模型、用户、业务设置和审计等管理页面，并验证新的任务删除与归档后永久删除逻辑。

验收价值是确认真实公网、真实前后端、真实数据库、Celery Worker 和已配置 AI 服务共同工作，而不是重复本地 Mock E2E 的结论。

## 已确认事实

- 公网入口为 `https://geo.962850.xyz`；仓库文档将其定义为预发布环境。
- 当前前端共有登录、改密、工作台、产品列表/详情、内容任务列表/详情、内容编辑、发布管理、GEO 观测/洞察/打印/问题库/更正、业务设置、用户管理、审计日志、平台类型、平台、Prompt、AI 渠道列表/详情等路由。
- 现有 `mvp-flow.spec.ts` 已定义本地纵向闭环，`ai-channel-management.spec.ts` 已定义渠道管理闭环；本任务借鉴业务顺序，但必须通过临时交互式 `playwright-cli` 操作真实公网 UI，不直接把本地测试结果当作线上证据。
- 连接测试会调用真实模型，测试后模型保持停用，必须由管理员显式重新启用。
- 未成功发布且无 GEO 关系、无运行中生成作业的任务可普通删除；成功任务必须先归档，管理员输入固定文本 `永久删除` 后才能永久删除。永久删除只清理 PartSignal 内部记录，不处理外部页面。
- 当前工作树已有用户拥有的未跟踪 `.playwright-cli/` 产物；本任务不得清理、覆盖或提交这些既有文件。
- 用户已确认核心任务选择现有“知乎”平台；“发布成功”只在 PartSignal 内模拟第三方人工发布并登记测试 URL，后续人工 GEO 观测也只在站内模拟成功，不登录知乎、不访问或改动外部页面。

## 范围与要求

### R1：执行边界与证据

- 使用唯一前缀的命名会话，不使用 `default`，不复用其他任务的浏览器进程。
- 测试实体统一带本次运行唯一标识，操作前记录被复用配置的初始状态，操作后恢复非测试配置。
- 不在日志、快照、截图、任务文档或最终报告中记录密码、API Key、敏感 Header、Cookie、CSRF Token 或完整凭据。
- 对每个页面记录：是否可达、关键数据是否加载、至少一个主要交互是否成功、控制台或关键网络请求是否出现应用级失败。
- 发现失败后保留最小证据并停止依赖该失败步骤的后续链路；不在本任务内修改生产代码或绕过服务端规则。

### R2：核心纵向业务闭环

- 以唯一测试标识新建产品，维护产品事实与公开 Evidence，完成事实审核批准。
- 新建内容任务，选择测试平台与已启用模型，触发真实 AI 生成；等待真实 Worker 终态并检查生成内容与追溯信息。
- 覆盖内容编辑、提交审核、批准，以及在现有配置允许时的自然化流程。
- 在发布管理中完成内部发布工作、成功验证和文章身份登记，并核对任务进入完成态。
- 登记 URL 使用知乎域名下带本次唯一标识、明确不存在实际发帖含义的测试路径；系统只记录该字符串，不把外部可访问性作为成功依据。
- 基于测试文章创建人工 GEO 观测，查看详情、分析洞察、打印视图和问题库；在有安全测试数据时覆盖更正入口。

### R3：管理与配置页面

- 平台类型、平台、平台 Prompt：用专用测试记录完成创建、读取、编辑/绑定和可安全执行的删除或解绑；不得修改现有业务配置的正文或归属。
- AI 渠道与模型：检查现有渠道列表与详情，选择一个可明确用于测试的已配置真实模型，执行启用、连接测试、测试后停用状态确认和重新启用；不得读取、替换或回显现有密钥。
- 业务设置：覆盖发布账号的主要可安全交互，测试记录可删除时清理。
- 用户管理与改密：创建专用工程师测试用户，覆盖临时密码、首次改密、权限隔离、停用与无业务引用时删除；不修改管理员自身密码。
- 审计日志：核对上述关键动作存在对应记录且详情不泄露敏感值。
- 工作台、主题、导航、列表筛选、分页、抽屉/弹窗等共享交互做代表性检查，不做像素级视觉回归。

### R4：删除生命周期与清理

- 创建一个不进入成功发布的独立测试任务，验证普通删除确认与删除后不可查询。
- 对完成纵向闭环的测试任务验证：普通删除不可用或被拒绝、归档后从默认列表隐藏、归档筛选可见、恢复保持业务状态、再次归档、永久删除预览、错误确认文本不发送请求、正确输入 `永久删除` 后聚合消失。
- 永久删除后核对任务详情不可访问、相关内部发布/独占 GEO 记录按契约消失、共享记录不被误删，并在审计页核对最小墓碑。
- 清理本次创建且无保留价值的产品、平台、Prompt、账号、测试用户等记录；若契约因历史引用阻止删除，保留记录并在报告中列出准确原因，不通过绕过或数据库直改清理。

## 验收标准

- [ ] AC1：使用独立命名的 `playwright-cli` 会话登录真实公网，结束前关闭该会话并通过 `playwright-cli list --all --json` 确认不再开放。
- [ ] AC2：核心闭环从测试产品和批准事实开始，经过真实模型生成、内容审核、内部发布成功登记，最终形成可在 GEO 页面选择的测试文章；每一步均由真实 UI 和真实服务端状态证明。
- [ ] AC3：所有当前路由至少完成可达性、数据加载、主要入口与应用级控制台/请求错误检查；动态详情路由使用本次测试实体进入。
- [ ] AC4：平台类型、平台、Prompt、AI 渠道/模型、业务设置、用户和审计页面各完成至少一个与其职责匹配且可恢复或可清理的主要交互。
- [ ] AC5：真实模型连接测试成功或返回可解释的供应商错误；测试后模型停用状态被观察到，并恢复为启用状态。任何调用费用和供应商限额影响记入报告。
- [ ] AC6：专用工程师用户完成首次改密，无法访问管理员页面或接口，随后被停用并在无业务引用时删除。
- [ ] AC7：独立未发布任务普通删除成功，删除后列表和详情均不可再访问。
- [ ] AC8：完成任务的归档、隐藏、归档筛选、恢复、再次归档、永久删除预览、确认文本门禁与永久删除全链路均符合契约。
- [ ] AC9：永久删除不宣称删除外部页面；内部任务聚合、独占发布/GEO 关系和旧子记录按契约不可查询，共享数据保持存在，审计只保留允许的墓碑。
- [ ] AC10：测试结束后恢复所有复用的非测试配置；本次可删除实体已清理，无法清理项有实体标识、阻断原因和人工后续建议。
- [ ] AC11：产出简洁验收报告，按页面/流程标记通过、失败、阻断、未执行，附不含敏感值的关键证据和残余风险；不把启动服务、页面打开或固定成功响应当作通过。

## 不在范围内

- 不修改、部署或热修生产代码、数据库、契约和服务器配置。
- 不运行依赖本地 Mock Provider 的公网纵向 E2E，不放宽 `AI_ALLOW_LOCAL_HTTP=false`。
- 不执行像素级截图基线、全浏览器兼容矩阵、负载测试、渗透测试或穷举每个输入组合。
- 不删除、覆盖或改写现有非测试产品、事实、内容、发布、GEO、平台、Prompt、渠道、模型、用户或审计历史。
- 不通过 SSH、SQL 或 API 直写代替被验收的页面操作；只允许用只读运维信息安全取得登录所需上下文。
