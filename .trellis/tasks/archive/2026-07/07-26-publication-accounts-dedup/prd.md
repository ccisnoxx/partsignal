# 发布账号与重复发布约束

## Goal

让运营人员在每个具体平台维护多个可选发布账号，但一篇已批准文章在同一平台只能选择一个账号完成一次公开发布；同时把目标问题管理恢复到 GEO 观测语义下，消除人工发布缺账号时的错误跳转。

## Background

- 当前一个具体平台可以保存多条 `PlatformAccount`，候选查询也会返回该平台全部启用账号，但账号页面只有新增和物理删除，没有编辑、停用或启用。
- 人工发布 Drawer 已使用单选控件选择一个账号，但界面没有明确提示“一篇文章只能选择一个账号”。
- 缺少匹配账号时，“前往业务设置”只跳到 `/settings`，默认打开目标问题页，没有带上候选的 `platform_profile_id`。
- `QueryTopic` 是人工 GEO 观测选择的问题主题和覆盖分析维度，新普通内容任务已不再使用它；“历史目标问题”名称和业务设置位置都与当前用途不符。
- 发布登记目前只按 `idempotency_key` 防止同一请求重复，不能阻止同一内容换账号后在同一平台重复公开发布。

## Requirements

### R1 发布账号恢复入口

- 人工发布候选缺少账号时，“前往业务设置”必须跳到发布账号页面。
- 跳转 URL 必须携带当前候选的 `platform_profile_id`，账号页打开后直接按该平台筛选，新建账号时默认选中该启用平台。

### R2 GEO 问题库导航

- “历史目标问题”统一改名为“GEO 问题库”。
- 页面入口移动到“GEO 观测”导航组，与“观测记录”“分析洞察”并列。
- 业务设置不再显示目标问题入口；发布账号继续属于业务设置。
- 问题实体、API、人工 GEO 观测关联和既有历史数据保持不变，本项只调整页面命名、路由归属和权威方案文档。

### R3 发布账号维护

- 同一具体平台可以维护多个不同账号；平台归属创建后不可编辑，平台填写错误时新建正确账号并按既有引用规则删除错误记录。
- 工程师和管理员沿用现有发布运营权限，可以新增、编辑业务标签与运营账号标识、停用和重新启用账号；只有管理员可以物理删除未被发布记录引用的账号。
- `account_identifier` 定义为内部“运营账号标识”，不再限定为公开主页名称；允许填写平台用户名，也允许填写“注册手机号 + 持有人”等仅供运营识别的组合。
- 运营账号标识写入前去除首尾空白，保留原始大小写用于展示；同平台唯一性按 `lower(btrim(account_identifier))` 判断。
- 运营账号标识只在已认证的内部工作台和发布上下文中展示，不写入审计详情、日志或对外页面；它不是密码、Cookie、令牌或登录凭据。
- 停用账号保留历史引用和展示，但不再出现在新发布候选中；重新启用后恢复候选资格。
- 账号是可变聚合，增加 `revision`；编辑和启停必须提交 `expected_revision`，服务端行锁后校验并递增 revision。
- 同一平台内规范化后的 `account_identifier` 必须唯一，停用账号仍占用该标识；不同平台可使用相同标识。
- 新增、编辑和启停成功后追加审计，不保存密码、Cookie、令牌或其他凭据。

### R4 单账号选择提示

- 人工发布登记 Drawer 在账号字段附近明确显示“本篇文章只能选择一个账号”。
- 继续使用现有单选 `Select`，不得增加多选、批量发布或账号轮换逻辑。

### R5 平台内容防重复发布

- “同一篇文章”由不可变 `ContentVersion.content_hash` 判断；该哈希已经覆盖标题、摘要、Markdown 正文和标签。
- 判重范围是同一 `platform_profile_id + content_hash`；不同具体平台之间不互相阻断。
- 同平台同哈希已有 `PENDING_MANUAL_PUBLISH` 或 `PLATFORM_REVIEW` 尝试时，禁止再创建另一条待发布记录。
- 同平台同哈希任一发布记录的追加式状态历史曾进入 `PUBLISHED` 或 `VERIFIED` 后，永久禁止再次登记或公开发布；后续 `REMOVED`、`VERIFICATION_FAILED` 不撤销该事实。
- 只有从未公开、最终进入 `REJECTED` 的尝试允许换同平台的另一个启用账号重试。
- 发布登记和 `mark-published` 都必须执行同一权威检查，并使用基于 `platform_profile_id + content_hash` 的 PostgreSQL 事务 advisory lock 串行化；前端禁用按钮不构成防重。
- 冲突返回稳定 `409 DUPLICATE_PLATFORM_CONTENT`，不得静默复用、自动换账号或覆盖既有发布记录。
- 既有 `idempotency_key` 语义继续保留，负责同一请求的幂等重放；它不再承担业务防重复职责。

### R6 契约与历史

- 更新 OpenAPI、数据库契约、GEO 系统方案和前端生成类型，删除权威文档中“历史目标问题属于业务设置”的失效描述。
- 发布记录、状态事件、账号引用和 GEO 观测历史不删除、不改绑。
- 新迁移在创建账号唯一约束前显式检查既有重复标识；若无法无损判断保留哪条，迁移必须明确失败并要求人工处理，不得自动合并或删除账号。

## Acceptance Criteria

- [x] 无匹配账号的候选链接为 `/settings?tab=accounts&platform_profile_id=<当前平台 UUID>`，打开后显示发布账号并按该平台筛选。
- [x] 主导航在 GEO 观测下显示“GEO 问题库”，业务设置不再显示“历史目标问题”或目标问题 Tab。
- [x] 同一平台可创建两个不同账号，并可编辑标签/标识、停用、启用；停用账号不出现在候选账号列表，历史发布详情仍可读取。
- [x] “账号 A”“账号 a”以及两侧带空白的等价值在同平台创建和编辑时均返回明确 409；不同平台仍可使用该标识，并发写入由数据库唯一约束最终拒绝。
- [x] 账号页面使用“运营账号标识（内部）”语义，允许保存“手机号 + 持有人”组合，但审计详情和日志不包含该原值。
- [x] 人工发布 Drawer 明确显示“本篇文章只能选择一个账号”，请求仍只提交一个 `platform_account_id`。
- [x] 同平台同内容哈希存在进行中尝试时，第二次登记返回 `DUPLICATE_PLATFORM_CONTENT`。
- [x] 未公开记录进入 `REJECTED` 后，可选择同平台另一账号重新登记。
- [x] 任一同平台同哈希记录曾出现 `PUBLISHED` 或 `VERIFIED` 事件后，换账号、下线后重试或并发 `mark-published` 都返回 `DUPLICATE_PLATFORM_CONTENT`。
- [x] 相同内容哈希发布到另一个具体平台不受阻断。
- [x] 迁移测试覆盖空库升级、revision/唯一约束、既有重复数据阻断；后端集成测试覆盖账号维护、重试状态矩阵和并发门禁；前端测试覆盖导航、定向跳转、账号交互与单账号提示。
- [x] OpenAPI、Pydantic、生成 TypeScript 类型、数据库契约、GEO 方案文档与实现一致。

## Out of Scope

- 不保存或管理平台账号密码、Cookie、Token、浏览器 Profile。
- 不实现自动发布、批量发布、同文多账号分发或账号轮换策略。
- 不根据相似度、标题或 URL 猜测重复文章；只使用冻结内容哈希。
- 不改造 QueryTopic 数据模型、GEO 指标口径或人工观测表单。
- 不自动清理既有重复账号或重复发布历史。
