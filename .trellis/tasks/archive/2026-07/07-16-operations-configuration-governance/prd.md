# 后台运营配置与内容治理重构

## 目标

在项目开发阶段补齐运营后台的数据清理能力、中文界面一致性和平台配置层级，使管理员能直接管理测试数据，并让工程师在清晰的中文界面中按平台选择 Prompt 生成内容。

## 背景

- 当前项目仍处于开发阶段，测试产生的产品事实、平台规则、平台类型和 Prompt 需要可控地物理删除。
- 前端仍存在较多直接暴露给运营用户的英文字段，与中文后台的使用场景不一致。
- 现有配置中心已完成二级路由和渠道详情页重构，相关任务为 `07-13-configuration-center-navigation`；本任务不得覆盖其未提交改动，也不重复实现已有页面拆分。
- 当前 AI 渠道卡片未直接显示已启用模型，管理员必须进入渠道详情才能确认可用模型。
- 当前“平台类型与 Prompt”和“具体平台规则”仍是并列配置域，不满足新的平台级 Prompt 归属需求。

## 已确认现状

- 产品列表只有查询、新增和编辑接口，没有删除产品或事实版本的契约与路由（`contracts/openapi.yaml:187`、`contracts/openapi.yaml:216`、`backend/app/routers/product_facts.py:56`、`backend/app/routers/product_facts.py:113`）。
- 事实工作区中的参考型号、证据、参数、替代关系和内容声明已经采用“保存时整体替换”：被用户从表单移除的当前草稿记录会被物理删除后重建（`backend/app/services/product_facts.py:284`）。这不等同于删除产品或不可变事实版本。
- `FactVersion` 被审核记录和内容任务等历史对象以 `RESTRICT` 引用；产品也被事实版本、内容任务和 GEO 观测引用，不能依赖数据库级联无条件清除历史（`backend/app/models/product_facts.py:213`、`backend/app/models/content.py:51`、`backend/app/models/geo_files.py:31`）。
- 当前 `platform_prompts` 以 `platform_type_id` 为主键，每个平台类型最多一份 Prompt；具体平台仅保存 `platform_type_id`，没有独立 Prompt 绑定（`backend/app/models/configuration.py:39`、`backend/app/models/configuration.py:58`、`backend/app/models/configuration.py:80`）。
- 平台类型和 Prompt 已有管理员物理删除接口；平台类型被具体平台引用时返回冲突，删除平台类型会级联删除其 Prompt（`backend/app/services/platform_configuration.py:77`、`backend/app/services/platform_configuration.py:150`）。具体平台及其规则版本目前没有删除接口（`contracts/openapi.yaml:410`、`contracts/openapi.yaml:492`）。
- 现有 `07-13-configuration-center-navigation` 明确避免渠道列表模型 N+1 查询，因此卡片显示启用模型需要复用单次聚合返回或调整列表契约，不能从前端逐渠道补请求。
- 英文显示不仅存在于配置中心，还包括各业务页页眉 eyebrow、枚举选项和部分字段标签；`model_id`、URL、Header、API Key、JSON 等属于技术标识，应保留英文原值并仅补中文说明。

## 已确认需求

### R1 开发阶段物理删除

- 管理员可在前端物理删除没有历史引用的产品及其当前事实工作区。
- 产品及当前事实工作区的物理删除仅允许 `ADMIN` 执行；`ENGINEER` 不显示删除入口，直接调用接口也必须被服务端拒绝。
- 删除校验以操作当下的数据库引用为准；存在引用时服务端拒绝，并返回可供前端中文展示的引用对象类型。
- 管理员通过各业务对象自身允许的删除流程清理全部引用后，可以再次删除产品及当前事实工作区。
- 产品删除接口不得自动级联删除、改写或转移事实版本、审核、内容、发布、文件或观测历史。
- 平台 Prompt 可直接物理删除，因为生成作业只引用不可变 Prompt 内容快照。
- 平台规则版本仅在未被内容任务等直接业务历史引用时物理删除；实现前以数据库外键矩阵确认全部直接引用。
- 未被历史引用的 `ACTIVE` 平台规则版本也允许物理删除；删除后平台保留并进入“无有效规则”状态。
- 无有效规则的平台仍在管理员页面展示，但工程师不能选择它创建内容任务，直到管理员激活新的规则版本。
- 具体平台仅在规则版本、平台账号及其他直接引用全部清理后物理删除。
- 未被发布记录引用的平台账号允许管理员物理删除，为清理具体平台引用提供完整路径；已被发布记录引用时返回冲突。
- 平台类型仅在没有具体平台引用时物理删除；删除类型不得自动删除具体平台。
- 所有平台配置删除冲突都由服务端返回具体引用对象类型；管理员清理引用后可以重试。
- 平台配置删除不得自动级联删除或改写历史业务记录。
- 删除操作必须由服务端鉴权和关系约束决定，前端隐藏按钮不能替代权限控制。

### R2 运营界面中文化

- 中文化覆盖整个运营前端，而不只覆盖产品事实和配置中心。
- 所有面向管理员和电子工程师的页眉副标题、状态、枚举选项、字段标签、操作、提示、校验错误和空状态统一为中文。
- `model_id`、API Key、URL、Markdown、JSON、Header 等行业或协议术语，以及模型 ID、参数键和代码标识符保持原值，不做错误翻译；必要时在界面补充中文说明。

### R3 AI 渠道卡片

- 改善渠道卡片的信息层级和视觉呈现。
- 渠道卡片直接完整显示该渠道所有已启用模型的显示名与 `model_id`，使用可换行标签；没有启用模型时显示“暂无启用模型”。
- 渠道列表通过单次请求返回模型摘要，前端不得为每张卡片发起模型列表 N+1 请求。
- 首期不增加模型截断、展开、悬浮详情或卡片内模型操作。
- 渠道详情继续承载模型发现、新增、编辑、测试、启停和删除，不在卡片上复制完整管理能力。

### R4 平台配置关系

- 平台类型、平台和 Prompt 形成清晰的业务层级。
- 配置中心导航设置三个并列页面：`平台类型`、`平台管理`、`Prompt 管理`；不恢复单页 Tabs 或嵌套大弹窗。
- 平台类型下绑定多个具体平台。
- 平台类型继续由管理员按业务需要增删改查，不收敛为固定五种系统枚举。
- 每个具体平台首期最多绑定一份当前 Prompt；Prompt 是普通 Markdown 文档，管理员保存时覆盖当前内容。
- 不同具体平台可以保存不同 Prompt；工程师选择平台后自动使用该平台当前 Prompt，不再单独选择 Prompt。
- 未配置当前 Prompt 的平台仍在管理员页面展示，但工程师不能选择它创建内容任务；前端显示“未配置 Prompt”，服务端创建接口执行同一校验。
- 内容任务只保存所选平台关系并展示该平台当前 Prompt，不复制可变 Prompt 内容。
- 每次创建生成作业时读取平台当前 Prompt，并把平台身份和 Prompt 完整内容写入不可变作业快照；管理员后续修改或删除当前 Prompt，不影响已有作业。
- 数据迁移直接把 Prompt 所有权从平台类型改为具体平台，不保留旧字段、旧接口或兼容分支。
- 旧平台类型 Prompt 复制给该类型下的每个现有具体平台；没有具体平台可归属的孤立 Prompt 直接删除。
- 管理员负责平台类型、平台和 Prompt 的增删改查，普通工程师只使用已启用配置生成内容。

## 交付拆分

- `07-16-configuration-hierarchy-cards`：先完成 Prompt 所有权迁移、平台可用性契约、生成快照、三个并列页面和渠道卡片。
- `07-16-controlled-physical-deletion`：依赖新的平台关系，补齐产品、平台规则版本、平台、平台账号和平台类型的受约束删除。
- `07-16-frontend-chinese-localization`：在最终页面结构上完成全站用户可见文本中文化，避免对即将删除的旧页面重复修改。
- 父任务最后统一更新业务/技术方案文档、相关 Trellis 规范并执行跨子任务验收。

## 验收标准

- [x] 管理员可从前端物理删除没有历史引用的产品及其当前事实工作区，删除结果与数据库一致。
- [x] 工程师看不到产品物理删除入口，直接请求删除接口返回权限错误。
- [x] 产品存在历史引用时删除失败并显示具体引用类型；清理全部引用后重试可以成功。
- [x] Prompt、平台规则版本、具体平台和平台类型均有物理删除入口，并按各自引用条件成功或返回具体冲突类型。
- [x] 未引用的平台账号可物理删除；被发布记录引用的平台账号返回包含引用类型的冲突。
- [x] 删除未引用的当前有效规则后，平台显示“无有效规则”，工程师选择集合立即排除该平台；激活新规则后恢复可用。
- [x] 运营用户可见界面完成中文化扫描，不再出现可合理翻译但遗漏的英文标签或状态。
- [x] 技术标识符和外部协议值保持原样，不因中文化而改变请求或存储值。
- [x] AI 渠道卡片在不进入详情页时即可看到全部启用模型的显示名与 `model_id`，列表只发起一次业务请求，并在空模型、长模型 ID 和移动端场景下正常展示。
- [x] 平台类型可管理所属平台，每个平台最多维护一份当前 Prompt；工程师选择平台后自动使用并在生成作业中锁定该 Prompt 快照。
- [x] 未配置 Prompt 的平台不进入工程师可用平台集合，绕过前端创建内容任务也会被服务端拒绝。
- [x] 配置中心以三个并列导航入口管理平台类型、平台和 Prompt，路由选中态、权限和移动端导航一致。
- [x] 管理员权限、普通工程师可见性、删除冲突和历史引用均有自动化测试覆盖。
- [x] 最终实现与 `07-13-configuration-center-navigation` 的现有路由、页面和未提交改动兼容，不产生第二套配置中心实现。

## 非目标

- 不新增 AI 供应商协议或模型调用路径。
- 不实现固定五种平台类型、五类批量 `TYPE_BASE` 内容或 `TYPE_BASE → PLATFORM` 两级生成；保持选择具体平台后单次生成完整内容。
- 不把协议字段、模型标识、URL、Header 或 JSON 参数键翻译为中文。
- 不在渠道卡片复制 Header、凭据、模型测试等详情管理功能。
- 不用级联删除绕过历史业务数据的归属和审计约束。
- 不为事实版本、内容任务、内容版本、发布、文件或观测等所有历史对象新增通用物理删除 API 和前端入口。
- 开发环境需要整体清空关联历史时使用项目已有的受控数据库重置流程，不把环境清理能力做成永久业务接口。
