# 支持删除发布成果

## Goal

让管理员能够从发布管理页删除错误登记、测试产生或不应继续保留的发布成果，同时由服务端在一个明确的业务边界内处理该成果拥有的发布历史、来源任务状态和下游引用，避免继续把“审计可追溯”错误地等同于“成果实体绝对不可删除”。

## Background and Confirmed Facts

- 当前成果详情明确显示“发布成果为只读历史，不提供修改或删除”，且成果动作类型只有 `OPEN_ISSUE`：`frontend/src/features/publications/PublicationsPage.tsx:502-564`、`backend/app/schemas/publication.py:26`。
- 当前 OpenAPI 仅提供成果列表、详情和登记内容问题，没有成果删除端点：`contracts/openapi.yaml:2121-2217`。
- `PublishedArticle` 与 `PublicationWork` 共用 ID；成功核验会同时完成发布工作和来源 `ContentTask`，因此只删除 `published_articles` 行会留下仍为 `COMPLETED` 的工作和任务，不能表达真正的“删除发布成果”：`backend/app/models/publication.py:211-225`、`backend/app/services/publication.py` 的成功核验流程。
- 成果拥有内容问题，并被 GEO 观测发布集合和引用记录用作文章身份；GEO 关系不复制成果标题或 URL：`.trellis/spec/backend/publication-workbench-guidelines.md:67-69`。
- 当前唯一合法清理路径是管理员先归档来源内容任务，再永久删除整个任务聚合；该路径会删除成果、问题、发布事件和核验，也会清理任务拥有的其他内容历史，粒度大于“删除一个发布成果”：`backend/app/services/publication.py:1322-1369`。
- 项目已有服务端 `available_actions`、required nullable `deletion`、`DeletionProjection`、危险操作确认、删除条件说明、revision 校验和保留型删除审计，可复用同一合同，不需要另建删除框架：`.trellis/spec/backend/available-actions-contract.md`、`backend/app/schemas/common.py:47-65`。
- 已归档任务永久删除不会验证或删除外部公开页面；发布管理系统也没有外部平台删除凭据，因此本任务只能删除内部业务记录，必须向用户明确外部页面仍可能存在。

## Requirements

### 1. 删除所有权

- 删除必须以发布成果所属的完整发布聚合为边界，不能只删 `PublishedArticle` 读模型后留下 `COMPLETED` 的 `PublicationWork`、核验、事件或来源任务状态。
- 服务端是删除资格、权限、依赖范围和状态转换的唯一权威；前端只消费 typed `available_actions` 与删除投影。
- 删除命令必须使用当前 revision、锁定权威记录、在事务内复核依赖并保证全成或全不成；不得依赖前端资格投影或裸外键错误。
- 删除成功保留最小删除审计，但不保留一套可恢复的成果副本或第二业务状态源。
- `PublishedContentIssue`、发布事件、核验和附件关系属于被删除发布聚合的内部范围；由问题创建的修复任务是独立任务，必须保留并通过现有外键语义解除来源问题关联。
- `GeoObservationPublication`、`GeoObservationCitation` 和 `ContentTaskGeoSource` 属于独立下游历史，不得级联、置空或静默解绑；任一引用存在都必须阻止成果删除。

### 2. 来源任务与可再次发布

- 删除发布聚合后，来源内容与已批准版本继续保留，来源任务不得保持虚假的 `COMPLETED`。
- 未归档来源任务应恢复到能够再次进入发布流程的权威状态；已归档来源任务保持归档属性，恢复后也必须能够重新发布。
- 删除不得修改已批准内容正文、事实版本或外部公开页面。

### 3. API、权限与前端

- OpenAPI 为发布成果增加服务端投影的删除能力、依赖预览和单次删除命令；后端 Pydantic 与生成 TypeScript 类型必须同步。
- 删除属于管理员危险操作，普通用户不得获得删除投影或调用删除端点。
- 发布成果列表与详情使用同一服务端资格；可删除时提供明确危险确认，不可删除时展示精确依赖和处理建议。
- GEO 观测中的发布集合和引用按去重后的观测数量投影为 `GEO_OBSERVATION`，GEO 优化任务来源投影为 `GEO_OPTIMIZATION_SOURCE`；无这两类引用的成果必须允许删除。
- 确认文案必须说明会删除哪些内部历史、来源任务会发生什么变化，以及不会删除外部公开页面。

### 4. 一致性与验证

- 更新数据库合同、发布工作台规范和 GEO 系统设计，使成果生命周期、删除边界和下游引用处理与代码一致。
- PostgreSQL 集成测试必须覆盖权限、revision、事务原子性、来源任务恢复、拥有记录清理、下游引用和数据库不可变守卫。
- 前端组件与浏览器回归必须覆盖删除可用、删除阻断、确认范围、成功刷新和失败后保留权威数据。

## Out of Scope

- 调用第三方平台删除外部文章，或声称内部删除代表外部页面已经下线。
- 批量删除、自动清理测试数据、按标题或时间猜测测试成果。
- 新建通用删除框架、回收站或与现有动作投影并行的权限系统。
- 修改已批准内容正文、事实版本或无关内容任务。

## Acceptance Criteria

- [x] 管理员在发布管理页能看见发布成果的删除能力或精确删除条件；普通用户看不到也无法调用。
- [x] 删除命令按一个发布聚合原子清理成果拥有的工作、事件、核验、附件和内容问题，不留下半删除状态。
- [x] 删除后来源内容与批准版本仍存在，来源任务不再是虚假的 `COMPLETED`，并可按归档状态恢复后重新发布。
- [x] 并发修改、过期 revision、权限不足或依赖阻断时不删除任何业务记录，也不写成功审计。
- [x] 不存在 GEO 观测/引用和 GEO 优化来源的成果可以删除；存在任一引用时返回精确类型与数量，成果及全部下游历史保持不变。
- [x] 成果问题随聚合删除；已有修复任务继续存在且不再引用已删除问题。
- [x] 用户在确认前能看到内部删除范围和外部页面不会被删除的明确说明。
- [x] OpenAPI、数据库合同、后端模型/服务、生成类型、前端行为、测试和权威设计文档一致。

## Notes

- 本任务修改公开 API、数据库生命周期、权限、状态转换和跨模块引用，属于复杂任务；实施前必须具备可审阅的 `design.md` 与 `implement.md`。
