# CORE-06 管理员显式重新分析

本轮仅本地实现及必要定向验证，不操作线上、不暂存提交推送。浏览器上传NOT_RUN_NO_EXISTING_PLATFORM与原外部等待边界保留，不新增自动跟进。

## 交付与完成条件

- 管理员通过服务端REANALYZE动作显式选择闭合原因，提交Run revision；新增HTTP入口复用reanalyze_run，保留User→Batch→Run锁、当前字典/批准事实冻结、同输入复用、事务审计和commit后派发。
- 返回实际接受的分析ID及诊断请求ID，不伪装为已完成或必然新建。历史版本可追溯，目标PENDING/COMPLETED/FAILED及当前指针从现有详情读取；终态Run有待处理分析时继续详情轮询。
- COMPLETED/NEEDS_REVIEW/FAILED且保有采集回答才可尝试；ADMIN、active、改密及总开关由服务端裁决，工程师不可通过直接POST绕过。FAILED不恢复为成功，原回答、历史分析/复核和采集时间/状态保留。
- pending防重复；409保留原因，显式重读后重新确认；未知结果冻结本次表单，只重读历史核对，不自动或原请求重放。允许明确关闭核对，不宣称取消后台分析或已经识别原请求结果。
- 主体撤销/卸载、旧读取迟到、确认后刷新失败均有安全行为。必要权限/事务/派发/历史及前端/实际路由验证通过，独立只读复核公共/并发边界。
