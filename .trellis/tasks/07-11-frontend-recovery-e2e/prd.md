# 前端失败恢复与全 UI 验收

## Goal

让关键业务页面明确区分加载、失败、无权限和真实空状态，并用不绕过 UI 的端到端场景证明补齐后的 MVP 主闭环可操作。

## Requirements

- 内容任务、发布、GEO 和事实工作区的依赖查询必须分别处理加载、失败、无权限和空数据。
- 查询失败显示可定位错误与重试，空状态提供正确前置操作入口，依赖未就绪时禁止提交。
- 关键恢复文案与操作使用中文，不把服务端失败伪装为空选择或空页面。
- 核心端到端测试必须通过用户界面完成任务创建、生成、审核、发布、验证、观测和更正，不用 `page.request` 绕过被验收步骤。
- 发布、审核和 GEO 子任务分别实现自身正常业务 UI；本任务只实现共享加载/失败/无权限/空状态、工作台聚合导航和最终跨域验收，不重复实现领域页面。
- E2E 可以通过受控 fixture 准备账号、平台、批准事实和测试模型等非本轮前置条件，但从内容任务创建开始的被验收业务步骤必须全部走 UI。

## Acceptance Criteria

- [ ] 关键依赖分别模拟 `500`、`403` 和空数组时，界面显示不同状态和可执行恢复动作。
- [ ] 查询错误可重试，空数据可进入正确前置配置，未就绪表单无法提交。
- [ ] 至少一条完整主闭环 E2E 全程通过 UI 完成，并覆盖发布平台一致性、审核证据、自动完成和 GEO 更正。
- [ ] 对新增 P0/P1 交互补充针对性组件测试，失败路径不以固定成功 Mock 掩盖。

## Dependencies

- 在 `07-11-publication-task-closure`、`07-11-review-evidence` 和 `07-11-geo-integrity-analysis` 契约稳定后进行最终收口。

## 最终计划同步

- 有效优先级：`P1`；属于最终执行顺序 Goal 4。
- 本任务不新增公共 API 或数据库变化，只消费 Goal 1～3 已冻结契约。
- `QueryFailure` 必须展示稳定错误码、request ID 和 retry；403 使用独立无权限状态，不提供无意义写重试。
- 业务 empty 状态由领域页面定义准确前置入口；共享组件不得根据空数组猜测业务原因。
- 从创建内容任务开始的生成、审核、发布、异常修复、GEO 更正和 Dashboard 深链均属于 E2E 被验收步骤，禁止使用 `page.request` 执行。
- 稳定路由使用发布 ID 定位发布详情、使用 `PublicationAttention` ID 定位异常详情与修复；不得从列表临时状态推断当前资源。
