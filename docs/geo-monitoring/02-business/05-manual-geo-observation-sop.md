# 人工 GEO 回答级观测 SOP

| 项目 | 内容 |
|---|---|
| 状态 | 已批准操作规范；依据本会话用户产品决策及 ADR-006 |
| 适用 | 核心版 MANUAL 回答级 Batch/Run；豆包、DeepSeek、元宝等人工观测 |
| 执行责任 | 计划指定员工执行；管理员维护配置；分析/复核人员按既有权限处理。具体人员由公司指定 |
| 边界 | 不授权 Browser 自动化；不改变 MANUAL/API 合同、指标或历史 |

决策见 [ADR-006](../05-decisions/ADR-006-defer-browser-collection-and-adopt-manual-first-core.md)，状态与证据流程见 [业务流程](./03-workflows-and-state-machines.md#5-人工采集流程)。本 SOP 使用当前正式表单，不能把目标设计当已上线能力。

## 1. 从计划领取 Run

1. 管理员准备明确平台的 MANUAL 观测面/Profile，配置语言、地区、登录模式、联网搜索策略、截图要求；每个平台使用独立配置。员工使用批准的人工访问方式，非公开问题仍按公司的数据外发规则处理。
2. 在 `/geo/plans` 预览计划，由服务端生成 `问题 × Profile × repeat` 矩阵。创建批次后，在 `/geo/runs` 选择 PENDING MANUAL Run，记下 Batch ID、Run ID、repeat_index 与计划窗口。
3. 计划协调人员明确每个 Run 的执行员工，避免两人同时人工提问。“领取”是工作分配，当前系统没有人工独占 claim/租约按钮；打开录入或保存草稿不授予独占权。出现草稿 revision 冲突时重新读取并协调，禁止覆盖他人内容。
4. 核对冻结问题及环境。无法按该环境采集时保持草稿/待执行，通过正确配置创建新的合适 Run，不修改旧 Run 的冻结输入。

## 2. 使用精确问题并记录环境

- 从 Run 输入快照复制完整精确问题，不改标点、型号、顺序或点名属性，不额外追加品牌提示或产品事实。只选择本 Run 对应平台。
- 在平台人工打开新的对话；有临时/无记忆方式时使用该方式。记录实际对话模式，不声称平台没有提供的隔离能力；不要沿用有额外上下文的旧对话作为同口径重复样本。
- 核对并记录平台/产品名称、语言、地区和登录模式。语言/地区/登录来自冻结 Profile，在录入页只读；现场必须匹配。可见的搜索状态据实选是/否，无法判断保持未知。
- 在“实际采集时间”填写回答完成时间并显式包含时区；不以录入时间替代历史采集时间。在来源产品/模型/版本字段只填平台实际可见标识，未知保持空，不根据品牌推测模型版本。
- 不上传账号头像、姓名、手机号、Cookie、密钥、浏览器 storage state、登录/支付/调试页面。截图裁去这些区域，同时保持问题、回答和来源证据可辨认。员工人工登录不导入 PartSignal Browser 会话。

## 3. 保存完整回答原文

等待平台回答自然完成后，复制完整可见原文，包括标题、列表、表格、免责声明及引用标记。不得改写、摘录、润色、补全截断回答或将自己的说明插入回答正文。按实际内容选择 TEXT/MARKDOWN 等表单格式，核对粘贴后完整性。

平台报错、访问挑战、空白或仍在生成时不正式提交成功回答。保留安全截图和草稿，通知计划协调人员；按现有可用取消/补测入口处理，不把失败录成“无提及”。普通页面把缺失/失败说明放在合并截图的独立说明区；表单没有任意附件、备注或新增文本证据关联入口，不将说明塞入回答正文或安全 raw summary。既有人工录入 API 支持关联合法 EVIDENCE 的 text/plain 文件，但不等于页面已提供该功能。

## 4. 登记引用与缺失原因

1. 按回答/来源面板的实际顺序逐条记录来源标题、原始完整 URL、位置（从 1 开始）；重复出现按真实位置保留，由服务端规范化/合并。不得按自有来源优先重排。
2. 核对服务端从 URL 派生的规范域名；域名不在表单中单独自由填写。平台只显示标题或短域名时不能猜完整 URL，不能用搜索到的相似网页替代该次引用。
3. URL 不可见时保存来源面板截图，并在独立证据说明中登记 Run ID、实际来源标题/顺序、可见域名（如有）、缺失项及原因，如“平台未展示完整 URL”。普通页面将说明合并到证据图的独立说明区；只有使用既有且有权限的人工录入 API 上传/关联流程时，才可通过 text/plain 原始证据文件保留，页面只显示/保留已有 raw_payload_file_id；不得覆盖或改写回答原文，也不伪造 URL 通过校验。
4. 当前结构化 Citation 必须有有效 URL，没有 URL 缺失原因专用字段。若只能登记部分来源，必须保留草稿与截图/原因，在补齐该次全部来源 URL 前不得正式提交；也不能把已知来源一并省略以回避完整性要求。当前服务端可能将非空但不完整的引用列表算入引用指标，截图说明和分析复核都不会自动使缺失引用变为 N/A；复核人员不能放行此类部分样本。全部 URL 均不可提取且保留完整截图/原因的样本，可据实不登记结构化引用，但不能宣称“平台没有引用”；当前服务端将无结构化引用的此类样本排除出引用指标，其他指标仍按各自资格裁决。
5. 无引用、未观察到引用、引用无法提取是不同情况。仅确认整段回答与完整来源面板后才描述“未见来源”；不要把缺失证据变成零覆盖结论。

## 5. 上传回答与来源截图

同时保存回答（包含精确问题）和来源面板截图，覆盖完整回答与来源顺序。当前每个回答只能关联一个 `screenshot_file_id`；多段截图在本地合并为一份 PNG/JPEG/WebP 证据图，明确拼接顺序，并把证据说明放在独立区域，不能遮挡或修改回答内容。

使用现有截图上传入口；文件类别 OPERATION_SCREENSHOT，INTERNAL/RESTRICTED，最大 10 MiB。检查文字清晰、无敏感账号区域，上传完成并验证后才关联。提交者必须关联自己上传的文件。可选原始 text/plain 证据属于 EVIDENCE、最大 50 MiB，仅通过既有有权限的文件/人工录入 API 上传并关联；当前页面没有新增上传/关联该文本的入口，只保留已有引用。常规页面操作将缺失说明并入单截图，不改扩展名绕过格式限制。无法在现有限制内完整保存时先留草稿，与复核/运维人员处理，不宣称已保存完整证据。

## 6. 保存草稿与正式提交

正式提交前逐项核对：Run/平台/冻结环境正确，精确问题一致，回答完整非空，实际带时区时间正确，引用及缺失证据真实，截图已验证且无秘密，模型/版本未知未猜测。草稿保存后可继续编辑，但不要重复向外部平台提问以挑选更好的答案替换本次采样。

正式提交通过既有权限、revision、文件归属与完整性校验，原子冻结 AnswerSnapshot、引用和文件，Run 进入 COLLECTED。提交回执不表示分析已完成。成功后不能编辑、覆盖或补写原始证据；发现错误时保留历史，报告原因，通过新独立采样或既有分析复核处理。响应不明时先刷新确认结果，不盲目重复提交或重新提问。

## 7. 分析与人工复核

查看 Run Detail 的分析/复核状态。分析失败时保留 FAILED 状态、原始证据及历史，通知计划负责人处理；当前版本没有公共重新分析 API、CLI 或页面动作，不重置失败状态、不承诺恢复指标资格。既存失败摘要中的“可显式重新分析”描述内部分析能力，不代表已交付员工可执行的入口；摘要属于历史记录，不能改写。NEEDS_REVIEW 按权限确认或修正提及、推荐、引用归属、声明及事实判断，复核追加记录。新的分析 revision 需要重新检查有效复核，不能用旧复核替代。

复核人员对照原文和截图，不补造引用或产品事实；不确定结论保持未知。复核只改变分析结论，不编辑原始答案。未通过必要复核的运行不得手工算入业务指标。

## 8. 数据资格与重复采样

- 从计划预先设定 repeat 和窗口，每个 repeat 对应一个独立 Run/回答，所有样本都保留。不得将同一回答/截图复制到多次重复、丢弃低表现样本、以取消失败替代成功零表现或事后挑选最佳答案。
- 精确问题版本、平台/Profile、MANUAL 模式、语言、地区、登录、搜索策略及规则应一致。环境变化另建正确采样配置/基线；MANUAL 不与 API/BROWSER 静默合并。
- COMPLETED、当前有效分析、必要人工复核、适用对象/问题和可比维度等资格仍由服务端裁决；缺引用证据或可靠排序时，相应指标可能不可用，空分母为 NULL。不要在表格里补零或维护另一套公式。
- 样本量和质量等级使用现有规则集与报告提示；样本不足不宣称趋势、不触发趋势型机会。每个结论回到 Run、原文、截图、引用与当前分析/复核。
- 严格复测按既有预览和基线门禁执行。模型/产品版本未知或环境变化可能阻断复测，不用人工备注或相似问题绕过；需要新基线时明确记录不可比原因。
- 证据依现有权限和保留规则管理；本 SOP 不新增保留天数、不删除历史。计划负责人分配采样与复核责任并处理缺失证据，具体频率按已批准人工访问范围执行。
