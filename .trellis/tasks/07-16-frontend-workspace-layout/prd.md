# 前端业务工作区布局重塑

## Goal

在保留现有 macOS 浅色/深色磨砂框架、业务信息架构、字段、操作入口、流程、权限、路由和数据契约的前提下，重塑列表/配置页与详情/审核长页面的空间结构，使高频业务信息更易扫描、关键操作更易定位，并减少卡片堆叠造成的视觉噪声与长页面的导航成本。

## Confirmed Facts

- 上一轮 `07-16-macos-glass-ui` 已完成并归档；全高磨砂侧栏、粘性磨砂顶栏、双主题 token、内嵌内容画布和玻璃使用边界继续作为本任务基线。
- 用户明确不满意的范围是列表与配置页、详情与审核长页面；登录页、工作台指标结构、全局导航信息架构、配色和玻璃材质不是本任务重点。
- 当前集合页主要使用 `PageHeader + Card + Table`；AI 渠道页例外，使用最低约 310px 的卡片网格。多数详情页使用 `PageHeader + 纵向 Card`，内容审核页在 `16/8` 外层中再次平分 Markdown 与预览，宽屏利用率不足且后续区块较长。
- `/products/:productId`、`/tasks/:taskId`、`/content/:contentVersionId`、发布详情与 `/configuration/ai/channels/:channelId` 已有稳定深链接和返回路径，不能增加同页详情状态作为第二套导航来源。
- 项目使用 React 19、TypeScript、React Router、Ant Design 6、TanStack Query 和共享 `global.css`；现有 `PageHeader`、`TableRegion`、Ant Design Table/Grid/Tabs 与章节导航可复用。
- `ui-ux-pro-max` 的相关可用结论是 Data-Dense、Minimalism、表格局部横向滚动、稳定粘性区、清晰焦点和多断点验证；其夸张字体、Web Font、GSAP 和展示型动效与项目目标冲突，不采用。
- 任务已在用户批准后进入 Codex inline 实施；实现必须继续遵守本文件的业务边界与完成门禁。

## Requirements

- **R1 业务边界**：保留现有导航层级、页面路由、字段集合及业务顺序、操作入口、业务步骤、权限判断、请求、状态转换、查询失效和交互语义。
- **R2 视觉连续性**：继续使用已完成的 macOS 浅色/深色磨砂设计系统；本任务只调整页面布局层级、组件编排、密度和响应式呈现，不重做主题、侧栏或顶栏。
- **R3 集合页范围**：统一处理 `/products`、`/tasks`、`/publications`、`/observations`、`/users` 的列表/工作区，以及 `/settings` 和 `/configuration/*` 的配置集合页；每个数据集使用紧凑页面上下文、所属工具栏和一个主要数据表面。除 AI 渠道卡片改表格外，继续保留承担标题、`extra`、提示、错误、空态或加载职责的 Card DOM，只收紧其视觉密度。
- **R4 配置列表形态**：AI 渠道首页改用行式列表或 Ant Design Table，完整保留名称、状态、API 根地址、超时、API Key 状态、Header 数量、已启用模型、查看详情、启停和删除入口；详情仍进入现有稳定路由。其他已使用 Table 的配置页只统一外层布局，不重写数据表。
- **R5 详情页范围**：统一处理产品事实、内容任务、内容审核、AI 渠道、发布记录、发布异常和修复任务详情；按页面职责使用摘要、主内容、对照内容、决策依据和次级区块，不强迫所有详情页使用同一列数。
- **R6 审核工作台**：内容审核页在 1440px 桌面视口同时呈现 Markdown、清理后预览和决策依据，建议比例约 `5:4:3`；章节入口和唯一一套审核操作共用同一个粘性工具条。中等视口先降为主内容双列加全宽决策区，小视口再降为单列。
- **R7 长页面导航**：复用现有章节锚点模式，为内容审核、内容任务详情和 AI 渠道详情提供粘性章节导航；产品事实保留现有导航，只有一至两个主要区块的发布详情不强加导航。条件区块的链接必须与目标使用相同条件渲染，区块继续按现有业务顺序留在同一文档流中，不用 Tabs、Collapse 或内部滚动隐藏审核证据和历史。
- **R8 密度与表面**：延续“框架宽松、业务区中等紧凑”；集合页减少无标题 Card 套 Table 的重复边界，长正文控制可读宽度。普通业务表面保持接近不透明，不新增 `backdrop-filter`。
- **R9 响应式与可访问性**：375px、768px、1024px、1440px 下无页面级横向滚动、粘性区域遮挡、不可达操作或双重滚动；表格只能在 `TableRegion` 内横向滚动。保持语义标题、键盘顺序、焦点可见、颜色非唯一状态提示、双主题对比度、200% 缩放和 `prefers-reduced-motion` 支持。
- **R10 最小实现**：优先复用现有组件、CSS 变量和 Ant Design；只增加实际被多个页面使用的布局类，不建设通用页面构建器、Schema 驱动布局、新 Provider、新状态层或新运行时依赖。

## Acceptance Criteria

- [x] **AC1**：所有 R3 集合/配置页使用一致的紧凑页面上下文与数据表面；字段、筛选、分页、状态、操作和空/错/加载状态完整保留。
- [x] **AC2**：AI 渠道首页不再使用大卡片网格；单行可扫描 R4 的全部信息与操作，点击渠道名称或详情入口仍进入 `/configuration/ai/channels/:channelId`，浏览器返回恢复集合页。
- [x] **AC3**：内容审核页在 1440px 下同时清晰呈现 Markdown、预览和决策依据，审核操作在主要阅读区域可达；Markdown 与预览不再嵌套于被二次平分的窄列。
- [x] **AC4**：内容审核、内容任务、AI 渠道和既有产品事实长页提供键盘可用的章节导航；条件链接不存在死目标，锚点不会被 72px 粘性顶栏遮挡，业务区块顺序与内容保持不变。
- [x] **AC5**：在 1024px 及以下按设计矩阵降级为双列或单列，不隐藏字段或操作，不增加独立移动业务流程。
- [x] **AC6**：浅色、深色和 `system` 模式下沿用现有 token 与玻璃边界；普通 Card、Table、Form、Markdown、审核区和配置区未新增模糊。
- [x] **AC7**：列表筛选、分页、详情导航、返回、表单提交、审核操作、危险操作确认和浏览器返回行为与改造前一致。
- [x] **AC8**：375px、768px、1024px、1440px 与 200% 缩放下，`documentElement.scrollWidth <= clientWidth`；宽表仅在 `TableRegion` 内滚动，粘性区不遮挡首项、末项或主操作。
- [x] **AC9**：相关单元测试、`npm run api:check`、Lint、类型检查、全量测试、构建和现有功能 E2E 通过；真实浏览器检查覆盖至少一个普通列表页、AI 配置页、内容审核页和产品事实长表单的四档视口与双主题。
- [x] **AC10**：diff 不包含后端、契约、数据库、部署、运行时依赖、主题架构或无关页面变化；不恢复截图基线。

## Out of Scope

- 修改登录页、工作台指标结构、品牌配色、主题 token、玻璃材质规则、全局侧栏或顶栏信息架构。
- 增删、合并或重排业务字段、操作入口、导航层级、页面路由或业务步骤。
- Finder 式同页主从详情、第二套路由状态、拖拽布局、可配置仪表盘、虚拟列表、页面构建器或新的设计系统文件。
- 用 Tabs、Collapse、固定高度内部滚动隐藏审核证据、差异、追溯或历史。
- 修改后端、OpenAPI、数据库、部署配置或业务数据。
