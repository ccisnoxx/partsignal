# 前端视觉系统重校准设计

## 1. 设计目标与共享不变量

本任务解决的是“已有页面虽然使用同一套 Token，但缺少经过批准的统一视觉标尺”，不是重新设计业务流程。四个批准锚点共同决定视觉结果：

- `13-dashboard.png`：总览、壳层、环境光、指标和状态；
- `01-users.png`：标准列表、筛选、表格和辅助详情；
- `08-geo-insights.png`：分析图表、矩阵和数据密度；
- `12-content-review.png`：复杂编辑审核工作区。

所有页面必须保持以下共享不变量：

1. API、权限、路由、URL 状态、服务端状态和真实可用操作不变；
2. `visual-system.md` 是唯一人类可读规范；
3. `theme.ts` 是运行时语义值唯一来源；
4. `AppLayout` 是应用壳层唯一所有者；
5. Ant Design 和现有共享组件继续提供基础实现；
6. 页面局部 CSS 只表达真实业务构图，不创建第二套主题或壳层。

## 2. 最小架构

不新建设计系统包、Token 目录、页面配置引擎或通用三栏组件。现有结构已经足够：

```text
批准原型与 visual-system.md
          ↓
theme.ts：精确语义值与 Ant Design 映射
          ↓
global.css：共享壳层、尺度和语义表面
          ↓
AppLayout + PageHeader + MetricTile + TableRegion + StatusTag
          ↓
页面局部 Grid/Flex、图表、编辑器和详情结构
```

本任务不拆成子任务。`theme.ts`、`global.css`、共享组件和跨页快照会被所有页面共同修改，拆成并行子任务会产生同文件冲突和两套中间视觉状态。实施改用顺序批次与人工审批点，每批都可独立验证和回退。

## 3. 目标视觉轮廓

### 3.1 浅色语义值

以下值是实现起点，也是人工审批前允许小幅光学校准的边界；任何调整仍只能发生在 `theme.ts`：

| 角色 | 初始目标 |
|---|---|
| 画布 | `#F4F7FC` |
| 普通表面 | `#FFFFFF` |
| 弱表面 | `#F7F9FD` |
| 下沉表面 | `#EDF2F8` |
| 玻璃表面 | `rgba(255,255,255,.74)` |
| 强玻璃表面 | `rgba(255,255,255,.90)` |
| 玻璃边界 | `rgba(102,122,160,.16)` |
| 主文字 | `#172033` |
| 次文字 | `#526079` |
| 辅助文字 | `#68758C` |
| 弱边界 | `#E5EAF2` |
| 默认边界 | `#D7DFEB` |
| 主交互起点 | `#315CF5` |
| 主交互终点 | `#5A3FF0` |
| 蓝色环境光 | `rgba(92,145,255,.16)` |
| 紫色环境光 | `rgba(132,102,255,.12)` |
| 粉色环境光 | `rgba(255,151,178,.10)` |

初始值的静态对比计算结果为：白字对主交互起点 5.28:1、对白紫终点 6.17:1，主文字对画布 15.15:1，次文字对白面 6.35:1，辅助文字对白面 4.65:1。实现仍以真实浏览器计算样式复核为准。

成功、警告、危险、中性和图表序列继续使用现有语义角色，但浅背景和文字对比按新画布校验。深色主题不追求复制浅色原型，只为新增主交互终点和环境光角色提供对应值，并保持现有可读性。

`actionPrimaryEnd` 是唯一新增主操作颜色角色；蓝紫渐变只允许由共享主按钮规则消费。`ambientBlue`、`ambientPurple`、`ambientPink` 是唯一新增环境光角色；不得在页面中复制颜色或从图表色推导页面表面。

### 3.3 环境光与玻璃

- `.app-shell` 使用三个大半径 radial gradient 与画布色组合环境光，颜色只能来自新增环境光语义变量。
- `.app-content` 改为透明，使环境光由应用壳层统一透出；不为路由设置不同背景。
- 侧栏、顶栏、轻指标、筛选、Drawer 和浮层可使用 24px 左右 blur。
- 表格、Markdown、正文和复杂表单保持白色或高不透明度表面。
- 不支持 `backdrop-filter` 时回退到强玻璃或普通表面，不降低文字对比。

### 3.4 主操作

- Ant Design 的语义主色仍使用渐变起点，以保持链接、焦点和组件算法稳定。
- 只有共享 `.ant-btn-primary` 使用起点到终点的克制渐变；Hover/Active 只调整起点状态、边界和阴影，不增加页面级彩色阴影。
- 成功和危险决策继续使用对应语义色，不套用蓝紫渐变。
- 静态视觉门禁只为该共享选择器开放精确例外，页面 `primary-action` 渐变仍然失败。

## 4. 共享组件与页面边界

### 4.1 AppLayout

- 修改既有 Sider 数值为 208/72，保持导航、权限、预取、折叠、移动 Drawer、搜索、主题、账号和焦点行为不变。
- 顶栏保持 64px，搜索最大宽度收敛到约 480px。
- 标题上下文不增加新路由判断；视觉不再由 pathname 分支决定。

### 4.2 PageHeader

- 不增加新 Props；通过共享样式统一 24px 标题、说明、面包屑、操作对齐和紧凑垂直节奏。
- `hero` 只保留现有特殊页边界，不扩散到普通业务页面。

### 4.3 MetricTile

当前 Dashboard、内容任务和 GEO 页面重复维护指标图标包装与 CSS。给 `MetricTile` 增加可选 `icon`，只负责稳定图标槽、tone 和排版，不计算趋势或业务口径。现有调用不传 icon 时保持兼容；迁移真实重复后删除页面图标包装，不新建指标卡工厂。

### 4.4 TableRegion 与 StatusTag

- `TableRegion` 接口不变，只调整稳定表面、焦点和局部滚动样式。
- `StatusTag` 保持既有业务映射；紧凑状态统一使用 6px 圆角、浅背景和非颜色表达，不合并业务状态。

### 4.5 页面局部

以下只在页面局部调整 Grid/Flex、列宽、滚动和真实内容层级：

- 用户、审计、发布账号、平台：标准列表和 340px 辅助区；
- Prompt、平台规则、AI 渠道、内容审核：各自不同的三栏工作区；
- GEO 观测与洞察：筛选、图表、矩阵、打印和详情；
- 发布与内容任务：真实工作流、Drawer 和任务状态；
- Dashboard：总览特有的状态摘要、待办、动态和快捷入口。

不得用一个新通用工作台组件抹平上述业务结构。

## 5. 实施批次与人工审批

### 批次 A：共享基础

校准 `theme.ts`、AppLayout、全局画布、排版、卡片、表格、按钮、状态和指标组件。只处理共享根因。

### 批次 B：四个锚点

按 Dashboard、用户、GEO 洞察、内容审核顺序完成页面局部校准，生成稳定 1440×1000 浅色截图和计算样式清单。主 Agent 向用户展示结果；用户批准前不得更新快照基线或推广到其余九页。

### 批次 C：九个局部参考页

在共享基础和批准锚点不再变化后，处理审计、发布账号、Prompt、平台规则、平台、GEO 观测、发布、AI 渠道、内容任务，只调整真实页面结构需要的局部样式。

### 批次 D：跨主题与响应式

完成深色/system、375/768/1024/1440px、真实 200% 缩放、键盘、reduced-motion、打印和移动 Drawer 验收。

### 批次 E：基线与收口

用户批准最终桌面结果后，才更新自动视觉基线、批准截图和 `visual-system.md`。随后运行完整质量门禁。

## 6. 验收与证据

- 四个锚点均保留原型、实施后稳定截图和人工批准记录。
- 批准记录统一写入任务 `assets/approved/manifest.md`，逐项记录页面、对应原型、实施截图文件名与 SHA-256、视口、主题、批准者、北京时间、用户原话或反馈结论。
- `manifest.md` 只登记用户明确批准的结果；未批准版本保留在实施过程证据中但不得登记为批准资产，也不得触发基线更新。
- 现有用户、Prompt、GEO 洞察九张自动基线继续承担回归；增加 Dashboard 与内容审核的稳定浅色桌面基线，使四个批准锚点都有自动保护。
- 动态身份、时间、正文和数值可以精确遮罩；卡片边界、表头、行高、列对齐、三栏比例和共享壳层不得遮罩。
- 壳层几何、字体、背景、对比度、响应式和焦点继续使用计算样式/行为断言，不用全页像素比较替代。
- 原型中的虚构数据不进入测试建数；E2E 继续使用真实 API，缺少前置数据显式失败。

## 7. 兼容、回滚与风险

### 兼容

- 不修改 OpenAPI、后端、数据库、权限、路由、URL 参数或业务状态。
- 共享组件新增 Props 只能是可选展示能力；现有调用保持类型兼容。
- 不新增运行时依赖、Web Font 或图标库。

### 回滚

- 每个批次保持独立 diff 和验证记录；发生问题时按批次反向修改，不使用 `git reset`。
- 批次 B 未获批准时，停止推广并只重新校准共享值或锚点局部。
- 旧快照保留到最终人工批准，避免错误设计被提前固化。

### 风险

- 原型是静态示例，无法决定真实数据长度、空态和权限态；以现有业务和真实数据为准。
- `global.css` 规模较大，公共选择器可能影响未直接修改页面；用全路由壳层矩阵和九页局部检查控制。
- 蓝紫主按钮和环境光可能降低对比度；以 4.5:1 文字、3:1 非文字和真实浏览器计算值为硬边界。
- 浅色是审美锚点，深色没有对应原型；深色只要求语义一致、清晰和无回归。
