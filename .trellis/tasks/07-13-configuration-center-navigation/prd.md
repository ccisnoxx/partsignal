# 配置中心信息架构与 AI 配置重构

## 目标

将管理员配置能力从单页 Tabs 和嵌套弹窗重构为清晰的二级导航与独立页面，使渠道连接、请求 Header、模型、平台 Prompt、具体平台规则和审计信息能够在稳定 URL 下完整展示和操作。

## 背景

- 当前配置中心把 AI 渠道、平台类型与 Prompt、具体平台规则、审计日志放在同一个 Tabs 页面，入口和内容层级过于扁平（`frontend/src/features/configuration/ConfigurationPage.tsx:16`）。
- AI 渠道列表把“Header 与模型”放在操作列，并通过 960px Modal 展示渠道详情（`frontend/src/features/configuration/ConfigurationPage.tsx:31`、`:33`）。
- 渠道详情同时承载连接、API Key、Header、模型发现、模型测试和模型启停，内容密度已经超过临时弹窗的合理边界（`frontend/src/features/configuration/ConfigurationPage.tsx:37`）。
- 全局侧栏目前只把配置中心作为单个叶子菜单，路由也只有 `/configuration`（`frontend/src/app/AppLayout.tsx:28`、`frontend/src/app/App.tsx:48`）。
- 当前工作副本已有主题、路由懒加载、预取和视觉测试改动；本任务必须基于这些改动增量实现，不覆盖或回退。

## 需求

### R1 二级导航

- 全局侧栏“配置中心”改为可展开的管理员二级菜单。
- 二级菜单固定包含：AI 配置、平台类型与 Prompt、具体平台规则、审计日志。
- 桌面折叠侧栏使用 Ant Design 子菜单弹层；移动端 Drawer 展示同一菜单树，点击叶子项后关闭 Drawer。
- `/configuration` 重定向到 `/configuration/ai`，旧书签可继续访问。

### R2 独立路由

- 使用以下稳定路由：
  - `/configuration/ai`
  - `/configuration/ai/channels/:channelId`
  - `/configuration/platform-types`
  - `/configuration/platforms`
  - `/configuration/audit`
- 配置路由统一经过管理员守卫；普通用户不能通过直接输入 URL 访问。
- 路由加载继续以 `routeLoaders.ts` 为唯一动态 import 来源，并保持 AppLayout 内的局部 Suspense。

### R3 AI 渠道列表

- AI 配置首页用响应式渠道卡片展示名称、启停状态、API 根地址、超时、API Key 配置状态和 Header 数量。
- 不为展示模型数量新增后端聚合接口，也不从列表页对每个渠道发起模型列表 N+1 请求。
- 新增渠道继续使用聚焦表单；创建成功后列表即时刷新。
- 点击渠道卡片或“查看配置”进入渠道详情路由，不再打开渠道详情 Modal。

### R4 渠道详情

- 渠道详情页固定展示三个主要区块：连接与凭据、请求 Header、模型。
- 页面顶部展示返回 AI 配置、渠道状态和启停等上下文操作；危险删除操作必须与常规操作区分。
- Header 表格直接展示名称、敏感性、配置状态和值的可见范围；新增和编辑可继续使用小型 Modal。
- 模型表格展示显示名、`model_id`、测试状态、启停状态、最近测试信息和请求参数摘要。
- 模型“测试”和“启用/停用”为高频行操作；编辑和删除收敛到次级操作，避免操作列堆叠。
- “获取模型”打开独立弹窗并立即请求远端模型列表；弹窗支持筛选，已配置模型明确标记且不可重复添加，未配置模型可逐个直接添加。
- 模型“测试连接”发送最小用户消息 `hi`，只验证当前渠道、Header、凭据、模型 ID 和自定义参数能否完成标准 Chat Completions，不要求返回业务草稿四字段 JSON。

### R5 其他配置页面

- 平台类型与 Prompt、具体平台规则、审计日志从 Tabs 拆成独立页面。
- 复用现有 API、表单和状态转换，不改变平台规则版本或审计业务行为。
- `SettingsPage` 只保留业务设置，不继续作为管理员配置组件的实现容器。

### R6 状态、错误与安全

- 使用现有 TanStack Query key、`QUERY_STALE_TIME.configuration`、CSRF 和错误解析机制。
- API Key 和敏感 Header 永不回显；视觉调整不能弱化现有安全提示。
- 所有 mutation 成功后只失效必要 query；不得用全局刷新掩盖状态同步问题。
- 失败、空状态、加载骨架和禁用原因必须在所属区块内明确展示。

### R7 响应式与可访问性

- 渠道卡片在手机单列、宽屏自适应多列；长 URL、模型 ID 和 Header 名不得造成水平页面溢出。
- 二级菜单、返回入口、卡片入口和行操作支持键盘访问，并具有明确可访问名称。
- 保持浅色、深色主题和现有设计 Token，不引入第二套颜色常量。

## 验收标准

- [ ] 管理员侧栏可展开四个配置二级菜单，选中态、展开态和页头标题与当前路由一致。
- [ ] 普通用户看不到配置中心，直接访问任一配置子路由会被重定向。
- [ ] `/configuration` 自动跳转 `/configuration/ai`，浏览器刷新渠道详情 URL 后仍能恢复页面。
- [ ] AI 配置首页不再使用渠道详情 Modal，渠道以响应式卡片展示且不存在模型查询 N+1。
- [ ] 渠道详情完整展示连接、凭据、Header 和模型，现有创建、编辑、发现、测试、启停和删除能力保持可用。
- [ ] 点击“获取模型”后在弹窗中看到远端模型列表；已配置模型不可重复添加，未配置模型可直接添加并刷新本地模型列表。
- [ ] “测试连接”的供应商请求只有一条内容为 `hi` 的用户消息，成功判定不依赖业务草稿 Schema。
- [ ] 平台类型与 Prompt、具体平台规则、审计日志均有独立 URL 和页面标题。
- [ ] 桌面折叠侧栏、移动 Drawer、浅色和深色主题均可正常导航，无严重级可访问性问题。
- [ ] 路由加载与预取仍通过唯一 loader/queryOptions 定义，不增加重复 import 或 query key。
- [ ] 新增或更新的单元测试、相关 E2E、`npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 通过。
- [ ] 最终 diff 未覆盖任务开始前已有的主题、性能、测试和视觉截图改动。

## 非目标

- 不修改 OpenAPI、接口路径、响应结构、权限契约或数据库；只调整模型测试接口内部的供应商请求语义。
- 不在本任务实现固定五种平台类型和两级内容任务的新业务契约。
- 不把业务设置、用户管理合并进配置中心。
- 不更新无关视觉回归基线，不执行部署、提交或推送。

## 开放问题

无。用户已确认采用全局二级菜单、渠道卡片列表、独立渠道详情路由，以及 Header/模型在详情页分区展示的方案。
