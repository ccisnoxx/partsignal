# 全项目功能回归测试（第二轮）：测试设计

## 1. 设计结论

本轮沿用项目已有测试栈、第一轮矩阵结构和探针，不创建第二套测试框架。执行时重新冻结当前范围，所有结论从 `NOT_RUN` 开始；历史报告只用于安排优先级。

任务保持单一 Trellis 父任务，不拆子任务。原因是路由、状态机、表格操作、删除副作用和审计需要在同一数据与证据口径下汇总；缺陷修复仍按共同根因另行立项。

## 2. 判定依据

按以下优先级确定期望行为：

1. `contracts/openapi.yaml`：HTTP 路径、请求、响应和错误合同。
2. `contracts/database.md`：状态、删除守卫、历史保留和数据库约束。
3. 当前后端实现、前端生成类型和调用链：运行时行为与页面消费。
4. `.trellis/spec/`：稳定开发、E2E 隔离、交互和质量约束。
5. 当前产品设计与验收文档。

来源冲突时记录各自内容、当前行为和用户影响，不选择“更容易通过”的解释。内容任务删除以当前数据库合同为准，旧部署验收文档的差异进入产品/文档决策项。

## 3. 执行环境

### 3.1 开发栈

- 使用当前 Compose 开发栈验证 Vite `/api` 代理、真实登录、全部页面、交互、console 和网络请求。
- 使用真实 PostgreSQL、Redis/Celery、API、前端和项目开发对象存储适配器。
- 正向测试数据优先通过真实页面和 API 建立；只操作本轮拥有的 `E2E-FULL-<run-id>` 对象。

### 3.2 隔离 E2E 栈

- 通过 `deploy/scripts/e2e-local.sh` 使用独立 allowlist 数据库和 `mktemp` 存储。
- 破坏性删除、重复/并发请求、失败注入和可重放场景优先在隔离栈执行。
- 每次运行必须检查 `E2E_CLEANUP ... status=deleted`；共享开发库不做模糊前缀清扫。

### 3.3 外部边界

- AI 正向/失败流程使用项目既有本机 OpenAI-compatible HTTP 测试边界，真实经过网络、解析和作业状态机。
- 浏览器 route 只用于 UI 失败恢复或视觉压力，不把被拦截的成功响应作为后端功能通过。
- 生产写入、真实第三方发布和无专用凭据的真实 AI 调用不执行。

## 4. 覆盖模型

### 4.1 全项目主流程

| 波次 | 业务范围 | 关键不变量 |
| --- | --- | --- |
| W0 | 登录、会话、用户、平台、Prompt、账号、AI 配置 | 角色、revision、敏感值、禁用与删除 |
| W1 | 产品与事实 | Markdown 单一来源、审核状态、批准后不可变 |
| W2 | 内容任务、生成、自然化、审核 | 快照、未知事实显式失败、重复请求、历史保留 |
| W3 | 发布候选、账号匹配、登记与状态事件 | 合法平台/账号、状态追加、已公开历史保护 |
| W4 | 发布异常与修复 | 唯一 OPEN 待办、修复任务与显式解决独立 |
| W5 | GEO 问题、观测、逐篇事实、纠错、洞察、打印 | 更正链、未知值、聚合口径、原历史保留 |
| W6 | 重复、并发、网络失败、刷新/后退/重登 | 服务端最终权威、恢复性、跨页面最终一致 |

### 4.2 路由与角色

- 从 `frontend/src/app/App.tsx` 冻结登录、改密、总览、产品/详情、任务/详情、编辑器、发布/详情/异常/修复、GEO/洞察/打印/问题/更正、设置，以及全部管理配置路由和 404。
- 每个可达路由至少检查管理员；存在角色差异的路由同时检查工程师和未登录直达。
- 动态路由分别覆盖有效 ID、无权 ID、缺失 ID 和从列表返回后的状态保持。

### 4.3 24 张业务表基线

执行开始时用当前页面和跨页测试复核以下基线，新增/移除项同步到矩阵：

1. 内容任务列表；2. AI 作业列表；3. 内容版本列表；4. 产品事实列表；
5. 事实版本列表；6. 待发布候选；7. 发布记录；8. 发布异常待办；
9. GEO 观测记录；10. GEO 文章观测结果；11. GEO 问题库；12. GEO 平台表现；
13. GEO 内容排行；14. GEO 覆盖矩阵；15. AI 渠道列表；16. AI 请求 Header；
17. AI 模型列表；18. AI 渠道操作日志；19. 全局审计日志；20. 模型发现弹窗；
21. 平台列表；22. 平台类型列表；23. 发布账号列表；24. 用户列表。

每张表记录身份字段、状态、时间/指标、查询能力、详情入口、全部操作、长文本槽、视口和结果。每个声明动作至少完成一次正向执行；行为随状态变化的动作覆盖其实际分支，每种禁止原因至少有一个服务端证据。共享组件只复用交互合同证据，不跳过对象级业务副作用。

### 4.4 13 个 DELETE 接口基线

| # | 对象 | 直接链路重点 |
| --- | --- | --- |
| 1 | 用户 | 最后管理员、停用/角色、审计 |
| 2 | 产品 | 事实和下游历史阻断 |
| 3 | 事实版本 | 状态、引用、批准历史 |
| 4 | 内容任务 | CANCELLED、任务拥有的未批准历史、发布/修复来源阻断 |
| 5 | 发布账号 | 平台、发布记录引用 |
| 6 | 发布记录 | 公开状态历史、GEO/异常引用、附件 |
| 7 | GEO 人工观测链 | 完整更正链、逐篇关系、附件、模型观测禁止删除 |
| 8 | 平台类型 | 平台引用 |
| 9 | 平台 Prompt | revision 与平台绑定 |
| 10 | 平台 | 类型、Prompt、账号与历史 |
| 11 | AI 渠道 | Header/模型、未执行作业、历史快照 |

每个接口统一验证：未登录/角色/CSRF、最小合法对象、保护关系、重复 DELETE、同目标双请求或确认期间状态变化、响应合同、数据库原子性、审计、附件/关联副作用及 UI 缓存。无法构造的分支只能标记 `NOT_APPLICABLE`，并引用合同依据。

## 5. UI/UX 设计

- 全部当前路由：`1440×1000` 与 `375×900`。
- 代表性布局临界点：`1024×768`、`320×800`。
- 登录、配置、数据列表、编辑审核、发布/GEO 五类页面：真实 200% 缩放。
- 浅色、深色、跟随系统；关键交互补 reduced-motion。
- 仅键盘完成登录、导航、表格菜单、表单、确认/取消，并检查弹窗关闭后的焦点恢复。
- 普通文字对比度至少 4.5:1，非文字界面至少 3:1；状态不能只依赖颜色。
- 宽表只允许在 `TableRegion` 内滚动；长文本必须保持行高、单元格边界以及 hover/focus 完整值。

截图只证明视觉状态。功能通过还必须有页面状态、真实请求、数据库或审计副作用中的至少一项证据。

## 6. 历史缺陷回归策略

### 6.1 已修复项

- `PS-QA-001`～`PS-QA-004`：GEO 打印、任务进度溢出、弹窗取消/焦点、自然化缺 Prompt。
- `PS-QA-101`～`PS-QA-110`：验收门禁、E2E 数据隔离、测试漂移和前端全量门禁。
- 24 表长文本/滚动/200% 缩放、内容任务术语与发布操作、开发环境 Vite API 代理。

对每类原缺陷复现最短原步骤并保存本轮结果；自动化通过不能替代真实浏览器缺陷的复测。

### 6.2 尚待确认项

- `PS-QA-201`：Dropdown 打开 `modal.confirm` 后取消，焦点是否回到原触发按钮。
- `PS-QA-202`：用户可见删除文案是否暴露存储实现术语“物理删除”。
- `PS-QA-203`：删除 AI Header 时是否明确说明连接/模型测试结果会失效。
- 第一轮缺口：逐 DELETE 并发、确认期间状态变化、迟到响应/缓存，以及全部操作列确认/取消/重复/键盘链。

这些都是待验证假设，不在执行前预填为缺陷或通过。

## 7. 结果、证据与缺陷

只使用：`PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`NOT_APPLICABLE`。单模块阻断时继续独立模块；相同失败在代码、配置或环境没有相关变化时不重复运行。

缺陷分级：

- P0：越权写入、敏感数据泄露、受保护历史破坏、错误/重复发布。
- P1：核心流程中断、核心状态错误、重要页面或键盘/移动关键路径不可操作。
- P2：有替代路径但明显损害理解、效率、恢复或数据判断。
- P3：不阻断任务的轻微视觉、文案或一致性问题。

任务产物：

- `research/coverage-matrix.md`
- `research/table-action-delete-matrix.md`
- `research/findings.md`
- `report.md`
- 大体积截图、trace、console 和网络证据：`artifacts/full-project-acceptance/<run-id>/`

证据不得包含密码、Cookie、Token、API Key、敏感 Header 或业务正文秘密。

## 8. 停止规则与取舍

- 出现 P0 数据破坏、越权写入、秘密泄露或跨环境串扰时，立即停止对应写路径，保留证据；仍可继续安全且独立的模块。
- 测试设施阻断可复现后记录 `BLOCKED`，不在本任务中修复。
- 不生成 24 套同质页面对象、不引入依赖、不把现有测试复制成第二套框架；只复用当前测试、脚本和必要的任务证据探针。
- 不把“所有固定菜单是否统一使用 `available_actions`”作为预设缺陷；它保持产品决策项，运行时越权或误导行为仍按事实判定。
