# 审计并修复全站表格列宽

## 目标

审计当前 25 张业务表的列角色、宽度分配、控件可读性和局部滚动合同，修复与人工观测登记表同类的 UI/UX 缺陷：短内容或次要列占用过多空间，导致状态、布尔值、操作或表单控件被挤压、换行、裁切，或让主要身份列失去合理可读宽度。

## 背景与确认事实

- 当前工作区在 `main`，任务创建前已有一处用户报告的修复：`frontend/src/features/geo-observations/GeoObservationForm.tsx` 将文章/平台列收紧、发现/提及列加宽，并把 `scroll.x` 从 890 调整为 780；该修改纳入本任务，规划审批前不继续修改其他产品代码。
- `frontend/tests/e2e/cross-page-visual-convergence.spec.ts` 已登记当前 25 张业务表，并验证桌面/移动页面边界、长文本省略和固定列背景。
- 归档任务 `07-30-sitewide-table-list-guidelines` 曾完成 24 表展示审计，但把 GEO 文章观测结果表判为通过；现有门禁能发现长文本越界，却没有检查有界字段控件是否因列宽分配失衡而换行或裁切。
- 当前源码静态复核发现多张表存在以下风险：固定列宽总和大于 `scroll.x`；唯一无宽度主列没有获得明确的最小可读余量；全列固定且剩余空间被机械分摊；可选列隐藏后仍保留原固定滚动宽度；操作、状态或布尔列宽度与实际控件不匹配。
- 现有 `TableRegion`、Ant Design `Table`、`TableCellText`、`.table-cell-ellipsis` 与前端视觉规范继续作为唯一实现基础。

## 范围内需求

### R1. 当前 25 表逐表审计

- 以 `sitewideTableInventory` 的当前 25 项为唯一清单，逐表记录：主身份列、辅助列、有界状态/布尔/数值/时间列、操作列、表单控件列、固定列宽总和、主列最小可读余量、`scroll.x`、选择列与动态/可选列影响。
- 将“源码静态风险”与“真实浏览器已复现缺陷”分开；静态风险必须通过真实 DOM 几何或明确的宽度合同确认后才能修改。
- 已有移动卡片替代表的发布管理页面继续按现有桌面表/移动卡片边界验收，不把移动卡片重做纳入本任务。

### R2. 列宽与密度合同

- 普通管理表优先保留一个主要弹性文本列；详情从属表、分析表和弹窗输入矩阵可以采用有界固定列，但 `scroll.x` 必须覆盖实际列宽合同。
- 状态、布尔、数量、短枚举、时间和操作等有明确上限的字段使用与真实内容相符的紧凑宽度，不得因次要列过宽挤压主身份或相邻控件。
- Checkbox、Select、Tag、Button、Dropdown 与复合操作组必须完整位于所属单元格内；短标签和操作文案在设计宽度内保持单行，不以隐藏、裁切或缩短业务文案掩盖问题。
- 可选列、条件操作列和行选择列必须进入当前表的宽度计算；列隐藏或条件变化后不得继续保留明显失真的滚动宽度。
- 长文本继续使用现有省略与完整值合同；本任务不重做已经稳定的 Tooltip、文本收缩和行高机制。

### R3. 最小、逐表修复

- 只修改浏览器已复现，或静态合同已能确定不成立的表格；源码与运行时均通过的表保持不变。
- 优先调整现有 `column.width`、弹性主列和 `scroll.x`；只有多个真实表共享同一缺陷时才修改共享 CSS 或测试辅助函数。
- 不新增列工厂、宽度注册表、通用表格包装器、运行时测量 Hook、页面级配置系统或依赖。
- 保留全部字段、查询参数、URL 状态、权限、`primary_task`、`available_actions`、写请求、确认流程和 API 载荷。

### R4. 防回归

- 扩展现有 25 表 Playwright 门禁，除长文本边界外检查可见有界控件与短标签：内容被所属 `td/th` 包含、没有多行文本矩形、没有被裁切，代表行高保持在所属表的既有档位。
- 至少用人工观测登记表、用户列表、平台列表和一张详情从属表覆盖四种结构：弹窗输入矩阵、带行选择管理表、弹性主列宽表、全固定紧凑表。
- 保留 1440×1000、375×900、页面无横向溢出、TableRegion 局部滚动和既有 200% 浏览器缩放验收。
- 回归测试必须在撤回对应宽度修复时能够失败；只比较 `scroll.x` 数字或只看截图不算充分证据。

### R5. 文档一致性

- 若本次形成了现有规范未覆盖的稳定规则，更新 `.trellis/spec/frontend/component-guidelines.md` 或 `quality-guidelines.md`；否则不重复维护既有表格合同。
- 不修改 OpenAPI、数据库合同、后端文档或业务设计文档，因为本任务只调整展示布局。

## 验收标准

- [ ] AC1：当前 25 张业务表都有逐表审计结论，静态风险、浏览器结果和最终处理决定可追溯。
- [ ] AC2：所有确认存在同类缺陷的表格已修复；短状态、布尔、数量、操作和表单控件不再因列宽分配失衡而换行、裁切或覆盖相邻列。
- [ ] AC3：每张桌面表的主要身份列保持可读；次要列不机械抢占空间；`scroll.x`、固定列、弹性列、选择列和条件列形成一致合同。
- [ ] AC4：375px 下页面根节点无横向溢出，宽表仅在 `TableRegion` / Ant Table 内滚动；已有移动卡片替代行为不变。
- [ ] AC5：现有长文本省略、hover/focus 完整值、固定列背景、键盘操作和主题行为不回退。
- [ ] AC6：25 表 Playwright 门禁能够捕获短标签/控件被挤压或换行的回归，并继续通过既有长文本与页面边界检查。
- [ ] AC7：未改变字段、列表能力、查询/分页、权限、状态机、服务端动作、API 合同或数据来源。
- [ ] AC8：未新增表格框架、宽度配置中心、运行时测量逻辑、重复组件或依赖。
- [ ] AC9：必需前端测试、lint、typecheck、定向真实浏览器验收与 `git diff --check` 通过；未执行的可选检查及残余风险明确记录。

## 范围外

- 重新设计表格信息架构、增删业务字段或把桌面表普遍改成卡片流。
- 修改搜索、筛选、排序、分页、导出、批量操作、权限或服务端动作。
- 重做长文本 Tooltip、主题 Token、全局表格视觉样式或 `TableRegion` 职责。
- 修改 backend、OpenAPI、数据库、部署配置或生成 API 类型。
- 为没有运行时证据的轻微数值差异做机械统一。

## 阻塞问题

无。用户已明确要求把检查范围扩展到其他存在同类问题的表格；仓库证据足以确定当前 25 表范围和实现边界。
