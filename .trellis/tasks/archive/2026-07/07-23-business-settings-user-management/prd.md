# 业务设置用户管理高保真复刻与功能闭环

## 目标

以用户提供并批准的 1581×995 原型为视觉与信息架构规格，在现有 `/users` 页面上完成“业务设置 > 用户管理”的高保真复刻，并基于 PostgreSQL、现有身份服务和服务端权限补齐真实统计、查询、分页、批量启停、CSV 导出、临时密码、审计及异常状态闭环。

不得创建平行用户页、第二套账号/权限模型、静态统计、无功能按钮、密码明文通路或用户删除能力。

## 用户价值

- 管理员能在一个可检索、可分页、可审计的工作台中查看和维护全部内部账号。
- 单个与批量启停、账号类型修改和临时密码均遵守同一服务端约束；部分失败、并发冲突和最后管理员保护不会被前端掩盖。
- 停用账号仍以原用户 UUID 保留全部业务归属，历史数据不会被删除、重写或迁移到第二身份。
- 原型视觉、真实交互、权限和密码安全可通过 Browser、契约检查与自动化测试复核。

## 已确认事实

- 接受规格是 `artifacts/user-management-prototype-1581x995.png`，原始像素为 1581×995；禁止 ImageGen 和重新设计。
- 现有真实页面为 `frontend/src/features/users/UserManagementPage.tsx`，路由为 `/users`；本任务只迭代该页。
- 当前 `/settings` 承载目标问题和平台账号标识，`/users`、`/audit` 位于配置中心导航；原型要求把四个入口归入展开的“业务设置”。
- 账号类型只有 `ADMIN`、`ENGINEER`，且 `users.account_type` 是权限唯一来源；所有用户管理接口最终由服务端 `AdminUser` 校验。
- 用户名创建后不可修改；显示名称、账号类型、启用状态可在带修订号的更新命令中修改。
- 停用用户会撤销其全部活动会话；停用或降权最后一个有效管理员会被事务锁和 `LAST_ADMIN_REQUIRED` 拒绝。
- 现有契约允许管理员在仍有其他有效管理员时停用或降权自己；没有系统内置账号标记，也没有运行中任务阻止停用的规则。
- 管理员不能通过重置接口修改自己的密码；重置其他用户时保存安全哈希、设置 `must_change_password=true`、撤销全部会话且审计不含密码。
- 强制改密同时受前端路由和服务端请求白名单约束；成功自助改密会清除标志、替换哈希并撤销其他会话。
- 应用没有用户删除 API；用户业务外键普遍 `RESTRICT`，停用/重启始终作用于同一 UUID。一次性 `0010` 迁移是唯一物理删除例外。
- 用户列表当前没有搜索、服务端筛选、真实分页、summary、批量操作或导出；前端仅对全量响应隐藏停用用户并按 10 条分页。
- 原型分页控件明确显示“20 条/页”，当前 API 响应也声明 `page_size=20`；页面现有本地 10 条分页不是继续沿用的权威默认值。
- 项目已有平台管理的“列表与 CSV 共用过滤/排序、全局实时 summary、UTF-8 BOM CSV”实现模式，可复用其结构而不抽象通用框架。
- 当前没有统计周期/快照、临时密码有效期、密码失败重试上限或账号锁定契约。

完整证据和功能分类见 `research/current-state.md`，量化视觉规格见 `research/visual-spec.md`。

- 审计日志页面本身的搜索、分页或详情重构；本任务只保证用户操作产生现有可查审计并调整其导航归属。
- 数据库新表、新字段或迁移；现有字段足以完成全部已知需求。

## 需求

### R1 信息架构与高保真页面框架

- 左侧导航按原型显示展开的“业务设置”，二级入口顺序为发布账号、历史目标问题、用户管理、审计日志；用户管理和审计日志仅管理员可见。
- 保留现有真实路由与业务页，不复制发布账号、目标问题或审计页面。兼容现有 `/settings?tab=accounts&platform_profile_id=...` 深链。
- `/users` 顶部使用“业务设置 / 用户管理”面包屑、页面标题、说明和“新增用户”按钮。
- 桌面 1581×995 优先还原五卡、筛选/表格主区、分页与约 300px 右侧说明栏；移动端只按现有规则堆叠并保证核心操作可完成。
- 复用现有设计 Token、Ant Design、共享页面组件和线性图标，不建立第二套设计系统。

### R2 权威统计、查询与分页

- `GET /api/v1/users` 增加用户名/显示名称搜索、账号类型、启用状态、页码和每页数量参数；权限仍为管理员。
- 搜索对用户名和显示名称执行服务端大小写不敏感匹配，并把 `%`、`_` 等输入作为普通字符，不允许隐式通配行为。
- 列表按 `created_at ASC, id ASC` 稳定排序；`total` 表示当前筛选总数，`page/page_size` 表示真实服务端窗口。
- summary 在同一响应中返回全部获权用户的用户总数、启用数、停用数、强制改密数和管理员数，不随列表筛选变化。
- 原型数字不得进入代码、迁移或种子。趋势没有权威来源，不计算并统一显示“暂无历史基线”。
- URL 拥有 `q/account_type/status/page/page_size` 可恢复视图；非法参数被显式清理，筛选变化回到第 1 页。

### R3 状态筛选与显示停用开关

- 状态筛选和“显示停用账号”不得各自拥有一套过滤逻辑；两者必须投影到同一个 URL/请求状态。
- API 状态参数只接受契约枚举；省略状态表示全部账号，以保持 API 的明确全量语义。
- 页面默认只请求启用账号；开关关闭表示 `ENABLED`，打开表示 `ALL`，选择 `DISABLED` 时开关仍为打开。
- 重置恢复默认启用账号、空搜索/类型条件、第 1 页和默认每页数量。

### R4 用户表格与单用户操作

- 表格列顺序为：选择、用户名及头像、显示名称、账号类型、状态、是否必须修改密码、创建时间、操作。
- 头像只做稳定的本地展示，不新增头像字段；所有类型/状态/是非标签同时显示文字和颜色。
- 编辑只允许提交现有契约字段：显示名称、账号类型、启用状态和 `expected_revision`；用户名、创建时间、强制改密标志不可在编辑表单直接修改。
- 单个启用/停用复用现有更新命令，必须经过管理员权限、CSRF、修订冲突、最后管理员保护、会话撤销和审计。
- 重置密码只对其他用户开放；表单使用 Password 控件，关闭即销毁字段状态，不把临时密码写入 URL、日志、审计、缓存或导出。
- 当前管理员若合法停用自己，成功响应后现有会话会失效并进入登录流程；前端不得把服务器允许的状态改变伪装成失败。

### R5 创建与临时密码

- 新建账号继续使用现有用户名规范化、唯一性、显示名称、账号类型和安全密码哈希。
- 创建表单的密码明确为“临时密码”，创建用户即设置 `must_change_password=true`；账号默认启用沿用现有行为。
- 临时密码首次成功自助修改后旧哈希被替换并清除强制改密状态；当前会话以外的其他会话被撤销。
- 本任务不增加临时密码明文返回，不允许刷新后再次读取管理员输入。
- 有效期、重试/锁定策略没有权威契约时保持未实现并在说明中如实表述，不显示原型中不存在事实支撑的“首次失败即失效”等文案。

### R6 批量启用与停用

- 批量目标只能来自当前表格的 Ant 原生选择；筛选、翻页或数据刷新后清除不可见选择，不做隐式跨页全选。
- 请求逐项携带用户 UUID 与当前修订号，并指定目标启用状态；重复 UUID、空列表和超过上限在服务端明确拒绝。
- 每个成功项复用单用户的行锁、修订校验、最后管理员保护、会话撤销和审计；不得在前端循环 PATCH 后汇总成伪批量成功。
- 批量最多 100 项、同一请求允许部分成功，响应包含成功用户和失败项 `{user_id, code, message}`。前端按已选行映射用户名并明确列出失败原因。
- 整体认证、权限、CSRF 或请求 Schema 错误使整批失败；逐项 404/409/最后管理员冲突只影响对应项。
- 不增加批量删除。

### R7 导出安全与审计

- 导出必须由服务端执行与列表相同的搜索、账号类型、状态和稳定排序，不受当前页窗口限制，也不能由前端先获取全量后拼装。
- 只允许管理员导出；响应失败、空集合和下载处理中都有明确反馈。
- 唯一导出格式为 UTF-8 BOM CSV，列为用户名、显示名称、账号类型、状态、是否必须修改密码、创建时间；不含 UUID、修订号、密码/哈希、临时密码、Token、Cookie、会话或内部敏感配置。
- 生成导出时通过现有 `append_audit` 机制记录 `user.exported`，详情只含非敏感筛选条件和行数；不得记录 CSV 正文或密码字段。

### R8 权限、审计与历史完整性

- 用户列表、统计、新增、编辑、重置、单个/批量启停和导出全部由服务端管理员依赖最终校验；写操作保留 CSRF。
- 创建、编辑/启停、重置、批量成功项和导出写入可查审计。更新审计只记录允许字段变化，不记录密码或会话内容。
- 批量操作失败不得写成功审计；成功项必须各自可追溯到操作者、目标用户和请求 ID。
- 停用、重新启用或修改显示名称/账号类型不得修改任何业务历史外键、快照或已批准内容；所有历史继续引用原用户 UUID。
- 不增加物理删除、级联删除、身份替换或兼容角色别名。PostgreSQL 继续是账号状态唯一来源。

### R9 右侧说明与快捷操作

- “账号类型说明”只显示真实 `ADMIN/ENGINEER`，摘要与服务端权限一致；不生成可编辑权限矩阵。
- “临时密码说明”只描述已确认的强制改密、哈希存储、会话撤销和安全告知规则，不声称未实现的有效期或锁定策略。
- “重要提示”明确系统不提供用户删除、停用保留历史、应定期审查无用账号。
- “快捷操作”中的批量启用/停用只在有选择时可执行，导出始终使用当前筛选；所有按钮连接真实逻辑。

### R10 状态、可访问性与响应式

- 覆盖加载、空数据、错误、无权限、表单校验、修订冲突、最后管理员冲突、部分批量失败和导出失败。
- 表单有可见 label；图标按钮有 Tooltip/可访问名称；键盘可完成搜索、筛选、选择、分页、弹窗与主要操作；焦点可见且关闭弹窗后合理归还。
- 状态不只依赖颜色；错误保留服务端 code/message 的准确业务含义，不加静默默认值或固定成功路径。
- 1581×995 主视口、375/768/1024/1440、200% 缩放及浅/深/系统主题无页面级横向溢出，核心操作可完成。

## 已确认决策

用户于 2026-07-23 确认以下最小契约包：

1. 新账号默认启用，但初始密码改为临时密码并强制首次改密；不新增有效期/重试/锁定政策。
2. 状态选择器和开关共享 `ENABLED | DISABLED | ALL` 单一视图状态，页面默认 `ENABLED`。
3. 统计趋势统一显示“暂无历史基线”，不增加快照或历史回填。
4. 批量状态请求上限 100，逐项修订校验并允许部分成功，返回结构化失败列表。
5. 只提供当前筛选的 UTF-8 BOM CSV，使用六个批准业务列并记录导出审计。

当前没有阻塞规划的开放问题。仍需用户评审本次收敛后的最终规划摘要，并在后续消息中明确批准实施；在此之前不执行 `task.py start`，不修改产品代码、契约或数据库。
