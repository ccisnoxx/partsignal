# 配置摘要、独立平台规则与事实版本清理

## 目标

核实并消除正式环境渠道卡片“已启用模型”与持久化模型状态不一致的问题；把平台规则从平台管理页面拆成独立管理能力；解除产品删除与事实版本无法删除形成的开发数据清理死路，同时保护已经进入内容流程的历史。

## 背景与证据

- 用户反馈重新部署后，渠道卡片仍像是展示渠道可发现的全部模型，而不是实际添加并启用的模型。
- `backend/app/routers/configuration.py:111` 的渠道投影只把 `model.is_enabled=true` 的持久化模型写入 `enabled_models`；`frontend/src/features/configuration/AIChannelsPage.tsx:79` 也只渲染该字段。
- `2026-07-16` 正式环境 PostgreSQL 中，渠道 `ds` 只有 `deepseek-v4-flash` 一条 `ai_models` 记录，状态为 `is_enabled=true`、`test_status=PASSED`；正式环境后端投影同样只返回这一条。
- 已部署前端资源直接遍历 `channel.enabled_models`，当前服务端和部署资源均未复现用户看到的错误集合。后续必须从登录态页面和真实网络响应继续定位，不能再用缓存失效或额外过滤猜测修复。
- 现有模型新增、更新、测试、启停和删除成功后都会失效渠道摘要查询；当前仓库没有“详情已更新、渠道卡片仍使用旧 Query 缓存”的已知缺口。
- 当前平台创建会同时创建首个 `ACTIVE` 规则版本（`backend/app/services/content_planning.py:95`），规则新增、激活、退役和删除操作嵌在平台管理页面（`frontend/src/features/configuration/PlatformsPage.tsx:20`）。
- 现有激活服务已经在同一事务中把旧 `ACTIVE` 退役并激活目标 `DRAFT`（`backend/app/services/content_planning.py:172`），无需新增第二套“当前规则”状态。
- 产品删除服务把全部 `FactVersion` 都视为阻断引用，但事实版本页面只提供审核状态转换和停用，没有物理删除接口，因此创建过任何事实版本的产品都无法完成清理（`backend/app/services/product_facts.py:283`、`frontend/src/features/product-facts/ProductFactsPage.tsx:75`）。

## R1 正式环境模型摘要

- “已启用模型”只允许来自已落库且 `is_enabled=true` 的 `ai_models` 记录。
- `/models` 发现结果、已添加模型、测试通过模型和已启用模型保持不同语义；发现或测试成功都不能自动进入渠道摘要。
- 先取得登录态页面 DOM 与 `/api/v1/ai-channels` 实际响应的可重复证据，再决定是否修改代码、部署流程或客户端刷新行为。
- 正式环境证据采集保持只读，并在任务内保存脱敏的时间、渠道 ID、DOM 集合、两份 API 集合、页面资源哈希和发布版本；不得记录 Cookie、CSRF、API Key 或敏感 Header。
- 若服务端响应正确而页面错误，修复实际部署或客户端资源问题；若服务端响应错误，修复后端权威投影或持久化状态。不得用前端二次查询、静默过滤或清缓存说明掩盖根因。
- 模型新增、测试、启停、删除后，渠道摘要、详情模型列表和重新登录后的结果必须一致。
- 正式环境不为本项验收新建、启停或删除模型；写路径一致性由自动化和受控本地 E2E 覆盖，部署前后只执行登录态只读复核。

## R2 独立平台规则管理

- 配置中心增加与“平台管理”“Prompt 管理”并列的“平台规则管理”页面；平台管理不再承载规则表单和版本操作。
- 继续复用 `PlatformProfileVersion`，不新增规则库实体或规则名称。页面用“平台名称 + V版本号”识别规则。
- 每条规则只归属于一个平台，不允许跨平台复用；每个平台可有多个版本，但同时最多一个 `ACTIVE`。
- 保留 `DRAFT → ACTIVE → RETIRED` 生命周期。`DRAFT` 可编辑；`ACTIVE` 和 `RETIRED` 不可原地修改。
- 新增平台时只保存平台身份、类型和允许域名，不再隐式创建或激活规则。无当前规则的平台允许管理员继续配置，但工程师不可用其创建内容任务。
- 规则管理页只展示真实存在的规则版本。新增规则时选择所属平台并创建 `DRAFT`；编辑只允许 `DRAFT`；删除成功后该行立即消失。
- 平台管理页通过下拉框显示当前 `ACTIVE`，并只允许选择该平台自己的 `DRAFT` 作为新当前规则。选择操作复用现有激活命令，原 `ACTIVE` 在同一事务中转为 `RETIRED`。
- 未被内容任务引用的任意规则版本仍可物理删除，包括 `ACTIVE`；删除当前规则后平台进入“无有效规则”，不自动恢复历史版本。存在内容任务引用时继续返回结构化 `409`。
- 内容任务和生成作业继续锁定具体规则版本及快照；当前规则后续切换、退役或删除不得改写既有历史。
- 所有规则写操作仅管理员可用，工程师仍只能读取任务锁定的规则。

## R3 事实版本物理删除

- 增加管理员专属的事实版本物理删除接口和前端操作；工程师不能看到删除按钮，服务端仍必须独立校验管理员权限。
- `DRAFT`、`PENDING_REVIEW`、`CHANGES_REQUESTED`、`APPROVED` 和 `RETIRED` 均可申请删除，不通过先停用制造额外步骤。
- 服务端锁定目标版本并统计全部外部直接引用。存在 `ContentTask` 或 `ContentVersion` 引用时返回结构化 `409 details.references`，不得删除或改写引用方。
- 事实版本自身的 `FactReviewRecord` 是该开发快照的从属数据，不作为阻断引用；删除版本时在同一事务中显式删除这些审核记录。
- 删除成功后该事实版本行立即消失，产品保留。管理员清理完全部事实版本后，可继续使用现有产品物理删除操作清理产品及当前事实工作区。
- 产品删除不自动级联事实版本；每个事实版本仍需管理员单独确认，避免一次操作误删多个快照。
- 删除操作记录审计摘要，但不得把事实快照正文或审核意见复制进审计日志。

## 验收标准

- [ ] 正式环境登录态渠道卡片、`GET /api/v1/ai-channels` 和模型明细对“已启用”集合给出一致结果；发现结果、未测试模型、测试通过但未启用模型和停用模型均不混入摘要。
- [ ] 任务内保留脱敏证据与根因分流结论；没有失败证据时不修改模型业务逻辑，也不把清缓存当作修复。
- [ ] 模型新增、测试、启用、停用、删除、页面刷新和重新登录均有覆盖该一致性的自动化或正式环境验收证据。
- [ ] 配置中心存在独立“平台规则管理”入口，平台管理页面不再内嵌规则编辑和版本列表。
- [ ] 新平台可以在没有规则的情况下创建，并明确显示“无有效规则”；工程师不能选择该平台创建内容任务。
- [ ] 管理员可以选择平台创建规则草稿、编辑草稿、删除未引用版本，并在平台管理下拉框中选择本平台草稿作为当前规则。
- [ ] 激活新规则时旧规则原子退役；`ACTIVE`、`RETIRED` 或其他平台的规则不能作为可选草稿被错误修改或绑定。
- [ ] 删除当前规则后平台保留且不可用于新任务；有历史引用时删除失败并展示引用类型，既有任务与作业含义不变。
- [ ] 管理员可以直接删除任意状态且无 `ContentTask`、`ContentVersion` 引用的事实版本；该版本自己的审核记录同步删除，列表立即移除该行。
- [ ] 工程师没有事实版本删除入口且调用接口被拒绝；存在内容任务或内容版本引用时管理员收到中文引用类型与数量，所有数据保持不变。
- [ ] 清理产品的全部无引用事实版本后，现有产品物理删除流程可以成功；产品删除不会自动级联未确认的事实版本。
- [ ] OpenAPI、数据库契约、后端、生成前端类型、自动化测试和方案设计文档描述同一关系。

## 非目标

- 不新增跨平台共享规则库、规则名称、标签、搜索或批量绑定。
- 不改变 OpenAI-compatible Chat Completions 协议、模型测试请求或生成输出格式。
- 不改写既有内容任务、生成作业、内容版本、发布或审核历史。
- 不删除、级联或改绑引用事实版本的内容任务、内容版本、生成、审核、发布和观测历史。
- 不引入第二个当前规则字段、兼容接口、前端 N+1 模型查询或业务缓存层。
