# 终止无效调试循环

整理已观察症状、尝试及其结果，找出先前解释无法覆盖的证据。根因可能在跨层合同、遗漏调用路径、状态生命周期或未经验证的假设，不预设“缺少规范”就是原因。

有多个解释时列出能支持或否定它们的具体观察，选择最小的区分性检查。无需给主观先验凑百分比，也不按随意置信度添加兜底。

说明根因证据、此前失败原因、剩余不确定性和建议修复。仅分析请求不自动写代码、规范、issue 或提交；已经授权修复则按证据继续相关实现与验证。

预防措施优先考虑现有边界校验、类型或行为测试；只有形成稳定的新合同/约定时更新对应项目规范。仅在证据显示同类根因共享时扩大排查，不自动启动架构改造。

遵守全局进展和预算规则；无新证据或环境阻塞时准确交付当前状态。项目维护只修改本地存在的权威文件，不引用上游专用模板目录。
