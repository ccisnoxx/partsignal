## 当前信息架构与页面

- `/settings` 是真实业务设置页，内部用 `tab=topics|accounts` 切换“目标问题”和“平台账号标识”。
- `/users` 和 `/audit` 是真实独立路由，仅管理员可见/访问。
- 当前侧栏把 `/users`、`/audit` 放在管理员“配置中心”下；批准原型要求把“发布账号、历史目标问题、用户管理、审计日志”归入展开的“业务设置”。
- 当前用户页是在现有 `/users` 上迭代的唯一目标，不创建平行页面。页面已有标题、列表、新增、编辑、重置密码和“显示停用账号”开关，但结构、密度和功能远少于原型。
- 当前用户页全量请求 `/api/v1/users` 后在浏览器过滤停用账号并分页；这不满足服务端搜索、组合筛选、真实分页和同条件导出要求。

## 真实账号、权限与状态模型

- 账号类型只有 `ADMIN` 与 `ENGINEER`；`users.account_type` 是唯一权限来源。`ADMIN` 可访问管理员接口，`ENGINEER` 与 `ADMIN` 均可执行工程师业务能力。
- 所有用户管理接口使用 `AdminUser` 服务端依赖；所有写请求同时需要与当前会话绑定的 CSRF 令牌。前端 `auth.isAdmin` 只用于导航和体验，不是安全边界。
- 用户状态只有 `users.is_active`；没有“锁定”“待激活”“系统内置”等额外状态或账号标志。
- 用户名创建时去空白、转小写并保持唯一；更新契约不含用户名，因此创建后不可修改。
- 显示名称、账号类型和启用状态可通过带 `expected_revision` 的更新命令修改。
- 停用有效管理员或把其降为工程师时，服务通过表锁和行锁保证至少保留一个有效管理员；修订号过期返回 `REVISION_CONFLICT`。
- 当前实现没有额外禁止管理员停用自己或降低自己角色：只要仍有另一个有效管理员，现有命令允许该操作。停用自己会在事务提交时撤销自己的会话。
- 当前没有“运行中任务阻止停用”的规则。停用只影响后续登录/会话，不修改任何历史业务对象。
- 应用没有单用户或批量用户删除 API；一次性 `0010` 遗留清理迁移是唯一物理删除例外。

## 登录、密码与临时密码

- 登录按规范化用户名读取用户，要求账号启用并使用 Argon2 哈希验证密码；失败统一返回“用户名或密码错误”，不会额外泄露账号状态。
- 会话和 CSRF 摘要存于 PostgreSQL；过期、撤销或停用账号的会话会被服务端拒绝。
- 管理员为其他用户重置密码时，服务只保存密码哈希，设置 `must_change_password=true`、递增修订号、撤销目标用户全部会话，并写入不含密码的审计记录；管理员不能通过该接口重置自己。
- `ProtectedRoute` 会把 `must_change_password=true` 的用户导向 `/change-password`；服务端同时只放行 `auth/me`、`auth/csrf`、改密和登出四类请求，不能靠前端绕过。
- 自助改密必须验证旧密码；成功后替换密码哈希、清除强制改密状态、递增修订号并撤销当前会话以外的其他会话。旧临时密码因此立即失效。
- 临时密码不会进入审计详情、URL、导出或持久化前端状态；审计工具会递归拒绝 `password`、`temporary_password`、`old_password`、`new_password` 等敏感键。
- 当前创建用户把管理员输入字段称为 `password`，创建后默认 `must_change_password=false`。用户已确认本任务把新用户初始密码改为临时密码并强制首次改密。
- 当前没有临时密码过期时间、失败重试上限或登录锁定机制。没有权威策略时不得在本任务中猜测期限或阈值。

## 用户与历史业务记录

- `users.id` UUID 是身份唯一来源。产品事实、事实审核、内容任务/内容版本、发布记录/状态事件、AI 配置与生成、平台配置、GEO 文件与观测等用户归属外键普遍使用 `ON DELETE RESTRICT`。
- `sessions.user_id` 使用 `CASCADE`，只表示删除身份时会清理会话；应用层本身不提供用户删除。
- `audit_logs.actor_id` 使用 `SET NULL`，用于保留一次性迁移删除遗留账号后的审计记录。
- 停用、重新启用和角色修改始终更新同一个用户 UUID，不新建第二身份，也不改写业务记录的外键。
- 用户名不可修改；显示名称是当前身份资料，修改后历史投影可能展示当前名称，但历史业务行和责任归属 UUID 不会被重写。
- 业务外键和应用无删除接口共同保证“停用账号仍可追溯、无批量删除、历史查询不因停用失败”。本任务不新增删除能力、级联或软删除字段。

## 功能分类与差异

| 原型/需求能力 | 当前状态 | 分类与最小处理 |
|---|---|---|
| `/users` 页面、新增、编辑、重置密码 | 已有真实 API 和前端表单 | 直接复用并重组现页 |
| 强制首次改密、会话撤销、最后管理员保护 | 服务端已有 | 补专用测试和准确说明 |
| 用户总数、启用、停用、强制改密、管理员统计 | PostgreSQL 字段已存在，响应无 summary | 新增同次实时聚合，不建快照 |
| 上周期趋势 | 无周期、快照或审计口径 | 不计算；已确认显示“暂无历史基线” |
| 用户名/显示名称搜索、类型/状态筛选 | API 无查询参数 | 新增服务端过滤 |
| 状态筛选与显示停用开关 | 仅前端 `inactive=1` 开关 | 统一为一个 URL 状态，避免双重规则 |
| 服务端分页、每页数量、跳页 | 当前全量返回、前端 10 条分页 | 新增 `page/page_size/total` |
| 单个启用/停用 | 现有 PATCH 可真实执行 | 使用既有更新命令与冲突保护 |
| 批量启用/停用、部分失败 | 不存在；仓库无表格 `rowSelection` 先例 | 用 Ant Table 原生选择和一个批量契约，不造第二种选择器 |
| CSV 导出和导出审计 | 用户导出不存在；平台页已有同筛选 UTF-8 BOM CSV 模式 | 复用该模式，新增允许列和 `user.exported` 审计 |
| 账号类型说明 | 类型与权限契约已有，右栏缺失 | 展示两类真实类型及现有权限摘要，不新增角色引擎 |
| 重要提示与快捷操作 | 不存在 | 使用现有事实文案并连接真实操作 |
| 加载、空、错误、冲突、无权限 | 当前仅合并 Alert/Table loading | 复用 `AsyncState`、表格 loading、Modal/Form 和结构化错误 |
| 业务设置展开导航与面包屑 | 当前用户页在配置中心，标题无面包屑 | 调整现有导航归组和 PageHeader，不创建新页面 |
| 通知、帮助、应用切换 | 原型有图标，项目没有对应真实能力 | 不增加空按钮，作为有依据的视觉差异 |

## 可复用边界

- 前端：React Router、TanStack Query、URL 查询参数、Ant Design `Table/Form/Modal/Dropdown/Switch/Pagination/Card`、`PageHeader`、`TableRegion`、`StatusTag`、`AsyncState`、现有主题 Token 和 Ant 线性图标。
- 服务端：`AdminUser`、`CsrfProtected`、`update_user` 的表锁/行锁/修订校验、会话撤销、`append_audit`、现有身份 Schema 和密码哈希工具。
- 查询/导出：`platform_configuration.py` 已有“列表与 CSV 共用过滤/稳定排序、全局 summary 不受筛选影响、UTF-8 BOM + 标准库 csv”的可复用结构；只复用模式，不抽象通用框架。
- 契约：继续以 `contracts/openapi.yaml` 为唯一 API 源并生成 `frontend/src/shared/api/schema.d.ts`；前端不维护第二套传输类型。

## 影响范围

- 前端：AppLayout 信息架构、用户页、URL/query key、样式、用户页与导航测试；业务设置保留现有真实页和查询参数兼容。
- 后端：身份 Schema、路由、服务命令/查询、身份管理专用集成测试；不新增通用用户框架。
- 契约：OpenAPI 增加列表参数、summary、批量状态和 CSV；数据库无新字段/表/迁移，但需补充现有身份状态、批量与导出审计的权威行为说明。
- 文档：更新业务/系统方案和前端 README 中的导航、用户查询与状态语义；稳定规则若有复用价值，再更新相关 Trellis spec。
- 历史数据：不迁移、不删除、不回填、不生成快照；所有操作继续作用于同一 `users` 行。

## 已确认的最小契约包

用户于 2026-07-23 确认以下方案：

1. 新建账号继续默认启用，但把管理员输入改为“临时密码”，创建即 `must_change_password=true`；不在本任务发明过期时间、重试上限或锁定策略。
2. 状态选择器与“显示停用账号”开关共享一个状态：默认/开关关闭=`ENABLED`，开关打开=`ALL`；选择 `DISABLED` 时开关保持打开。API 省略状态表示全部，前端默认显式请求启用账号。
3. 统计卡只显示实时全局计数，原型趋势位置显示“暂无历史基线”。
4. 批量状态操作最多 100 个账号，逐项携带修订号；同一请求内允许部分成功，返回每个失败账号的结构化原因，成功项复用单用户锁、最后管理员保护、会话撤销和审计。
5. 导出只提供一种 UTF-8 BOM CSV，列为用户名、显示名称、账号类型、状态、是否必须改密、创建时间；不含用户 UUID、修订号或任何认证/会话字段，并记录 `user.exported` 审计。
