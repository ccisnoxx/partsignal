# 配置中心与 AI 生成策略

## Goal

提供由管理员维护的 AI 渠道、模型、平台类型和 Prompt 配置，使公司电子工程师可以选择目标平台与模型，输入专业产品资料生成可追溯的 Markdown 草稿，并自行审核、修改和批准。

## Background

- 当前系统使用 `platform_profiles` 与不可变的 `platform_profile_versions` 管理具体平台规则，但没有平台类型和可编辑 Prompt。
- 当前 `ContentTask` 锁定批准事实与平台规则版本，`GenerationJob` 保存输入快照，但 Worker 只使用确定性开发生成器。
- 当前内容任务只有受众、内容角度、转化目标、格式、长度和权威 URL，没有完整可编辑的产品说明。
- 当前 `ContentVersion` 正文以 Markdown 为唯一可编辑源，人工修改创建新版本。
- 当前身份模型使用六种业务角色并禁止事实和内容创建者自审；本任务将其调整为管理员与工程师两种账号类型，并允许自审。
- PostgreSQL 继续作为业务状态唯一来源，Redis 只作为 Celery Broker。

## Requirements

### AI 渠道与模型

- R1：管理员可以创建多个 OpenAI-compatible 渠道，每个渠道维护多个模型；真实 LLM 调用进入 MVP，确定性生成器只用于本地开发和自动化测试。
- R1.0：协议固定为 Chat Completions；`base_url` 是包含版本前缀的 API 根地址，系统只调用 `GET {base_url}/models` 与 `POST {base_url}/chat/completions`，不支持 Responses API，也不尝试其他路径。
- R1.0.1：生产环境只允许公网 HTTPS 云端地址，禁止私网、回环、链路本地、云元数据地址和 HTTP 重定向；开发环境才可显式允许本机 HTTP。保存配置和每次连接前都必须重新校验目标。
- R1.1：渠道提供“获取模型”操作，返回结果只用于选择，不自动创建或启用模型。
- R1.1.1：获取模型失败时允许管理员手工填写 `model_id`，但仍执行相同的测试和启用规则，不猜测模型名称。
- R1.2：模型包含 `display_name`、`model_id` 和管理员可增删改查的自定义请求参数；普通工程师不能覆盖参数，作业必须冻结实际参数。
- R1.3：自定义参数采用唯一“参数名 + JSON 值”，支持 JSON 字符串、数字、布尔、数组和对象。`model`、`messages`、`stream` 为系统保留字段，其他参数按原名原值发送，不自动改名、转换或丢弃。
- R2：API Key 使用部署环境主密钥加密保存于 PostgreSQL，明文只在写入和调用边界短暂存在；任何读取接口只返回配置状态和更新时间。
- R2.0：渠道允许配置大小写不敏感且名称唯一的自定义 Header。`Authorization`、`Host`、`Content-Length`、`Connection`、`Transfer-Encoding` 不可覆盖；`HTTP-Referer`、`X-Title`、`Accept-Language`、`User-Agent` 等未保留 Header 可以配置。
- R2.0.0：自定义 Header 统一属于渠道，并用于获取模型、测试和正式生成；模型不能定义第二套 Header。Header 名和值必须拒绝换行等非法字符。
- R2.0.1：Header 由管理员标记为普通或敏感；敏感值与 API Key 使用相同的加密、只写和永不回显规则。作业不保存 API Key 或敏感 Header 明文，重试使用渠道当前凭据。
- R2.0.2：模型和生成请求不得提交 Header；服务端只从渠道配置构造实际 Header。
- R2.1：渠道和模型都支持启用、停用及管理员物理删除。普通工程师只能选择渠道与模型均启用的组合；删除当前配置不得删除历史作业快照。
- R2.2：渠道和模型默认停用。完整测试只在具体模型上执行，使用固定非业务消息和模型自定义参数，并通过与正式生成相同的严格四字段 JSON 校验。
- R2.3：新增模型或修改 `base_url`、API Key、Header、`model_id`、自定义参数后，相关模型测试状态重置；至少一个模型测试成功后渠道才可启用，每个模型仍需分别测试成功才能启用。
- R2.4：模型测试不得使用真实产品数据，不得创建 `ContentTask`、`GenerationJob` 或 `ContentVersion`；测试结果只记录时间和不含敏感信息的错误摘要。
- R2.5：渠道 `timeout_seconds` 由管理员在 10 至 600 秒内配置并统一用于该渠道请求。单个生成作业不自动网络重试，超时或网络失败显式失败。

### 平台类型与 Prompt

- R3：管理员维护名称与唯一 `slug` 的平台类型，并把具体 `PlatformProfile` 归入一个类型；每个平台类型最多存在一份 Prompt。
- R3.0：平台类型被具体平台引用时不能删除，管理员必须先重新归类。删除未被平台引用的类型同时物理删除其当前 Prompt，但不影响历史作业快照。
- R3.0.1：既有平台迁移后可以暂时未归类，但未归类前不能用于新建内容任务或生成；新平台必须明确选择类型，不自动猜测或填充默认类型。
- R3.1：Prompt 是一份普通 Markdown 文档，作为管理员可编辑的平台 `system_prompt`。编辑框支持常规全选、复制、粘贴和修改，不引入变量、循环、条件或 Prompt 编排器。
- R3.2：管理员保存 Prompt 时原地覆盖并立即对新作业生效，不设版本或启停状态；管理员可以物理删除当前 Prompt。生成作业保存完整 system message 快照，因此配置修改和删除不得改变历史。
- R3.3：普通工程师可以在任务页只读查看当前完整 Prompt Markdown，但不能修改；非管理员不能调用平台类型、Prompt、渠道或模型写接口。
- R4：具体平台在创建 `ContentTask` 时选择并锁定，生成时按任务的平台类型解析唯一 Prompt，不允许重新选择平台。缺少平台类型或 Prompt 时显式失败。

### 生成输入、输出与追溯

- R5：`ContentTask` 保存可自由编辑的 `user_prompt` Markdown，用于产品描述、参数、特性、产品对比和写作要求；更新使用任务修订号并发控制。
- R5.1：每次创建生成作业时，用户明确选择一个当前可用模型，服务端一次性冻结当时的任务 `user_prompt`，后续修改任务草稿不影响历史作业。
- R5.2：服务端自动附加任务绑定的 `APPROVED FactVersion`，并清晰分隔工程师输入与只读事实块；前端不能覆盖、删除或伪造批准事实。
- R5.3：固定 system 契约声明批准事实优先，并包含严格输出 Schema；工程师输入可以补充本次专业资料，但不能覆盖已批准事实，过期事实需先创建并批准新版本。
- R6：每个生成作业冻结渠道与模型身份、非敏感连接信息、模型参数、最终 system message、工程师 `user_prompt`、批准事实、任务要求和固定契约版本；配置变化不得改变历史含义。
- R6.1：云端请求只允许包含最终 system message、工程师 `user_prompt`、文本化批准事实值和任务要求，不发送证据文件、附件、私有源文档、对象存储地址或访问凭据。
- R6.2：完整生成快照长期保留，无单独删除入口，也不复制到运行日志或普通审计详情。
- R7：`choices[0].message.content` 必须是可直接解析的单个 JSON 对象，且只能包含非空 `title`、`summary`、`body_markdown`、`tags`。系统不剥离代码块、截取文本、修复 JSON 或从其他字段补值。
- R7.1：`body_markdown` 是完整文章和正文唯一可编辑源。模型不返回 `used_fact_ids`、`used_evidence_ids`、`required_disclosure_ids`；追溯依赖系统快照，不依赖模型自报 ID。
- R8：模型只能创建 `DRAFT ContentVersion`。工程师修改内容时继续创建新版本，提交、批准和发布仍使用显式状态转换并记录审计。
- R9：自动检查验证正文数字来自批准事实或本次 `user_prompt` 的并集，并继续检查必要披露、禁用表达及标题/正文长度。自由 Markdown 与批准事实之间的语义冲突无法可靠自动识别，固定契约声明事实优先，其他技术陈述由工程师人工审核。
- R9.1：事实追溯展示绑定 `FactVersion`、完整 system/user Prompt 快照、渠道、模型和请求参数；不展示模型自报事实或证据 ID。
- R10：失败作业重试复用原始模型 ID、参数、Prompt、用户输入和事实快照，只读取渠道当前 API Key 与敏感 Header。渠道或模型已物理删除时不能重试，使用当前配置必须创建新作业。
- R11：作业保存供应商请求 ID、本地响应耗时及供应商实际返回的 `prompt_tokens`、`completion_tokens`、`total_tokens`；缺失值为不可用，不估算、不补零，首期不计算金额。

### 账号、权限与界面

- R12：账号类型简化为 `ADMIN` 与 `ENGINEER`。`ADMIN` 拥有全部工程师业务权限并额外管理用户和系统配置；`ENGINEER` 不能进入管理功能。
- R12.1：管理员可以新增、停用、启用用户并重置他人密码。用户不物理删除；停用立即撤销会话并禁止登录，但保留全部历史引用。
- R12.2：系统始终至少保留一个有效 `ADMIN`，停用或降级最后一个管理员必须在服务端事务内拒绝。
- R12.3：管理员重置他人密码时设置临时密码、撤销目标用户全部会话并标记强制改密；临时密码登录后只能修改密码或退出。管理员修改自己的密码必须验证旧密码。
- R12.4：`FactVersion` 和 `ContentVersion` 都允许创建者自行批准；只移除审核者必须为另一用户的限制，其他证据校验、状态机、质量门禁和审计不变。
- R13：主导航仅为管理员显示独立“用户管理”和“配置中心”。配置中心包含 AI 渠道与模型、平台类型与 Prompt、具体平台规则和审计日志；所有管理 API 继续执行服务端管理员鉴权。

## Acceptance Criteria

- [ ] 管理员可以创建两个渠道，在一个渠道下通过远端列表或手工 `model_id` 添加两个模型；非管理员调用配置写接口被拒绝。
- [ ] 系统只调用配置根地址下的 `/models` 与 `/chat/completions`，生产环境拒绝非公网 HTTPS、私网/回环/元数据地址及重定向。
- [ ] 模型自定义 JSON 参数按原名原值发送，`model`、`messages`、`stream` 被拒绝，普通工程师不能覆盖参数。
- [ ] API Key 和敏感 Header 只保存密文并永不回显；普通 Header 可查看。保留 Header、重复名称和换行注入被拒绝。
- [ ] 获取模型、模型测试和正式生成使用同一渠道 Header；修改连接、凭据、Header、模型或参数后必须重新测试。
- [ ] `/models` 成功不能代替模型测试；固定测试通过严格 JSON Schema 后模型才能启用，测试不创建业务作业或内容。
- [ ] 渠道或模型停用后立即不能新选，物理删除后历史作业仍可查看；模拟超时只产生一次外部调用和一个失败作业。
- [ ] 管理员可以维护平台类型并关联具体平台；同一类型创建第二份 Prompt 被拒绝，被平台引用的类型不能删除。
- [ ] 迁移不自动分类既有平台；未归类平台不能新建任务或生成，新平台必须选择类型。
- [ ] Prompt 可在单一 Markdown 编辑框原地保存并立即生效；删除后该类型不能新生成，历史作业保留旧 system message。
- [ ] 任务页展示锁定的平台、类型和只读 Prompt，不允许生成时改平台；普通工程师不能进入配置管理。
- [ ] 工程师可以持续保存任务级 `user_prompt`；修改前后创建的作业分别保留各自快照。
- [ ] 实际云端请求自动附加批准事实，但不包含证据文件、附件、私有源文档、对象存储地址、API Key 或敏感 Header。
- [ ] 同一任务可以选择不同模型或在 Prompt 修改前后生成多个草稿，各作业保留完整且互不漂移的配置与输入快照。
- [ ] 合法模型响应只含 `title`、`summary`、`body_markdown`、`tags`；代码块、附加说明、额外字段、缺失字段或非法 JSON 均显式失败。
- [ ] 自动检查阻断来源并集之外的数字、缺失必要披露和平台规则违规；界面明确其他技术陈述仍需人工审核。
- [ ] AI 输出只创建 `DRAFT ContentVersion`，工程师编辑创建新版本，事实追溯展示系统快照而非模型自报 ID。
- [ ] 重试保持原作业非敏感快照并使用渠道当前凭据；配置已删除时重试被拒绝，不会静默切换模型、Prompt 或开发生成器。
- [ ] 作业详情显示供应商请求 ID、响应耗时和可用 token 用量，供应商缺失字段显示不可用而不是 `0`。
- [ ] 管理员可新增、停用、启用 `ADMIN`/`ENGINEER` 用户并重置密码；普通工程师看不到入口且直接调用被拒绝。
- [ ] 停用用户撤销会话但保留历史归属；最后一个管理员不能停用或降级。
- [ ] 临时密码登录后必须改密；管理员修改自身密码需要正确旧密码，密码内容不进入响应、日志或审计。
- [ ] 同一用户可以提交并批准自己创建的事实和内容，但非法状态、缺失证据或阻断质量问题仍被拒绝。
- [ ] OpenAPI、数据库契约、运行时 Schema、前端生成类型、迁移、后端测试、前端测试和端到端流程一致。

## Out Of Scope

- 自动按成本、延迟或故障切换渠道或模型，以及单个作业内自动网络重试。
- OpenAI Responses API、Anthropic 等非 OpenAI-compatible 私有协议及通用多协议适配框架。
- 多阶段 Prompt 链、跨模板组合、模板变量表达式和通用 Prompt 编排器。
- 模型训练/微调、向量知识库、Prompt 自动优化、调用金额计算和自动发布。
- 证据文件、附件或私有源文档的模型读取，以及把 `user_prompt` 自动沉淀为已批准产品事实。
- 外部 OIDC/SSO、组织架构同步和跨公司多租户。
