# 前端 macOS 磨砂玻璃简白风改造

## Goal

在不改变现有信息架构、操作入口、业务流程、权限、路由和数据契约的前提下，将 PartSignal 前端重建为浅色与深色同等级的 macOS 磨砂玻璃一体式工作区，提升层级辨识、视觉一致性和日常操作舒适度。

## Confirmed Facts

- 前端采用 React 19、TypeScript、Vite、Ant Design 6、React Router 和 TanStack Query。
- `frontend/src/app/theme.ts` 统一生成 Ant Design Token 与项目 CSS 变量；`ThemeProvider` 统一拥有 `light`、`dark`、`system` 的解析、持久化、跨标签同步与减少动画状态。
- `frontend/index.html` 在 React 挂载前同步主题模式与画布色，避免首屏闪烁；这是运行时主题唯一来源之外的必要启动边界。
- `frontend/src/styles/global.css` 已集中管理页面框架、卡片、表格、表单、登录页、响应式布局和减少动画规则；`AppLayout` 已具备侧栏、顶栏、内容区和移动抽屉结构。
- `ui-ux-pro-max` 的主设计系统建议为 Minimalism、浅灰白背景、高对比正文、轻阴影和 150–300ms 动效；当前全局 CLI 与项目内 skill 均为 `2.11.0`，项目数据和 React 检索文件完整，实施前仍须通过临时目录生成结果核对模板一致性。
- 项目仍处于开发阶段，旧的 Midnight Signal 视觉、蓝/青品牌配色和视觉兼容不是交付约束；允许删除或替换旧视觉实现，不保留过渡分支。
- 项目已移除截图式视觉基线；本任务继续使用功能 E2E、主题测试和人工浏览器检查，不恢复 PNG 快照工作流。

## Requirements

- **R1 视觉方向**：从新的 macOS 双主题设计系统重新定义视觉。浅色模式采用中性灰白画布、半透明浅色表面、细边框、柔和阴影、系统字体和单一系统蓝品牌强调色；深色模式采用同等级的深色磨砂玻璃语言，以深中性画布、半透明深色表面、可见亮边和低眩光阴影建立对应层级。状态色与图表色仅按功能语义保留，不继承旧蓝/青品牌分工；两种模式均不使用高饱和渐变或装饰性拟物元素。
- **R2 玻璃使用边界**：磨砂玻璃仅用于顶栏、侧栏、移动抽屉、弹窗和悬浮操作条等需要表达层级的区域；表格、表单、正文和高密度业务卡片保持接近不透明。
- **R3 主题一致性**：可删除、重命名或重建旧主题 token；随主题变化的颜色、透明度、模糊、阴影和焦点环由 `frontend/src/app/theme.ts` 与其生成的 CSS 变量统一管理，浅深主题共用的字体、圆角、动效和间距继续由 `frontend/src/styles/global.css` 管理。不保留旧视觉兼容分支，不新增第二套同类运行时视觉常量来源。`frontend/index.html` 只允许为 React 挂载前首屏同步浅/深画布色，并须通过测试证明与主题配置一致。
- **R4 双主题一致性与业务边界**：浅色、深色模式均完成同等级视觉重塑，`system` 跟随系统映射到对应完整主题。保留现有信息架构、导航层级、页面划分、字段集合、操作入口、业务流程、权限判断、路由、请求、状态转换和交互语义；仅重建全局框架的视觉呈现、层级、密度、间距和组件外观。
- **R5 可访问性**：正文和控件文字满足至少 WCAG AA 4.5:1 对比度；焦点可见；颜色不是唯一状态提示；保留 `prefers-reduced-motion` 支持；玻璃效果不可用时仍可正常阅读和操作。
- **R6 响应式**：375px、768px、1024px、1440px 视口下无新增横向滚动、遮挡或固定区域覆盖内容问题。
- **R7 变更范围**：优先重建共享主题和全局样式覆盖全站；允许删除或替换旧视觉选择器，并在必要时调整共享布局或页面结构，但禁止逐页复制视觉样式或为旧外观保留兼容层。
- **R8 工具前置**：实施前验证全局 CLI 版本，并在临时目录生成 Codex 模板；仅当项目内 `ui-ux-pro-max` 与当前模板存在差异时，定向同步 `.codex/skills/ui-ux-pro-max/`，不得覆盖其他项目 skill。细分风格、UX 和 React 检索必须可运行；生成结果只作为设计输入，项目现有交互与可访问性约束优先。
- **R9 密度策略**：采用“框架宽松、业务区中等紧凑”。导航、顶栏、页头、页面分区和内容画布增加留白与层级间距；表格、表单、审核工作区、配置页和数据摘要保持高效的信息密度，不通过放大字号、控件或行高制造展示型留白。
- **R10 全局框架**：采用 macOS 一体式工作区：桌面端为全高磨砂侧栏、粘性磨砂工具栏和内嵌内容画布，内容面板通过圆角、边框与阴影表达层级；移动端沿用抽屉导航并使用同一材质体系。不得把侧栏、顶栏拆成占用额外边缘空间的悬浮玻璃岛。

## Acceptance Criteria

- [x] **AC1**：浅色与深色模式的全局框架、导航、弹层、卡片、表格、表单和登录页呈现成对一致的 macOS 磨砂玻璃视觉层级，且玻璃效果仅出现在 R2 规定的区域。
- [x] **AC2**：两种模式均采用高对比正文与可见边框；关键文字和控件通过对比度检查，键盘焦点清晰可见。
- [x] **AC3**：`light`、`dark`、`system` 三种模式仍可切换并持久化，`system` 能随系统配色实时映射到完整浅色或深色玻璃主题。
- [x] **AC4**：现有前端单元测试通过；主题、布局和响应式相关测试根据实际行为补充或更新。
- [x] **AC5**：在 375px、768px、1024px、1440px 下完成真实页面检查，导航、表格、表单、弹窗和悬浮操作条无新增布局问题。
- [x] **AC6**：`npm run typecheck`、`npm run lint`、相关 `npm test` 和前端构建通过；浏览器烟测覆盖登录页、工作台和至少一个高密度配置页面。
- [x] **AC7**：diff 不包含业务契约、API 类型、权限、路由或数据流变化，也不新增运行时依赖。
- [x] **AC8**：导航与页头的空间层级明显宽松于现状，同时代表性表格、长表单、审核工作区和配置页的主要操作在相同视口下没有明显增加无效滚动或降低信息可扫读性。
- [x] **AC9**：桌面端呈现连续的一体式工作区，侧栏、工具栏、内容画布的边界清晰且无双重滚动；移动端抽屉、工具栏和内容区使用同一视觉语言，未引入额外边缘空隙或内容宽度损失。

## Out of Scope

- 重新设计业务信息架构、页面流程或权限模型。
- 增删、合并或重排现有字段、操作入口、导航层级和业务步骤。
- 新增品牌 Logo、插画、3D、复杂动效或全站玻璃卡片。
- 修改后端、OpenAPI、数据库、部署配置或业务数据结构。
- 为追求视觉一致而重写 Ant Design 组件或引入新的 UI/CSS 框架。
- 保留 Midnight Signal 名称、旧蓝/青品牌视觉或旧样式兼容层。
