# 验收文档同步

## 1. 目标与价值

处理第二轮全项目回归的 `PS-QA2-DEC-001`：让当前活动验收与系统设计文档准确描述 `0033_task_owned_history_delete` 已实施的内容任务受控删除规则，避免验收人员继续把“存在任意生成作业或内容版本”误判为删除阻断条件。

## 2. 已确认事实与根因

- `contracts/database.md:277-285,338` 是数据库规则的权威来源：只有 `CANCELLED` 任务可删除；允许同时清理该任务的生成作业、审核记录和 `DRAFT | PENDING_REVIEW | CHANGES_REQUESTED` 内容版本；`APPROVED | SUPERSEDED` 内容、任一发布记录或非空修复来源必须阻断。
- `contracts/openapi.yaml:1308-1317`、`backend/app/services/publication.py:920-1045`、迁移 `backend/alembic/versions/0033_task_owned_history_delete.py` 和现有集成测试已经实现并验证该合同，本任务不重新设计它。
- `docs/deployed-full-functional-acceptance-plan.md:133,231,540-548` 仍把任意生成作业或内容版本视为删除阻断，且测试数据准备没有区分“可清理的任务自有历史”与“受保护下游历史”。
- `docs/GEO多平台内容运营系统方案设计.md:112,482,659,853,1083` 与 `docs/GEO系统前后端技术与部署方案.md:499,1123` 保留同一旧规则。
- 根因是 `0033` 放宽任务自有历史清理边界后，合同、迁移、实现和测试已更新，但既有验收与设计文档没有同步，形成多处过时副本。
- `PS-QA2-DEC-002` 已由用户批准，并在归档任务 `08-01-global-resource-available-actions-convergence` 中实施完成；本任务只记录这一状态，不再次讨论或扩展 `available_actions` 合同。

## 3. 范围内需求

- 明确生成作业、审核记录和未批准内容版本属于可随任务清理的任务自有历史；
- 明确 `APPROVED | SUPERSEDED` 内容、任一发布记录或发布修复来源属于受保护历史并阻断删除；
