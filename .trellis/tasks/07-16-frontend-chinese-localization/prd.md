# 运营前端全站中文化

## 目标

在最终页面结构上完成全站用户可见文本中文化，使管理员和电子工程师使用同一套清晰、准确的中文运营界面，同时保持 API 值、协议字段和行业术语不变。

## 依赖与范围

- 依赖 `07-16-configuration-hierarchy-cards` 和 `07-16-controlled-physical-deletion` 完成，避免翻译即将删除或重构的旧页面。
- 覆盖 `frontend/src` 中管理员和工程师能够看到的全部页面、组件、导航、弹窗和表单，以及前端直接展示的已知后端业务错误。
- 项目只提供中文界面，不引入 i18n 框架、语言包或语言切换能力。

## 需求

### R1 必须中文化的内容

- 页眉 eyebrow、副标题、导航项、面包屑和页面说明。
- 业务状态、角色、枚举选项及其筛选标签。
- 字段标签、按钮、表格列名、弹窗标题和确认文案。
- 占位符、帮助文字、校验错误、操作反馈、空状态和加载失败提示。
- 图表图例、统计卡片标题、时间/数量单位及面向用户的可访问性文本。
- 已知业务错误若由后端 message 直接展示且仍为英文，在权威后端错误出处改为中文，稳定 `error.code` 不变。

### R2 必须保持原样的内容

- `model_id`、API Key、URL、Markdown、JSON、Header、Prompt 等行业或协议术语。
- API 字段、配置键、Header 名称、模型 ID、自定义参数键、slug 原值和状态/枚举的机器值。
- 产品型号、品牌、渠道名、供应商返回值、用户输入和生成内容。
- `PARTSIGNAL` 等产品标识。

必要时采用“唯一标识（slug）”这类中文说明加原术语，不把机器值翻译或回写。

### R3 映射与一致性

- Select、Radio、筛选器和状态标签使用中文 `label`，提交值保持原枚举值。
- 补全现有 `StatusTag` 等共享显示映射；只有多个页面共同使用的稳定枚举才提取共享映射。
- 页面专属选项留在所属 feature，不建设无边界全局翻译字典。
- 相同业务状态在全站使用同一中文词语，不出现同值多译或中英文混排。

### R4 视觉与行为保持

- 中文化不得改变权限、请求参数、状态转换、路由、表单提交或缓存行为。
- 中文文本在桌面端、移动端、浅色和深色主题下不得造成页面级横向滚动、按钮遮挡或关键信息截断。
- 保留技术内容的复制、粘贴、代码样式和原值展示能力。

## 验收标准

- [x] 全站用户可见页眉、副标题、状态、枚举、字段、提示、校验、错误和空状态完成中文扫描，不再出现可合理翻译的英文业务文本。
- [x] 所有机器值、API 请求、模型/参数/Header/URL 原值和用户数据在中文化前后完全一致。
- [x] 相同状态和枚举在各页面中文标签一致，Select 提交值未改变。
- [x] 管理员和工程师权限路径均完成检查，包括配置、产品事实、内容生成、审核、发布、GEO、用户和设置页面。
- [x] 375/768/1024/1440 宽度及浅/深色主题无新增溢出、遮挡或不可操作控件。
- [x] 单元测试、前端测试、类型检查、构建和关键 E2E 通过。

## 非目标

- 不引入多语言、运行时 locale、翻译服务或新依赖。
- 不翻译协议术语、代码标识、机器值、业务数据或用户生成的 Markdown。
- 不借中文化重构业务状态、权限、API Schema 或页面信息架构。
- 不翻译仅供开发者使用且不会进入界面的测试名称、内部日志键或第三方协议文本。
