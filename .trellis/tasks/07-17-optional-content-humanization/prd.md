# 可选文章自然化修订

## Goal

在保留原始 AI 草稿、批准事实边界和完整生成追溯的前提下，允许工程师对具体 AI 内容版本显式发起一次自然化模型修订，创建语言更自然的新草稿；不得覆盖原文、隐藏第二次供应商调用或宣称必然降低第三方 AIGC 检测分数。

## Background

- `Humanizer-zh` 是面向 Agent 的中文编辑提示词规则，不提供可嵌入后端的 SDK 或 HTTP 服务；本功能采用其中适合产品内容的编辑原则，不引入 Skill 运行时。
- 当前平台 Prompt 与固定严格 JSON/批准事实契约在 `backend/app/services/content_production.py:155` 合并，供应商调用位于 `backend/app/services/generation.py:393`。
- `generation_jobs` 是 PostgreSQL 权威作业状态，Redis 只传 UUID；同一作业至多调用供应商一次。`ContentVersion` 正文不可原地修改，`source_job_id` 和 `based_on_id` 分别记录 AI 作业及修订来源。
- 第三方模型只允许处理任务与全部事实证据均已明确标为 `PUBLIC` 的冻结输入。

## Requirements

### R1. 显式触发与来源资格

- 原草稿成功后，用户只能对具体 `ContentVersion` 单独发起自然化；原生成请求不得自动串行执行第二次调用。
- 所属 `ContentTask` 必须为 `OPEN`，源版本必须是 `source_type=AI` 且状态为 `DRAFT` 或 `CHANGES_REQUESTED`。
- `PENDING_REVIEW`、`APPROVED`、`SUPERSEDED` 及 `source_type=HUMAN` 版本不得作为来源。
- 同一源版本同时最多有一个 `PENDING` 或 `RUNNING` 自然化作业；成功产生的新 AI 版本可再次自然化。

### R2. 全局自然化 Prompt

- 系统只维护一个管理员可编辑的全局当前自然化 Prompt，不提供平台级副本、每次操作临时 Prompt、代码常量回退或第二来源。
- Prompt 使用乐观锁和审计；数据库迁移后保持未配置，管理员必须首次显式保存，`updated_by` 必须是真实管理员。
- 未配置时自然化入口说明不可用原因，服务端返回明确错误，不使用默认 Prompt。
- 作业快照冻结 Prompt 完整 Markdown、revision 和最终消息；后续修改不得改变历史作业或重试语义。

### R3. 模型与冻结输入

- 发起自然化时，用户必须从当前已启用且测试通过的模型中选择 `ai_model_id`；不强制复用源生成模型，也不建立自然化专属模型配置。
- 作业冻结源版本全部发布正文、内容哈希、原始生成批准事实、任务要求、PUBLIC 分级证据、模型、渠道、请求参数、Prompt 和最终 system/user message。
- 执行与重试继续遵守现有配置删除、停用、敏感 Header、固定目的地址、超时和严格响应边界。

### R4. 作业与不可变版本

- 自然化复用现有异步作业状态机和 Celery UUID 消息，不建立第二套作业表、队列、恢复器或指标来源。
- 每个自然化作业最多调用供应商一次，并沿用幂等创建、超龄 `PENDING` 补投递、`RUNNING` 不重放、租约过期显式失败和显式重试规则。
- 成功作业创建一个新的不可变 `DRAFT ContentVersion`：`source_type=AI`、`source_job_id` 指向自然化作业、`based_on_id` 指向源版本；源版本正文和状态不变。
- Worker 在调用前和落库前均复核任务、事实、产品、源版本身份、状态、类型和冻结哈希；调用期间资格变化时不得写入迟到结果。

### R5. 输出、事实与审核

- 模型响应继续严格限定为非空 `title`、`summary`、`body_markdown`、`tags` JSON，不提取、修复、补值或接受附加说明。
- 自然化不得新增批准事实之外的型号、参数、数据、引用、用户反馈、专家观点或第一人称经历。
- 落库前运行现有确定性质量检查和近重复提示；未知数字、禁用表达或缺少必要披露继续形成既有质量问题。
- 审核上下文必须展示原始生成追溯、沿版本链发生的全部自然化追溯及源版本差异，审核人员仍是内容语义与事实一致性的最终确认者。

### R6. UI、可观测性与文档

- 配置中心允许管理员首次创建和按 revision 更新全局自然化 Prompt。
- 内容任务页允许对合格版本选择模型并发起自然化，展示作业类型、源版本、状态、失败原因、token、耗时、供应商请求 ID、结果版本和比较入口。
- Prompt、正文、模型响应和凭据不得写入日志或 Redis；非敏感作业指标继续保存在 PostgreSQL。
- 项目文档提供经过批准事实约束裁剪的 `Humanizer-zh` 建议模板及 MIT 归属说明，管理员审阅后自行保存；数据库不得自动种子该模板。

### R7. 效果边界

- MVP 不接入任何 AIGC 检测器，不保存或展示 AIGC 分数，也不把检测结果作为审核或发布门禁。
- 自然化成功只表示创建了通过结构解析和既有质量检查的待审核草稿；产品不得宣称检测器分数必然下降。

## Acceptance Criteria

- [x] AC1：未配置全局自然化 Prompt 时，新环境不存在隐式默认，入口显示不可用，服务端不创建作业；管理员首次保存后功能可用，审计记录真实管理员。
- [x] AC2：不触发自然化时，现有生成 API、作业执行、重试和内容版本结果保持不变。
- [x] AC3：合格 AI 版本可使用用户选择的当前可用模型创建独立作业；相同幂等键返回同一作业，冲突载荷返回明确错误。
- [x] AC4：非 `OPEN` 任务、非法版本状态、`HUMAN` 来源、同源已有活动作业、Prompt 缺失、模型缺失/未测试/停用或非 PUBLIC 输入均在供应商调用前被拒绝。
- [x] AC5：成功作业只调用一次供应商并创建一个新 `DRAFT` AI 版本；新版本 `based_on_id` 等于源版本 ID，源版本正文和状态不变。
- [x] AC6：作业快照完整冻结源正文及哈希、Prompt revision、模型渠道和原始批准事实；当前配置变化不改写历史，失败重试复制原快照。
- [x] AC7：严格响应失败、输出新增未批准数字/禁用表达、重复消息、并发 Worker、Broker 中断、租约超时或调用期间来源失效均不会产生重复或迟到内容版本。
- [x] AC8：自然化结果可再次自然化；同一源版本任一时刻最多一个活动作业，数据库约束与服务端校验共同成立。
- [x] AC9：内容任务页可发起、轮询、失败重试、进入结果和比较版本；审核上下文展示完整原始生成与自然化链路。
- [x] AC10：系统不调用 AIGC 检测服务，不把自然化成功描述为检测分数下降。
- [x] AC11：OpenAPI、Pydantic、前端生成类型、数据库契约、架构/测试文档和实现一致；迁移、单元、PostgreSQL 集成、前端组件、契约和端到端验证通过。

## Out of Scope

- 对 `source_type=HUMAN` 的人工修订正文执行自然化；未来若支持，必须为完整修订正文建立独立、显式的数据分级边界。
- 自动保证通过任意 AIGC 检测器，或集成检测服务、阈值、样本集和评分历史。
- 平台级自然化 Prompt、用户临时 Prompt、自然化专属模型配置或自动串行自然化。
- 新 Agent/Skill 运行时、Prompt 编排框架、非 OpenAI-compatible 协议、自动发布或绕过人工审核。

## Notes

- 本任务是一个共享作业与内容版本不变量下的单一纵向功能，不拆分父子任务；数据库/API、Worker、审核追溯和 UI 必须按同一契约串行落地。
- 这是跨数据库、公共 API、异步作业、前后端和权威文档的复杂任务；`prd.md`、`design.md`、`implement.md` 通过评审并执行 `task.py start` 前不得实施。
