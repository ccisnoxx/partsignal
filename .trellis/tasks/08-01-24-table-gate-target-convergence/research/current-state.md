## 4. 隔离环境与复用边界

- `deploy/scripts/e2e-local.sh` 创建一次性 PostgreSQL 数据库和对象存储，启动本地假 AI 服务，并在退出时精确清理。
- `backend/app/cli.py` 的 `seed-demo` 只创建管理员和内容工程师，不提供业务表数据。
- `frontend/playwright.config.ts` 使用 `workers: 1`，`e2e` project 依赖 `shared-data.setup.ts`，因此 setup 是本门禁稳定数据的权威前置。
- `mvp-flow.spec.ts` 已验证 AI Header/模型/作业、内容批准、人工发布和 GEO 观测的真实 API 顺序；本任务复用最小子集，不等待该文件（它在目标 spec 之后执行）也不复制其全部验收流程。

## 5. 最小修复判断

只给两张弹窗补选择器能修复报告中的最短复现，但仍不能满足“每个清单项唯一根节点”的权威验收，因为同一 `surface` 的任务详情、发布工作台和 GEO 洞察仍只会被全局扫描一次。最小完整修复是：在现有清单增加运行时 region 身份、让 helper 接受精确目标，并仅在现有共享 setup 中补齐条件表需要的数据；无需修改任何生产组件或创建新测试框架。
