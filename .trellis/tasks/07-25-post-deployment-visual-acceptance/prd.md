# 线上部署后视觉验收

## Goal

在不修改预发布业务数据或配置的前提下，确认已推送的 PartSignal 统一视觉系统正确部署并通过真实公网浏览器渲染，及时区分部署版本、缓存、字体、主题或页面 CSS 引起的线上视觉偏差。用户于首次部署身份检查失败后，明确授权将已推送的 `main@bee2ef4` 重新部署到预发布并继续同一任务。

## Background

- 预发布环境的权威地址是 `https://geo.962850.xyz`，部署与验收边界以 `docs/Hostdzire部署上线流程.md` 和 `docs/Hostdzire部署附录.md` 为准。
- 本轮视觉系统的工作提交是 `2f00036`，任务归档和会话记录后的 `main` 提交是 `bee2ef4`。
- 人工批准的视觉证据位于 `.trellis/tasks/archive/2026-07/07-25-frontend-visual-system-recalibration/assets/approved/`，包含四张统一锚点和九张页面局部参考。
- `.trellis/spec/frontend/visual-system.md` 仍是唯一人类可读视觉规范；批准截图只作为规范从属的验收证据。
- 除用户明确授权的单次 `bee2ef4` 重部署外，公网浏览器验收必须从本机访问真实域名，只读操作，不创建业务数据、不修改线上配置、不运行依赖本地 Mock Provider 的纵向 E2E，也不更新自动视觉基线。

## Requirements

### R1. 部署与资源身份

- 只读确认预发布当前 release 对应已推送的 `main`，并且至少包含工作提交 `2f00036`。
- 检查公网首页、健康端点、SPA 路由和实际加载的带哈希前端资源；若部署版本不匹配、资源失败或缓存头不符合 Runbook，停止视觉结论并报告部署问题。
- 首次检查发现旧 release 后，允许按 Runbook 新建并切换到精确对应 `bee2ef4` 的 release；该授权不包含修改 Nginx、共享环境文件、业务数据或部署源码，也不包含额外部署、回滚或清理。

### R2. 安全登录与运行信号

- 优先复用已有的已认证浏览器会话；需要登录时，只允许按 Runbook 将管理员密码读入浏览器自动化内存。
- 密码不得输出到命令、日志、对话、截图、DOM 快照或临时文件；提交密码前不得抓取可能包含密码值的页面证据。
- 登录前后控制台不得出现应用级 `error` 或 `warning`，静态资源、认证、脚本和页面 API 不得出现非预期失败。
- 只读取已有页面和已有对象；不得点击新建、保存、提交、批准、退回、删除、启停、测试连接或其他写操作。

### R3. 1440×1000 浅色主验收

优先检查四张统一视觉锚点：

1. 总览 `/`
2. 用户管理 `/users`
3. GEO 分析洞察 `/observations/insights`
4. 内容审核 `/content/:contentVersionId`，仅打开已有内容版本

随后检查九张页面局部参考：

1. 审计日志 `/audit`
2. 发布账号 `/settings?tab=accounts`
3. Prompt 管理 `/configuration/prompts`
4. 平台规则 `/configuration/platform-rules`
5. 平台管理 `/configuration/platforms`
6. GEO 观测 `/observations`
7. 发布管理 `/publications`
8. AI 渠道与模型 `/configuration/ai`
9. 内容任务 `/tasks`

每页按 `visual-system.md` 和对应批准资产检查：

- 共享壳层的 208px 侧栏、64px 顶栏、20px 桌面内容边距、统一搜索区和环境光关系。
- 页面标题、正文、表格、指标、状态、按钮和辅助文字的字体层级与密度。
- 玻璃仅用于允许区域，表格、正文、编辑器和复杂表单保持高不透明度。
- 卡片、圆角、边界、阴影、状态色、图表和详情栏比例无明显页面级漂移。
- 动态身份、时间、数值和正文只比较布局与层级，不要求与批准截图中的业务内容一致。

### R4. 代表性主题、缩放与窄屏检查

- 四张统一锚点补查深色和跟随系统主题，确认语义颜色、边界、图表、焦点和玻璃降级正常。
- 四张统一锚点使用真实浏览器 200% 缩放，确认关键内容、导航和操作入口未丢失，页面无非预期横向滚动。
- 在 1024px 和 375px 代表宽度检查四张锚点；表格只允许在 `TableRegion` 内横向滚动，移动导航使用 280px Drawer。
- 不对公网环境运行本地视觉基线测试，不创建或更新 Playwright snapshot。

### R5. 验收报告

- 记录已验证的 release/commit、浏览器、视口、主题、页面 URL 和检查时间，不记录凭据或敏感正文。
- 发现问题时按严重程度列出页面、区域、可复现条件、实际表现、批准规范期望和最可能的责任层。
- 明确区分部署/缓存问题、运行时错误、结构性视觉偏差和仅由动态数据导致的正常差异。
- 本任务只报告结论；除已批准的 `bee2ef4` 重部署外，任何代码修复、额外部署、回滚、基线更新或视觉规范变更必须另行获得用户授权。

## Acceptance Criteria

- [x] AC1：确认预发布 release 包含 `2f00036`；公网首页、健康端点、SPA 路由和带哈希静态资源正常。
- [x] AC2：真实公网域名登录和只读导航可用，控制台及网络无非预期应用级失败，凭据未被输出或持久化。
- [ ] AC3：13 个批准页面均在 1440×1000 浅色主题完成视觉复核，四张锚点和九张局部参考没有未说明的重大构图、配色、字体或密度偏差。
- [ ] AC4：四张锚点的深色、跟随系统、200% 缩放、1024px 和 375px 代表场景无关键内容丢失或页面级横向溢出。
- [x] AC5：验收报告包含覆盖范围、通过项、问题清单和残余风险，所有结论可追溯到 URL、视口、主题及规范条目。
- [x] AC6：除已批准将 `bee2ef4` 发布并原子更新 `current` 外，验收过程未创建业务数据、修改线上配置、执行额外部署或回滚、运行公网纵向 E2E 或更新视觉基线。

## Out of Scope

- 已批准的 `bee2ef4` 重部署之外的部署、重启、回滚、`current` 更新或远端 release、镜像和数据清理。
- 修复验收中发现的代码、样式、缓存或部署问题。
- 修改后端、API、数据库、权限、业务状态或线上配置。
- 在公网运行依赖本地 Mock Provider 的完整纵向 E2E。
- 将线上动态业务数据与批准截图中的示例内容做逐像素比较。

## Risks and Stop Conditions

- 当前 release 不包含 `2f00036`、公共资源或健康检查失败时，停止视觉验收并报告部署阻断。
- 无法安全取得已认证会话或浏览器能力不可用时，记录“UI 未验证”并停止，不用 `curl` 替代真实渲染。
- 登录后存在敏感信息暴露风险时，不保存页面截图，只记录不含业务正文的结构化结论。
- 缺少可只读访问的既有详情对象时，不创建测试数据或猜测详情 ID；记录该页面未验证并继续不依赖该对象的其他页面。
- 线上动态数据可能改变行数、数值和正文；只把稳定壳层、组件几何、表面层级和语义样式作为视觉判断依据。
