# 事实与内容审核证据闭环设计

## 核心不变量

1. 审核记录追加且不可覆盖，读取顺序稳定。
2. `request-changes` 意见去除空白后必须非空；`submit` 与 `approve` 意见可选。
3. 内容审核上下文只来自当前不可变内容版本、任务锁定事实版本、生成快照和追加式记录。
4. 后续事实工作区或新事实版本不能改变历史内容审核上下文。
5. 服务端执行批准门禁，前端仅显示证据与允许动作。

## 查询投影

### 通用 `ReviewRecord`

事实和内容复用统一展示结构：

- `id`
- `action`
- `comment`
- `actor`：`id`、用户名和展示名摘要
- `created_at`

普通 Engineer 不依赖管理员 `/users` 接口补全演员信息。投影在后端联表生成，不复制用户状态。

### `FactReviewContext`

返回目标事实版本的不可变快照、证据摘要、当前状态、服务端允许动作和完整审核历史。Goal 2 提供稳定的事实版本审核 API 与页面内版本交互；`tab=versions&fact_version_id=...` 的可恢复 URL 由 Goal 4 统一路由工作完成。

### `ContentReviewContext`

一次查询返回：

- 当前不可变 `ContentVersion` 和任务摘要。
- 当前正文、质量问题和服务端允许动作。
- 任务锁定 `FactVersion` 的产品/参考型号、关键参数、测试条件、替代等级、成立/排除条件、声明和证据。
- 相对源版本或上一版本的规范化差异。
- 生成作业的非敏感追溯摘要。
- 追加式审核历史。

该对象是运行时读取投影，不持久化为第二份事实、内容或审核状态。

## API 设计

- `GET /fact-versions/{fact_version_id}/review-context`
- `GET /content-versions/{content_version_id}/review-context`

若独立历史列表没有其他消费者，不额外创建只做转发的端点；上下文内包含完整历史。未来确有分页压力时再拆分。

审核命令继续使用现有事实/内容状态入口，但请求 Schema 按动作校验：

- `request-changes`：`comment` 必填且非空。
- `submit` / `approve`：`comment` 可选或允许空字符串规范化为空。
- 所有命令追加审核记录和审计。

## 服务端所有权

- 事实版本及其冻结证据是审核事实的唯一来源。
- 质量阻断规则只在服务端实现一次，`available_actions` 根据状态、质量和权限投影。
- 版本差异只比较已确认字段，不对任意 JSON 做模糊 diff。
- 不根据模型自报的事实/证据 ID 重建追溯；继续使用任务事实版本和生成快照。

## 前端设计

保留 `/content/:contentVersionId`，改为消费单一 `ContentReviewContext`，避免多个请求部分成功导致版本错配。页面按以下顺序呈现：

1. 当前正文与质量问题。
2. 版本差异。
3. 冻结事实、证据和替代边界。
4. 审核历史与最新退回意见。
5. 服务端允许的审核操作。

事实页面在 Goal 2 内通过明确版本交互定位审核对象，Goal 4 再补齐刷新可恢复的稳定 URL。任一审核上下文查询失败时禁止批准或退回；错误由共享失败组件处理，真实空证据则显示明确业务缺口。

内容审核页在 Goal 2 已切换为单一上下文查询，并完成失败禁用、真实空证据、退回/重新提交和批准确认测试。事实版本稳定 URL 不因页面内交互存在而提前判定为已实现。

可复用 `ReviewTimeline`、`ReviewEvidencePanel` 和字段化 `VersionDiffViewer`，但组件只消费 OpenAPI 生成 DTO，不定义传输类型或业务状态机。

## 迁移与兼容

现有事实与内容审核记录表已经保存所需历史，预计不新增业务表。OpenAPI 增加读取投影并收紧退回意见校验；旧空退回记录继续按历史显示，不补造意见。

不保留前端拼接旧多请求路径。新上下文上线后前端同批切换，契约检查保证 Schema 一致。

## 最终确认补充

- 审核应用服务唯一拥有事实/内容状态转换、质量门禁、审核记录追加和 `available_actions` 投影。
- 上下文查询必须在一次数据库读取边界内装配，避免内容、事实和审核记录来自不同版本时点。
- `ActorSummary` 通过联表投影用户名和展示名，不复制用户启停状态，也不要求 Engineer 访问管理员用户接口。
- 上下文任何必需来源缺失时返回明确错误，不以当前工作区、空数组或默认字段代替。
- Router 只负责路径、请求 Schema 和响应映射；不得继续承载状态机或跨域拼接逻辑。
- 与发布闭环只共享冻结后的 OpenAPI 类型和任务锁定语义；审核应用服务不拥有发布状态、异常待办或修复任务状态。
