# 完整发布与上线回归设计

## 发布不变量

`origin/main` 的单一不可覆盖 release 是应用镜像、Compose、Nginx 模板和验收证据的共同来源。`current` 只在全部验收通过后更新，且不作为流量开关。

## 执行设计

1. 本地校验干净 `main`、目标提交、Nginx 安全检查和部署脚本自检。
2. Hostdzire 只读确认身份、当前 release、共享环境权限、资源、容器和 Nginx 状态。
3. 从目标提交制作安全归档，上传并创建唯一 release，链接既有 `.env.staging`。
4. 对已有数据库执行备份；在 release 内以默认 `full` 模式运行 Compose 校验、构建、只读完整性门禁、迁移、服务启动和健康检查。
5. 从同一 release 安装 staging Nginx 模板与项目安全 snippet，`nginx -t` 后 reload。
6. 先执行命令行公网验收，再建立命名浏览器会话完成管理员回归；经用户明确授权，通过正常 UI 创建无业务历史的隔离工程师账号，完成首次改密和权限回归后先停用再删除。
7. 全部通过后原子更新 `current`，最后复核容器重启/OOM、Nginx 错误日志和浏览器清理。

## 停止与回滚

- 主机身份、共享环境权限、备份、预检、迁移、健康、Nginx 或浏览器验收任一失败均停止后续阶段。
- 容器已替换但验收失败时，用上一已验证 release 的镜像重启固定 Compose 栈；若涉及 Nginx，同时恢复该旧 release 的模板与安全 snippet。
- 不删除失败 release、备份、镜像或持久数据，不自动修改业务状态。

## 安全边界

凭据仅从 Hostdzire 既有 root-only 环境读取到所需进程内存；不输出、不写入任务或证据。浏览器不调用模型、不修改业务配置；唯一写操作限于用户明确授权的隔离工程师测试账号生命周期，账号无业务历史，删除后保留不可变审计。
