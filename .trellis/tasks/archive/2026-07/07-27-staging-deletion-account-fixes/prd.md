# 修复预发布删除与账号治理缺陷

## Goal

补齐尚未进入内容生产的已取消任务和无业务历史的停用账号删除能力，清除 E2E 账号长期累积的根因，同时收敛平台列表 Logo 尺寸与重置临时密码长度。

## Background

- 内容任务当前只有创建、查看和取消接口；任务详情在取消后没有删除动作，`contracts/openapi.yaml:1217-1254` 未定义 `DELETE`。
- `generation_jobs.content_task_id` 与 `content_versions.task_id` 均以 `ON DELETE RESTRICT` 直接引用内容任务；没有生成作业和内容版本时，取消任务没有业务子记录。
- 用户列表摘要由 `backend/app/services/identity.py:_user_summary` 对全部 `users.account_type = 'ADMIN'` 实时计数，包含停用管理员；前端不重复计算。
- 2026-07-27 对预发布 PostgreSQL 的只读核对确认：除启用的 `admin` 外，存在两次 E2E 遗留的停用管理员 `admin-a49ac55d`、`admin-d0e548ae`，以及对应的两个停用工程师。四个账号只有会话和审计操作者引用，没有业务表引用。
- `sessions.user_id` 已是 `ON DELETE CASCADE`，`audit_logs.actor_id` 已是 `ON DELETE SET NULL`，其余用户业务归属外键均是 `ON DELETE RESTRICT`。
- 实施核对发现 `audit_logs_append_only` 是无例外的 `BEFORE UPDATE OR DELETE` 触发器；外键执行 `SET NULL` 时同样会触发并以 PostgreSQL `55000` 拒绝。因此必须新增一条迁移，为当前事务显式声明的用户删除只放行 `actor_id: UUID -> NULL`，其他审计更新/删除继续拒绝。
- 平台列表在 `frontend/src/features/configuration/PlatformsPage.tsx:363` 固定使用 26px Logo；外部 URL 的 `sz` 参数只改变源图片像素，不能改变列表展示尺寸。
- 用户确认：删除账号后保留历史审计记录，过去由该账号执行的审计记录允许把 `actor_id` 置空。

## Requirements

### R1. 受约束删除内容任务

- 新增 `DELETE /api/v1/content-tasks/{content_task_id}`，权限与取消任务一致，并继续要求 CSRF。
- 仅 `CANCELLED` 内容任务可删除；`OPEN`、`COMPLETED` 或不存在的任务必须明确失败。
- 服务端锁定任务并确认不存在生成作业和内容版本；存在引用时返回结构化 `409 CONTENT_TASK_IN_USE`，不得级联删除、改写或隐藏历史。
- 成功删除追加 `content_task.deleted` 审计并返回 `204`。
- 任务详情仅在服务端 `available_actions` 包含 `DELETE` 时显示危险操作，经确认后删除并返回任务列表；不得由前端自行推断业务可删除性。

### R2. 受约束删除停用账号

- 新增 `DELETE /api/v1/users/{user_id}`，仅管理员可调用并继续要求 CSRF。
- 仅已停用用户可删除；启用用户返回明确 `409`，不得自动停用后继续删除。
- 服务端锁定目标用户后执行删除。会话由既有 `CASCADE` 清理，历史审计由既有 `SET NULL` 保留；任一业务归属 `RESTRICT` 外键阻断时返回明确 `409 USER_IN_USE`，不得级联删除或改绑。
- 删除服务必须在事务内设置目标用户 UUID；新审计触发器仅当 `actor_id` 从该 UUID 变为 `NULL` 且审计行其他字段逐值不变时放行。缺少声明、目标不匹配、其他字段变化或删除审计行仍以 `55000` 失败。
- 成功删除追加 `user.deleted` 审计，删除审计保留执行管理员、目标 UUID、账号类型和停用状态，不保存密码或其他敏感值。
- 用户列表“更多操作”仅对停用账号显示删除入口；确认文案明确会话删除、审计操作者置空和业务引用阻断，不提供批量删除。
- 管理员统计继续按数据库现有全部 `ADMIN` 口径实时计算；删除停用管理员后自然减少，不改成只统计启用管理员。

### R3. 防止 E2E 账号再次累积

- 账号治理 E2E 使用新增删除接口清理符合其精确命名规则的历史测试账号，并在成功路径删除本次创建的停用工程师和管理员。
- 测试不得删除不符合自身用户名和显示名称双重规则的账号，不得修改真实业务账号。
- 本任务不自动删除预发布现有四个遗留账号；功能上线后由管理员通过新入口确认删除。

### R4. 重置临时密码最小长度

- `ResetPasswordRequest.temporary_password` 的服务端与前端最小长度从 12 调整为 8。
- 恰好 8 位的重置临时密码必须成功，7 位必须由请求校验拒绝。
- `UserCreate.temporary_password` 和 `ChangePasswordRequest.new_password` 继续保持最小 12 位；登录密码输入继续保持最小 8 位。
- 明文临时密码仍不得进入响应、日志或审计。

### R5. 平台列表 Logo

- 平台管理列表 Logo 的固定展示尺寸从 26px 调整为 24px，继续复用 `PlatformAvatar`、`object-fit: contain` 和统一容器。
- 不根据外部图片的固有像素或 URL 查询参数动态改变行高，不修改其他页面的 Logo 尺寸。

### R6. 契约、文档与验证

- 同步更新 `contracts/openapi.yaml`、生成的前端 API 类型、`contracts/database.md` 和系统方案文档；新增唯一必要的审计触发器迁移，不创建第二套契约。
- 后端集成测试覆盖删除成功、状态阻断、业务引用阻断、权限、审计保留与密码 8/7 位边界。
- 前端测试覆盖两个危险操作的确认/失败/刷新或导航、重置密码 8 位校验，以及平台 Logo 24px。
- 运行相关后端测试、前端 Vitest、API 类型生成一致性、typecheck、lint、production build 和最小 Playwright 回归。

## Acceptance Criteria

- [x] AC1：已取消且无生成作业/内容版本的任务可从详情页确认删除，删除后返回列表；其他状态或有引用任务保持不变并返回明确错误。
- [x] AC2：管理员可删除已停用且无业务引用的账号；会话删除，既有审计行保留且该账号过去的 `actor_id` 置空，删除审计仍可追溯执行管理员和目标 UUID。
- [x] AC3：启用账号和存在任一业务归属引用的停用账号无法删除；前端不提供自动停用、级联删除、改绑或静默成功。
- [ ] AC4：删除停用管理员后 `admin_total` 按原口径自然减少；E2E 成功运行不再留下本轮创建的用户，且历史清理只匹配测试自身精确命名规则。
- [x] AC5：管理员重置他人临时密码时 8 位成功、7 位失败；新建账号临时密码和自助正式密码仍至少 12 位。
- [x] AC6：平台管理列表 Logo 固定为 24px；外链 Logo 继续统一对齐，外部图片像素不改变表格行几何。
- [x] AC7：OpenAPI、数据库契约、方案文档、生成类型、迁移、实现与测试一致；无新增字段/表/依赖或未说明业务行为变化。

## Out of Scope

- 删除带有生成、内容、发布或其他业务历史的内容任务或用户。
- 批量删除用户、自动清理预发布数据、自动部署、推送或执行线上删除。
- 修改管理员统计为“启用管理员数量”。
- 把新建账号临时密码或用户自助正式密码的最小长度降到 8。
- 根据外部图片固有尺寸动态改变列表 Logo、表格行高或其他页面 Logo 尺寸。
- 放宽审计行的通用追加式约束，或允许应用任意更新/删除审计记录。

## Risks

- 用户删除会使该账号过去审计记录的操作者投影为空；这是用户已批准的显式取舍，审计行本身不得更新或删除。
- 审计 `SET NULL` 是外键触发的物理 UPDATE；迁移必须把例外限定到事务本地声明的目标 UUID 和唯一字段变化，并验证直接 SQL 不能伪造其他审计更新。
- 删除命令必须区分已批准的外键阻断与其他数据库异常，不能把未知错误吞成“存在引用”。
- E2E 历史清理若匹配范围过宽会误删真实账号，必须同时约束用户名和显示名称并只处理停用测试账号。
