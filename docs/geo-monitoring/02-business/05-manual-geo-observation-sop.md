# 人工 GEO 回答级观测 SOP

| 项目 | 内容 |
|---|---|
| 状态 | 已批准操作规范；依据本会话用户产品决策及 ADR-006 |
| 适用 | 核心版 MANUAL 回答级 Batch/Run；豆包、DeepSeek、元宝等人工观测 |
| 执行责任 | 计划指定员工执行；管理员维护配置；分析/复核人员按既有权限处理。具体人员由公司指定 |
| 边界 | 不授权 Browser 自动化；不改变 MANUAL/API 合同、指标或历史 |

决策见 [ADR-006](../05-decisions/ADR-006-defer-browser-collection-and-adopt-manual-first-core.md)，状态与证据流程见 [业务流程](./03-workflows-and-state-machines.md#5-人工采集流程)。本 SOP 使用当前正式表单，不能把目标设计当已上线能力。

## 1. 从计划领取 Run

1. 管理员准备明确平台的 MANUAL 观测面/Profile，配置语言、地区、登录模式、联网搜索策略、截图要求；每个平台使用独立配置。员工使用批准的人工访问方式，非公开问题仍按公司的数据外发规则处理。
2. 在 `/geo/plans` 预览计划，由服务端生成 `问题 × Profile × repeat` 矩阵。从计划详情的“运行中心”进入建批时，URL 保留该计划 `plan_id`，页面直接读取并展示该计划的当前名称、revision和矩阵，不必重新选择；列表搜索/分页不会替换这份上下文。核对后显式创建，成功进入对应批次并保留来源计划。切换计划同步URL，刷新或前进后退恢复该身份；读取失败不能自动改选，版本冲突后显式重读再确认，结果未知仅用原请求与原幂等键确认。创建批次后选择 PENDING MANUAL Run，记下 Batch ID、Run ID、repeat_index 与计划窗口。
3. 计划协调人员明确每个 Run 的执行员工，避免两人同时人工提问。“领取”是工作分配，当前系统没有人工独占 claim/租约按钮；打开录入或保存草稿不授予独占权。出现草稿 revision 冲突时重新读取并协调，禁止覆盖他人内容。
4. 核对冻结问题及环境。无法按该环境采集时保持草稿/待执行，通过正确配置创建新的合适 Run，不修改旧 Run 的冻结输入。

## 2. 使用精确问题并记录环境

- 在人工录入或运行详情的冻结问题全文旁选择“复制完整问题”，待页面提示成功后使用；复制的是本 Run 输入快照的 `prompt_text`，原样保留换行与格式。复制失败时手动选择该处全文，不使用问题标题、当前题库或计划模板替代。不改标点、型号、顺序或点名属性，不额外追加品牌提示或产品事实。只选择本 Run 对应平台。
- 在平台人工打开新的对话；有临时/无记忆方式时使用该方式。记录实际对话模式，不声称平台没有提供的隔离能力；不要沿用有额外上下文的旧对话作为同口径重复样本。
- 核对并记录平台/产品名称、语言、地区和登录模式。语言/地区/登录来自冻结 Profile，在录入页只读；现场必须匹配。可见的搜索状态据实选是/否，无法判断保持未知。
- 在“实际采集时间”填写回答完成时间并显式包含时区；不以录入时间替代历史采集时间。在来源产品/模型/版本字段只填平台实际可见标识，未知保持空，不根据品牌推测模型版本。
- 不上传账号头像、姓名、手机号、Cookie、密钥、浏览器 storage state、登录/支付/调试页面。截图裁去这些区域，同时保持问题、回答和来源证据可辨认。员工人工登录不导入 PartSignal Browser 会话。

## 3. 保存完整回答原文

等待平台回答自然完成后，复制完整可见原文，包括标题、列表、表格、免责声明及引用标记。不得改写、摘录、润色、补全截断回答或将自己的说明插入回答正文。按实际内容选择 TEXT/MARKDOWN 等表单格式，核对粘贴后完整性。

平台报错、访问挑战、空白或仍在生成时不正式提交成功回答。保留安全截图和草稿，通知计划协调人员；按现有可用取消/补测入口处理，不把失败录成“无提及”。普通页面把缺失/失败说明放在合并截图的独立说明区；独立原始文本证据也可按下述文件合同上传并关联。表单没有任意附件或自由备注入口，不将说明塞入回答正文或安全 raw summary，文本文件关联也不表示本次采样已成功。

## 4. 登记引用与缺失原因

1. 按回答/来源面板的实际顺序逐条记录来源标题、原始完整 URL、位置（从 1 开始）；重复出现按真实位置保留，由服务端规范化/合并。不得按自有来源优先重排。
2. 核对服务端从 URL 派生的规范域名；域名不在表单中单独自由填写。平台只显示标题或短域名时不能猜完整 URL，不能用搜索到的相似网页替代该次引用。
3. 显式选择“已完整记录引用”（COMPLETE）、“确认无引用”（NONE）、“引用部分缺失”（PARTIAL）或“无法判断引用”（UNKNOWN）。只查看完整回答及来源区域后才能确认无引用；空列表不会自动等于无引用。
4. URL 不可见、来源面板不完整或无法展开时保存截图，填写引用缺失原因（最多2000字符），说明缺失项、可见标题/顺序/域名。来源部分已知用 PARTIAL，保留实际已知 URL；全无可确定引用且无法判断用 UNKNOWN。不得猜 URL 或将说明塞进回答正文。COMPLETE 至少一条引用，NONE/UNKNOWN 不带结构化引用；状态矛盾时由操作者核对，不自动删除引用。
5. PARTIAL/UNKNOWN 可以随真实回答和必要证据正式提交；服务端将其排除出引用类指标，其他指标按各自资格计算。NONE 在其他门禁通过后提供可观察无引用依据；零引用份额仍为 N/A。草稿可暂留“未记录”，新正式提交必须明确选择。历史未记录维持原样和既有统计行为，不补填完整性，不能宣称已经确认无引用。

## 5. 上传回答与来源截图

同时保存回答（包含精确问题）和来源面板截图，覆盖完整回答与来源顺序。当前每个回答仍关联一个 `screenshot_file_id`。选择单张截图继续直接上传；多张可在页面本地按顺序预览、上移/下移、移除或追加，再选择“合成并预览截图”。合成按当前顺序自上而下原像素拼接为单张 PNG，不缩放、裁剪或修改原文件；宽度不同时其余部分留空。通过“查看原尺寸合成图”检查完整性、文字和敏感信息，再选择“上传合成截图”。证据说明放在独立区域，不能遮挡或修改回答内容。

页面本地合成容量为单边不超过16384像素、总计不超过3200万像素，输出仍不超过10 MiB。损坏、超限或编码失败会明确提示并保留顺序，不自动降低质量；可减少截图或使用本机图片工具整理后单张上传。尚未完成的本地整理会阻止保存/提交，离开时提示丢失；它不随草稿保存，刷新后需重新选择。可取消合成或显式“放弃本地截图整理”；远端上传结果未知时先走原有核对/放弃上传流程，再继续处理本地整理。只有文件校验为VERIFIED后才替换当前表单截图关联，随后保存草稿或正式提交。原图列表和预览仅留在当前页面，只有确认上传的最终截图进入文件服务。

使用现有截图上传入口；文件类别 OPERATION_SCREENSHOT，INTERNAL/RESTRICTED，最大 10 MiB。检查文字清晰、无敏感账号区域，上传完成并验证后才关联。提交者必须关联自己上传的文件。

可选原始纯文本证据通过“上传原始文本证据”选择文件，要求明确的 text/plain 类型、非空且不超过50 MiB；文件类别 EVIDENCE，新上传为 INTERNAL。上传前人工检查并移除凭据、个人信息等不应保留的内容；页面原样传输文件字节，不读取文件内容来填充回答，也不自动脱敏或按扩展名猜类型。等到显示“已校验原始文本证据”后，该文件才关联到当前表单，随后保存草稿或正式提交。已有引用会恢复显示；“移除原始文本证据关联”只修改当前表单，保存后生效，不直接删除文件或历史。冻结配置要求截图时仍须截图，文本不能替代。

截图与文本任一上传尚未确认时均不能保存或提交，离开会提示丢失。失败保留旧关联和本地回答；传输或校验结果未知时，先使用对应的“核对状态”“重试校验”或“放弃上传”，不要重复发送文件。冲突后重读保留本地关联，只有显式采用服务端草稿才替换。文件归属、大小、类型和对象完整性仍由服务端最终重验。不改扩展名绕过格式限制；无法在现有限制内完整保存时先保留草稿，与复核/运维人员处理，不宣称已保存完整证据。

## 6. 保存草稿与正式提交

正式提交前逐项核对：Run/平台/冻结环境正确，精确问题一致，回答完整非空，实际带时区时间正确，引用及缺失证据真实，截图已验证且无秘密，模型/版本未知未猜测。草稿保存后可继续编辑，但不要重复向外部平台提问以挑选更好的答案替换本次采样。

正式提交通过既有权限、revision、文件归属与完整性校验，原子冻结 AnswerSnapshot、引用和文件，Run 进入 COLLECTED。提交回执不表示分析已完成。成功后不能编辑、覆盖或补写原始证据；发现错误时保留历史，报告原因，通过新独立采样或既有分析复核处理。响应不明时先刷新确认结果，不盲目重复提交或重新提问。

### 未能完成本次采样时

尚未正式提交的人工运行，可从运行详情选择“取消未提交人工运行”，填写实际原因并核对运行/已保存草稿版本后确认。取消保留已保存草稿和文件引用，临时草稿继续按既有保留策略管理；其他已提交回答和历史证据不变。未保存的本地内容应先自行保存。取消不是“没有提及”的成功样本，也不允许借此删除已提交的低表现结果。

版本冲突时保留原因，显式重读条件后再确认；网络或服务端错误导致结果未知时，只重读运行详情核对取消记录，不盲目重发。已正式提交的回答不能取消或回退编辑，仍按原历史与复核流程处理。

## 7. 分析与人工复核

查看 Run Detail 的分析/复核状态。分析失败时保留 FAILED 状态、原始证据及历史，通知计划负责人处理。管理员可在运行详情的“管理员重新分析”区域选择“显式重新分析”，按实际情况选择规则更新、对象词典更新、批准事实更新或重试失败分析的原因，核对当前运行与分析版本后确认。只有保有原始采集回答、状态为 COMPLETED/NEEDS_REVIEW/FAILED 且服务端提供 REANALYZE 动作时才可操作；管理员权限、账号状态和 GEO 总开关仍由服务端最终裁决，普通员工不能绕过权限直接调用 API。

重新分析读取当前规则、对象词典及批准事实，保留原始回答、既有分析/复核及失败摘要；相同输入可能复用既有分析版本。接受回执不代表计算完成，也不会将 FAILED 采集状态改为成功或保证恢复指标资格。版本冲突后显式重读运行与分析历史，再核对确认；结果未知时只重读历史并保留请求 ID 供核对，不盲目重复提交。

NEEDS_REVIEW 按权限确认或修正提及、推荐、引用归属、声明及事实判断，复核追加记录。新的分析 revision 需要重新检查有效复核，不能用旧复核替代。

复核人员对照原文和截图，不补造引用或产品事实；不确定结论保持未知。复核只改变分析结论，不编辑原始答案。未通过必要复核的运行不得手工算入业务指标。

## 8. 数据资格与重复采样

- 从计划预先设定 repeat 和窗口，每个 repeat 对应一个独立 Run/回答，所有样本都保留。不得将同一回答/截图复制到多次重复、丢弃低表现样本、以取消失败替代成功零表现或事后挑选最佳答案。
- 精确问题版本、平台/Profile、MANUAL 模式、语言、地区、登录、搜索策略及规则应一致。环境变化另建正确采样配置/基线；MANUAL 不与 API/BROWSER 静默合并。
- COMPLETED、当前有效分析、必要人工复核、适用对象/问题和可比维度等资格仍由服务端裁决；缺引用证据或可靠排序时，相应指标可能不可用，空分母为 NULL。不要在表格里补零或维护另一套公式。
- 样本量和质量等级使用现有规则集与报告提示；样本不足不宣称趋势、不触发趋势型机会。每个结论回到 Run、原文、截图、引用与当前分析/复核。
- 严格复测按既有预览和基线门禁执行。模型/产品版本未知或环境变化可能阻断复测，不用人工备注或相似问题绕过；需要新基线时明确记录不可比原因。
- 证据依现有权限和保留规则管理；本 SOP 不新增保留天数、不删除历史。计划负责人分配采样与复核责任并处理缺失证据，具体频率按已批准人工访问范围执行。
