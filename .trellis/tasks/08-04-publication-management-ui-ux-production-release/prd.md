# 发布管理 UI/UX 重构生产上线

## 目标

把已经完成并验收的发布管理 UI/UX 重构安全发布到现有 Hostdzire 环境 `https://geo.962850.xyz`，让线上用户获得新的“待处理 / 发布成果 / 历史记录”信息架构、桌面高密度表格、移动任务卡片和详情抽屉，同时保持发布业务状态、权限、历史与生产数据不变。

## 背景与事实

- 本地 `main` 包含工作提交 `72c4dd3`、任务归档提交 `d96ec2d` 和会话提交 `e5f9b64`，当前领先 `origin/main` 三个提交。
- UI/UX 重构未修改后端、OpenAPI、数据库迁移、依赖、认证、权限、全局路由、应用壳层或生产配置；定向组件测试、lint、typecheck、build、发布闭环核心段、24 表边界、200% 缩放和真实 API 视觉验收已通过。
- 用户确认本任务的“生产上线”就是仓库唯一受支持、历史同类任务使用的 Hostdzire `https://geo.962850.xyz` 环境；Runbook 将其命名为预发布环境，不新建另一套 production 目标。
- 2026-08-04 只读基线为 release `mvp-20260803-211435-63d7a5b0bfaa`。Hostdzire 的 PartSignal 服务运行正常，共享环境文件权限为 `0600`，`nginx -t` 和公网 `live` / `ready` 冒烟通过。
- 已部署版本到当前 `HEAD` 的运行时代码差异只涉及发布管理前端组件、样式和测试；`redeploy-staging-fast.sh` 的六个关键门禁路径均未变化，符合快速重部署条件。

## 需求

- R1：部署来源必须是干净、已推送且 `HEAD == origin/main` 的本地主工作目录 `main`；只推送本次已审核提交和任务规划，不带入未识别文件。
- R2：只执行仓库入口 `make staging-redeploy-fast`，由脚本完成来源校验、安全归档、Hostdzire 资格门禁、构建、容器替换、健康检查、Nginx 校验、公网探针和 `current` 原子更新；不得手工绕过拒绝条件。
- R3：正常升级只链接 Hostdzire 现有 `/root/partsignal/shared/.env.staging`，不得读取、下载、输出、修改或重新生成真实秘密。
- R4：本次不备份、重建、恢复或迁移数据库，不修改线上业务数据，不创建验收数据；PostgreSQL 持久卷和 `/root/partsignal-data` 保持不动。
- R5：脚本成功后必须从本机通过真实公网域名完成 API 冒烟和登录后的 `/publications` 只读浏览器验收；不得在服务器安装浏览器，不得运行公网纵向 E2E 或更新视觉基线。
- R6：浏览器验收必须覆盖桌面、移动、三个一级视图、详情抽屉、现有状态与动作投影；只允许导航、筛选、打开/关闭详情和退出登录，不触发任何写操作。
- R7：任一来源门禁、部署、健康检查、浏览器或控制台检查失败即停止；不手工更新 `current`，不清理 release、镜像、备份或持久数据。若容器已经替换，则按既有兼容应用回滚路径恢复上一个已验证 release。
- R8：发布后进行 10 分钟有界观察，复核公网 `ready`、关键容器状态和应用级错误；记录 release ID、commit、回滚点、验收结果和残余风险，不记录凭据或业务正文。

## 验收标准

- [ ] AC1：部署前工作树干净、分支为 `main`，`HEAD == origin/main`，远端包含 `72c4dd3`、`d96ec2d`、`e5f9b64` 及经批准的本任务规划提交。
- [ ] AC2：`make staging-redeploy-fast` 成功生成不可覆盖的新 release，脚本自动探针通过且 `current` 指向该 release。
- [ ] AC3：公网 `live`、`ready` 和首页标题通过独立复核，PostgreSQL 与 Redis 状态为 `ok`。
- [ ] AC4：桌面 `/publications` 显示“待处理 / 发布成果 / 历史记录”，首屏可见行动区，无页面级横向滚动或遮挡。
- [ ] AC5：375×900 下发布工作和开放问题使用移动列表；关键操作入口可见，打开详情后 Drawer 占满可用宽度并可关闭、恢复焦点。

- [ ] AC7：页面操作只来自服务端 `primary_action` / `available_actions`，当前权限下不存在删除入口或前端猜测动作；验收不执行任何命令动作。
- [ ] AC8：登录、工作台和发布管理控制台无应用级 error，关键请求无认证、脚本、资源或路由失败。
- [ ] AC9：10 分钟观察后公网 `ready`、API、前端、Worker、Scheduler、PostgreSQL、Redis 与 `fake-oss` 仍正常，未发现本次发布引入的持续错误。
- [ ] AC10：任务记录包含部署 commit、新 release、前一 release、验证结果、失败处置或残余风险，且不含秘密或业务正文。
