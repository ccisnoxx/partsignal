# T6-C 删除恢复、T6-G 验收与 AC11 收尾

用户授权修复和定向验证，不部署、不提交推送。上一轮未提交的任务整理全部为保护基线。

## 设计与范围

- TanStack Query 持有服务器预览；弹窗只持有确认文本与显式恢复确认，不从错误 message 推导语义。
- 共享 lifecycle 是 List/Detail 删除命令 owner。永久删除失败关闭旧确认；重开后必须读实时预览并重新输入。读取失败后后台成功不能自动解冻；显式重读成功才恢复。提交前复核精确 Query 状态与服务端动作。
- 普通 DELETE 遇 GEO context/chain 409 后冻结该任务删除；显式重读 Detail 成功、关闭恢复弹窗后，用户重新打开并确认；不自动 replay。普通 revision 冲突沿用现有行为。
- 按预览/确认生命周期抽出永久删除弹窗，避免继续扩张原 480 行文件。保持既有认证 continuation、焦点、删除后缓存失效。
- 浏览器证实普通确认需要 RowActions 传递真实触发器；详情各读取分支固定弹窗挂载位置，防恢复失败丢失状态。列表 resolveTask 保持数据依赖且稳定回调，防表格单元格无谓重挂。
- T6-G 复用既有实现，核对 exact code、cached read failure、显式重载/重新确认、no replay；只补实际缺失的定向测试。
- AC11 历史前置指纹永远保留 NOT_CAPTURED，不重写历史通过。本轮开始保存独立基线；以当前行为验收、范围指纹和独立复核构成新的验收记录，明确其不证明历史无越界。
